## 1. Contract and source binding

The controlling report is [the pinned exact-data bridge](https://github.com/AgentSlop-Si/research/blob/511689fb34ffa88921b3d2a0dc801e048b49dce2/math/finalized/2026-10-17-resumed-mathematics-0916/reports/alg064/REPORT.md), sections 2 and 5–7. Its exact Git blob is `456f54002032c99901e7e842651235c658052261`; `sources/controlling_report.md` contains the exact fetched bytes. The earlier selection-directory copy had a trailing-newline difference, so it is not used as the byte authority. No historical source or untrusted package was executed.

Input consists of N>=1 exact complex dyadics x_j and exact rational 0<epsilon<=1. The target is

    X_k = sum_j x_j exp(+2 pi i j k/N), 0<=k<N.

All N returned values are complex dyadics and satisfy max_k |y_k-X_k|<=epsilon, in ordinary complex Euclidean modulus. This is absolute error and the transform is unnormalized. N=1 is copied exactly; an all-zero vector is returned exactly. Empty input, non-dyadic components, inexact floating inputs, malformed optional cap metadata, and invalid tolerances are rejected. The prior discovery semantics and declared-span convention are unchanged. The fallback's optional cap is validation metadata only; this module deliberately performs no recurrence discovery.

Exact arithmetic is over unbounded integers/rationals. The mathematical algorithm terminates for every finite valid input with sufficient resources. Allocation failure or interruption is a failed execution, never a certified result. The implementation may return a very conservative error bound; no relative-error or fixed-machine-word promise is made.

The underlying all-length chirp-convolution idea is classical Bluestein, not a new FFT claim. See [L. Bluestein, IEEE Transactions on Audio and Electroacoustics 18(4), 451–455 (1970)](https://doi.org/10.1109/TAU.1970.1162132), whose publisher metadata was checked. The construction and complete finite-precision proof needed here are supplied below rather than borrowed from an unspecified numerical library.

## 2. All-length identity, padding, signs and normalization

For N>=2 let L be the least power of two >=2N-1, and ell=log2 L. Then 2N-1<=L<4N. Define

    q_j = exp(pi i j^2/N),
    a_j = x_j q_j for 0<=j<N, and a_j=0 otherwise,
    b_0=1,
    b_r=b_(L-r)=conjugate(q_r) for 1<=r<N,
    all other b entries zero.

The two nonzero arms of b do not overlap because L>=2N-1. For j,k in [0,N-1], the difference k-j belongs to [-(N-1),N-1]; hence the circular lookup b_((k-j) mod L) is exactly exp(-pi i (k-j)^2/N). There is no alias to another populated coefficient. Therefore

    q_k sum_j a_j b_((k-j) mod L)
      = sum_j x_j exp(pi i [j^2+k^2-(k-j)^2]/N)
      = X_k.

Roots for q_j are constructed at residue j^2 modulo 2N. Reducing modulo N instead would be wrong for some parities. Mirroring b by equal values is correct because (-r)^2=r^2; it is not an additional conjugation of the mirrored arm.

For length L write F_+ and F_- for unnormalized DFTs with signs + and -. Orthogonality of the geometric sum gives

    circular_convolution(a,b) = (1/L) F_-(F_+(a) * F_+(b)).

The backend uses precisely two positive transforms, pointwise multiplication, one negative transform, and division by L. The final positive q_k recovers the requested positive-exponent N-transform. These identities hold for every positive integer N; there is no prime, smoothness or dyadic assumption on N.

The length-L DFT is computed by explicit bit reversal followed by spans 2,4,...,L. At a span s, its butterflies multiply the second arm by exp(sign*2 pi i j/s), indexed as root[j*(L/s)] in the length-L root table. Splitting the DFT into even and odd input indices proves each radix-2 combine; induction on ell proves the backend. No root is generated by a running floating recurrence.

## 3. Grids, root construction and termination

Put S=sum_j (|Re x_j|+|Im x_j|), a nonnegative exact dyadic, and let b be the largest denominator exponent of an input component. Select p>=b below and write h=2^-p. Every chirp and twiddle is stored at grid h/16. Initial x_j*q_j multiplication is rounded at grid h and then embedded exactly in grid h/16. Both FFT inputs, all butterfly data and pointwise products use grid h/16. Division by L converts to grid h with one rounding, and the final chirp multiplication rounds once to grid h.

Nearest-grid rounding of both real components has l1 error at most one grid unit; thus its Euclidean error is at most that unit. All additions/subtractions on a common grid are exact. Integer multiplication is exact before the two component roundings. Negative halfway cases are handled by the documented nearest-integer rule with ties toward positive infinity. Every local rounding error used below is bounded by h; the FFT's actual h/16 grid is a strictly finer implementation of that budget.

### A paid root constructor

The exact rational arctangent sums use

    pi = 16 atan(1/5)-4 atan(1/239).

For completeness, if a=atan(1/5), then tan(2a)=5/12 and tan(4a)=120/119. Subtracting atan(1/239) gives tangent 1. The resulting angle lies in (0,pi/2): a<1/5, while a>1/5-(1/5)^3/3 makes the difference positive. Thus 4a-atan(1/239)=pi/4.

For each alternating arctangent series, continue until the first omitted term is <=h/65536. Its absolute remainder is at most that term. Form the exact rational Machin sum, then round it to grid h/4096. The resulting pi approximation has an exactly computed error e_pi with

    e_pi <= 20h/65536+h/8192 = 7h/16384.

For any requested residue k modulo m, center k so |2k/m|<=1, and set alpha=(2k/m)*pi_hat. The code verifies |alpha|<4. Taylor degree t is selected by exact rational recurrence until

    4^(t+1)/(t+1)! <= h/128.

The degree-t cosine and sine polynomials are summed exactly at alpha, then rounded to grid h/16. Lagrange's real Taylor remainder bounds each component by h/128, and the mean-value theorem bounds its angle perturbation by e_pi. Thus the total l1 root error is at most

    2e_pi+2h/128+h/16 <= (647/8192)h < h.

The implementation computes the actual rounding differences and verifies the resulting rational radius <=h for every root. The stored receipt radius is rounded outward to grid h/256, still <h by the displayed slack. Conjugating a certified positive twiddle gives a certified negative twiddle with unchanged error.

Arctangent tails decrease geometrically; O(p+1) terms suffice. For the Taylor degree, after a fixed starting index the ratio of consecutive remainder bounds 4/(t+2) is <=1/2, so O(p+1) degree suffices. All loops terminate without assuming an external transcendental oracle.

## 4. Radix-2 forward-error lemma

Suppose an exact length-L input has maximum component modulus <=A, its stored input error is <=e_0, all twiddle errors are <=h, every butterfly multiplication rounding error is <=h, and h<=1/L. Let e_s be the maximum error after s stages. An exact intermediate entry has modulus <=2^s A. Approximate roots have modulus <=1+h. Therefore

    e_(s+1) <= (2+h)e_s+h*2^s*A+h.

Indeed the product error is <=(1+h)e_s+h*2^s*A+h; adding the first-arm error contributes one more e_s. The plus/minus butterfly additions are exact on the dyadic grid.

Set f_s=e_s/2^s. Then

    f_(s+1) <= (1+h/2)f_s+h*A/2+h/2^(s+1).

Since ell*h<=1, (1+h/2)^ell <= exp(1/2)<2. Unrolling gives

    e_ell <= L(2e_0+ell*h*A+2h)
            <= 2L[e_0+(ell+1)h(A+1)].              (FFT)

The same proof works for either exponent sign and for the finer grid h/16. It does not require relative accuracy, nonzero data or absence of cancellation.

## 5. Explicit end-to-end absolute-error budget

Define positive exact quantities

    C = 2L(2ell+3),
    D = (S+1)[(L+1)C+C^2]+1,
    K = 4D+4(ell+1)(SL+1)+S+3.

Select the first p>=b satisfying

    h<=1/L, and K h<=epsilon.                     (P)

For exact a and b from Section 2, the initial errors satisfy e_a<=h(S+1) and e_b<=h, with max |a_j|<=S and max |b_j|<=1. Applying (FFT) yields forward-transform error bounds

    E_A <= C h(S+1),   E_B <= C h.

The exact transformed amplitudes satisfy |A_k|<=S and |B_k|<=2N-1<=L. A rounded pointwise product consequently has error at most

    S E_B+L E_A+E_A E_B+h
      <= h[(L+1)C(S+1)+C^2(S+1)+1] = D h,

where h<=1 was used only to replace h^2 by h. The exact pointwise product has maximum modulus <=SL.

Apply (FFT) again to the negative transform. Divide by L exactly and round once to grid h. The convolution error is at most

    E_c = 2h[D+(ell+1)(SL+1)]+h.

For each requested coefficient, exact convolution modulus is <=S, by summing |x_j| against the unit-or-zero b coefficients. Multiplication by the approximate final chirp and final rounding thus give

    |y_k-X_k| <= (1+h)E_c+Sh+h
               <= 2E_c+(S+1)h
               = K h <= epsilon.

This proves the contract simultaneously for all N outputs. It covers zeros, cancellation, large dynamic range and arbitrarily small epsilon; no unspecified conditioning constant appears.

### Finite precision

K is an explicitly computable positive dyadic polynomial in S,L,ell, so (P) holds for sufficiently large p. More explicitly,

    p = max(b, ceil(log2 L), ceil(log2(K/epsilon)))

suffices. The code obtains the least such integer by exact comparisons, avoiding floating logarithms. Since K=O((S+1)L^2(ell+1)^2),

    p = O(b+log(N+1)+log(S+1)+log(1/epsilon)+1).

The bit length of the *encoding* of epsilon is separately charged: a rational very close to one can have a long encoding despite small log(1/epsilon).

## 6. Complete operation, bit and storage ledger

Let E_raw be the raw data/epsilon encoding length, T the maximum raw input integer or denominator bit length including epsilon, and let r be the number of supplied failed-work records. Let E_invoice be their complete encoding length, including strings and integer fields, and T_invoice the maximum bit length of a supplied integer field (take T_invoice=1 for r=0). Write E=E_raw+E_invoice, W=O(p+log(S+1)+log(L+1)), and

    H = O((p+1)(p+log(L+1)+log(p+2))).

Let A(t) bound an exact rational/integer scalar operation including multiplication M(t), division D_int(t), gcd/reduction G(t), comparison, addition and copying on O(t)-bit operands. One conservative choice is A(t)=O(M(t)+D_int(t)+G(t)+t). Constants account for temporary products of two t-bit integers.

Why H suffices: the root angle denominator divides m*2^(p+12), with m<=max(2N,L)<=L+1. If the angle has denominator q and Taylor degree t, every partial-sum denominator divides q^t t!. Its logarithm is O(t(p+log L+log(t+1))). Partial-sum magnitudes are bounded by exp(4), so numerator lengths have the same bound. Arctangent partial sums have denominators dividing a geometric power times the product of the odd indices used, with O(p log(p+2)) bits. Fraction reduction and temporary cross-products preserve these O(H) bounds. The deliberately simple rational constructor is therefore fully finite and charged, without a free root table.

Why W suffices: exact inputs on grid h have integer magnitude <=2^p S. FFT stage growth and the displayed error bounds keep all stored data magnitudes bounded by a fixed polynomial in L,ell,S+1, for example O(L^2(ell+1)^2(S+1)). Their grid is h/16; integer products have at most twice the stated stored width. Hence W covers kernel operands/results up to constants. Original numerator/denominator reads and epsilon comparisons are charged separately at T and E, not silently squeezed into W.

| Stage | Count and charged width | Live storage |
|---|---|---|
| Validate/read exact raw data and epsilon; compute S,b | O(E_raw) bit reading plus O(N) exact operations at O(T+log N) | O(E_raw) input storage |
| Validate/copy all r prior invoices and sum counters | O(E_invoice+r A(T_invoice+log(r+1))) | O(E_invoice+r(T_invoice+log(r+1))) retained/receipt bookkeeping bits |
| Select L,p and compute C,D,K | O(p+log N+1) operations at O(T+p+log N) | O(T+p+log N) bits |
| Certified pi and degree selection | O(p+1) rational operations at H | O(H) scratch bits |
| N chirps and L/2 twiddles | O((N+L)(p+1)) rational operations at H; residue squares/moduli included | O((N+L)W)+O(H) bits |
| Form two padded arrays and initial chirp products | N complex products, O(L) initialization/copies | O(LW) bits |
| Three radix-2 transforms | exactly 3(L/2)ell complex rounded products and same number of butterfly add/subtract pairs; O(L ell) index operations | O(LW) bits |
| Pointwise products | L complex rounded products | O(LW) bits |
| Normalization and final chirps | N complex divisions/roundings and N complex rounded products | O(NW) bits |
| Output all N dyadics and receipt | O(N) fraction reductions/writes and actual output bits | O(NW) bits plus invoice storage |

The code's meter records named routine invocations and maximal observed operand/result widths. These are **not** CPU instruction counts and do not claim to count each hidden Python Fraction gcd separately. The mathematical A(H) ledger explicitly pays for those gcd/division operations. Logged wall time is an observation of the finite regression only.

One conservative full fallback bit bound, including setup, is

    O(E
      + r A(T_invoice+log(r+1))
      + N A(T+log(N+1))
      + (p+log(N+1)+1) A(T+p+log(N+1))
      + (N+L)(p+1) A(H)
      + L log(L+1) A(W)
      + output_bits).

Peak additional numerical fallback storage is O(LW+H+T+p), besides raw input and returned output. Separately charge O(E_invoice+r(T_invoice+log(r+1))) for retained/copied invoice records, list bookkeeping and accumulated counters; this conservative bound includes all supplied strings and integer fields. The r records need not be bounded by N, and their scalar-operation counters need not fit in T or W. Summing them uses at most r additions on T_invoice+ceil(log2(r+1))-bit integers, which explains the separate invoice term. No invoice accounting is hidden inside an O(N) input scan. The reference holds several constant-many FFT arrays concurrently; no in-place-memory optimization is claimed. Root preparation stores only constant-many large rational temporaries per root; the tables contain dyadic grid integers.

### Cumulative unsuccessful front-end charges

If discovery, a coefficient adapter or a residual certificate fails after work C_1,...,C_r, the invoice is

    C_total = C_1+...+C_r+C_this_fallback.

No front-end cost becomes zero because fallback was selected. In particular the prior full cap solve retains its controlling bound O(N(d+1)^2 A(H_solve)) and its validation/verification work if actually performed. Any earlier failed attempts are likewise added. Their peak space is charged in the full pipeline; it can be released before the FFT, so sequential peak space is the maximum, not the sum, of stage peaks (plus retained inputs/invoices).

`FailureCharge` is an immutable pass-through record of stage label, scalar-operation count, operand width, symbolic bit-cost expression and detail. The fallback validates the record shapes, retains every supplied record in order, totals counts and copies every bit-cost term. It does not falsely claim it can detect an upstream caller that omits work before invoking it. Production integration must supply the truthful complete existing invoice. The late-rejection regression performs two real supplied-coefficient verification attempts, rejecting the second only at tail index 16, then checks that all 170 performed real-operation/comparison charges survive. This does not redo recurrence synthesis or claim a new discovery algorithm.

### Precisely what improved

The numerical transform kernel changes from O(N^2) arithmetic to O(N log N) rounded complex arithmetic, for every N. The *whole reference*, including rational root construction and processing r prior invoices, uses O(r+N(p+log N+1)) scalar operations with nonuniform bit widths, plus the separately charged encoding reads. It is not being advertised as O(N log N) total bit time, as a near-optimal root algorithm, or as empirically faster Python. For precision growing faster than N, the rational preparation may dominate the former quadratic kernel. Efficient roots, tighter constants and production benchmarking remain separable optimizations.

## 7. Fresh checks and independent transcendental enclosures

Run `python checks.py` from this directory. Only newly authored standard-library modules are imported. `CHECK_RESULTS.json`, `OUTPUT_VECTORS.json` and `checks.log` bind the source hashes actually used. There are 34 cases, 600 output bins, N from 1 to 65 and maximum selected p=379. Twenty-nine cases use the FFT branch, three the zero branch and two N=1 copying. The family includes odd, prime, nonprime composite, power-of-two, zero, positive-sign and unnormalized-constant sentinels, large cancellation/dynamic range, and late rejection with cumulative invoices.

`independent_oracle.py` does not import the backend and uses no chirp convolution or FFT. Its independent pi formula is

    pi=4[atan(1/2)+atan(1/3)],

proved by tangent addition and the first-quadrant angle. Its independently coded alternating sine/cosine recurrences use first-omitted-term bounds once term magnitudes decrease; it directly sums the N-transform at every output. Each real/imaginary target is enclosed in an outward-rounded dyadic rectangle. The checker verifies that the farthest rectangle corner from each returned y_k has squared distance <=epsilon^2. Every serialized box therefore supplies an independently checkable exact enclosure witness, rather than a rounded floating agreement or reuse of the backend node function.

Six source mutations are rejected by these enclosures: wrong chirp sign, missing chirp square, wrong inverse sign, missing L normalization, insufficient padding and wrong twiddle stride. Five receipt mutations are independently rejected: dropping an earlier failure charge, declaring roots free, undercounting butterflies, false precision and false error bound. Ten malformed-interface controls and four non-string invoice-detail controls are rejected. The source mutation hashes are recorded; the mutated files derive only from this freshly authored module.

Independent review found that the first candidate did not type-check `FailureCharge.detail`, allowing an invalid mutable list in an otherwise frozen record. The corrected candidate requires a string detail before accepting any invoice, including on the N=1 shortcut. List, dict, None and integer detail regressions now reject; the complete numerical/ledger suite was rerun on the corrected bytes. Review also separated the cost of an arbitrary number r of arbitrary-width prior invoices from raw input validation. A new N=1 interface test preserves 129 synthetic records carrying 4,097-bit counters and 2,049-bit width fields; these are explicitly encoding controls, not claims of performed discovery work. These corrections change invoice-shape validation and accounting, not the numerical proof.

Finite checks support transcription and code binding. The all-N guarantee is the proof in Sections 2–6, not extrapolation from N<=65. Independent proof/source review remains necessary for acceptance; the author's independently formulated numerical oracle is not being mislabeled as a different human/agent review.
