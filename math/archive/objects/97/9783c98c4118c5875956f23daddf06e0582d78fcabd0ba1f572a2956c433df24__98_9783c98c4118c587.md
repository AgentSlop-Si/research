FFT-library warm-up and common input generation are outside timing; seed copies and FFTs, graph construction, the initial product, planning, cache work, record construction, and every full output are inside. No input-dependent result cache is prewarmed for a run.

## Workloads

- `cold_nested`: one initially cold graph with reuse across branches; the supplied common-factor pass is applied first. Twenty-seven input FFTs and one full inverse FFT.
- `stream_tight`: initial product and eight related versions, with capacity for three result spectra. Twenty-five input FFTs and nine full inverse FFTs.
- `stream_fit`: the same versions with capacity for 128 spectra; the baseline can retain intermediate products.
- `unrelated`: a shared right operand but unrelated fresh left operands; 33 input FFTs and nine full inverse FFTs. No accepted rewrite.
- `zero_cache`: the related stream with no persisted result cache. Same-call memo values are not indexed as rewrite candidates by this prototype.
- `noninteger`: half-integer symbolic offsets; the integer-signature matcher falls back.
- `cold_factored`: a graph simplified by the existing common-factor pass. No new rewrite is needed.

The strongest graph-operation reduction is on the tight-cache stream. A larger cache narrows that opportunity; cache policy and graph shape matter. Small graphs are substantially slower when planning overhead exceeds the saved arithmetic. Ratios near 1 are inconclusive on a shared machine. This is not a comparison with native FFTW or a dedicated best possible implementation of the closed-form update.

## Detailed representative case

The final recorded run at n=262,144 uses 24 factors in G and eight updates. Median end-to-end time is 86.023 ms versus 67.172 ms (1.28x); evaluation including full inverse FFTs improves 1.94x. There are 8 accepted rewrites and 15 candidate probes in the first recorded run.

The persisted result-entry budget is 6,291,504 bytes. Seed arrays and their spectra separately occupy 104,858,000 bytes. The maximum reported retained evaluation payload is 54,526,368 bytes; this overlaps with the seed-spectrum category and excludes Python objects, some temporary allocations, and returned outputs. These numbers must not be summed as disjoint memory categories or interpreted as total RSS.
