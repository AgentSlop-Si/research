Completed 2026-10-10 UTC. This package covers all 25 exact hashes assigned by batch_05.json: 109,783 bytes and 2,449 source lines, read first to last. All 44 recorded source occurrences were independently matched to the assigned bytes across 20 original archives and local Library copies. **The assignment's source-reading work is complete. This is not automatic mathematical, runtime, novelty, authorship, or security certification.** No supplied source was executed, imported, compiled, or AST-parsed. ## Results that materially change interpretation

1. **The two-round verifier has partial candidate-word coverage.** The exact 00fb1213… source tests baseline_word and candidate_word only when a key is present (lines 38–43). All ten saved certificates include baseline_word; only one includes candidate_word. It also compares reported add/sub counts to a formula rather than deriving them from the circuit (line 58). The overall saved PASS does not establish candidate-word replay for the other nine cases. All ten stored full-state target matrices and their digests do reconcile, which is a separate, narrower result. Stored gate words were not executed here.

2. **The adaptive optimizer does more work than its headline/cost proxy suggests.** The 05bdb054… source can run full greedy replanning before add_coefficient/add_point (lines 418–426), despite the opening single-append producer-update claim. Every group cache hit republishes copies for all group members (lines 307–322), work absent from the union-width proxy. Partition history grows without a bound, and storage_bytes reports selected arrays rather than total process memory. The archived changing-workload scenario already shows a 0.962546× speedup ratio, i.e. a slowdown. Other archived scenarios improve, but these are historical measurements and not universal performance guarantees.

3. **The binary profile reader is only partially endian-normalized.** The exact 8e2e391d… C++ source calls a normalizing helper for its header, but subsequent scalar, frame and transition reads use raw host byte order (lines 35–39). Its little-endian producer format therefore requires a little-endian reader host as written. The exact header dependency was inspected inertly; no C++ compilation occurred.

4. **The reduced-center script does not establish an every-length exponent.** It checks a finite coefficient identity, finite-network parameters, and numerical comparisons. Its small matrix test algebraically subtracts the same off-diagonal coefficient; it does not independently replay the actual restoration schedule. The final comparison of 5e-10 with a tensor gap is not a proof of the finite-to-every-length interface. Fresh integer and high-precision Decimal checks do reconcile the h24 padded tensor gap near 5.2296989632709109e-10, without certifying the stronger claim.

5. **The v4 stored data retain word/table-budget failures.** Fresh data arithmetic confirms 15 of 20 descriptor keys exceed the stated one-word budget and all 20 exceed the stated table-exponent budget. There are 9,796 misses in 10,240 lookups. Stored decoder errors satisfy their recorded bound, but that does not repair the separate budget violations. The optional external macro-manifest check was null in the historical output.

6. **Packed-transpose semantic checks are not uniformly 64-bit word checks.** Only 15 of 30 cases in one saved transpose report and 17 of 36 in the other fit a 64-bit tile. Largest stored tiles are 8,192 and 7,168 bits, respectively. Full packed rows and intermediates need their own width bounds. Arbitrary-precision Python identities cannot be billed automatically as one machine-word operation.
