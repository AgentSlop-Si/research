# Exact integer recovery: error accounting and a structured fast path

Research continuation, 9 October 2026. This package separates two questions:

1. Can the approximate full-output surrogate be rounded into a certified exact
   integer convolution without losing its asymptotic saving?
2. Can the user's baseline-plus-correction idea give a useful exact integer
   multiplication fast path without relying on that approximation?

The first question is resolved here only for the stated worst-case error
certificate: it forces the integer-input sampler to its exact-input bypass.
That is not a lower bound on every approximation/refinement algorithm. The
second question has a working positive answer for operands with few constant
runs, few nonzero digits, or a repeated-digit baseline with few exceptions.
These are standard algebraic identities turned into explicit exact programs;
no novelty or arbitrary-input FFT breakthrough is claimed.

## 1. Correct convolution normalization and rounding budget

Let a,b be integer coefficient vectors, padded with zeros to a power of two N
at least len(a)+len(b)-1. Write U for the unitary N-point DFT, La=||a||_1,
Lb=||b||_1, A2=||a||_2, and B2=||b||_2. Ordinary linear convolution is

    c = sqrt(N) U* ((Ua) pointwise-multiplied by (Ub)).

Assume approximate forward transforms satisfy the simultaneous bounds

    ||e_a||_infinity <= epsilon_a La/sqrt(N),
    ||e_b||_infinity <= epsilon_b Lb/sqrt(N).

By expanding `(Ua+e_a)(Ub+e_b)`, applying Cauchy-Schwarz, and using
||U* z||_infinity<=||z||_2, exact inverse transformation gives coefficient error
at most

    E_forward = epsilon_a La B2 + epsilon_b Lb A2
                + epsilon_a epsilon_b La Lb.                 (1)

For example, the first term follows from
`sqrt(N)||e_a pointwise Ub||_2 <= sqrt(N)||e_a||_infinity ||b||_2`.
The cross term follows by bounding one error in infinity norm and the other in
2-norm. No factor of N is silently dropped.

If the inverse transform also uses the strong surrogate contract with parameter
epsilon_i on the approximate product w, its additional convolution error is
epsilon_i||w||_1. Since

    ||w||_1 <= (A2+epsilon_a La)(B2+epsilon_b Lb),

a sufficient complete bound is

    E = E_forward
        + epsilon_i (A2+epsilon_a La)(B2+epsilon_b Lb)
        + rho < 1/2.                                        (2)

Here rho is a separately certified absolute coefficient-error allowance for
numerical implementation effects. Under the stated error assumptions, nearest
integer rounding then recovers every coefficient exactly. The code substitutes
integer upper bounds ceil(A2),ceil(B2), computed by integer square roots, making
its displayed rational bound conservative.

The word **certified** matters. A Monte-Carlo tail theorem does not verify that
its good event occurred on this run. Applying (2) to such bounds gives exact
rounded coefficients only on their joint success event, with failure at most
delta_a+delta_b+delta_i by a union bound. It does not turn the algorithm into a
deterministically correct or Las Vegas multiplication routine.

## 2. What this certificate requires of accuracy

For two length-n digit arrays whose magnitudes are of order D=base-1,
La,Lb are of order nD and A2,B2 are of order sqrt(n)D. The positive terms in
(2) require forward epsilon of order at most

    1/(n^(3/2) D^2)

when both forward errors have comparable budgets, and inverse epsilon of order
at most `1/(n D^2)`. Thus the sample count `O(epsilon^-2 log(N/delta))` becomes
polynomially large and the existing exact-input fallback activates. This is a
sufficient-certificate analysis, not a necessary accuracy bound for every
possible structured or correlated-error transform.

There is a sharper statement for this PARTICULAR bound and integer inputs.
Suppose b is a nonzero integer vector. Certification of (2) implies

    epsilon_a La B2 < 1/2.

For a nonempty integer residual tail of a, let Lt be its l1 mass and s_t its
nonzero count. Then Lt>=s_t>=1 and B2>=1. The head/tail sample request obeys

    k_tail >= 4 Lambda (Lt/La)^2 / epsilon_a^2
            > 16 Lambda Lt^2 B2^2 >= s_t,

where Lambda=log(4N/delta)>1. The deterministic head-only condition would require
`Lt<=epsilon_a La<1/(2B2)<=1/2`, impossible for a nonempty integer tail.
Therefore, under this certificate, EVERY nonempty integer tail reaches the
exact-input bypass rather than a genuinely sparse sampled residual. The same
argument applies to b. Empty tails and zero operands are trivial exact cases.

This closes a specific proposed bridge through the current l1-scaled sampling
certificate. It does not rule out better error structure, correlated sketches,
deterministic residual recovery, modular methods, or other representations.

## 3. Finite precision, verification, and carries

If pointwise multiplication introduces a certified error gamma in each Fourier
product coordinate, exact inversion contributes at most N*gamma to coefficient
error. With an approximate inverse, its l1-based allowance can grow by another
epsilon_i*N*gamma. These terms, plus inverse-output and final-rescaling errors,
must be included in rho or explicitly separated. Forward numerical errors must
already be included in the forward allowances. The present code does not
provide interval-certified FFT arithmetic.

Convolution coefficients of nonnegative n-digit inputs can reach
`n*(base-1)^2`. Merely resolving adjacent integers near that magnitude requires
roughly log2(n)+2log2(base) significant bits, before stability guard bits.
This magnitude observation is not a sufficient floating-point stability proof.
The finite q-kernel's conditioning issues are not removed by final rounding.

After coefficients are exact, ordinary divmod-by-base carry propagation is
exact. Carries do not generally repair coefficient-rounding errors; one wrong
coefficient can change many later digits. `unique_integer_from_interval` only
accepts an externally certified interval containing precisely one integer;
it does not create a certificate for the interval itself.

A random modular polynomial fingerprint can cheaply reject many wrong candidate
convolutions: if the error polynomial is nonzero modulo a prime p and has degree
d, evaluation at a uniform field point misses it with probability at most d/p.
That is still a probabilistic verifier. A fixed collection of such tests is
not asserted to prove equality for every error polynomial. Evaluating at a huge
integer that encodes all coefficients also does not make the required large
integer multiplication free. No new general deterministic linear-time verifier
is claimed here.

## 4. Positive exact bridge: shared baseline plus sparse corrections

For base beta>=2, let A have n little-endian digits a_j. If a candidate digit k
occurs at all but h positions, then

    A = k R_n(beta) + sum_(j in exceptions) (a_j-k) beta^j,
    R_n(beta) = (beta^n-1)/(beta-1).

Consequently

    AB = k B R_n(beta)
         + sum_(j in exceptions) (a_j-k) B beta^j.            (3)

This is the requested baseline/correction identity at the digit-polynomial
level. The correction discovery and every shifted product are charged.
The implementation detects a majority baseline with a linear scan, counts its
exceptions, also counts nonzero digits and constant runs, and inspects both
operand orientations. The majority candidate is not claimed to find an
arbitrary mode; it does find a baseline with h<n/2 exceptions. Every selected
decomposition is nevertheless exact and checked before execution.

The public `max_terms` cap bounds structural work. If none of these descriptions
fits the cap, the routine returns `None` with metadata, leaving the caller's
general multiplication fallback explicit. It does not run a hidden quadratic
or FFT backend on unrelated inputs.

### Full integer coefficient convolution

For a constant run of length ell and digit k, its convolution with b has
coefficient

    k * sum_(i=max(0,t-ell+1))^(min(m-1,t)) b_i.

One prefix-sum table of b serves every run. Sparse exceptions add signed shifted
copies of b. `try_structured_convolution` materializes every ordinary convolution
coefficient and preserves the requested length, including leading zero input
coefficients. It costs O(n+m+h*m) for a repeated-digit baseline with h exceptions,
or O(n+r*m) plus output initialization for r constant runs. The symmetric
orientation is available. Fixed h or r therefore gives O(n+m) exact arithmetic
work for every value of the other operand.

These coefficients require O(log(min(n,m))+2log(beta)) bits. The bound is on
exact arithmetic/word work with sufficiently wide words, not unit-cost arbitrary
precision bit operations. Prefix sums and arithmetic traffic are included.

### Integer product with bounded digit carries throughout

The separate `try_structured_product` avoids wide convolution coefficients.
For the baseline term in (3), it:

1. Multiplies B by the single digit k.
2. Subtracts that result from its n-digit shift, obtaining kB(beta^n-1).
3. Divides exactly by the single digit beta-1.
4. Adds or subtracts each single-digit-multiplied, shifted correction.

All kernels operate on digit lists. Whole-integer multiplication is used only
by the test oracle. In single-digit multiplication, the carry is below beta;
in single-digit division, the remainder is below beta-1 and the next numerator
is below beta^2. Addition and subtraction use one-bit carry/borrow. Negative
corrections cannot make the running result negative: the baseline covers every
not-yet-subtracted digit, and positive corrections only increase it.

A nonzero constant run is the same repdigit calculation shifted to its location;
the program sums those terms exactly. A sparse operand uses one shifted
single-digit product per nonzero coefficient. These paths take
O(s*(n+m)) digit work for s structural terms, including shifts, copies and
all carry operations. With a fixed term budget this is linear digit work.

For w=ceil(log2(beta)), arithmetic kernels manipulate at most 2w-bit temporary
values, so their arithmetic bit cost is O(s*(n+m)*(M(w)+D(2w,w))), using the
chosen small multiplication/division implementation. For a fixed radix their
arithmetic kernels are constant-width streaming passes. Planning and address
operations use O(log(n+m))-bit counters; no claim is made that Python's entire
runtime or arbitrary-word bookkeeping has unit bit cost. This is a restricted
exact integer path, not a worst-case integer-multiplication improvement.

## 5. Verification and use

Run `python3 run_audit.py` with the standard library. The audit checks bases
2,3,10,256,65536; repdigits, sparse exceptions, constant runs, sparse operands,
zero inputs, both orientations, and an explicit unstructured decline. Direct
integer products and ordinary coefficient convolution serve as independent
oracles only in the test file. No floating-point FFT participates.

The captured run has 154 accepted exact products and one declined case,
151 full coefficient-convolution checks, and five rational rounding-budget
checks. Inputs reach 4,096 digits. For two
exceptions from a repeated base-256 digit, the recorded arithmetic digit-kernel
steps are 706, 2,818, 11,266, and 45,058 at lengths 64,256,1024,4096. These are
counts for the implemented restricted workload, not native runtime speedups.
Input scans, planning, shifts, copies and output writes are additional charged
linear work, and are not presented as included in that particular kernel counter.

```python
from structured_integer import try_structured_product

digits, info = try_structured_product(a_digits, b_digits, base=256, max_terms=8)
if digits is None:
    # Use the existing general multiplication backend.
    pass
```
