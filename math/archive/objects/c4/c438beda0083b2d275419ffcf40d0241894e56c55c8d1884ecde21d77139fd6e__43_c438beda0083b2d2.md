# Phase 8 research note — persistent sums of convolution products

**Date:** 9 October 2026  
**Scope:** An adaptive numerical software system for *families of related inputs*. Not a new universal sub-N-log-N FFT or integer multiplication bound.

## 1. The central result: one-variable convolution jets

Fix length N. Work in the commutative algebra `R = K[z]/(z^N-1)`, where addition is coefficientwise addition and multiplication is length-N **circular convolution**. Signals are elements of R. Let `F(x,b_2,...,b_s)` be a finite expression built using addition, scalar multiplication and convolution; inputs may be repeated and subexpressions shared. Regard all inputs except x as fixed. Then `F` is a polynomial in x over R, with some finite degree d:

`F(x+u) = C_0 + C_1*u + ... + C_d*u^{*d}`.

This is an identity in `R[u]` and is valid over any commutative coefficient ring, including finite fields. The coefficients are the Hasse/Taylor coefficients `C_h`, not derivatives divided by a possibly non-invertible `h!`. Their recursive construction follows ordinary polynomial arithmetic: at addition nodes, add coefficient vectors; at product nodes, convolve coefficient vectors in the *degree* dimension, using circular convolution in R for coefficient multiplication. The graph is traversed once in topological order and preserves structural reuse.

For an impulse edit `u=Δe_t`, the unit impulses satisfy `e_t*e_s=e_(t+s mod N)`, so

`F(x+Δe_t)[q] = C_0[q] + sum_{h=1}^d Δ^h C_h[(q-ht) mod N]`.

The formula is **exact algebraically** and handles higher powers of the edited input. It avoids invalid first-order approximations for repeated leaves (for example `x*x`).

The FFT maps convolution to pointwise multiplication. We compute C_h via the same polynomial graph with half spectra as scalar coefficients, then invert to the time domain. All arrays are real-valued, so rFFT compression applies. The equations are exact; the SciPy implementation is finite precision.

### Complexity with every charge visible

Let S be the number of distinct initial signal leaves, E the number of reachable graph nodes, d the polynomial degree of target x, and M the number of related variants. The current polynomial-jet compiler has a conservative arithmetic upper bound:

- Initial independent seed FFTs: `O(S N log N)`.
- Degree-coefficient construction: `O(E d² N)` pointwise operations; input-independent symbolic construction is also performed and consumes memory.
- Up to d+1 inverse FFTs: `O((d+1) N log N)`, excluding coefficients proven to be short impulse combinations.
- Temporary jet work arrays: up to `O(E d N)` complex values, plus input and output arrays and the normal graph/caches.
- One known impulse edit, full length-N output: `O(N d)`, and output size is already `Omega(N)`.
- One known impulse edit, Q selected output coefficients: `O(Q d)` after kernels are prepared.
- M single-edit versions: `O(S N log N + E d² N + (d+1)N log N + M d N)` total arithmetic, under a fixed interpretation of the graph and assuming S,E,d are small relative to N.

For fixed S,E,d and many explicit full-output versions, amortized per version approaches `Theta(N)`. **This is a restricted dynamic workload, not a theorem about fresh arbitrary Fourier transforms.** We do not claim general sum-product polynomial circuits always have small d, E, or preparation state.

For k distinct known edit positions, `u=sum Δ_t e_t`, and the polynomial's hth power contains up to k^h ordered terms. The engine supports explicit shifted sums when small; otherwise it uses `rfft(u)` reconstructed directly from phases, forms the polynomial in frequency space and calls `irfft`. The latter costs `O(kN+dN+N log N)` arithmetic after precomputation (plus input bookkeeping), not `O(dN)` for unbounded k.

### A worked nonlinear example

Let `Y=A*A + B*C`. Then `Y(A+Δe_t)=Y(A)+2Δ roll(A,t)+Δ²e_(2t)`. The three coefficients are `C0=A*A+B*C`, `C1=2A`, `C2=e0`. The prepared graph detects `C2=e0` exactly as a **symbolic impulse**, not by thresholding floating-point values. Thus the quadratic term changes just a single output location.

For `Y=A*A*A+2A*B+C*D*E`, the coefficients are

- `C0=A*A*A+2A*B+C*D*E`
- `C1=3A*A+2B`
- `C2=3A`
- `C3=e0`

One-position edits therefore require two shifted dense kernels, one impulse correction and one base copy, not a new FFT.

## 2. Persistent canonical algebra

Our hash-consed DAG performs local simplification for scalar constants, combines identical additive terms, flattens associative operations, and sorts children for commutativity. It is **not** a complete canonical representative of equivalence modulo distributivity, nor an equality-saturation solver. `factor_common` performs one conservative deterministic common-factor rewrite across the terms of a sum. This can reduce per-frequency pointwise operations on *any input*, but makes no asymptotic improvement to arbitrary FFT complexity.

`replace` and `edit_version` preserve input leaves and share unchanged subtrees. Because multiplication is normalized to n-ary nodes, a leaf change in an m-factor product may require O(m) tuple copying at the changed parent. This intentionally differs from the O(log m) balanced-tree rewrite in Phase 7 and is an engineering tradeoff of canonicalization versus edit locality.

## 3. Exclusion of inflated novelty claims

- The convolution theorem, polynomial difference expansion, truncated Taylor jets, reverse/forward automatic differentiation, and shared expression graphs are established ideas. For context see `jax.experimental.jet` (Taylor AD), `egg` (e-graphs), and classic arithmetic-circuit differentiation.
- Precompiled kernels beat fresh optimized FFT on streams where changes and target operands are known, but a **hand-written specialized formula beats our general compiler in the benchmark**. Better ergonomics/generality are not an asymptotic breakthrough.
- Degree d and circuit size E can scale with the problem. The claimed fast path is conditional on small d and reuse over M variants.
- Selected time coefficients cost O(dQ) only after kernels have been prepared. This is not the same output requirement as a full transform.
- Phase 7 import trusts the source spectrum as already computed and copies arrays. Incorrect/malicious source metadata can break consistency; no costly verification FFT is performed.
- This is numerical float64 code. Exact mod-97 tests validate algebra for small cases but do not certify rounding at large N, nor supply OpenAI #130's exact complex-arithmetic implementation or the fixed-tape integer-multiplication theorem.

## 4. Executable checks

`python -m unittest discover -s tests -v`: numerical comparisons with independent SciPy expressions for linear/quadratic/cubic and multi-edit cases, hashing/canonical forms, memory budget, fallback, graph persistence, and Phase-7 seed-spectrum integration.

`python exact_modular_audit.py`: 480 exact, independent **time-domain** comparisons over F_97, on four expression graphs with degrees 1–4. The reference directly evaluates the changed inputs, while a separate integer polynomial-jet calculator expands the change and checks the outputs. These cases are reproducible and do not call FFTs.

`python benchmark.py`: cold total-time comparisons at N=4,096,16,384,65,536,262,144; 48 variants, d=1,2,3, and partial output. Includes 5 seed rFFTs for each method, preparation time and output materialization. A repeated benchmark still has cache/machine noise. No FFTW/eFFT/CrocSwap head-to-head claim is made.

## 5. Next falsifiable research targets

1. **Compiled kernels:** Generate specialized array instructions from the symbolic `C_h` graphs, so generic execution approaches the hand-written baseline. The current graph is usually slower than an expert-written update formula.
2. **Reuse across multiple varying leaves:** Derive and cache low-total-degree multivariate jets without enumerating every monomial; benchmark representation size versus bitset support and circuit size.
3. **Structured exact arithmetic:** Implement the same algebraic optimizer over native modular polynomial coefficients, using a correct NTT/CRT backend and explicit bit-cost accounting. Do not conflate a dynamic input update with a fresh multiplication upper bound.
4. **Structural optimality study:** Define a constrained rewrite grammar and cost measure (calls, memory traffic, cache misses), compare the restricted factoring search to `egg`-style equality saturation. A finite example can be independently checked; no claim of beating all known algorithms follows from it.
5. **External comparator:** Benchmark identical workloads against event FFT/eFFT and hand-specialized C++ FFTW; include preprocessing, input acquisition, and the same output scope.
