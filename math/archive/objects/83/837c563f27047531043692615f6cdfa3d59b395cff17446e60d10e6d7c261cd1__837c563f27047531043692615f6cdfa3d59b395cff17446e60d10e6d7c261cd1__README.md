# Exact fusion of noncommuting affine-cycle Fourier filters

This is a constructive composition of previous graph ideas, with shared
coefficient preparation and shared cyclic closure. It is more than choosing
the fastest existing fast path: the audited input is rejected by both
individual filters, while their ordered composition succeeds.

For a supplied list of d affine-cycle filters, r pooled scalar parameters,
and a verified final defect with s nonzero entries, the method computes all
exact Fourier outputs using

    (1+r+6d+2s) N + r(log2 N+2) + d

field operations. This includes root-table construction and validation,
every source row at every layer, the complete defect transform, every
cyclic solve, and the input-dependent closure inverses. For two filters
sharing one parameter and one final defect, it is **16N+log2 N+4**.

The filter parameters are supplied side information, not discovered for
free. The method is a restricted-family fast path. It does not establish
an arbitrary-input exact o(N log N) Fourier transform.

## 1. Operators and why the order matters

Use the positive-exponent DFT F, with entries q^(kj). For an affine
monomial operator

    (M_i x)[j] = q^(b_i j) x[(a_i j+c_i) mod N],

the preceding affine-cycle component proves

    F M_i = Mhat_i F,
    (Mhat_i y)[k] = q^(-c_i a_i^-1(k+b_i)) y[a_i^-1(k+b_i)].

Set L_i=I-lambda_i M_i and Lhat_i=I-lambda_i Mhat_i. A query is accepted
only after explicitly computing and verifying

    u = L_d L_(d-1) ... L_1 x,

with at most s nonzero coordinates. Apply F to obtain

    F u = Lhat_d Lhat_(d-1) ... Lhat_1 F x.

Compute every coordinate of v=Fu from the s defects. Starting with v,
solve Lhat_d first, then Lhat_(d-1), and so on down to Lhat_1. The final
vector is exactly Fx. These operators generally do not commute, so the
reverse-order solve is essential. Their intermediate residuals may be
dense; the algorithm never attempts to Fourier-transform each intermediate
residual separately.

Choose N dyadic, a_i=1 mod4, and b_i,c_i odd. Both the source and target
affine permutations are single N-cycles. The proof is included in the
dependency's README, and every actual cycle is also verified by traversal.

## 2. Shared preparation is real reuse

Filters reference a finite pool of r supplied lambda values. Every value
must be used by at least one filter. A pool entry is prepared once during
the query; there is no cross-query cache.

For each pool value lambda, build one table

    scaled[e] = lambda q^e,  0 <= e < N.

Both source-edge coefficients lambda q^(b_i j) and target-edge coefficients
lambda q^(-c_i a_i^-1(k+b_i)) are merely different indexings of this same
table. In particular, they require no second N-entry set of field products.

Each target cycle has edge-weight product -lambda^N, independently of its
affine parameters. Thus all filters with the same lambda share the exact
closure inverse

    h_lambda = (1+lambda^N)^-1.

Compute lambda^N by log2 N squarings, and pay one addition and one inversion.
If 1+lambda^N=0, decline before applying the source filters or transforming
the defect. This is explicit singular handling, not an unverified division.

For a target recurrence y_j=v_j+d_j y_perm(j), backward accumulation gives
B such that y_0=B+(-lambda^N)y_0. Multiply B by the shared h_lambda, then
perform another backward traversal to recover every output. The solve now
costs exactly 4N+1 field operations because its closure was already prepared.

## 3. Concrete family that individual methods miss

The audited witness has N=32 over the prime field 65,537, q primitive,
lambda=2 shared by both filters, and

    M_1 x[j] = q^j x[5j+1],
    M_2 x[j] = q^(3j) x[9j+5].

Let u be the first coordinate vector and define
x=L_1^-1 L_2^-1 u. Independent Gaussian or forward-recurrence generation
is used in the tests; it is not part of the Fourier evaluator.

| Checked property | Exact result |
|---|---:|
| Nonzero entries in x | 32 |
| Nonzero entries in L_1 x | 32 |
| Nonzero entries in L_2 x | 32 |
| Nonzero entries in L_2 L_1 x | 1 |
| Nonzero entries in L_1 L_2 x | 32 |

The previous single-filter discovery algorithm rejects x with a one-defect
budget for each of these graphs. The composed algorithm accepts and returns
the independently checked full Fourier transform. The two orders yield
different results, demonstrating a noncommuting composition rather than a
single-filter rewrite or a selector among old methods.

For complex numbers, lambda=2 gives nonsingular filters for every dyadic N.
The family x=L_1^-1 L_2^-1 u is therefore defined uniformly. The particular
finite witness proves that full density and failure of both individual
one-defect methods occur; no claim is made that every parameter choice or
every length has all coordinates nonzero.

## 4. Complete cost accounting

The primitive Nth root q and exact field are common inputs to this method
and the comparator. All root powers and root-order validation are paid.
Exact field addition, subtraction, multiplication, and inversion each count
as one operation. Equality tests and bounded-word indexing are separately
bounded by the same asymptotic work; arbitrary-precision bit complexity is
not claimed to equal field-operation complexity.

| Work | Exact field operations |
|---|---:|
| Root powers and validation | N |
| r shared scaled-root tables | rN |
| r shared closures, including inversions | r(log2 N+2) |
| Verify all d composed source layers | 2dN |
| Compute every output of the s-entry residual's DFT | 2sN |
| Invert d Fourier-side weighted cycles | d(4N+1) |
| **Total** | **(1+r+6d+2s)N+r(log2 N+2)+d** |

Affine integer descriptors are provided as O(log N)-bit words and reduced
modulo N during preparation; reading or reducing arbitrarily large integers
would have an additional bit cost outside this bounded-word contract.
Index preparation, cycle validation, data movement, and materialization use
O(N(d+r+s)) bounded-word operations. Affine modular inverses are computed
using Euclid; their O(d log N) word work is absorbed in O(dN). Graphs are
generated one at a time and discarded, so the algorithm stores O(N(r+1)+d)
words. It does not store an N-by-N matrix or a previous Fourier answer.

With d=2,r=1,s=1, audited cold counts are:

| N | Composed method | Ordinary radix-2 comparator |
|---:|---:|---:|
| 1,024 | 16,398 | 16,384 |
| 4,096 | 65,552 | 77,824 |
| 8,192 | 131,089 | 167,936 |
| 32,768 | 524,307 | 770,048 |

The comparator costs N+(3/2)N log2 N under its explicit arithmetic schedule.
The small case loses; the larger structured cases win in this field-call
metric. These are not wall-clock claims or comparisons against the best
possible radix constants. No work to discover the supplied continuous
parameters is concealed in the table: discovery is not implemented.

For fixed d,r and a fixed defect budget, a rejected attempt costs O(N).
The all-input wrapper then pays for an ordinary FFT, including a fresh
root table. Consequently its unrestricted worst-case cost is O(N log N).
Allowing d or s to grow must be charged in the formula; a growing number
of O(N)-cost filters is not a constant-time macro operation.

## 5. Exact limitation of this family

Over the complex numbers, fix N and bounds d,r,s. There are finitely many
affine graph choices modulo N, pool assignments, and defect support choices.
For any one such choice, an accepted input is

    x = L_1^-1 ... L_d^-1 u.

On the domain where all filters are nonsingular, every coordinate of x is
a rational function of at most r scalar lambda values and s defect values.
Therefore the Zariski closure of that family has complex dimension at most
r+s. A finite union preserves this bound. If **r+s<N**, these families
cannot contain every vector in C^N, even if a hypothetical search always
found the best graph choices and parameters whenever they existed.

This is a parameter-dimension statement about this precise representation,
not a lower bound for general Fourier algorithms. It applies to exact
complex inputs, not as stated to a finite-field counting problem. For
universality within this representation, r+s>=N is necessary. Since every
pool value is used, d>=r. The directly evaluated source layers and defect
modes in the present implementation would then take Omega(N^2) field work.
An improved method for transforming large defects or a richer representation
would be a different mechanism and would need its own proof and cost.

## 6. Reproduction and exact checks

Keep this directory beside `fft_bidirectional_graph_research`, which is an
explicit dependency. Run `python3 run_audit.py` here. The only imported
runtime helpers are the prior counted field wrapper, cycle traversal,
ordinary FFT comparator, and exact prime/cyclotomic field implementation.
`results.json` records source and dependency hashes.

The audit passed 144 accepted modular cases across depths one, two, and
three; 72 used independently generated Gaussian-inverse inputs. It also
passed four exact cyclotomic cases, 24 arbitrary-input declines followed
by fully checked FFT fallbacks, 11 singular-parameter declines, 12 lambda=0
cases, nine invalid-descriptor checks, the noncommuting witness, and four
larger comparisons against an independent radix-2 transform. An outer field
wrapper checks every arithmetic call and the exact total formula on the
small cases. All accepted small outputs are checked against direct DFTs.

The result advances exact graph reuse by composing genuinely different
relations and sharing their preparations. The arbitrary-input exact
o(N log N) goal remains open for the project.
