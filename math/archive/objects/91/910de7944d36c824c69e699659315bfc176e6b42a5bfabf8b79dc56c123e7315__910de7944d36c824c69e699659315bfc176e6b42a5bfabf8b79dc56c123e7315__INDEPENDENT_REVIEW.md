# Independent review of rational related-query reuse

The reviewed H-operator implementation (`rational_reuse.py`), its README,
`grading.py` dependency, and `run_audit.py` have no unresolved correctness or
cost issue within their stated exact-field, trusted-anchor contract. This is
a verified related-query result; the initial complete transform remains paid.

For a cyclic band of width w<=2, the code removes exactly its wrapping
entries into U V^T, with V selecting the first w coordinates. Each column of
`responses` is T^-1 U_j, and `closure[i][j]` is delta_ij plus that response's
i-th coordinate. The implemented 1-by-1 and 2-by-2 inverses therefore give
the usual boundary-closure formula. The constant diagonal is -lambda, so
the triangular solver correctly requires nonzero lambda. Checking the small
closure determinant is equivalent to checking invertibility of the full
cyclic matrix because T is invertible.

The grading identity H R = D H implies
H(R-lambda I)^-1=(D-lambda I)^-1 H. Since the weighted cycle of R has weight
product one, its characteristic polynomial is z^N-1; similarity gives the
same spectrum for D. Thus lambda^N!=1 is exactly the additional nonsingularity
condition. The explicit resolvent sum in the README has the correct sign.
For nonzero lambda, a coordinate vector does give a fully supported source
resolvent under R because the cycle's N powers reach distinct coordinates
with nonzero coefficients.

Preparation uses at most two triangular scans and a constant-size closure
inverse; each solve uses one such scan and at most two correction columns.
All are O(N) exact field operations and O(N) live field elements. A new lambda
may require new preparation, but that is still linear and is explicitly
charged. The evaluator does not call H or an FFT during a query edge. The
call path was inspected; the literal zero-transform counters alone are not
the basis for this conclusion.

The benchmark's baseline now pays the same source-query generation and its
preparation, while sharing the ordinary H evaluator's preparation across all
fresh transforms. The graph additionally pays target preparation, every
full relation check, and every target solve. Both pay the first anchor and
emit the same complete outputs. This supports O(N log N+QN) for Q promised
related queries, in contrast to separately invoking the selected ordinary
O(N log N) comparator. It supplies no claim about arbitrary query discovery,
all possible transform algorithms, bit complexity, or floating-point
conditioning. Output/copy/index work is linear and is covered by the stated
word-work bounds rather than exhaustively counted as physical accesses.

The supplied primitive roots, exact field representation, grading plans,
and cached anchor are trust/model boundaries. Full relation verification
cannot authenticate a corrupted anchor output. The field-element storage
bound is not a byte bound for the explicit cyclotomic tuple backend. No old
functional audit was rerun for this review; the saved test scope was checked
against the audit source, and the all-size claims were checked algebraically.

## Full-DFT intertwining extension: independent algebra check

For the positive-exponent Fourier matrix F[k,j]=q^(kj), consider

    E[i,i] = -q^i,
    E[i,i+1] = -q^i(q^(i+1)-1),

with the final upper edge zero, and cyclic target bands

    J[k,k+1] = q^(-k-1)-1,
    J[k,k+2] = -q^(-k-1).

Direct expansion yields

    (F E)[k,j]
      = (q^(-k-1)-1) q^((k+1)j) - q^(-k-1) q^((k+2)j)
      = (J F)[k,j].

The j=0 boundary is valid: its absent upper-edge term is zero because
q^0-1=0. The cyclic interpretation on J uses q^N=1. E is upper triangular
with diagonal -q^i. For dyadic even N, its eigenvalues form the same set of
Nth roots of unity, so E-lambda I and J-lambda I are invertible exactly when
lambda^N!=1. A triangular source solve with individually inverted nonzero
diagonal entries, or a charged batch inverse, is O(N); the existing cyclic
width-two target solve is O(N) when its nonzero-lambda representation applies.
Therefore the proposed full-output identity

    F (E-lambda I)^-1 x = (J-lambda I)^-1 F x

is valid and needs one paid Fourier anchor. Unlike the cyclic R resolvent,
the E resolvent is upper triangular: e_j has j+1 nonzero source coordinates,
not necessarily N. The last basis vector and generic dense vectors can
produce dense source queries. The every-basis dense assertion must remain
specific to the R family.

The completed `fourier_rational.py`, `audit_fourier.py`, current README and
`fourier_results.json` have now also been inspected. The source diagonal,
upper edge, target bands, and separate common-preparation ledger match the
formulas above. Batch inversion checks every denominator, uses one field
inverse, and charges its prefix/suffix multiplications. All shifted source
diagonals are nonzero under the stated lambda condition. The computed last
upper coefficient is zero and is correctly omitted from the triangular
source action/solve. Query verification checks all source coordinates before
using the trusted Fourier anchor. There is no hidden fresh Fourier call in
either query solver.

As a focused independent accounting check, the following exact scalar totals
were derived from the loops rather than copied from the counters:

| Operation | Scalar field operations |
|---|---:|
| Common source preparation | 9N |
| Complete rational preparation | 21N+7 |
| Generate a related source query | 3N-2 |
| Verify the source relation and solve the target | 12N-2 |

Let L=log_2 N and Q be the number of additional queries. The ordinary FFT
comparator as implemented charges 3NL/2 gates per action, including all twiddle
multiplications. Its shared setup costs N+L. Therefore the complete cold
comparison is exactly

    graph = 3NL/2 + (22+15Q)N + L + 7-4Q,
    fresh = 3(Q+1)NL/2 + (10+3Q)N + L - 2Q.

These independently computed formulas matched all ten small preparation/
source/verified-query ledgers and all four large same-target comparison
ledgers. In particular, they reproduce 2,306,004 versus 3,190,765 at
N=8192, Q=16. The graph loses at N=128 as reported. This compares the selected
ordinary radix-two implementation, not the best possible constant-optimized
FFT or a measured wall-clock runtime. Indexing, equality checks, allocation,
and full output writes add the documented O(N) word work per query.

No old functional audit was rerun; this new check independently verified the
saved scalar ledgers by closed-form loop counts. The previous every-basis
density concern is resolved in the README by explicitly distinguishing the
triangular E family from the cyclic R family. No unresolved correctness or
accounting issue remains within the stated related-query and trust contract.

## Fresh inputs with a sparse recurrence defect

The new `corrected_fourier_output` and `try_recurrence_fourier` code was also
inspected. Let A=E-lambda I and B=J-lambda I. The already verified identity
F A=B F gives, for an exact anchor y_0=F x_0,

    u=A x'-x_0,
    F x'=B^-1 (y_0+F u).

The correction sign is positive. Setting x_0=y_0=0 is a valid cold algorithm:
for a fresh input x with a verified s-sparse defect u=A x, it computes the
complete exact Fourier vector without a previously paid transform anchor.

The implementation computes the entire residual, scans every coordinate for
exact zero, and declines if support exceeds `max_defects`. It then evaluates
F u at every output coordinate using one phase recurrence per nonzero defect,
adds the trusted anchor coordinate, and applies the same linear target solve.
The `_power` helper explicitly charges construction of each needed phase root
q^j by repeated squaring. This costs O(s log N), which is included in
O(N(s+1)); no free phase lookup or input-dependent support oracle is used.

Let P be the sum of those charged repeated-squaring multiplications. The
actual accepted online scalar count is

    13N-2 + (2N-1)s + P.

This includes source action (3N-2), all N residual subtractions, Ns additions
and (N-1)s phase advances, and the 9N target solve. Cold mode conservatively
still subtracts zero anchors. Adding the previously verified plan preparation
gives `34N+5+(2N-1)s+P` scalar operations. Exact support comparisons, input
reads, zero-vector creation, copies and all N output writes add O(N+s) word
work. A declined input pays 4N-2 online field operations and N support tests,
plus any newly prepared plan; decline is not reported as a zero-cost decision.

There are genuinely dense accepted inputs for s=1. Take u=e_(N-1) and solve
A x=u. Every shifted diagonal and every nonfinal source upper edge is nonzero,
so backward substitution makes every coordinate of x nonzero. The generation
of this witness is itself linear and can be charged if part of a workload.
Thus the corollary is stronger than merely evaluating sparse input vectors.

The cost remains conditional on the discovered defect being small for the
supplied admissible lambda. The current code does not search for a favorable
shift. Root validity, the exact field representation, and any nonzero cached
anchor remain explicit contract boundaries. The corollary does not cover
arbitrary fresh dense vectors and supplies no universal sub-N-log-N exact
FFT result. The implementation review here does not duplicate the new
functional audit; its algebra and full loop costs were checked independently.
