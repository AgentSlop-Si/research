## Material findings

### F01. Standalone quartic exports require their already-documented chart guards

inverse_quartic.py lines 72–108 and 233–258 export the thirty anchored lower/upper minors, but export neither det(C) != 0 nor nonzero B[7,0], B[0,7] conditions. These are indispensable for the advertised inverse and regular separated-generator chart interpretation.

There is a direct symbolic counterexample to treating the equations alone as a feasibility certificate. Set all 26 variables to 1. The displayed generators give C equal to the 8-by-8 all-ones matrix. It has rank one and cannot be A inverse. With a primitive eighth root, F C P inverse = 8 e_0 1^T: the geometric sums in every row except row zero vanish. Every exported anchored lower and upper minor is therefore zero. This uses the formulas as printed; no source was executed. The diagonal-one normalization itself also covers only an appropriate nonzero-diagonal gauge patch, not every invertible quasiseparable matrix. Correct use must retain invertibility and chart inequalities (or an equivalent saturation/auxiliary-equation formulation), plus a separate treatment of omitted strata. The source appropriately disclaims Fourier exclusion, but its output phrase “exact reformulation” requires these qualifications. This is an already-recognized boundary of the wider package, not a newly discovered mathematical error: exceptional_charts.py dfa0341b67ad5460b75cb051f2d2e1b7a6aa079bb6b9bac977218fabc0039e7a lines 26–41 constructs this same all-ones example, and test_inverse_gate.py e98e455fca2f94c6157ba136031ba103c30aa30bac30bbafe7d48abe9013303a lines 54–57 explicitly tests it. Those short excerpts were checked for context only and receive no full-read credit here. The actionable issue is preserving the open-patch conditions when the equation JSON is consumed independently.

### F02. The sampled cut-tangent dimension inequality is reversed

mincut_tangent.py lines 50–69 constructs valid tangent covectors only for sampled saturated cut ranks. If d is their rank, n²−d is exactly the dimension of their joint kernel. The full cut-variety tangent space satisfies these and any unsampled cut constraints, so its dimension is **at most** n²−d, not at least. The field `dimension_of_cut_tangent_lower_bound` is misnamed/misinterpreted for the full cut variety. The Jacobian tangent image lies inside the sampled kernel, but this does not reverse the inclusion for the full cut tangent space. The `unexplained_by_sampled_cuts` field is a sampled linear deficit, not an established gap for all cut constraints, a generic characteristic-zero tangent gap, or Fourier exclusion.

### F03. Superconcentrator verification does not validate a 60-by-60 supplied minor

superconcentrator_gate.py lines 99–116 never requires the supplied row and column lists to have length 60. Empty lists select a 0-by-0 matrix, for which determinant_mod (lines 29–42) returns its initialized value 1. With a matching supplied determinant 1, the minor check passes, and the success string still calls it a “60x60 determinant.” This is a static acceptance construction assuming the other checks pass for the supplied generator seed. The independent recomputation rank_mod(J)==60 remains, so the rank claim has a separate check; the specific serialized 60-by-60 witness does not. The verifier also ignores certificate field_prime, image-dimension, upper-bound, codimension, and several count metadata fields. Explicit shape, index uniqueness/range, modulus, and dimension metadata checks are needed for a hostile-input certificate interface.

### F04. Gauge operation counts undercount the implemented additions

Gauge.action in gauge_fft.py lines 63–71 starts dot at zero and performs n additions in the dot loop, then n output additions, totaling 2n. It records 2n−1, undercounting one executed addition per gauge call. There are 2(log2(n)−1) gauge calls in a dressed transform, so the displayed addition total is low by that amount. This difference is between executed operations and a reduced arithmetic convention that ignores addition to zero; the code explicitly describes executed scalar gates. Multiplication count 2n+1 matches the displayed operations. Logical reads/writes also omit list-copy/allocation and coefficient accesses, so they are not full machine-memory traffic. Preparation metadata does not charge all modular powering and coefficient-generation work. None of these changes the negative-control conclusion that this implementation adds work to an ordinary FFT.

### F05. MILP outputs are numerical optimization evidence, not exact zero-optimum certificates

milp_superconcentrator.py faithfully formulates a binary side partition, finite cut-edge slacks, directed closure for large edges, and a continuous t <= both endpoint counts. For each integer side partition a negative objective means an endpoint rank-capacity violation; restricting t >= 1 loses no negative witness. But solver status/bounds are floating-point outputs. After rounding the returned side, the code does not explicitly validate every large-edge closure constraint, and when a negative witness is independently queried, it records the max-flow without asserting that it is below t. The exact cut-capacity-vs-rounded-objective assert alone does not establish closure. Its header correctly says a zero optimum is not a formal proof. Preserve that scope and require a complete exact witness/dual certificate for stronger use.

### F06. Assertion-only acceptance is not robust to optimized Python

Most certificate and positive-control checks use assert. In particular, superconcentrator_gate.verify places every exhaustive oracle query directly inside assert; optimized Python would omit those queries while incrementing its count. Its rank recomputation is also inside assert. network_certificate can print `CERTIFIED` after its decisive comparisons are removed. cost_audit puts the only two apply calls inside assert, so under optimization both counters stay zero and its later ratio can divide by zero. benchmark's correctness calls also disappear under optimization. These are source-path observations, not actual optimized executions. Treat assertion-enabled execution as part of the runtime contract, or replace critical acceptance guards with explicit failures.

### ca75c080eccfee026aa54c9002e258e64bea8d9fb32db29aad4a53c6a9322704 — gauge_fft.py — lines 1–133

The radix-2 DIT FFT uses initial bit reversal and primitive-root powers at each span. The default fixed prime is suitable; generic p assumes a field because Gauge.make uses Fermat inversion. H=I+alpha*u*v^T and H inverse=I−alpha/(1+alpha*v^T*u) u*v^T follow Sherman–Morrison when the denominator is nonzero.
