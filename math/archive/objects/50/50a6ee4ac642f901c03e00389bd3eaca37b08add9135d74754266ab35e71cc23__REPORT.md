# Orbit and geometry source review

## Coverage and result

Completed first-to-last inert inspection of all **80 new assigned exact hashes: 367,025 bytes and 8,739 lines**. Two already-covered hashes were deduplicated. No overlap remained with the frozen inventory or additive registry observed at completion. `COVERAGE.json` has one exact coverage row per new hash; `per_hash/` holds the detailed mathematical, cost, test and provenance review for each.

**No supplied program was executed, imported, compiled or AST-parsed.** Five fresh, separately authored controls passed. Those controls test narrow arithmetic/provenance issues, not the supplied test suites. This closes only this assignment, not the entire corpus, external dependency/data closure, or all mathematical claims.

## Material findings

- **F02: General scan-order capacity is underweighted.** `gf2_depth_certificate.py` returns rank-one boundary capacity even when called with r>1. A fresh identity-layout control at k=9,t=2,r=2 gives 62 reported versus 124 required capacity. Listed generated examples use r=1; this does not refute the underlying depth theorem.
- **F01: Required certificate witnesses can be omitted.** Several data-driven checkers lack complete expected-record assertions. Most concretely, the moving-certificate verifier permits an empty modular-witness list and then skips every Fourier-rank recomputation. Actual input-certificate omission was not established.
- **F03: Operation ledgers are incomplete.** Orbit-union reconstruction omits active-entry multiplications; phase6 omits sum additions and some root/inversion work; phase8 omits bare root inversions and some tests. A scaling script labels all phase modes active without measuring them. These findings limit exact cost claims, even where asymptotic special-family bounds may remain valid.
- **F04: One replay does not establish fresh output.** The paid-shears wrapper copies baseline results into its temporary directory before comparison. A successful no-write checker could leave those bytes unchanged. The phase38 isolated wrapper does not copy outputs and avoids this particular flaw.
- **F05: Packager reruns can corrupt integrity metadata.** An existing MANIFEST is hashed before being rewritten and then appended again to ZIP members, producing a stale hash and duplicate manifest entry in that state.
- **F06–F07: Guard/domain boundaries need tightening.** The early Weyl prototype silently returns zero for inverse-of-zero, affecting undefined resolvent entries. Its later split implementation fixes that zero check, but character-packet entrypoints still admit n=2 despite the odd-prime derivation. A fresh n=2,p=5,alpha=2 example has a passing shared guard and a singular literal Green inverse. Phase8 also admits N=K=M=1 before an out-of-range table access. Intended sampled domains avoid these boundaries.

Other per-hash limitations include heuristic versus exhaustive search, modular versus complex rank, floating-point versus exact certificates, local versus full-product obstructions, sampled versus universal tests, and borrowed dependency or theorem assumptions. No reviewed special-family construction establishes a generic faster FFT, and no restricted rank gate establishes an unrestricted FFT lower bound.
