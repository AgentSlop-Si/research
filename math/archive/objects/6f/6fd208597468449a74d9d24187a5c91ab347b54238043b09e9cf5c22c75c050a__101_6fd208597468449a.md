# Fresh structured FFT research: audited Phase 11 and a full-DFT extension

Audit date: 2026-10-08. This is a separate derivative; the two uploaded archives are unchanged.

## Main result

Phase 11 genuinely processes fresh inputs. Its linear-time improvement applies when a low-degree polynomial filter makes an operand sparse. It does not establish a faster transform for arbitrary fresh inputs.

This package adds an exact **full-DFT** demonstration: given a degree-d filter Q for which Q·A has s nonzero coefficients, evaluate every Fourier bin in O((d+s+1)N) field arithmetic, with explicitly supplied valid roots. For an order-d recurrence, s ≤ 2d, giving O((d+1)N). The proof handles the polynomial's right boundary and the exceptional roots where Q vanishes. These are classical generating-function identities, with no novelty or priority claim. See `structured_dft/` for the detailed theorem, assumptions and exact tests.

For arbitrary inputs, the filtered polynomial can remain dense. The demonstration may then use quadratic work and is not a universal replacement for an FFT. It is separate from the exact-width H16 finite-circuit search.

## What changed

- `phase11/fresh_factor.py`: corrected the returned plan after a forced `mode` override. Previously an NTT execution could report `structured`, or vice versa.
- `phase11/tests/test_plan_reporting.py`: three regressions verify the selected strategy and which routine runs.
- `structured_dft/`: independent exact full-DFT implementation, proof and examples.
- `audit/`: reproducible additional tests and the original/updated results.
- `phase10_numpy_source/`: two unchanged source modules needed to reproduce the Phase 10 numerical and cancellation checks. No shipped native libraries are included.

`Plan.method` reports the selected top-level strategy. With integer inputs, `ntt` routes through the existing exact-CRT strategy, whose documented large-coefficient fallback is schoolbook multiplication. Its estimates remain heuristic work estimates, not calibrated runtimes.

## Verified here

- Original Phase 11: all 11 manifest hashes matched; all 15 bundled tests passed.
- Patched Phase 11: all 18 tests passed.
- Independent Phase 11 checks: 2,160 exact convolution comparisons, 350 random recurrence cases and 120 multiplication cases passed. Integer coefficients reached 600 bits; all five bundled primes were covered.
- The binary-filter barrier experiment reproduced: 8 filters biject all 256 length-8 inputs; the degree-8 random-input example had minimum weight 470 of 1024.
- Full-DFT extension: its targeted self-tests passed, plus 740 additional all-bin exact comparisons over four primes, including 180 cases with singular bins.
- Phase 10: all 25 manifest hashes matched. NumPy-only evaluation passed 120 full-output and 120 selected-output checks. Maximum absolute error was 2.274e-12.
- Phase 10's symbolic cancellation defect was reproduced: `(2^53)A + A - (2^53)A` becomes zero during graph construction, whereas the exact expression is A.

Native binaries were deliberately not loaded for this audit. This was a safety choice, not an observed permission denial. No AOT performance, native correctness, or fresh-process startup claim was independently validated. Supplied benchmark JSON files are upstream measurements, not newly reproduced timings.

## Reproduce

The Phase 11 and DFT tests use Python's standard library. Phase 10's optional numerical checks require NumPy; SciPy is used when installed, otherwise the source falls back to NumPy FFT. Nothing needs to be downloaded or compiled by these commands.

From this directory:

```
(cd phase11 && PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -v)
(cd phase11 && PYTHONDONTWRITEBYTECODE=1 python3 barrier_audit.py)
PYTHONDONTWRITEBYTECODE=1 python3 audit/independent_phase11_checks.py
PYTHONDONTWRITEBYTECODE=1 python3 structured_dft/structured_dft.py
PYTHONDONTWRITEBYTECODE=1 python3 audit/independent_structured_dft_checks.py
PYTHONDONTWRITEBYTECODE=1 python3 audit/independent_phase10_checks.py
sha256sum -c SHA256SUMS
```

Read `AUDIT.md` for the limitations and comparison with earlier work. `PROVENANCE.json` maps the exact uploaded filenames and Library IDs. The original Phase 11 manifest is retained as `phase11/UPSTREAM_SHA256SUMS`; it describes the unmodified upload, so the patched source will intentionally differ. The package-level `SHA256SUMS` covers the delivered files.
