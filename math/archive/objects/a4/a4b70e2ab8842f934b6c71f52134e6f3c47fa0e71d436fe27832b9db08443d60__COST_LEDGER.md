# Phase 24 cost ledger — native radix-2 is the correct dyadic baseline

**Model:** count each prime-field `+`, `-`, `*`, or inverse as one field operation. Shared preinitialized Fourier roots, unchanged field/Green setup, and all compiler/certificate arithmetic for both algorithms. Native radix-2 uses the *same supplied root table*. Memory, word and Python operation counts are separate.

**Critical:** The generic Phase 24 fallback does not beat native FFT. The previous Phase 23 comparison used full Bluestein as a reference even at powers of two, where native radix-2 is considerably cheaper. Our research should always compare against the best straightforward applicable algorithm, not only an inherited generic-length fallback.

## Exact per-graph accounting

| Quantity | Formula for ten + neighbor probes |
|---|---:|
| Old direct residual probes | `19N` field operations |
| Eager lazy input FFT preview | `129N/16 - 33` |
| Deferred input FFT preview | `49N/8 - 12` |
| Green conjugation for ten samples | 20 multiplies + 10 adds = 30 |
| Preview backup writes and peak live words | `N-11` |
| Native full radix-2 FFT, on fallback | `3N log2(N)/2` total butterfly field operations |
| Recomputed butterflies, on fallback | **0** |

Memory gets charged in separate `reads`, `writes`, `backup_writes` and `backup_reads` counters. Field arithmetic does *not* include these memory costs. The lazy graph has `O(N)` data, saved-branch and node-state slots, using a supplied root table of `N` entries. The per-experiment counters and branch choices are in `PHASE24_BENCHMARK.json`.

## Explicit scope

The certificate accepts only a restricted sparse-rational family, and searching for it is expensive at moderate sizes. The total all-input exact bound remains `O(N log N)+O_s(N)` in the finite-field arithmetic model, with `O(N)` scratch words (and a supplied `N`-root table); no general `o(N log N)` claim is warranted. Prime/root setup, bit complexity and numerical stability are not solved.
