# Joint decoding by discovered sparse annihilator multiples

9 October 2026. This package adds an executable support-adaptive route to the
supplied cross-block and decoded-state fusion material. It computes every
requested value exactly for arbitrary fresh amplitudes on the supplied support.
On supports admitting a short sparse annihilator, it removes the half-grid,
Toeplitz-extension and terminal-transform stages altogether. A paid conventional
FFT fallback retains the existing arbitrary-support upper bound.

The improvement is **restricted to certified support structure**. It does not
establish a uniform o(N log k) algorithm for arbitrary k-element supports, a
faster arbitrary dense FFT, or a practical timing improvement. Sparse recurrences
and annihilating polynomials are classical; no mathematical priority is claimed.

## What was already in the supplied material

The source `fused/FUSION.txt` already proves that all terminal decoders can
be moved through the residue tree. Its decoded-state extension is

\[
J_Q=-T_{1/Q}U_Q,\qquad
[f_0,\ldots,f_{2L-1}]=[v;J_Qv].
\]

It also fuses a whole subtree into a short-by-long reciprocal convolution.
Those identities are the starting point here, not new findings. Ordinary
FFT implementations still cost O(N log k). The original scripts were inspected
before this work; none of the supplied files was changed or executed in place.

The new implementation changes the annihilator used for the joint output map.
The minimal denominator may be dense even when a somewhat higher-degree
multiple has only a few nonzero coefficients. The extra initial values can
cost much less than repeatedly applying dense extension maps.

## Exact annihilator and recurrence

Input consists of N>=1, distinct nonzero field elements z_1,...,z_k, and
arbitrary amplitudes a_1,...,a_k. The desired output is

\[
f_m=\sum_{s=1}^k a_s z_s^m,\qquad 0\le m<N.
\]

The original problem has z_s^N=1. The following identity also works for
arbitrary distinct nonzero z_s; it uses no root-of-unity approximation.

For any positive integer stride b, form the set of distinct powered roots
Lambda_b={z_s^b}, let d_b=|Lambda_b|, and compute

\[
R_b(t)=\prod_{\lambda\in\Lambda_b}(1-\lambda t)
      =1+\sum_{i=1}^{d_b}r_i t^i.
\]

The polynomial R_b(t^b) is an annihilating denominator for the original
sequence. In particular, for M=b d_b,

\[
\boxed{f_m=-\sum_{i:r_i\ne0}r_i f_{m-bi}\quad(m\ge M).}
\]

For each mode, the right side minus f_m is proportional to
R_b(z_s^(-b))=0. Summing over amplitudes proves the identity. Every accessed
index is nonnegative when m>=M. Equivalently the minimal denominator
Q(t)=product_s(1-z_s t) divides R_b(t^b). Distinctness and nonzero roots
ensure M>=k and a nonzero leading coefficient; the recurrence always has
at least one nonconstant tap.

Let tau be the number of nonzero r_i for i>=1. The implementation computes
the first min(N,M) values by a fully charged direct modal prefix, then
generates each remaining output using tau multiplications and tau-1 additions.
Negative recurrence coefficients are prepared once. The output is already in
its final order. There are no child spectra, inverse transforms, rational
sample divisions, pole corrections, or separate terminal maps in this route.

This is valid for one full fresh input of k arbitrary amplitudes. It does not
assume that independently supplied child states share an unproved relation,
or recover modal amplitudes from a numerator for free. If the starting data
were only P,Q rather than the given roots and amplitudes, conversion costs
would be an additional problem.

### Why powering helps beyond sparsity of the minimal denominator

If the support lies in d fibers of z -> z^b, then d_b<=d, so R_b(t^b)
has at most d nonconstant taps and degree at most b d. A fiber is a set of
roots having one common bth power; the support need not contain the whole
fiber. Consequently Q itself may be dense.

Coefficient cancellations in R_b can help further: the implementation measures
actual nonzero coefficients, not just d_b. For example, the tested N=4096,
k=16 support

\[
\{\omega^{a+256j}:a\in\{1,3\},\ 0\le j<8\}
\]

uses a primitive 4096th root omega. Its minimal Q has 16 nonconstant taps.
The planner finds a degree-32 annihilator with only two taps. It actually
selects b=2: R_2 has degree 16 but only two nonzero nonconstant coefficients,
so R_2(t^2) has the same degree/tap advantage as a larger-stride description.
The first 32 outputs are paid; all subsequent values need two multiplications
and one addition each. This is an exact larger-order/fewer-taps tradeoff.

## Discovery, cost and storage

`prepare_adaptive` always includes b=1. By default it tests dyadic strides
1,2,4,... up to min(N,k^2). An explicit positive-integer candidate list can
also contain non-dyadic strides. Every candidate is paid for:

- binary powering of every supplied root, with each actual multiplication counted;
- grouping by exact field equality, using an explicit scan rather than an
  assumed free hash/discrete-log operation;
- successive linear-factor multiplication to form R_b;
- exact zero tests on all its nonconstant coefficients;
- comparing the fully charged online ledgers of the candidates.

The chosen candidate minimizes the sum of its predicted additions and
multiplications, breaking ties by initial-prefix length and stride. This is
a unit-field-operation policy, not an assertion about native runtime. Selection
depends only on the support and requested length, not on the amplitudes.

For M0=min(N,b d_b), the exact online ledger is

| Field operation | Count |
|---|---:|
| Multiplications | k(M0-1)+(N-M0)tau |
| Additions | (k-1)M0+(N-M0)(tau-1) |
| Inversions | 0 |
| Transforms | 0 |

The direct initial prefix advances each weighted mode multiplicatively, with
O(M0) storage rather than a k-by-M0 table. Its operations are in the first
terms of the ledger, including contributions from every amplitude.

For h candidate strides bounded by b_max, support setup uses
O(h k log b_max+h k^2) field operations, O(hk^2) equality tests and O(hk)
coefficient-zero tests. Candidate normalization/sorting adds O(h log h)
word operations. The default h=O(log(k+1)), b_max<=k^2 gives polynomial-in-k
setup and M<=k^3. Thus the total bound is

\[
O(k^2\log(k+1)+k\log^2(k+1)+k^4+N\tau)
\]

for a selected default candidate, plus the explicitly counted word work.
This is a sufficient upper bound, not a claim that every case incurs k^4.
With k=Theta(log N), setup and initialization are polynomial in log N.
If the discovered tau=o(log k), the complete cold route is o(N log k);
fixed tau gives O(N)+polylog(N). These are **conditional support-class
improvements**, not guarantees for arbitrary supports.

Storage is O(N+k+h), including the returned N-vector. Only one current and
one best denominator are retained; candidate records contain small count
summaries. Recurrence addressing and its repeated reads cost O(N tau), and
initial-prefix reads/writes cost O(kM0). The reported `full_output_writes=N`
is the final endpoint count, not a count of every initial-prefix update,
temporary array allocation or copy. All of those fit the displayed word-work
and storage bounds.

The arithmetic model treats supplied field elements and O(log N)-bit indices
as words. Arbitrarily large custom stride integers have their own input and
bit-manipulation costs. Exact field representation, coefficient growth and
floating-point stability are separate. Root values z_s are supplied in the
source problem's contract; if only support indices and a primitive period
root are supplied, forming all z_s adds O(k log N) field multiplications.
No auxiliary FFT roots or field inversions are needed by the adaptive route.

## Same-target decoded-state FFT baseline and safe fallback

`fft_decoded_baseline.py` implements the supplied J_Q identity with ordinary
radix-two FFTs. It forms Q from the same supplied roots, computes the first
L coefficients of 1/Q, and prepares both fixed Toeplitz spectra, where
L=max(2,next_power_of_two(k)). Each new contiguous L-value block costs two
truncated convolutions, hence four length-2L transforms. It generates the
same complete sequence and pays for a possibly discarded final partial block.

This comparator requires a **supplied primitive 2Lth root eta**. Its order is
independently checked in the audit; production preparation treats it as a
precondition. Root finding or constructing an unavailable extension field is
not hidden in its counters. This extra root is not required for the recurrence
route. The baseline is a straightforward implementation, not a best-constant
FFT library or a native timing comparison.

For ell=log2 L and B=max(0,ceil(N/L)-1), its online counts are

- k(L-1)+B(4L ell+12L) multiplications;
- (k-1)L+4BL(ell+1) additions;
- 4BL(ell+1) subtractions;
- BL negations.

Every inverse-transform normalization and multiplication by a trivial twiddle
is counted. Complete setup counts are checked by a separate closed formula
in the code and stored in the report.

`hybrid.py` first pays all adaptive discovery. It then compares the selected
recurrence's online cost against the baseline's additional preparation plus
online cost. If the baseline wins, its entire preparation and application are
charged too. Thus the hybrid has an arbitrary-support upper bound

\[
O(N\log(k+1)+\operatorname{poly}(k,\log N))
\]

under the same suitable-root assumptions as the supplied FFT route. Candidate
search does not create an unreported worst-case regression to O(Nk). The
search overhead is real and can make finite cases slower than using a known
baseline directly; the examples below report cold costs and make no universal
constant-factor claim.

## Exact results

All totals below count field operations with unit weight. Equality tests,
zero tests, index work and N final writes are separately reported/charged as
word work, rather than mislabeled as field arithmetic.

| N=4096 support | k | Original Q taps | Selected annihilator taps | Initial prefix | Adaptive cold | Minimal-Q recurrence cold | Decoded FFT cold |
|---|---:|---:|---:|---:|---:|---:|---:|
| Complete multiplicative coset | 16 | 1 | 1 | 16 | 5,517 | 4,833 | 283,029 |
| Two partial power fibers | 16 | 16 | 2 | 32 | 14,412 | 127,248 | 283,029 |
| Three partial power fibers | 18 | 18 | 3 | 48 | 23,495 | 143,702 | 332,660 |

The minimal-Q column is a separately prepared b=1-only sparse recurrence,
computing exactly the same output. The adaptive compiler improves that
stronger comparator on the two dense-Q examples. For a complete coset, Q
is already one-tap sparse and broad candidate discovery adds unnecessary
work; the table reports that cost rather than claiming a win over b=1.

For the two-fiber case, adaptive preparation is 909 multiplications,
279 subtractions and 56 negations. Online is 8624 multiplications and
4544 additions. Discovery also uses 450 support-equality checks, 54
coefficient-zero checks and 16 nonzero-root checks. Every one of the 4096
outputs is returned. No first-input cache or prepared amplitude table is used.

The focused hybrid test chooses the conventional FFT on an unstructured
N=1024,k=128 input. Its report includes 61,090 discovery field operations
even though that work does not yield the chosen evaluator. This is a
correctness/scope control, not evidence that discovery helps every input.

The exact audit passes 47 configurations, 112 amplitude-basis vectors,
94 mixed/zero amplitude vectors, 71,080 output-coordinate comparisons,
and five invalid-input controls. Fields are F_65537, F_998244353, F_97
and exact cyclotomic fields Q(zeta_8), Q(zeta_16). Tests include arbitrary
supports, complete and incomplete power fibers, an explicit stride-three
candidate, padded blocks, and arbitrary fresh amplitudes. The two additional
hybrid cases verify both selection branches. They compare against direct
geometric sums and, independently, the implemented decoded-state FFT baseline
and the b=1-only minimal-Q recurrence.
Every recorded online and baseline-preparation count formula is asserted.

Run:

```bash
python3 run_audit.py
python3 run_hybrid_audit.py
```

Results are `results/joint_decode_audit.json` and `results/hybrid_audit.json`.
The original source files remain immutable. Dependencies are the earlier
exact-field helpers in `fft_qweyl_boundary_research` and ordinary radix-two
FFT helper in `fft_qbasis_research`.

## Prior work and remaining target

The supplied decoded-state/reciprocal convolution is classical recurrence
extension. Bostan, Lecerf and Schost's
[*Tellegen's Principle into Practice*](https://cs.uwaterloo.ca/~eschost/publications/p33-bostan.pdf),
section 5.2, relates it to transposed polynomial remaindering. Bostan and
Mori's [linearly recurrent sequence algorithm](https://arxiv.org/abs/2008.08822)
provides the broader parity-recursion context. The identity that a polynomial
vanishing on every modal root annihilates the sequence is elementary; using a
nonminimal sparse multiple is not claimed as a new recurrence theory.

What this package adds to the project is an actual discovery-and-selection
implementation, a proof that both paid decoding stages disappear on its
certified support classes, and end-to-end exact ledgers against the supplied
kind of decoder. Arbitrary supports may have no useful sparse multiple among
these candidates. The remaining universal task is still a genuinely cheaper
joint output map for those supports, with all setup and output work included.
