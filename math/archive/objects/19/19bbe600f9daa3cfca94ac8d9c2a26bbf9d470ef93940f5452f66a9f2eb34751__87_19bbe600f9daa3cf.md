# Phase 9 — Unified projected graph reuse

This follow-on package integrates the supplied Phase 7 persistent chains, query engines v2/v3, Phase 8 sum-product jets, and the earlier Phase 6 graph planner. It adds projected persistent circuits, interval-product indexes, repaired consumer grouping, and a small exact modular/CRT bridge.

The useful result is a set of measured algorithms for **known related inputs and explicit output requirements**. It establishes no new general FFT or integer-multiplication exponent. The linked `integer-mult-kappa` work remains a separate conditional result with a different cost model; see `INTEGER_MULT_BRIDGE.md`.

Read `RESULTS.md` for the measured positive and negative regimes, `RESEARCH.md` for bounds and proofs, and `LATEST_INPUT_AUDIT.md` for the new uploads' role.

## Choose the computation by its output

| Workload | Implementation | Main condition |
|---|---|---|
| Selected frequencies of general sums/convolutions, persistent forks | `projected_circuit.py` | Register the union of requested bins; known expression graph |
| Many sparse forks of a long fixed factor chain | `range_product.SegmentProductIndex` | Pay index preparation; unchanged factors retain order |
| Same problem, constant-count interval products | `range_product.FrozenProductIndex` | Extra O(m q log m) storage; experimental, slower than segment control in measured cold runs |
| Low-degree changes to a repeatedly used leaf; selected frequencies | `algebra_projection.py` | Import Phase 8 symbolic coefficients; O(q(k+d)) query after preparation |
| Full or selected **time** coefficients of those changes | `baseline_sum_product_v8/algebra_fft.py` | Prepared dense kernels; degree and preparation costs matter |
| Full output, one edited factor in a convolution chain | `baseline_phase7/persistent_chain.py` | Cached base and leave-one-out convolutions |
| Mutable low-rank/sparse state with overlapping consumers | repaired `multi_view.py` and `view_optimizer.py` | Known basis projection; bounded history and group-cache budget |
| Related full FFT spectra with useful candidate edges | `baseline_phase6_graph/graph_reuse.py` | Phase 6 restricted one-parent planning model |
| Exact algebra and small signed integer examples | `modular_bridge.py` | Quadratic direct modular DFT; correctness reference only |

These are explicit APIs, not one universally optimal automatic dispatcher. For small chains, direct vectorized products or a hand-specialized formula are often fastest.

## Small example

```python
import numpy as np
from projected_circuit import ProjectedCircuit
from range_product import SegmentProductIndex

n = 4096
e = ProjectedCircuit(n, [0, 1, 17, 300])
a = e.register(np.sin(np.arange(n)))
b = e.register(np.cos(np.arange(n)))
factor = e.relation([(a, 2, 3), (b, -1, 0)], [(11, .25)])
original = e.product([factor, a, b, a])
fork = original.edit(2, 19, .125)
four_bins = fork.frequencies()

# A separate static index for many forks of this same factor list.
index = SegmentProductIndex.from_circuit(original)
same_bins = index.branch().edit_many([(2, 19, .125)]).query('range')
np.testing.assert_allclose(four_bins, same_bins)
```

Registration reads each dense seed but stores only its selected projection. The engine does not retain the seed signal or its full spectrum. It does not support adding a new frequency after registration without new source data. Numerical execution is complex128; long products can underflow, overflow, or accumulate rounding error. Zeros in spectra are supported because none of the reuse paths divide by them.

`cache_bytes` limits evaluated node vectors only. Registered projections, graph metadata, returned outputs, and temporary workspace are separate. The organizer's `max_group_cache_bytes` likewise limits only group spectrum payloads. Memory reports name exclusions; isolated peak RSS measurements include the full process.

## Reuse existing research

`ProjectedCircuit.from_phase5(states)` imports single- and multi-basis states without calling `signal()`. `algebra_projection.import_algebra(source, roots, target)` imports the new sum-product graphs without another FFT. `prepare_projected_jet` compiles all coefficients up to the actual degree or rejects an excessive degree; it never silently truncates the polynomial.

The original uploaded sources are kept under `baseline_*`. New fixes live at the top level. Their APIs and numerical scope remain distinguishable. No source from the linked integer-multiplication repository was modified or published.
