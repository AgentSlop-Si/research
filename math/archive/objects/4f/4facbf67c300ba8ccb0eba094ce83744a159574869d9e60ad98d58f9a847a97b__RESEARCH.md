# Phase 7 Research: Factored persistent convolution without intermediate expansion

**Date:** October 9, 2026

**Scope:** A numerical implementation of a persistent, compressed algebraic representation for circular-convolution chains. Includes testable conditional complexity bounds for known relationships to prior state. This is **not** a novel worst-case `o(n log n)` transform or multiplication result.

## 1. Problem we address

An ordinary long chain

`C = A_1 * A_2 * ... * A_m`

may be computed by repeated convolutions, generating `m-1` dense intermediate arrays. For only the final output, the known convolution theorem already permits computing all factor FFTs, multiplying their spectra, and running a *single* inverse FFT. The novelty cannot be “avoiding intermediates” by itself: this is well known.

Our practical hypothesis is narrower: **persistently forked, related versions** of the same chain may reuse the spectra and unchanged algebraic subgraphs, while clients request only selected coefficients or the final fully materialized product. Expansion of `m` factors with two additive terms each contains up to `2^m` symbolic terms, but a factored representation has `O(m)` nodes. An efficient implementation must avoid expanding the product, avoid dividing by zero Fourier values, and account for recognition, storage, initialization and output bandwidth.

## 2. Exact invariant

Work with circular convolution `*` over length `N` and the DFT `F`. For each factor `i`, define

`x_i = g_i roll(b_i, s_i) + sum_{t in E_i} delta_(i,t) e_t`, where `b_i` is immutable and `E_i` is sparse.

The transform of the complete product is

`Y[k] = product_{i=1}^m (g_i exp(-2 pi i k s_i/N) B_i[k] + sum_{t in E_i} delta_(i,t) exp(-2 pi i kt/N))`.

No intermediate convolution arrays are necessary for a frequency-bin request. A single bin can be evaluated in `O(m + K)` arithmetic where `K=sum_i |E_i|`, assuming the seed spectra have already been prepared; computing the input relationship metadata is additional. This bound is independent of how many terms the fully distributed polynomial would contain. Given `Q` requested frequencies, naive factored evaluation uses `O(Q(m+K))` arithmetic, plus lookup/memoization.

For a balanced, persistent binary convolution-product DAG, replacing one factor creates `O(log m)` new DAG nodes and shares the other subtrees. Nodes cache requested frequency bins under a bounded LRU. After a particular bin has been evaluated for the unmodified tree, an edited version can use the cached unaffected subtrees to evaluate that bin in `O(log m + k)` where `k` is the edited leaf's number of pending impulses. The engine additionally specializes the **one-modified-factor case**, caching the original all-factor spectral product and the product excluding the edited factor. After these are present, a queried frequency costs `O(log m + k)` in the current implementation (factor access plus correction), or `O(k)` if direct factor metadata is supplied.

## 3. Leave-one-factor-out formula (including shift and scaling)

Let `C = b_1 * ... * b_m`, and let `C_{-j} = b_1 * ... * b_{j-1} * b_{j+1} * ... * b_m`.

Replace exactly one factor by

`x_j = g roll(b_j,s) + sum_{t in E} delta_t e_t`.

Convolution distributes, and `e_t * u = roll(u,t)`. Therefore

`C_new = g roll(C,s) + sum_{t in E} delta_t roll(C_{-j},t)`.

This is an **exact identity** over any commutative ring supporting circular convolution; FFT is not needed for the per-branch arithmetic. It remains valid at zero Fourier bins: the code **never divides** by `B_j[k]`. In the numerical implementation, seed spectra are obtained using `rfft`, `C` and `C_{-j}` using `irfft`, and the update is a series of NumPy array reads and additions.

For `Q` selected time coefficients and `k` known distinct sparse edits, the arithmetic is `O(Q(1+k))`, once the base and complement output arrays exist. This code also requires `O(log m)` time to locate the modified factor in its balanced tree. For explicit full outputs, `O(N(1+k))` time. When `k=O(1)`, this is `Theta(N)` including the `Omega(N)` cost of writing all N outputs.

The initial cost must be counted. The package precomputes `m` rFFTs in `O(mN log N)`, then computes `C` and an exclusion product in `O(mN + N log N)` for one requested excluded factor (the direct implementation multiplies the other seed spectra without division). Repeated variants targeting this same factor amortize that cost.

## 4. When many factors change

The symbolic graph stays factored and has `O(m + K)` state description, ignoring fixed-size pointer overhead, for a single version after `K` distinct edit entries. A straightforward symbolic distribution can generate `2^m` terms if every factor has a base and a nonzero impulse. The graph intentionally **does not distribute** these products.

For dense output with multiple changed factors, the implementation assembles each factor's half spectrum in `O(N(1+k_i))`, multiplies those spectra in `O(mN)`, and calls one inverse real FFT in `O(N log N)`. This is roughly

`O(N(m + K + log N))`

arithmetic after cached seed spectra, not the `O(N)` single-factor guarantee. Distinct versions preserve unchanged subtrees and cached frequency-bin results. There is no claim that the general factored representation implies an arbitrarily fast dense-output algorithm.

### Graph storage

One balanced fresh m-leaf tree uses `2m-1` nodes; one replacement creates `O(log m)` new nodes, with structural hash-consing and a weak interning table. The engine keeps all registered immutable seeds and their half spectra, costing `Theta(mN)` words; cache budgets apply to complements, stored full base products and per-frequency partial values. Cache bookkeeping is not free and all time measurements include it. Multi-root chains with different base sets may trigger independent precomputations; base-output eviction may recompute them.

## 5. Implementation results (local exploratory run)

The benchmark includes input seed registrations, full baseline and exclusion preparations where needed, the creation of forked versions, and all requested outputs.

| N | 48 prepared-kernel FFT recomputations | Phase 7 sparse reconstruction | Ratio |
|---:|---:|---:|---:|
| 4,096 | 2.29 ms | 1.94 ms | 1.18x |
| 65,536 | 39.53 ms | 11.50 ms | 3.44x |
| 262,144 | 269.88 ms | 81.97 ms | 3.29x |

The comparator uses one `rfft` on the modified factor plus one `irfft` per version, with a precomputed spectrum of the other factors. It is optimized as an FFT comparator but *not* the strongest incremental-algebra comparator. A hand-coded exact leave-one-out update has essentially the same arithmetic complexity as our engine and may outperform its general Python dispatcher.

For 128 variants of a 128-factor chain, asking for only 4 frequency bins:

- 20.52 ms: directly multiply each prepared factor's bin (seed FFT prep charged);
- 23.43 ms: Phase 7 generic persistent code (seed FFT prep charged);
- 6.98 ms: a specialized leave-one-out formula (its own seed FFT prep charged);
- warm-only versions can favor the generic engine, but this changes what is being counted.

The failure against the hand-specialized formula is a useful boundary: **the persistent graph improves flexibility and reuse across complex workloads, not every fixed query type.** No eFFT head-to-head data is claimed.

At 24 independently modified factors, the factored engine did not expand the `2^24 = 16,777,216` possible distributed terms; it retained fewer than 100 active structural nodes at measurement time, and produced an answer agreeing with a separately assembled Fourier reference. That does not outperform the usual frequency-domain algorithm, which also never expands all terms.

## 6. Correctness and experimental scope

- 57 regression tests (including unchanged Phase 5/6 modules), spanning circular convolution, basis imports, fork invariants, shifts, sparse edits, multi-factor products, frequency-bin queries, cache budgets, zeros, and random state transformations.
- 1,600 exact modular checks over four prime fields, including products with zero Fourier bins and edits to two factors, compare modular DFT and independent direct circular convolution. These verify algebraic identities on finite examples, not all possible numeric inputs or the large-N floating-point FFT.
- The FFT backend is SciPy's compiled real FFT. The new graph is Python; no SIMD/native C++ code is claimed. Double precision has finite accuracy and can overflow/underflow in extremely long products.
- Input is a *list of real length-N arrays*; to obtain linear convolution, sufficient zero padding must be applied to all arrays before registration. There is no general arbitrary-precision integer multiplication implementation in Phase 7.

## 7. Relation to known results

This is an implementation project based on established algebra, not a claim of discovering the convolution theorem, dynamic convolution, FFT packing, or algebraic DAG sharing.

- The [convolution theorem](https://en.wikipedia.org/wiki/Convolution_theorem) already converts chains into pointwise spectral products; what we add is persistent relation metadata and lazy per-bin retrieval across related versions.
- General leave-one-out products can be computed without inverses using segment/prefix-suffix structures; see [a published commutative-semigroup discussion](https://pmc.ncbi.nlm.nih.gov/articles/PMC7502207/). Our exclusion FFT products follow the same general algebraic pattern and should not be claimed as a new identity.
- [eFFT](https://github.com/raultapia/efft) is relevant incremental-FFT prior art. We have not run its native benchmark on matching Phase 7 workloads.
- [OpenAI #130](https://github.com/openai/math/blob/main/lean/docs/130.md) concerns sub-`N log N` exact DFT in an unrestricted complex-arithmetic model; Phase 7 relies on SciPy and does not implement or improve its universal worst-case exponent.
- The [CrocSwap repository](https://github.com/CrocSwap/integer-mult-bounds) works on integer multiplication using input-independent rank-optimized networks and finite-tape recurrences, not simply persistent cached transform versions.

## 8. Next falsifiable questions

1. Compare a C++/FFTW implementation of the persistent engine to eFFT and a hand-specialized exact leave-one-out update on the **same workloads**, with acquisition, setup, and memory traffic charged.
2. Add a compact representation for each input that is a *sum of several basis signals plus a sparse residual*, avoiding the current Phase-5 importer fallback that materializes multi-basis states.
3. Profile total cache memory when many distinct chain roots and excluded-factor products coexist; choose a cost-aware eviction policy based on expected reuse, rather than a simple LRU.
4. Extend the graph to include **addition of convolution expressions** without distributing their products. Verify circuit-size and bin-query bounds and clearly measure partial-output workloads.
5. Explore exact modular or block-integer input arithmetic without conflating a dynamic time bound with fresh integer-multiplication bit complexity.

**Bottom line:** We have a tested, mathematically correct dynamic-chain compression and reuse mechanism with useful full-output wins in a specific related-version workload. A general sub-`N log N` FFT or improved integer-multiplication exponent remains unproved.
