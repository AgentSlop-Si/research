# Fair eFFT comparison boundary

Source: https://github.com/raultapia/efft (Tapia, Martínez-de Dios, Ollero). The README describes 2024 eFFT and 2026 eFFT-C++ implementing event-driven FFT updates with cached radix-2 trees. The Python API has `eFFT(size)`, `Stimulus(x, y, polarity)`, `update`, and `get_fft`. The implementation is distributed under GPL-3.0 and depends on Eigen3, with FFTW optional for native benchmarks. Source verification: Oct 9, 2026.

**The native eFFT package was not available in this runtime.** An isolated `pip install --target` failed because outbound package-index DNS resolution is disabled. No eFFT execution or direct speed comparison was performed. No eFFT source is copied into this project.

## What is actually comparable?

| Feature | eFFT | Phase 9 |
|---|---|---|
| Object computed | FFT of event-integrated 2D signal | Time coefficients of a user-defined sum/product of circular convolutions (plus selected frequency queries via Phase 8) |
| Changes | Event insertion/removal with a 2D coordinate and polarity | Real-valued known amplitude edit at one 1D signal position, to a named leaf inside a polynomial convolution graph |
| Main state | Incrementally maintained radix-2 computation tree | Cached basis spectra plus Taylor convolution correction kernels; fused update compiler |
| Output | 2D Fourier matrix | 1D time-domain convolution coefficient vector or a selected subset |
| Exactness | Mathematically exact FFT updates in a numerical implementation | Exact polynomial identity executed in floating point; independently checked over finite rings |

A defensible head-to-head needs a **single common contract**: update a specific image pixel and return the entire same 2D frequency spectrum after each event, with initial state and materialization included. Our current Phase 9 sum-product engine does **not** implement that contract, so quoting a speed ratio versus eFFT would be misleading.

The reproducible comparison **we did perform** is with fully materialized 1D circular-convolution outputs, using SciPy's optimized real FFT baseline and a hand-specialized Numba formula implementing exactly the same relation and output scope.
