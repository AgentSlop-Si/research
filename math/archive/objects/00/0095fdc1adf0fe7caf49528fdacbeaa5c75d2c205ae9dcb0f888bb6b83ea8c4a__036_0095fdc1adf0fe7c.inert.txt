**Status:** Verified implementations and mathematically derived restricted-class bounds. **No new uniform sub-\(N\log N\) algorithm for arbitrary fresh complex FFTs or exact arbitrary integer multiplication was established by this project.**

## Executive verdict

The most useful contribution of the project is **a relation-aware FFT architecture**: rather than always recomputing a complete transform, it uses knowledge about an input's relationship to cached data. This yields exact algebraic descriptions of sub-\(N\log N\) update costs in special cases, tested implementations, and a clear identification of when collision-based reuse fails. Separate input-independent split-radix and finite-field table experiments reproduced existing published techniques, with explicit accounting of arithmetic and lookup costs.

## Core mathematical insight: cost conditioned on *relationship* to cache

Let \(F_N\) be the DFT and let \(X=F_N(x)\) already be cached. If a new signal is \(x'=x+e\) and \(e\) has \(k\) known nonzero positions, then

\[F_N(x')=X+F_N(e).\]

A pruned radix-2 algorithm needs at most \(\min(2^d,k)\) active subtrees at recursion depth \(d\), each of size \(N/2^d\). Summing all butterfly work gives \(O(N(1+\log(k+1)))\) arithmetic. Thus one edit takes \(\Theta(N)\), and \(k=(\log N)^c\) yields \(O(N\log\log N)\), for explicit dense outputs and known change locations. This is **a dynamic problem**; the first fresh dense transform still costs \(O(N\log N)\) with the baseline backend.

If \(x=Bc+e\), with \(r\) known basis columns of \(B\), cached basis spectra, and a known \(k\)-sparse residual, the same reasoning gives \(O(N(r+1+\log(k+1)))\) for a dense output. This is little-o of \(N\log N\) if \(r+\log(k+1)=o(\log N)\). The cost of **discovering** \(B,c,e\) must be included unless a producer supplies them as trusted metadata.

A promising API is therefore `fft_from_delta(base_id, [(index, delta),...])`, `fft_from_shift(base_id, shift)`, `fft_from_basis(basis_ids, coefficients, sparse_residual)` and lazy materialization of spectra. A planner should compare this against native `rfft/fft` on every request.

## Engineering results and obstacle

The available Python projects have **18 structural** and **14 adaptive** unit tests passing as re-run on 9 October 2026. The saved C++/FFTW benchmark report (its C++ implementation is not available in the active container for independent re-run) records ~1.76–1.89× speedup for exact repeated inputs of sizes 65,536 and 262,144. By contrast, scanning for cyclic shifts made the C++ prototype slower (0.38–0.56× baseline); single-edit reuse was near break-even at 262,144 even after porting from Python. A 128-signal rank-2 batch with **explicit** dense outputs was only ~1.02× baseline at length 65,536, because writing the outputs is expensive. Numbers are hardware-specific exploratory benchmarks, not mathematical theorems.

**Crucial engineering conclusion:** removing Python interpreter overhead does *not* remove the dominant cost of discovering a relation by scanning \(N\) values, materializing \(N\) outputs, and moving data through memory. The highest-value next experiment is **upstream relation metadata plus lazy spectrum views**, with end-to-end timing and memory-bandwidth measurements. This is distinct from simply running another CrocSwap-style rank-weighted circuit search.

## What caching alone cannot prove

Repeated small binary input blocks are guaranteed, but a length-\(m\) independent binary block matches another with probability \(2^{-m}\). For large \(m\), exact collisions are rare, and only the bottom \(O(\log\log N)\) radix-2 recursion levels have abundant repetitions at typical sizes. That does not remove a growing *fraction* of all \(\log N\) stages. Counting saved butterflies alone omits hashing, verification, intermediate storage and output writes. Allowing an uncharged oracle storing every possible answer makes linear lookup trivial for *any* finite-input function and is not a uniform complexity proof.

The finite-field tabulation result is different: it uses a *bounded state alphabet* at **every** grouped layer, and reuses the same complete small-block table throughout the transform. For fixed \(\mathbb F_p\), a block of \(b=2^t\) values has \(p^b\) possible inputs, with \(\Theta(bp^b)\) total table cells. Choose \(b\asymp c\log_pN\), \(0<c<1\), then preprocessing is \(O(N^c\log N)=o(N)\), while online passes require \(O(N\log N/\log b)=O(N\log N/\log\log N)\). The initial 2023 result belongs to Alman, not to this project.

For complex FFT, even binary initial values don't guarantee a small intermediate alphabet: at a primitive \(2^t\)-th root \(\omega\), one selected DFT coefficient on binary vectors assumes exactly \(3^{2^{t-1}}\) possible exact values, by linear independence of the first \(2^{t-1}\) powers of \(\omega\) over \(\mathbb Q\). For an exact prime-field NTT, the necessary modulus \(q\ge N+1\) makes exhaustive lookup expensive. These are specific obstacles, not proofs that no different method works.

## Important external-result correction

As of October 2026, the OpenAI math repository also describes **result #130, exact Fourier transforms below \(n\log n\)**: a uniform algorithm with bound \(O(n(\log n)^{1-10^{-13}})\) for exact DFT/convolution in an unrestricted exact complex-arithmetic and logarithmic-word-indexing model, with a supplied root of unity. Its Lean documentation describes the scope of selected formalized statements. **This is an independent external claim, not a breakthrough made in these chats**, and it should not be confused with stable floating-point FFT, bounded-coefficient linear lower bounds, or integer-multiplication bit complexity. Source: https://github.com/openai/math/blob/main/lean/docs/130.md

The CrocSwap repository improves an integer-multiplication asymptotic exponent in the specific fixed-tape framework of OpenAI result #109; its shared circuit construction is **algebraically input-independent**, not a cache of repeated numerical FFT inputs. These claims remain distinct from our engine.

## What would count as the project's *next* genuine contribution?

A reproducible adaptive engine in which the producer supplies certified relationship metadata and a cost-aware dispatcher chooses between:

- existing/cached spectra and views;
- O(N) shift/single-edit update;
- pruned FFT for a known \(k\)-sparse residual;
- a cached low-rank basis and sparse residual;
- packed real FFT or optimized native `rfft/fft` fallback.

The output representation should be explicit: **dense numeric array** or **lazy basis-plus-delta representation**. Measure metadata cost, initialization, table planning, validation, cache memory, peak allocations, and output materialization. Publish parameterized complexity and honest break-even maps rather than claiming a new worst-case arbitrary-input FFT result.
