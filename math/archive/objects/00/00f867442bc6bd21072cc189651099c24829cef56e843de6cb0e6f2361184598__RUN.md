# Reproduce Phase 39

All tests and audits use exact finite-field or rational Gaussian arithmetic. No floating-point rank or approximate fitting is used.

```
cd fft_green_phase39_bivariate
python -m unittest -v tests_phase39
python charzero_n4.py
python generic_control.py
python create_certificates.py
g++ -O3 -std=c++17 -Wall -Wextra phase39_exact_audit.cpp -o phase39_exact_audit
./phase39_exact_audit instances/phase39_N8_p998244353.txt 0 cubic
./phase39_exact_audit instances/phase39_N8_p2013265921.txt 0 quartic
./phase39_exact_audit instances/phase39_N16_p998244353.txt 0 cubic
./phase39_exact_audit instances/phase39_N16_p2013265921.txt 0 cubic
./phase39_exact_audit instances/phase39_N256_p998244353.txt 0 cubic 100000
sha256sum -c SHA256SUMS.txt
```

The second argument is the number of **lexicographically first** mappings to check (`0` means exhaustive). With a fourth argument, the verifier instead checks that many **deterministically dispersed** mappings. The third argument selects `cubic` (four quadrics times linears, rank 10) or `quartic` (three quadrics times quadratics, rank 15).

**Recorded exhaustive counts per prime:** `N=4:288`, `N=8:94080`, `N=16:10483200` (cubic only at N=16). Both primes passed with no rank deficiencies. The larger-size `sampled_native_audit.json` is **not** exhaustive and must not be described as such. Direct symbolic `Q(i)` full ranks hold at `N=4`.

For independent re-creation of the inputs, run `python phase39_bivariate.py`; `build(n,p,g)` regenerates `T,G2,G3,G6` from the deterministic cycle orders. Building `T` takes dense work used for certification only.
