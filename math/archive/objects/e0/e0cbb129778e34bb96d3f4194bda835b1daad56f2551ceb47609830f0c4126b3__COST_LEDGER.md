# Phase 29 — fully charged field arithmetic

## Unit convention

Addition/subtraction or multiplication by a prepared field constant not equal to 1: one field operation. No free `±i` or scalar multiplier. Roots, coefficient preparation, integer address calculation, memory movement and bit complexity have separate scope.

`N=120h`, `h=2^t`, `g=8h`.

| Component | Additions | Multiplications |
| --- | ---: | ---: |
| 120 length-`h` dyadic FFTs | `120ht` | `60ht−120h+120` |
| 15 copies of `(8,h)` CT twiddles | 0 | `105(h−1)` |
| `h` nested 120-point WFTA kernels | `1038h` | `140h` |
| **Phase 29 total** | **`120ht+1038h`** | **`60ht+125h+15`** |

Phase 28 at the same input length costs `120ht+1008h` additions and `60ht+168h+15` multiplications. Phase 29 performs **30h additional additions but 43h fewer multiplications**, saving `13h` scalar field operations.

## Cold setup

Phase 28 and Phase 29 use one identical base root/table and existing 15-point diagonal, whose total preparation cost is recorded as `common_setup` in the JSON benchmark. Phase 28 then prepares 17 additional tensor multipliers; Phase 29 prepares 74 field operations worth of new constants (72 multiplications plus two additions). Therefore the new one-shot cold penalty is 57 operations, for cold saving `13h−57`. This is positive from `h=8`, `N=960`.

At `N=61,440` Phase 29 makes 1,084,416 additions and 340,495 multiplications, while Phase 28 makes 1,069,056 additions and 362,511 multiplications. All results were reproduced in both prime fields.

The new diagonal has 144 prepared field scalars versus the Phase 28 fused 60-point diagonal's 72. At execution, intermediate arrays contain up to 144 values per tensor stage, plus separate buffers. Input, output, 120 dyadic row spectra, and the length-`g` root table require `O(N)` field storage, not zero traffic. The reference implementation allocates multiple intermediate lists and is not optimized for cache or wall-clock performance.

## Rejected weighted-four experiment

The formal six-channel weighted-four tensor costs 468 additions +107 multiplications =575 operations on generic nonzero phase blocks; the Phase 28 60-point kernel plus 45 twiddles costs 558, **17 fewer**. At zero phase the weighted-six-channel tensor costs 572 versus 513 for the Phase 28 fused kernel; see `weighted4_gate.py`. This excludes coefficient preparation from both executed kernel estimates. It is a scoped negative result, not a general obstruction against all fusion strategies.

## Important modeling limits

- Finite-field primality and primitive-root order are checked with modular powers but not their complete machine-verifiable proof certificates; constants in code were supplied from inherited research.
- A scalar operation may require multiple bit operations; e.g. modular multiplication is not uniformly 1-bit-operation.
- CRT index arithmetic, full-array allocations, data-movement counts and floating-point rounding may dominate runtime; no practical speedup is claimed.
- The saving is `Theta(N)` while the leading term remains `Theta(N log N)`.
- The comparator is the **specific optimized Phase 28 network**, not FFTW, pocketfft or the globally best FFT/NTT circuit.
