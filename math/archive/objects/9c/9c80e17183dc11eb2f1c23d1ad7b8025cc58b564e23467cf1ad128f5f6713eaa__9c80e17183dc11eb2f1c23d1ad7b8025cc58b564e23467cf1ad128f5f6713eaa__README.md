# Linear-time preparation of the complete q-kernel spectrum

**Constructive result: every bin of the length-2N spectrum of the fixed
q-Pascal convolution kernel can be generated in O(N) exact field work.** This
removes a preprocessing FFT from a conventional application of that kernel.
The implementation still uses ordinary FFTs on the fresh input. It does not
give a fresh-input transform below N log N, or a bit-complexity improvement.

This is new to this project's checkpoint, with an independent algebraic proof
below. Global novelty is not asserted. The q-Pascal factorization and
q-exponential coefficient relations are established mathematics; see Alexey
Kuznetsov, *Using q-calculus to study LDL^T factorization of a certain
Vandermonde matrix*, https://arxiv.org/abs/1507.02959 . The code below implements
a particular finite root-orbit specialization and cost comparison.

## Inputs and exact identity

Let N be a power of two at least 2. Work over a field of characteristic not
dividing 2N, with a **supplied primitive 2N-th root eta**. Set q=eta^2. This
extends the previous checkpoint's supplied primitive N-th-root model: eta is
additional data and need not lie in the field generated by q. No root search or
construction from q is silently assumed free. For complex roots, the statement
is an exact arithmetic identity; its field-operation model is not a bit model.

Set f_j=product_{a=1}^j(1-q^a), t_j=1/f_j, and

    H(z) = sum_{j=0}^{N-1} t_j z^j.

Since product_{a=1}^{N-1}(1-q^a)=N, we have t_{N-1}=1/N. The coefficient
recurrence (1-q^j)t_j=t_{j-1} implies the **polynomial identity**

    H(qz) = (1-z)H(z) + z^N/N.                     (1)

This is stronger than a congruence modulo z^N. The final term is essential when
evaluating on a nonzero Fourier grid. In particular H(q)=1/N, whereas omitting
the final term would incorrectly give H(q)=0.

Let v_k=H(eta^k) for 0<=k<2N, with subscripts interpreted modulo 2N.
Equation (1) becomes

    v_{k+2} = (1-eta^k)v_k + (-1)^k/N.            (2)

Thus all 2N values separate into just two first-order affine cycles.

## Exact O(N) construction

For the even cycle, at k=0 the multiplier is zero. Therefore v_2=1/N; starting
there and executing N-1 further updates produces all even positions including
v_0.

For the odd cycle, compose its N affine updates starting at the temporary
value b=0:

    b <- (1-eta^(2r+1))*b - 1/N,  r=0,...,N-1.

The full affine map has slope

    product_{r=0}^{N-1}(1-eta*q^r)
      = 1-eta^N = 2.

Consequently its fixed point obeys v_1=2v_1+b, hence v_1=-b. Replaying N-1 odd
updates materializes every remaining odd position. This requires no additional
inverse and works exactly in every stipulated field. The first pass determines
the starting scalar; it is not a transform of the arbitrary input.

The powers eta^k are generated once by a multiplicative chain. The integer
bit-reversal permutation used by the later FFT is generated in O(N) total
integer operations by doubling a list at each step. Storage, preparation
addressing, and every spectrum write are O(N); no table of exponentially many
inputs is used.

More generally, on any nonzero orbit z=a*q^r, the forcing is a^N/N and the
composed multiplier is 1-a^N. If the composition starting at zero ends at b,
the required initial value is b/a^N. Thus the same proof evaluates all N
points on that orbit in O(N) field work, including one constant division if
its inverse is not already known. A primitive M-th-root grid with N dividing
M splits into M/N such orbits, giving O(M) spectrum preparation with supplied
compatible roots. The implementation and finite audits in this package use
M=2N, where the orbit inverses are just +1 and -1.

## Charged arithmetic comparison

Let L=log2(N). Both implementations prepare the same 2N powers, the same
bit-reversal permutation, and 1/N plus 1/(2N). They count a single inversion to
obtain the constant 1/2 and then L+1 multiplications. In a model supplying 1/2,
that inversion can be omitted. All multiplications by 0 or 1 are still counted.

| Preparation method | Multiplications | Additions | Subtractions | Negations | Constant inversions |
|---|---:|---:|---:|---:|---:|
| Orbit recurrence | 5N+L-2 | N-1 | 4N-1 | 1 | 1 |
| Kernel generation plus ordinary radix-2 FFT | NL+4N+L-1 | N(L+1) | NL+2N-1 | 0 | 1 |

The baseline already uses a linear kernel-generation recurrence: t[N-1]=1/N
and t[j-1]=(1-q^j)t[j]. Its FFT is of the zero-padded kernel of length 2N.
Thus the comparison does not hide a quadratic baseline.

One application of the lower triangular kernel T to an arbitrary length-N
input pads to 2N, computes its FFT, multiplies all 2N bins by v, computes the
inverse FFT, normalizes, and returns the first N entries. Since both polynomials
have degree at most N-1, their product has degree at most 2N-2, so no cyclic
wraparound contaminates the answer. The fully materialized result is exact.

Online counts for either preparation method:

    multiplications: 2NL + 6N
    additions:       2N(L+1)
    subtractions:    2N(L+1).

This includes inverse normalization and every pointwise product. Memory and
integer address operations remain O(N log N) online and peak live array storage
is O(N). Reported array-traffic counters are for a logical array implementation;
Python list temporaries add O(N) operations and storage. They are not a claim of
exact interpreter traffic or a native timing benchmark.

| N | Orbit preparation, all counted field operations | Baseline preparation | Either online application |
|---:|---:|---:|---:|
| 16 | 162 | 307 | 544 |
| 64 | 644 | 1,605 | 2,944 |
| 256 | 2,566 | 7,943 | 14,848 |
| 1,024 | 10,248 | 37,897 | 71,680 |
| 4,096 | 40,970 | 176,139 | 335,872 |

These are operation counts, not measured elapsed speedups. Reusing the same
prepared kernel across several inputs amortizes either preparation; their online
graphs remain identical.

## Applying the result to the previous Fourier factorization

The previous exact identity is F_N=S T D T^transpose S, and
T^transpose=R T R for reversal R. Reusing this single spectrum for both T
actions gives four length-2N FFTs plus the diagonal work. For the ordinary
radix-two implementation supplied here, the total online counts are

    multiplications: 4NL+15N
    additions:       4N(L+1)
    subtractions:    4N(L+1),

with additional O(N) preparation of S and D. A direct ordinary length-N radix-2
FFT costs NL/2 of each of these three operation types in the same unoptimized
counting convention. The factorized route is therefore substantially more
expensive in this implementation, despite its improved cold spectrum setup.

Adjacent Fourier transforms do not cancel immediately when substituting the
convolution implementations: zero padding, truncation, reversal, and the
nonconstant middle diagonal intervene. Proving a cheaper complete fused graph
remains a separate construction problem. This observation is not an
impossibility theorem about such fusion.

The recurrences can suffer cancellation and large exact intermediate values.
No numerical stability, bounded coefficient, or bit-complexity claim follows
from the scalar field-operation counts.

## Verification and reuse

Run `python3 audit.py`. The audit verifies:

- 1,044 exact spectrum values against direct polynomial evaluation and an
  independently computed radix-2 FFT of the coefficients;
- 522 full basis vectors for the triangular operator, plus mixed inputs;
- 74 full basis vectors for the complete Fourier factorization;
- the nonzero boundary term, odd-cycle multiplier, and the exact operation-count
  formulas in every case.

There are 17 configurations: N=2 through 128 over each of F_65537 and
F_998244353, plus N=2,4,8 over the exact rational cyclotomic fields containing a
primitive 2N-th root. Root orders are explicitly verified in the audit. These
finite tests verify the implementation; the all-N argument is equations (1)-(2)
and affine-cycle closure above. `prior_exact_arithmetic.py` is copied unchanged
from the preceding fixed-kernel checkpoint.

The deliverable is a usable linear-preparation routine for a specific fixed
convolution graph. It is not an independent sub-N-log-N Fourier algorithm.
