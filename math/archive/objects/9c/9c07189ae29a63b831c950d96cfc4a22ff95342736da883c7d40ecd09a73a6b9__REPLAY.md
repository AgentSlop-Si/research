# Portable replay and verification

Requirements: Python 3.8 or newer, standard library only. No network, uploaded research source, third-party package, compiler, or original predecessor directory is needed to replay the new checks.

Copy these two scripts into the same directory:

- `independent_extension_checks.py`
- `conversion_and_cost_checks.py`

Run from that directory:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 independent_extension_checks.py > replay-independent.json
PYTHONDONTWRITEBYTECODE=1 python3 conversion_and_cost_checks.py > replay-conversion.json
```

Both scripts terminate with nonzero status if any assertion fails. On success, compare their JSON contents with `INDEPENDENT_CHECKS.json` and `CONVERSION_AND_COST_CHECKS.json`. Seeds are fixed. No run time or memory measurement is interpreted as a RAM-complexity benchmark.

`SHA256SUMS` seals all delivered report, script, result, receipt, and input-hash files, excluding the manifest itself. Verify with `sha256sum -c SHA256SUMS` from this directory. Python bytecode cache files are outside the sealed artifact set.

`INPUT_SOURCE_SEALS.json` records the byte hashes and sizes of every file present in the predecessor directory when reviewed. `SEALED_INPUT_HASHES_BEFORE.txt` and `SEALED_INPUT_HASHES_AFTER.txt` are identical and provide the original absolute-path evidence that those files were not changed. Portable replay does not require those absolute paths to exist.

`PRIMARY_SOURCE_RECEIPTS.json` records primary-literature URLs and the exact mathematical facts imported. These are bibliographic/read receipts, not bytewise seals of the remote PDFs. No remote-PDF byte hash is claimed: the papers were read through the web tool, and PDF bytes were not downloaded into this package.

The report's two derived extensions remain pending separate second proof review. Replaying successful finite checks does not close that mathematical-review requirement or establish historical novelty.
