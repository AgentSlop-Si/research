# Phase 5: bounded corrective derivative

Prepared 8 October 2026. This is a new derivative of the supplied Phase 5
implementation. The uploaded files were not modified. No new Fourier or
integer-multiplication complexity claim is made.

## Included files

- `cost_aware_fft.py`: patched Phase 5 implementation
- `phase.py`: unchanged compatible dependency from the supplied Phase 4 ZIP
- `tests/test_regressions.py`: 12 focused tests, including parameterized normal cases
- `reproduce_cases.py`: four bounded original-versus-patched reproductions
- `changes.diff`: exact change from the original Phase 5 source
- `SOURCE_SHA256.txt`: original-source and dependency identity

Requires Python 3.10+, NumPy and SciPy for the tests. Validated with Python
3.12.14, NumPy 2.3.5 and SciPy 1.17.0. No packages were installed.

Run from this directory:

    python -m unittest discover -s tests -v
    python reproduce_cases.py
    python reproduce_cases.py --source '/path/to/cost_aware_fft(1).py'

## Confirmed issues and bounded fixes

1. **Spectrum-only auto dispatch dropped the reference signal.**
   Original `cost_aware_fft(1).py` lines 518–531 create a dummy zero signal,
   forbid explicit `native`, but allow `auto` to select it. For the rFFT of
   `arange(8)` plus an edit `(1, 2)`, auto returned DC=2 instead of 30; maximum
   absolute error was 28. Auto now uses the valid direct spectral path.
   No inverse transform or hidden input reconstruction is introduced.

2. **Calibration could admit a candidate that execution rejected.**
   Original line 479 checked 16N bytes; line 407 required 16N+8(N/b).
   At N=16 with a 256-byte budget, calibration raised `MemoryError`.
   Admission and execution now share one conservative estimate. Calibration
   also skips a pruned candidate if its backend allocation raises `MemoryError`,
   and never selects a partially measured candidate. Other errors are not hidden.

3. **Phase-cache accounting omitted retained padding.**
   Original lines 275–292 count the visible phase slice. Phase 4 `phase.py`
   lines 37–38 retain a larger padded array. At N=4096, a 2049-value view has
   32,784 visible bytes but holds 49,152 bytes of backing storage. The LRU now
   charges that backing allocation on insertion and eviction. With a 32,784-byte
   limit, this phase is returned to the caller but is not retained in the cache.

4. **The pruned temporary guard counted too few simultaneously live arrays.**
   Original lines 407–419 omit the transform result, possible transpose copy,
   and accumulation/phase temporaries. For N=65,536 and k=8, a 1,114,112-byte
   budget admitted a measured ~4,327,000-byte incremental allocation peak;
   excluding the returned spectrum still leaves ~3,803,000 bytes.
   The patched estimate conservatively charges six N-length complex buffers,
   six (N/b)-length float buffers and 64 KiB of padding/small-array allowance.
   The formerly admitted low-budget case is rejected before allocating the kernel.

`max_temp_bytes` is explicitly a conservative work-array eligibility budget,
not a hard allocator or process-RSS cap. FFT/runtime hidden allocations remain
backend-dependent; persistent phase-cache storage has its separate budget.
Caller-owned bases and output handles remain separately reported, as before.

## Validation

All 12 tests passed. Normal-case checks cover 13 lengths from 1 through 65,536,
including odd lengths; shifts, combinations, edits, direct/native/auto/pruned
materialization where valid; individual and selected bins; output-cache
isolation and invalidation; fork isolation; and tracked subscriptions with
external-mutation detection. Worst absolute error in these bounded checks was
6.685e-10, within `atol=1e-9, rtol=3e-11`.

The four repros demonstrate the original failures and corrected behavior.
No full performance benchmark or competitor benchmark was run. These results
do not establish stability for arbitrary magnitudes, arbitrarily long streams,
all backend versions, or exact arithmetic.

## Remaining research boundaries

The calibration key describes size/edit-count/term-count/shift presence, but
does not encode phase-cache warmth or edit locality. A warm calibration can
mis-predict cold or changing-position requests. This patch does not redesign
that policy or claim a speedup.

The supplied benchmark JSON contains software versions and timings but no
random seed, despite the report saying the seed is included. Its benchmark
driver was not among the four Phase 5 attachments. Those are needed for a
fully reproducible fresh run.

The official [eFFT repository](https://github.com/raultapia/efft) and
[2026 software paper](https://openresearchsoftware.metajnl.com/articles/10.5334/jors.642)
confirm prior event-tree FFT reuse. The documented implementation uses 2D
power-of-two frames, activation/deactivation stimuli and `std::complex<float>`.
Phase 5 uses 1D float64 signals and additive real edits. A fair head-to-head
must first align geometry, stimulus semantics, precision, setup and output
requirements. Repeated activation is not automatically another additive +1.
