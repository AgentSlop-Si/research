## Executive result

The canonical-input algebra in these versions agrees with the previously independently reconstructed fixed-family exclusions. This static review finds **real false-positive paths in two saved-certificate validators**, a **limited-run enumeration defect**, an incorrect packed-record docstring, and an input-normalization false exclusion. These findings do not undo the separately reconstructed Phase30 mathematical result. They do mean that a successful return from the affected source validators is not adequate evidence for that result.

The algebraic gates remain necessary-condition exclusions for their fixed family. A rank-deficient Macaulay matrix, moment match, finite-field point, or five-term dimension obstruction does not establish a Fourier construction. Applying a known constant-size sum of cyclic Green operators is linear in field-operation count; selecting Fourier-correct parameters is a different problem. No arbitrary-length Fourier construction or FFT lower bound is certified here.

## Fresh corrections, with exact-version evidence

### G01. Saved N4 Macaulay verifier can accept no witnesses, or empty minors

File `phase29_macaulay.py`, SHA-256 `c118559b75e6045dff1abbb00637c9c1281d9c3647939ffbc9ab0f3fbdd93fae`, lines 145–155.

`verify_saved_audit` asserts only that the claimed prime equals the imported prime, n=4, and the claimed `full_rank_cases` is 576. It then builds the family and iterates the supplied `pivot_witnesses` dictionary. It does not require any witnesses, all 576 keys, valid permutation keys, or exactly 15 distinct valid selected rows.

Direct counterexample: `{prime: 998244353, n: 4, seed: 2804, full_rank_cases: 576, pivot_witnesses: {}}` reaches `return True` after `build_family` returns normally. The loop checks zero witnesses. This is a control-flow proof; the uploaded function was not called.

There is a second independent hole: `determinant_modp([])` returns 1 by lines 82–103. Its n=0 shape check and pivot loop are empty, leaving `out=1`. Thus even adding a nonempty/all-keys check alone is insufficient: each purported witness could use `selected_rows: []` and `determinant_modp: 1`. The verifier must insist on a 15×15 minor formed from 15 distinct legal row positions and every exact permutation pair, recompute rather than trust coverage counters, and verify family identity. These are high-severity defects if this function is used to accept untrusted certificates. The generated honest family and the previously independently reconstructed result are separate evidence.

### G02. Two-parameter saved-slice validator does not validate the theorem preconditions

File `phase29_two_parameter.py`, SHA-256 `004a841d1b437c197c71f3fbafc7c8af6089b4c580d5192aa226031762728108`, lines 135–140.

`validate` checks nominal array lengths, equality to self-reported leading coefficients, and a Bézout identity. It does not require nonzero leading coefficients, the expected parameter-independent leading terms, correct prime, seed, slice, or correspondence of either polynomial to the generated matrices.

Explicit n=4 counterexample: P1=`[1]+[0]*16`, P2=`[0]*33`, U=`[1]`, V=`[0]`, leading values=`[0,0]`. Every validator predicate is true even though actual degrees are 0 and undefined/zero-polynomial, rather than 16 and 32. The independent control checks these predicate facts without invoking uploaded code. The production `certificate` function does check full degrees, expected leading values, and coprimality before returning; this defect is in the standalone saved-object validator, not a demonstrated failure of those production computations.

Both this validator and G01 use `assert` as their complete verification guard. Python optimization disables assertions. User-facing certificate verification should use explicit rejecting branches and preserve nonzero/coverage/shape conditions in all interpreter modes.

### G03. Fixed-N8 C++ limit is not a global case limit

File `fullminor_audit.cpp`, SHA-256 `c7080fd13999a0a41323d38e59fdb735f433326eb3c6fdebbc675716abaebca5`, lines 98–105.

The range-for loops are nested without an outer termination condition. `break` at line 104 exits only the column-triple loop. After reaching the limit, each remaining row triple contributes one more mapping. A limit of 1 or 0 checks 336 mappings; 10 checks 345; 336 checks 671. The independent control reproduces only this loop structure. A limited file is not a contiguous prefix of the full lexicographic stream after the premature break. Default unlimited enumeration is unaffected and visits all 336²=112,896 mappings. The separate generic C++ version uses one linear index interval and does not share this bug.

Correction: use a single global index interval, or check the limit in both loops; define limit=0 explicitly. Require expected index coverage when consuming partial files.

### G04. Python packed-record documentation promises determinants that are not written

File `phase30_macaulay.py`, SHA-256 `534d11889aa5784df1238229b075f0da81076c42eae32664f86a0f251ed04590`, lines 257–296.

The docstring promises rank + 20 selected rows + a four-byte determinant (25 bytes at degree 3). The writer at line 284 emits only rank + selected rows + 255 padding to the basis dimension (21 bytes at degree 3). Determinants are computed only for the JSON examples. The actual Phase30 RUN.md correctly calls the native N8 record 21 bytes. Correct the stale Python docstring and bind a format version, degree, field, family, enumeration order, and record count to any standalone stream. The generic C++ program writes rank bytes alone. A rank stream is a record of results, not a self-checking polynomial certificate.

### G05. Raw zero counting can falsely exclude equivalent residue matrices

File `phase28_synthesis.py`, SHA-256 `7a4502b853c81fc442d846720f744eee670f4abd948de21c940ed00165fc3862`, lines 125–140.

The entry-zero count uses raw `x == 0`; later arithmetic is modulo P. With target=`[[P,1],[1,1]]` and middle=`[[0,1],[1,1]]`, the matrices are identical over the field, but the raw counts are 0 versus 1 and the function returns `excluded`. Normalize entries at the API boundary or test `x % P == 0` consistently. Canonical matrices built by the reviewed generators are reduced, so this does not change the seeded-family conclusions. Related raw truthiness checks in `ratio_correlation` reject/mishandle noncanonical zero residues by an inverse error rather than reliably recognizing support.

### G06. Field, import-closure, output-integrity, and cost preconditions need explicit boundaries

- `phase28_synthesis` reads the modulus and generator from environment variables without primality or exact root-order checks. `fft_matrix` checks power-of-two length and divisibility, not root order. Other root-building entry points do not even make those length checks. The approved default/second-prime families were independently checked in the prior mathematical audit. An arbitrary environment override is not thereby certified. Fermat inversion in Phase30 rank routines/C++ requires a prime modulus; the Python inverse helper's successful modular inverse alone does not establish a field.
- Both C++ sources permit compile-time modulus replacement. Their u32 addition/subtraction reductions are safe for the two documented primes, which are below 2^31; they are not a generic full-u32-prime implementation because addition can overflow for larger primes. Input entries are multiplied through u64 and reduced before their use in these additions. No overflow issue was found for 998244353 or 2013265921.
- Native readers check the matrix header and truncation, but do not reconstruct or authenticate the Fourier/Green family. They read native-endian 32-bit words without an endian/version declaration. A full-rank result for arbitrary supplied matrices does not certify that those matrices are the advertised seed/root/coupling construction.
- Both native programs return success after processing even when deficient ranks occur. The generic program also accepts an empty interval. Neither checks write/close failure before printing its summary. A zero exit code is not an exclusion certificate, and complete file length/hash plus histogram/index coverage must be independently checked.
- `phase30_four_parameter` prepends a sibling directory to `sys.path`. Import provenance must be recorded; a same-named sibling can override bundled Phase29 dependencies. Exact equality of a source file across archives does not imply equality of its import closure.
- The `FourGreenExecutor` initialization-O(N) docstring is unsupported literally: roots are generated by n separate exponentiations and inherited permutation validation sorts. The reviewed Phase28/29 constructors have the same setup pattern. Per-application O(N) for a fixed number of terms remains valid in scalar field-operation accounting, with correctly sized vectors and prepared data. No constant-bit-cost or arbitrary-precision claim follows.

## Algebra and implementation review

### Phase28 synthesis and exact invariants

The batch inversion prefix/suffix algorithm, row-pair reciprocal-ratio moments, vertex fingerprint relabeling, and final all-entry scalar reconstruction are consistent for nonempty square canonical residue matrices with nonzero entries over a field. Fingerprint multiplicities return `inconclusive` rather than guessing a permutation. Mismatched exact necessary invariants exclude; unique signatures force the candidate permutations, so a failed all-entry reconstruction legitimately excludes in the field. The recovered row/column scalings are nonzero when target and middle have nonzero entries.

The ratio-correlation similarity identity is correct, and trace(C²)=n³+2 times the sum of unordered row-pair first moments. Both moments and traces are necessary invariants, not sufficient factorization criteria. A modular mismatch of rational/cyclotomic invariants can lift only after the relevant local denominators and roots are valid; the source helpers alone do not verify the complete lifting contract.

The dense cyclic Green matrix uses the geometric resolvent `(1-alpha^n)^-1 sum_{k=0}^{n-1} alpha^k W^k`. It is correct for an actual Hamiltonian successor cycle. A singular denominator raises via modular inverse. The general helper does not validate an externally supplied successor permutation/cycle; malformed or multicycle input can produce an invalid resolvent. Canonical callers generate Hamiltonian cycles. Dense inversion raises on singular outer matrices; there is no silent pseudoinverse or float tolerance.

### Phase28 polynomial certificates and exceptional loci

The common denominator is the product of all n² affine entries. The implemented trace polynomial sums each reciprocal-ratio term with the correct two entry factors removed and the two numerator factors restored. For power s it uses D^s, giving total degree at most s n². Synthetic division proceeds from the nonzero constant coefficient, which is an explicit precondition; constant-zero affine factors raise, rather than silently invalidate the identity. Polynomial Euclidean/Bézout operations are exact modular arithmetic for canonical coefficients over a field.

Consecutive interpolation reconstructs the polynomial from degree+1 field samples and checks the characteristic bound. A zero matrix entry at a sample raises with a request for a shifted grid; the code does not silently interpolate through a pole. The API does not implement automatic shifted-grid recovery, and the interpolated variant omits the direct variant's positive-s validation. Empty-polynomial/malformed-shape inputs and `xgcd(0,0)` are not supported cleanly; generated positive-degree inputs are the relevant domain.

For n=16, seed=2816 the exceptional-coupling routine removes one/two powers of an actual affine entry factor after checking the shared-root relations. At that removed root the middle matrix has zero support entries and cannot match an everywhere-nonzero target using invertible masks. Coprimality of the reduced polynomials therefore suffices on the admissible support-open set. A certificate consumer must still establish target nonzero support, exceptional-factor provenance, and the valid characteristic-zero lift. `nonzero_full_degree_leading_terms` / `both_leading_nonzero` by themselves are weak labels: trimming makes a nonzero polynomial's last coefficient nonzero, and the returned actual degrees must be checked against the claimed upper bounds. A modular GCD result alone does not preserve degree or prove characteristic-zero coprimality in degenerate reductions.

### Phase29 transverse slice and ternary Macaulay gates

The family has two affine parameters and homogeneous variables `(lambda,mu,nu)`. The dense target is checked entrywise nonzero. The main slice producer enforces mu degrees n² and 2n², computes their parameter-independent leading coefficients directly from G2, and proves a specialized Bézout identity. In conjunction with the degree/leading-term and valid-reduction reasoning, this rules out a shared component, not all points. The finite complex intersection bound 2n^4 is a Bézout upper bound for the polynomial locus, not a count of admissible Fourier factorizations.

The anchored quadratic orientation matches `Tij*T00*Mi0*M0j - Ti0*T0j*Mij*M00`. Multiplication by all degree-two ternary monomials generates the degree-four ideal piece, whose basis has 15 columns. Full span excludes all nonzero projective solutions, including singular/zero-entry parameter points. Rank deficiency does not prove existence of an admissible solution. N4 all-permutation loops cover 24²=576 mappings. The partial 3×3 anchored gate uses 4 quadrics and 6 multipliers, a 24×15 matrix; its exhaustive mapping count is `[n(n-1)(n-2)]²`. Random trials remain samples.

The ordinary elimination and determinant routines are consistent on their generated canonical matrices. Source enumeration keys concatenate decimal indices and are unambiguous for the intended N4 use; this must not be generalized past single-digit indices without changing the serialization. The saved verifier defects are G01, separate from the rank mathematics.

### Phase30 four-variable full minors and dimension gate

The coefficient order `(lambda,mu,rho,nu)` is consistently mapped from generators `(G0,G1,G2,G3)`. All nine 2×2 minors of the target-scaled 3×3 window have the correct cross-multipliers. The polynomial has 10 quadratic monomials; multiplying by four variables gives a 36×20 cubic Macaulay matrix. Full rank puts every cubic, including every variable cube, in the homogeneous ideal and excludes every nonzero projective parameter over the algebraic closure. This negative certificate needs no saturation. The affine executor's nu=1 family is contained in the projective family.

Python incremental elimination and C++ pivot-basis elimination have consistent ascending-pivot reduction and correct original-row selection. Early exit at full column rank is legitimate. The C++ `det` accumulator is not saved or used as a determinant claim; both return `det=0`, with comments acknowledging pivot-sign handling is absent. Python's determinant computation independently handles row-swap sign. The native record's selected rows can support determinant recomputation only after matrix/format/coverage binding.

The full N4 triple restriction is exhaustive because a triple extends uniquely at n=4. N8 has 336²=112,896 mappings; N16 has 3360²=11,289,600. A sampled larger-n list is not exhaustive. `max_cases` in Python breaks both loops, unlike G03; a nonpositive max_cases still checks at least one and should be validated if that API is used.

Anchored 3-column equations with four homogeneous coefficients have forced anchor-zero solutions, so increasing degree cannot repair that anchored formulation. Full minors remove the anchor-specific defect. The dimension threshold `q >= (m-1)^2+1` is correct for the rank-one Segre intersection when the **restricted window map** is injective. If it is not injective, a nonzero parameter maps to the zero window and all minors vanish anyway. Global Green-generator independence is not sufficient to call the window image a P^(q-1). `minimum_minor_block` returns the first m escaping the forced bound for positive q; it is a gate limit, not a constructive sufficiency theorem.

The five-term routine checks deficiencies at degrees 3,4,5 and labels an expected projective intersection. It does not determine reducedness, the existence of finite-field points, invertibility, nonzero support, nu≠0, full-matrix compatibility, or a Fourier algorithm. Six-dimensional sampled quotients are finite-field Hilbert-function observations, not six certified admissible solutions.

### Executors and resource accounting

The two-pass cyclic recurrence is correct: after one traversal the affine accumulator supplies the periodic predecessor through division by `1-alpha^n`; a second traversal gives all solution values. Random shuffles and subsequent gauge RNG consumption match the dense generators. Rotating the fourth term's traversal to start at vertex zero leaves the same cyclic resolvent. The Phase29 executor replaces the inherited second coefficient with lambda and adds the independently seeded alpha=1/7 term. The Phase30 executor adds alpha=1/11 and requires the constant G0 coefficient to equal 1. It is an affine four-term executor, not an arbitrary homogeneous coefficient executor.

The applications are O(n) for a constant number of terms, all vector writes/masks/additions included, and use O(n) storage. Constructors and applications assume consistent vector/mask dimensions; missing shape validation can raise or, with inconsistent term lengths, truncate/mis-handle inputs. They are not robust public arbitrary-input APIs. Denominator inverses raise on singularities. No floating-point tolerance enters the mathematical kernels. Timings printed by main blocks are merely timings and do not certify correctness or asymptotics.

Dense construction/inversion, high-degree polynomial construction, factorial permutation scans, and O(n^6) triple-pair scans are offline costs. Exact finite-field applications are not automatically a numerical FFT, and the coefficient/precision/preparation contract remains relevant to any all-length proposal.
