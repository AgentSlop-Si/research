# Native adaptive DIF: useful structured-input gains, no universal FFT win

This continuation replaces the Python per-node work with a C++17 implementation
of the energy-pruned, full-output, unitary FFT. It also implements two ordinary
native radix-2 baselines (iterative DIT and DIF) with the same input validation,
scaling, coefficient construction, and output handling.

The meaningful positive result is a measured improvement over these native
baselines on coherent inputs. At N=262144 and epsilon=.125:

| Input | Adaptive | Faster native baseline | Speedup | NumPy | Relative L2 error |
|---|---:|---:|---:|---:|---:|
| Pure tone | 7.005 ms | 11.248 ms | 1.61x | 6.401 ms | 2.99e-15 |
| Fifteen tones | 9.128 ms | 11.614 ms | 1.27x | 6.527 ms | 6.26e-16 |
| Exact constant | 6.633 ms | 11.219 ms | 1.69x | 6.013 ms | 0 |

These are medians of nine calls in one environment. They establish a useful
native implementation result on these inputs, not a new exact worst-case
algorithm. NumPy remains faster in these examples.

Across all sizes and epsilons, 24 approximate cases retained nonzero output
and had measured relative L2 error at most 1e-10 (in fact at most 3.00e-15).
Adaptive DIF had a lower median than the faster native baseline in 21 of
those 24 cases; 20 had nonoverlapping middle halves of the measured timing
samples. Its one median win against NumPy in this group was marginal
(ratio .993), with overlapping timing spreads. We do not claim a demonstrated
NumPy speedup for the useful high-fidelity group.

## Implementation and charged work

`native_fft.cpp` uses one in-place complex work vector, N/2 roots, the full
N-element output, and an O(log N) DFS stack. Excluding caller input, storage
is 2.5N complex entries plus stack state. There are no per-node vector copies
and no external C++ dependencies.

The DIF butterflies are unnormalized internally. At depth d, the node vector
has norm 2^(d/2) times its unitary counterpart. Accordingly the approximate
test is

    node_energy <= epsilon^2 * root_energy * 2^d.

Child energy sums are accumulated while writing butterfly outputs, so they
do not need an extra vector scan. Output normalization is performed at the
leaves. Computing the normalized value before restoring the input scale
avoids premature underflow of `scale/sqrt(N)` for subnormal inputs.

For epsilon=0 the implementation prunes only branches whose computed real
and imaginary components are literally zero. It does not use squared norms
for this decision: squaring a tiny nonzero value can underflow. This mode
introduces no deliberate approximation, but it remains a floating-point
FFT, not an exact cyclotomic computation. On exact constant input it uses
N-1 butterflies and O(N) total work; on generic numerical inputs it can
visit the full tree and is slower than the baselines.

All measured native calls include fresh work allocation, finite-input checks,
component scaling, root construction with sin/cos, threshold tests, full
output writes, finite-output checks, and consumption of every output
component. Both full baselines use the same cold preparation and scaling.
No root table, transform plan, or computed output is reused across calls.

Counters are collected in separate executions using compile-time
instrumentation. The timed instantiation removes counters. Verification
checks that these instantiations return identical arrays. Counters include
butterflies, visited nodes, threshold tests, norm/zero-test volume, root pairs,
computed and pruned bins, output coverage, and stack depth. `full_output_writes`
counts the complete N-entry write pass; adaptive nonzero leaf overwrites are
additionally represented by `computed_outputs`.

## Accuracy and the all-zero trap

The underlying mathematical criterion is

    max_k |approx[k]-FFT_unitary(x)[k]| <= epsilon * ||x||_2.

Its proof assumes ideal arithmetic and exact comparisons. This implementation
does not provide interval bounds or a machine-precision certificate. A tested
threshold case produced ratio .12500000000000003 at epsilon=.125; test
tolerances acknowledge floating-point rounding rather than silently
advertising an exact inequality.

The criterion is weak for diffuse spectra. Among 63 approximate benchmark
cases, 31 returned all zeros and had relative L2 error approximately one.
Those cases are explicitly separated in `summary.json`. They account for
seven of eight median NumPy wins in the unfiltered set, and should not be
presented as faithful transform speedups. A heavy-tail example retained some
bins yet lost substantial total energy, so nonzero output alone is also not
enough: both relative L2 error and retained-energy fraction are reported.

## Benchmark and verification scope

Environment: AMD EPYC 9V74 virtual CPU, x86-64 Linux, g++ 13.3.0, C++17,
`-O3 -march=native`, without fast-math. Complete compiler/platform/affinity,
NumPy version, and thread-environment data are recorded in `results.json`.

Sizes: 4096, 65536, 262144. Families: Gaussian input, pure tone, exact
constant, time impulse with diffuse spectrum, fifteen tones, sixty-four
threshold tones, and a heavy-tail spectrum. Positive epsilons are .125,
.25, and .5; zero-only pruning is a separate mode.

Methods are timed in randomized order for nine rounds. Code is warmed once;
"cold" refers to rebuilding algorithmic setup, not flushing hardware caches.
Medians, quartiles, minima, and every raw timing are saved. Results can vary
with concurrent host load. Nonoverlapping interquartile ranges are descriptive
evidence, not confidence intervals or significance tests.

The native comparison chooses the faster median of DIT and DIF. The NumPy
comparison uses ordinary `np.fft.fft(..., norm='ortho')` plus the identical
output-consumption routine; NumPy's internal implementation and validation
contract differ from the native routines. This is clearly a separate
comparison, not an assertion that the two have identical setup internals.

`verification.json` records:

- 127 complete basis inputs and 762 method/epsilon comparisons;
- identical instrumented and uninstrumented outputs;
- three near-threshold controls;
- four retained odd-frequency outputs of size about 1e-200 that squared-norm
  zero tests could incorrectly discard;
- six exactly representable constant/alternating-tone cases;
- three minimum-subnormal rescaling controls.

`results.json` additionally contains 64 dynamic-range checks from zero,
1e-200, ordinary, and 1e200 input scales. These finite numerical tests audit
the implementation and do not prove a general floating-point bound.

## Reproduce

Requires g++ and Python with NumPy. The C++ library itself uses only the
standard library.

    python3 verify.py
    python3 benchmark.py
    python3 summarize.py

The scripts compile the shared library locally. `FFT_BENCH_REPEATS` and
`FFT_BENCH_SIZES` optionally select a different timing run. No compiled binary
is needed in a portable research package.

The next practical target is reducing cold root/setup and output-handling
overhead, or adding a stronger error contract that preserves total energy.
This checkpoint does not resolve the independent exact arbitrary-input
sub-N-log-N FFT goal and makes no global algorithmic novelty claim.
