# Adaptive FFT C++ bookkeeping experiment

This is a C++20 port of the hot path from the Python `AdaptiveFFT` research engine. It is designed to answer one engineering question: **was Python bookkeeping hiding the payoff from FFT reuse?**

It uses the same FFTW real-to-complex backend for both baseline and adaptive measurements. The FFTW runtime is linked directly; no FFTW development header is required by this source because the small ABI used by the experiment is declared locally.

Implemented ablations:

- `hash_only`: hash the full input, then always FFT. Isolates fingerprint cost.
- `exact_cache`: hash + full byte verification + bounded cache, then FFT on misses.
- `structural`: exact cache plus sparse-edit and cyclic-shift relationship detection/reconstruction.
- `rank2_detect`: detect/verify a rank <= 2 batch, FFT only the basis, reconstruct all spectra.
- `known_basis`: coefficients and basis are supplied, so only two FFTs plus O(MN) reconstruction remain.

Timing columns separate fingerprint, lookup, relation detection, FFT, reconstruction, and cache update. This does not claim a sub-NlogN worst-case FFT; it tests amortized reuse on related inputs.

## Build / run

```bash
python run_benchmark.py
```

or

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/adaptive_fft_cpp > results.csv
```

The Python wrapper also writes `cpp_benchmark_results.json`.
