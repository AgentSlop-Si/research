## Guards and limitations
The public helpers assume prime p, a valid exact-order power table, canonical field residues, compatible dimensions and positive lengths. recognize checks only part of that contract with assert. For example field_for(0) never advances its prime search; arbitrary unreduced samples can defeat the raw any(x)/center tests. These are out-of-contract API risks, not demonstrated errors in the stored run, whose fields and samples are generated internally. All mathematical assertions disappear under Python -O. The saved package does not establish that an optimized-mode run was used. Matrix shape and singularity errors are not caught as friendly validation failures.

## Cost accounting
Eliminant construction is O((r+1)! r^2), not the polynomial-r extension. Phase scanning is O(nD); at most min(D,n/gcd(2,n)) candidates each incur O(nr+r^3) recurrence/root/solve/full-verification work. A successful transform uses O(nr+n) field operations after the shared Gauss base. Thus O_r(n) is a fixed-r, supplied-field/root-table arithmetic statement; it excludes naive prime/root search and is not uniform linear cost in r or bit complexity. The exhaustive audit is exponential in n and direct DFT references are quadratic.
