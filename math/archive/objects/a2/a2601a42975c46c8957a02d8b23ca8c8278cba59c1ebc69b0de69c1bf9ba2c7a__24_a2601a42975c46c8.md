# Global reuse for a fresh exact FFT: the linearization gate

**Date:** 9 October 2026. **Status:** mathematical reduction, exact computational witnesses, and a falsifiable do-not-repeat checkpoint. **No new O(N) or improved worst-case DFT algorithm.**

## 1. Research target and independence from earlier work

The goal is the explicit, complete, **fresh arbitrary-input** DFT, preferably O(N) sequential exact arithmetic with preprocessing and code/constants charged. This is *not* the CrocSwap integer-multiplication kappa race, a relation-aware cache, a sparse-output DFT, the fixed-input-pattern collision problem, or an approximate sampler.

The latest predecessor `fft_chirp_global_reuse_audit/RESEARCH.md` ruled out a naive fast evaluator for a quadratic-chirp convolution using a first-order variable-coefficient annihilator: the filtered map has rank N-1, and its moment ladder still requires N independent moments. The canonical checkpoint previously ruled out repeated-subtree collisions, fixed finite tables, input-low-rank branches, bit-codelets, and simply rewriting Fourier as a compact rank-one displacement operator. The proposed **new test** here asks whether an algorithm using *nonlinear algebraic intermediate expressions* and *data-dependent k* can circumvent the need to optimize a global **linear** computation.

## 2. A linearization theorem (standard mathematical principle, new checkpoint here)

Let K be a field. Let C be a division-free straight-line arithmetic program with s unit-cost binary gates in {+, -, ×} and constants from K. Suppose its vector output, as a **polynomial identity on K^N**, is the linear map L(x)=Mx, where M is a fixed matrix (in particular the DFT). We count scalar multiplications and all additions. Constants and direct input wires are leaf nodes. At each gate g write

- `c_g = g(0)` (constant term),
- `l_g(x) = coefficient of t in g(tx)` (degree-one homogeneous part).

For leaves, `c_{x_i}=0, l_{x_i}=x_i`; for a constant a, `c_a=a, l_a=0`. Propagate the pair `(c,l)` through the circuit:

- addition: `(c_a+c_b, l_a+l_b)`;
- subtraction: `(c_a-c_b, l_a-l_b)`;
- multiplication: `(c_a c_b, c_a l_b+c_b l_a)`.

The linear output of C is exactly Mx because C(tx)=tMx. Every original addition/subtraction creates at most one **linear** addition. Every original multiplication creates at most two scalar-by-constant multiplications and one addition. Therefore the extracted **linear** circuit has at most **3s** arithmetic operations, possibly fewer after zero and duplicate elimination. Constructing its constants `c_g` by running the original circuit at zero takes at most s additional operations. Thus a hypothetical **uniform division-free O(N) arbitrary-input exact FFT automatically implies a uniform O(N) linear FFT** in the same exact arithmetic gate model. This does not prohibit either one.

This is an elementary form of first-order homogenization/automatic differentiation, not a new mathematical theorem or priority claim. It is closely related to classic circuit-homogenization and Baur–Strassen differentiation techniques. A useful reference is I. Sergeev (2008), which discusses differential arithmetic circuits and Baur–Strassen.

### Division gates

If the algorithm also has divisions, select any basepoint `x0` where *every intermediate denominator* is nonzero and the program computes the rational function L(x). Differentiate with respect to the formal direction `v` at x0. Because L is linear, its directional derivative is `D L(x0)v = Mv`, independent of x0. At a division gate a/b,

`d(a/b) = (1/b0) da - (a0/b0^2) db`.

Again at most three linear gates per original arithmetic gate. Arithmetic gate evaluations at x0 give the constants. **Extra caveat:** choosing and encoding a nonsingular x0 for a uniform circuit may itself have nonconstant preparation costs, so the clean uniform corollary above assumes division-free circuits or denominators defined at the origin. The nonuniform arithmetic-circuit reduction needs only the existence of such a point.

### Generic finite branching

In a bounded finite algebraic decision tree over an **infinite** field, with branches depending on polynomial/rational equalities/nonzero tests, a Zariski-open set follows a generic path. If the algorithm outputs the same linear map at all inputs, the rational formula along that path equals L on an open dense set and therefore equals L as a rational function. Apply the derivative argument to that path. This gives a *nonuniform* linear circuit with O(s) arithmetic gates if every path had at most s. It does **not** automatically account for the uniform cost of discovering the path, choosing basepoints or generating scalars. It also does not cover arbitrary RAM/table access, bit-level operations, or unbounded control constructs for free.

## 3. The user's A-k idea in differential form

For a DFT and a potentially nonlinear scalar selector k(x), choose any fixed input basis coordinate e_t. Define

`Y(x) = F_N(x - k(x)e_t) + k(x) F_N e_t`.

Because the DFT is linear, `Y(x)=F_N x` for **every** x, with no condition on k(x). Differentiating gives

`dY = F_N(dx - dk e_t) + dk F_N e_t = F_N dx`.

The two k-dependent pieces cancel *as whole vectors*. This is why choosing k from the input does not by itself remove the hard fresh transform of the residual. It can still be useful on **restricted structured inputs**, as the earlier annihilator and near-power experiments established. The present result does not rule out another genuine linear circuit improvement through a clever algebraic reorganization.

## 4. Exact experiments and independent verification

The package includes an arithmetic DAG containing true products of input-dependent values and divisions of input-dependent expressions. `jet_linearize.py` extracts the linear direction circuit without using an FFT-specific rule. Three test families are constructed:

1. **Square cancellation:** replace each FFT output s by `((s+7)^2-s^2-49)/14`, a nonlinear polynomial program computing exactly s.
2. **Rational cancellation:** replace s by `s(1+x0)/(1+x0)`, an exact rational identity wherever its denominator is nonzero; not a total algorithm at x0=-1 without a fallback.
3. **Nonlinear k rewrite:** choose `k=x0*x1+x0`, transform `x-k e0` with the full FFT, then add k to every output (since F(e0) is the all-ones vector). This is defined on every field input.

For N=2,4,8,16,32,64, an ordinary radix-2 modular FFT is constructed as a DAG over F_998244353. A separate plain dual-number interpreter computes derivatives independently of the extracted DAG. `run_audit.py` uses five basepoints and eight independent directions each for all 24 circuit/size combinations. **All 960 cases matched the direct finite-field DFT.**

`verify_matrix.py` does something stronger than random vectors: for each extracted **linear** circuit, it independently verifies *every matrix column* against the exact power formula `omega^(jk)`, without importing the reference direct DFT implementation. It checked 504 basis columns / 21,840 matrix entries, all correct. Therefore the extracted circuits compute the complete matrices at these finite sizes, not just sampled answers. `symbolic_complex_audit.py` separately verifies the nonlinear-k identity and all 16 Jacobian entries of F4 as exact polynomials over the complex numbers using SymPy.

## 5. A crucial exception: finite alphabet or finite field *function* equality

**Do not overgeneralize this result!** The proof needs a polynomial/rational identity, not merely agreement on a finite input subset. Over any field, `x^2=x` on inputs `x∈{0,1}` but the degree-one part of `x^2` at x=0 is zero, not x. Over F_p, `x^p=x` on every field element as a function even though they are different polynomials and formal derivative of `x^p` is zero. Tests in `tests/test_domain.py` verify both counterexamples, so our argument cannot simply rule out special algorithms for binary arrays and fixed-field functions.

The original user's fixed-alphabet collision intuition is genuinely **a different model**. But the previous occupancy and full-state table analyses already show why exact-match caching alone does not give O(N) for iid binary inputs with polynomial resources. This gate audit is specifically about arbitrary complex inputs and polynomial/rational straight-line computation.

## 6. What this does, and does NOT, imply

- **Does:** any full arbitrary-complex DFT calculated as a division-free polynomial arithmetic circuit of size O(N) can be replaced by an O(N) linear circuit, with constants generated in O(N) arithmetic. Data-dependent nonlinear k identities do not automatically circumvent global transform complexity.
- **Does:** division/rational intermediates regular at a basepoint can be linearized with constant-factor gate overhead. The same applies to a generic finite algebraic branch, subject to uniformity caveats.
- **Does NOT:** prove an Omega(N log N) general lower bound, reject every nonlinear adaptive algorithm, or imply that the current best exact complex FFT exponent cannot be improved.
- **Does NOT:** transfer bounded-coefficient or well-conditioned linear lower bounds automatically to circuits involving unbounded cancellations, or say anything about finite-bit numerical stability without additional analysis.
- **Does NOT:** rule out finite-alphabet algorithms exploiting polynomial identities only valid on {0,1}^N, boolean operations, or bounded word-RAM lookup.
- **Does NOT:** make claims of priority; this linearization method is classical.

Nir Ailon's well-conditioned linear-circuit lower bound and Morgenstern's bounded-coefficient lower bound concern *restricted* linear models. OpenAI #130 already produces a sub-NlogN all-length exact DFT in a more permissive model, and its uniform theorem's Lean scope is documented separately. Our theorem is compatible with all three.

## 7. Next falsifiable problem

This audit narrows, rather than solves, the original O(N) challenge:

> Produce a **new uniform family of global linear circuits** for the full exact Fourier transform, with charged coefficient generation, addressing and all N output values, whose total cost beats the current all-length exact-DFT bound in the same arithmetic model.

The next candidate should start with a **concrete linear operator evaluation identity and a complete cost recurrence**. Reject it *before coding* if it requires recomputing all moments, treats a large operation as one gate, relies only on short exact subtree collisions, or smuggles a native full FFT into preprocessing. It must also be checked against standard Cooley–Tukey, chirp, butterfly, displacement, multi-table, algebraic rank, and the prior #130 techniques already on the canonical research register.

There is currently **no surviving new O(N) evaluator** in these files. The valid contribution of this pass is an independently tested research filter that rules out a wide class of superficially novel nonlinear proposals under explicit assumptions, while preserving the finite-alphabet loophole for separate investigation.
