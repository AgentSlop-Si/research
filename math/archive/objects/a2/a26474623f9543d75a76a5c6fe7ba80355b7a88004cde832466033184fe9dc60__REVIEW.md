## Material findings

1. **The literal Weyl recovery helper is not linear-time as written.** In 1106a6c7… lines 89–95, each new cycle ID is tested with `current not in labeled`, where labeled is a growing list. On the allowed d=1, c=N case, all IDs are distinct and the test scans 0+1+…+(N−1) elements: Θ(N²) Python comparisons. The displayed `linear_pass_counts` at lines 124–126 omits this. Line 93 additionally calls modular exponentiation separately for each cycle before the root table is built at lines 109–110. This is an implementation/cost-accounting defect, not a counterexample to the normal-form theorem. A visited array and a precomputed root table implement the stated linear schedule. No edits were made.

2. **Frozen inventory statuses are historical, not current review truth.** e9ec24c5… embeds its thirteen review decisions at lines 13–65, including next-pivot and variable-block items marked queued. Exact additive post-v21 evidence now independently accepts their bounded claims. Preserve the checkpoint20 bytes and add the new mapping; rerunning this old utility would simply reproduce its old status strings. Its hard-coded research_round_2156 and v19-manifest paths are also nonportable.

3. **Finite, chart-restricted and one-stage results retain their scope.** Four Fourier-8 adjacent-anchor cases have full commutator rejections; the four halves-anchor cases need the nonsingular-diagonal-endpoint axis guard. None excludes a free first layer, arbitrary order pairs, endpoint permutations or singular endpoints throughout the eight-chart family. The projective solver accepts only the selected row subsystem. Root/Schur helpers do not supply the retained coupled inverse, polynomial-unknown closure, or a faster FFT.

4. **These are test programs, not hardened or production evaluators.** Six of the eight newly read files execute their test/inventory body and overwrite sibling outputs on import. All depend on Python assertions for substantive verification, so an optimized `python -O` run is not a valid verification run. Fixed valid fixture inputs do not make the helpers general validated APIs. Dense oracles, finite-field enumeration, modular exponentiation, dictionaries and diagnostic coefficient loops are not covered by the production arithmetic schedule merely because a separate theorem states a linear bound.

No false mathematical PASS on the advertised fixed fixtures was established by the inert review. That is a static-review conclusion, not a fresh runtime pass or proof of all-size extrapolations.
