# Bridge to integer-mult-kappa: keep the route independent

The project can retain the external route as a future component. It cannot automatically inherit its exponent by replacing a NumPy call, reusing numerical spectra, or counting fewer graph nodes. The current useful connection is an explicit algebraic interface with independently checkable operations.

## Concrete interfaces now available

| Interface | What is executable now | What remains before a stronger transfer claim |
|---|---|---|
| Expression schedule | `ProjectedCircuit.export` produces topologically ordered basis/impulse/add/mul/scale/shift operations | A uniform generator for the intended arbitrary-input problem, with all input-dependent metadata charged |
| Exact ring replay | `modular_bridge.replay` evaluates the same schedule over verified prime fields | A suitable native exact backend and explicit modulus/word growth costs |
| Integer encoding/output | `integer_product` verifies padding, coefficient bounds, CRT reconstruction and carry propagation on signed examples | A fast backend, scalable prime/CRT method, and an end-to-end bit-cost proof |
| Dynamic reuse | DAG cache boundaries and range indexes expose the actual computation reused | Proof that sufficient reuse exists for every input in the target theorem; no free relationship oracle |
| External rank certificate | Pinned reference and assumption map | A valid input-independent side network, compatible frames/roles, child-width histogram and rank-sum/deficit/moment checks in that framework |
| Precision/storage | Complex128 payload and process RSS reported | Required exact/finite-precision bounds plus data movement on the specified finite-tape machine |

No row invents a kappa value from empirical speedups. Our portable schedule is a functional arithmetic DAG, not a rank-frame certificate. In particular, a small graph can still manipulate long numbers or require expensive data movement.

## Exact reference example

```python
from modular_bridge import integer_product

answer, evidence = integer_product(-123456789012345, 9876543210)
assert answer == -123456789012345 * 9876543210
assert evidence['crt_modulus'] > evidence['coefficient_bound']
```

The program expands magnitudes in radix 2^b, pads to N at least the sum of digit lengths minus one, and evaluates full modular spectra. Each convolution coefficient is nonnegative and bounded by min(length_a,length_b)(2^b-1)^2. Distinct primes with N dividing p-1 and product exceeding that bound uniquely determine every integer coefficient. An inverse modular DFT yields residues, CRT recovers the coefficients, and carrying reconstructs the signed product.

This is exact but deliberately slow: direct modular DFTs take quadratic arithmetic, and the basic prime search is not optimized. It tests the bridge's semantics; it provides no multiplication speed claim and does not implement the linked repository.

## Recommended next experiment, after this package

Use the serialized graph to select one **input-independent** recurring arithmetic motif that occurs inside a target multiplication construction. Supply a uniform motif generator and an exact operation schedule, then compare its charged operations, coefficients, storage, and movement with the external framework's accepted motif. Only after compatibility and certificate checks should the derived recurrence be evaluated. If the improvement depends on unrelated calls sharing a cache, report an amortized related-workload result instead.

We can adopt an independently validated faster transform or multiplication backend later while preserving the higher-level relation APIs. Whether its asymptotic saving composes with those APIs must be proved under one common model; compatibility is an engineering goal, not an established theorem.
