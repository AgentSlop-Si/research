# Inverse, Green, condition and FFT engine source review

## Result

All 91 assigned exact source hashes were read completely as inert text: 387,300 bytes and 8,940 lines across 25 frozen batches. All 91 are new coverage relative to both the frozen inventory and the final observed additive registry (785 full static reads; no overlap). Exact snapshots and one line-referenced report per hash are preserved.

No supplied program was executed, imported, compiled, or AST-parsed. The central registry and prior packages were not changed. The two deliberately excluded large generated cancellation sources were neither read nor credited. One assigned CMake compiler-identification source is included as build boilerplate, with no research-result credit.

## Important findings

1. Four-stage certificate input validation is incomplete. Source 013 (4c86f966cf8a372f10eca4e0a22ccdeeb8c64f36e3491cb554c185fb53897abf), lines 57–74, accepts an empty determinant-record list and prints “two determinants valid.” For mixed shuffles it also omits the strict cut-capacity < target-rank check. A fresh review-owned fixture removes all 128 starting input wires at N=256, has cut capacity equal to the target rank and no determinant records. Static evaluation shows these checks accept that non-obstruction. This does not show that any existing saved certificate is invalid, and the original verifier was not run.

2. Numerical gate searches remain heuristic and often lack replayable coefficient witnesses. Sources 042 and 049 check gate/output condition numbers but omit the initial diagonal; an exact two-coordinate control exhibits initial condition 8 followed by a permitted cross-ratio-minus-one gate with condition 1. Source 048 likewise skips an explicit initial check, but its first fixed unitary C gate preserves that condition, so its omission alone does not cause the same undercount. Several optimizers retain a post-update state associated with a pre-update error; final recalculated errors avoid direct misreporting, but best-state bookkeeping is not exact. Most saved JSON contains only schedules/residuals, not fitted coefficients.

3. FFT merge benchmarks are for supplied bases, selected bins, or relation maintenance. Sources 079–090 generally record errors without acceptance assertions. Timed query/compaction paths are often different from final-only correctness checks. Source 083 compares only a scalar checksum across two related implementations; source 088's multi-consumer function has no correctness check and is not invoked by default. Storage ratios usually compare only projection arrays with hypothetical full spectra. Source 084 starts timing after planner construction, and source 087 excludes baseline stacking. These are measurement-scope limitations, not evidence of failed numerical results.

4. Exact cancellation results stay within their cost/search models. Sources 054–060 count signed sums, doubling and halving; common output normalization is separate. The five-bit SMT encoding is nonwrapping within its half-integer coefficient and 1–24 gate limits. Timeout/unknown does not establish infeasibility. The DOCX generator's counts and “checks passed” prose are hardcoded, not live evidence. The large excluded generated sources receive no coverage.

5. Theorem boundaries remain explicit. Green inversion does not cheaply produce Fourier forcing; finite-field checks do not alone prove complex full-spark statements; cut passing does not synthesize coefficients; nondegenerate semiseparable gates exclude degenerate branches; exact macro reset does not erase roundoff. The height extractor validates bookkeeping and proof-reference presence, not field degree, nonzero proofs, a DFT identity, or the #130 implementation. The recurrence-moment helper also needs positive-gap/input validation. Sources 073–076 check finite arithmetic for the F32 rank gate but rely on companion proof for rank interpretation and sharpness.

## What completion means

This package completes static source reading for exactly this assignment. It does not complete transitive dependency review, reconcile companion reports/logs, assert successful supplied tests, establish general FFT optimality, or close the global material backlog. The frozen inventory records no exact-hash execution attribution for these 91 sources; generated PASS strings and self-description do not add any.

The fresh check is separate: fresh_checks/check_review_findings.py was newly authored for this review and run using only standard-library exact arithmetic. It does not read, import or execute supplied code. Metadata utilities only read/hash/copy bytes and JSON. All original source bytes were rechecked unchanged before sealing.
