# Independent review: sparse annihilator-multiple decoder

Reviewed 2026-10-09 by the exact-factorization agent. The production
algorithms were reviewed independently; no production code was changed.
The author audit's existing broad sweeps were not rerun. Focused edge
checks are in `review_edge_checks.py` and
`results/independent_edge_checks.json`.

## Correctness

For a candidate positive stride `b`, let the distinct values among
`z_s^b` be `lambda_1,...,lambda_d`, and put

\[
 R_b(t)=\prod_{j=1}^d(1-\lambda_jt)
       =\sum_{i=0}^d r_it^i.
\]

For every support value `z_s`, `R_b(z_s^{-b})=0`. Therefore every sequence
`a_s z_s^m`, and their arbitrary-amplitude sum, satisfies

\[
 f_m=-\sum_{i=1}^d r_i f_{m-bi} \qquad(m\ge bd).
\]

The implementation stores precisely the nonzero negative coefficients
`-r_i` and their positive distances `bi`. It computes the first
`min(N,bd)` values directly. If recurrence outputs are needed, their first
index is `bd`, so every referenced index is nonnegative and already
computed. There is no cyclic wraparound or omitted initial condition.
Because roots are nonzero, the degree-`d` coefficient is nonzero; a valid
plan always has at least one tap. Equality comparisons must use canonical
field values, as with the supplied exact-field helpers.

This argument does not require the support values themselves to be roots
of unity. Powers may merge support values, but mergers are not necessary:
coefficient cancellation alone can produce a sparse annihilator.

## Exact arithmetic ledgers

Writing `M=min(N,bd)` and `tau` for the selected number of taps, the code
uses exactly

\[
 \begin{aligned}
 \mathrm{mul}&=k(M-1)+(N-M)\tau,\\
 \mathrm{add}&=(k-1)M+(N-M)(\tau-1).
 \end{aligned}
\]

The direct prefix begins with the first amplitude rather than an
unnecessary zero addition. Each later modal contribution uses one addition
per prefix entry, and each mode uses `M-1` recurrence multiplications to
generate its powers. Each recurrence output initializes its sum from the
first tap. These details explain the subtracted ones in both formulas.

All tested candidates' binary powers, distinct-root denominator products,
and the selected tap negations are charged to preparation. Discovery is
paid even when the fallback wins. The default candidate set has
`h=O(log(k+1))` strides bounded by `min(N,k²)`. Direct denominator formation
and comparisons give `O(hk²)` preparation arithmetic/comparisons, while
binary powers cost `O(k sum_b log(b+1))`. Normalization additionally costs
`O(h log h)` integer comparisons in the implemented sort. These word and
equality costs are separate from the displayed scalar-arithmetic totals.

The full output has `N` entries. Its `N` reported final writes are not a
claim that all internal array traffic is exactly `N`; prefix accumulation,
recurrence reads, and FFT workspace traffic follow the actual loops and
have the same asymptotic bounds as their charged arithmetic, plus linear
initialization/copy costs. Exact extension-field operations and Python
big-integer operations are not bit-unit operations.

## Conventional fallback

The baseline uses `L=max(2,nextpow2(k))` and requires a **supplied primitive
`2L`-th root**. It neither finds that root nor certifies primitivity. This
is a precondition, not a hidden universal-field construction. The adaptive
recurrence itself requires no auxiliary transform root.

For a current block `v_j=f_(aL+j)`, the contribution of the old block to
the next block's recurrence has matrix entries

\[
 (U_Q)_{ih}=Q_{L+i-h}\quad(h\ge i),
\]

with coefficients beyond degree `k` interpreted as zero. The next block
is `-T_(1/Q) U_Q v`. The high-index cyclic kernel implements this upper
triangle after zero padding; the second convolution implements the
truncated lower inverse. Both use length `2L`, so the retained first `L`
entries are ordinary, not aliased, products.

The baseline's denominator, reciprocal, transform plan, two fixed spectra,
full initial length-`L` prefix, four transforms per subsequent block,
pointwise products, inverse normalization, sign changes, and incomplete
last block are all charged. I independently derived the displayed
`expected_preparation` and `expected_online` formulas and found them equal
to the code's counters. Computing `L` initial values even when `N<L` is
inefficient but fully counted.

The hybrid compares adaptive online cost against baseline preparation plus
online cost. Since adaptive discovery has already been paid in either
branch, its complete scalar total is exactly

\[
 D+\min\{A,\ P_{FFT}+F\},
\]

where `D` is discovery, `A` is the chosen recurrence action, and the other
terms are baseline preparation/action. It does not compare a warm cache
on one side to a cold calculation on the other.

## Scope and verified example

The method is exact for arbitrary amplitudes on its supplied support. A
small-tap annihilator is a support restriction, not an all-support FFT
theorem. With default candidate discovery and the supplied transform root,
the fallback preserves
`O(N log(k+1) + k² log(k+1))` total arithmetic/word work. For logarithmic
`k`, discovery is lower order asymptotically. A constant-tap selected
annihilator with adequately bounded paid prefix gives a linear-output
restricted algorithm. No universal little-o improvement follows.

For `N=4096`, support indices `a+256j` with `a in {1,3}` and `0<=j<8`, I
verified over both supplied prime fields that the original denominator has
all **16** nonconstant coefficients nonzero. The selected candidate is
`b=2,d=16,M=32,tau=2`, and the recorded cold arithmetic totals are
**14,412** versus **283,029** for the conventional fallback. The selected
stride does not merge roots; its benefit comes from cancellation in
`R_2`. A larger stride gives the same sparse annihilator but is not the
selected tie-break result. These are exact abstract field-operation
counts, not measured runtime or a comparison with every possible decoder.

The author's final audit adds the stronger standalone `b=1` minimal-Q
recurrence comparator, including its own preparation. Its two-partial-fiber
cold cost is **127,248**: 126,960 online operations plus 288 preparation
operations. I derived these numbers independently from the recurrence
ledger. The three-partial-fiber comparator is 143,702 versus 23,495 for
adaptive discovery. For a complete coset, `b=1` costs **4,833**, beating
broad discovery's 5,517; the final README explicitly reports this loss.
The additional comparator checks and result fields were inspected. No
production algorithm changed.

The independent focused checks passed **45 configurations**, covering
`N<k`, `N=1`, incomplete output blocks, arbitrary nonzero field elements,
empty/duplicate custom candidate lists, strides exceeding the output
length, exact scalar ledgers, and equality of hybrid cold cost with the
formula above. The two dense-denominator controls also passed. Existing
author results report 47 configurations, 112 amplitude-basis vectors, 94
mixed vectors, and 71,080 output-coordinate checks.

No correctness or arithmetic-ledger correction was required. The final
README was read and includes the requested supplied-root, fixed-word,
candidate-normalization, array-traffic, and restricted-support scope.
