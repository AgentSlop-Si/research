# FFT Phase 6 — Persistent convolution and dynamic integer products

Phase 6 extends the Phase-5 adaptive real FFT engine with **relation-aware circular convolution**, sparse edits to both factors, cached base-pair convolution, coefficient subscriptions, dynamic bit-product updates, and a native-versus-reuse cost crossover calibration.

> **Claim boundary:** For inputs related to cached bases through known shifts, linear combinations and sparse changes, each full convolution may cost `O(N)` after preprocessing. This is a classical dynamic algebraic identity, **not** an `O(N)` algorithm for a fresh arbitrary FFT or arbitrary fresh integer multiplication. This project does not implement OpenAI #130.

## Minimal API

```python
import numpy as np
from cost_aware_fft import RelationFFT
from relational_convolution import RelationalConvolver, subscribe_convolution

fft_engine = RelationFFT()
a = fft_engine.register(np.arange(1024, dtype=float))
b = fft_engine.register(np.ones(1024))
conv = RelationalConvolver(max_core_bytes=64 * 1024**2)

# Two different inputs use one shared base convolution.
c1 = conv.product(a.fork().edit(17, 1.), b)
c2 = conv.product(a.fork().edit(17, -3.), b)
full_c1 = c1.full(method='auto')
only_coefficient_20 = c2.at(20)
selected_spectral_bins = c2.frequency_bins([0, 1, 7])

# Subscribed output coefficients for changes to EITHER operand.
tracked = subscribe_convolution(conv.product(a, b), [0, 20, 50])
tracked.edit('left', 17, +2.)
tracked.edit('right', 22, -1.)
print(tracked.values())

# Hardware calibration is optional and has a nonzero one-time cost.
receipt = conv.calibrate_sparse(a, b, k_values=[1, 2, 4, 8, 16])
print(receipt['cutoff'], receipt['calibration_ms_excluding_basis_registration'])
```

## Files

- `cost_aware_fft.py`, `phase.py`: self-contained copied Phase-5 source.
- `relational_convolution.py`: Phase 6 convolution engine, subscriptions, exact integer product updater.
- `tests/`: inherited and new regression tests.
- `exact_modular_audit.py`: independent randomized checks over four exact prime fields.
- `benchmark.py`: end-to-end dense convolution, single-bin and dynamic big-integer timings.
- `crossover.py`: warm-kernel threshold vs pending-edit count.
- `benchmark_subscription.py`: time-coefficient subscription vs partial direct recomputation.
- `RESEARCH.md`: proofs, performance records, scope, prior work and next research hypotheses.

All native timings are exploratory and CPU-dependent. Software uses IEEE floating point for convolution and exact Python integers for bit-product changes. See `RESEARCH.md` for explicit resource accounting.
