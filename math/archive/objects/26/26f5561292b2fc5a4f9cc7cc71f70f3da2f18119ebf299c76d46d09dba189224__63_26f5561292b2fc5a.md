# Phase 5 — Relation-Aware FFT Dispatcher

**Status:** runnable research implementation, checked against SciPy. Not a new universal FFT complexity theorem. Not an implementation of OpenAI #130's exact-complex circuit.

This project extends our Phase 4 Fourier cache into a single dispatcher designed for *known relationships between transforms*. It keeps compressed spectral states until a consumer requests output, and uses a native SciPy FFT whenever reusing a relationship is unlikely to pay off. The numerical implementation supports finite real 1-D signals and returns the nonredundant `rfft` half-spectrum.

## Quick start

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python demo.py
OPENBLAS_NUM_THREADS=1 python benchmark.py
```

Benchmark results are written to `benchmark_results.json`. They include correctness checking outside the timers, initialization inside all multi-query timing paths, and separate timing of calibration candidates. The 4-bin benchmark compares against a full FFT after each event; it should **not** be interpreted as beating other algorithms that compute only four bins.

## Minimal example

```python
from cost_aware_fft import RelationFFT, subscribe
import numpy as np

engine = RelationFFT(max_cache_bytes=64 * 1024**2)
base = engine.register(np.random.default_rng(7).normal(size=65536))

# Two different inputs share one reference spectrum, without copying it.
a = base.fork().edit(123, 1.5)
b = base.fork().edit(123, -0.4)
A = a.spectrum()          # chooses direct update or SciPy fallback
B = b.spectrum()

# Right circular shift and change; nothing computes until requested.
c = a.shift(7).edit(36, 0.5)
print(c.bin(11))          # only one frequency, O(r+k) work

# Subscribe to 4 frequency bins; each known edit updates just 4 bins.
t = subscribe(base, [0, 7, 19, 80])
t.edit(123, 2.0)
t.edit_many([(100, 1.0), (100, -0.25)])
print(t.values())

# Known rank-two family, many different arrays, two basis FFTs.
bases = np.random.default_rng(8).normal(size=(2, 65536))
coefficients = np.random.default_rng(9).normal(size=(32, 2))
versions = engine.states_from_bases(bases, coefficients)
output_0 = versions[0].spectrum()

# Inspect hardware-specific costs for this state and cache/memory counters.
profile = engine.calibrate(a.fork(), repeats=4)
print(profile.best_method, profile.median_seconds)
print(engine.memory_report())
```

## Supported paths

| Situation | How supplied | Dispatcher behavior | Complexity after base transforms exist |
|---|---|---|---|
| Completely fresh/unrelated signal | `engine.fft(signal, cache=False)` | SciPy/NumPy `rfft` | `O(N log N)` |
| Unannotated repeated signal | `engine.fft(signal, cache=True)` | Bounded exact-cache, hash + full equality check | `O(N)` input scan / copy on hit |
| Known sparse edits | `state.edit(position,delta)` | Merges edits, lazy, direct phase update or native fallback | `O(Nk)` direct; `O(N(1+log k))` optional pruned route |
| Shifted signal | `state.shift(s)` | Phase multiplication, no input scan | `O(N)` dense reconstruction |
| Known low-rank family | `states_from_bases(bases,coeffs)` | Share basis FFTs, lazy combinations | `O(rN)` per dense result |
| Only selected frequencies | `state.bin(q)` / `.bins(qs)` | Evaluate only requested bins | `O(Q(r+k))` |
| Many edits + subscribed bins | `subscribe(state,qs)` | Update just Q bins each event | `O(Q)` per supplied edit |

Here `k` counts **distinct current changed positions**, `r` is the number of terms/bases, and `Q` is the number of queried frequency bins. Input relations are assumed supplied with the request and verified by construction. Discovery of an unknown shift, sparse relation or low-rank basis is *not* included in these bounds. The engine intentionally does not run expensive scans looking for hypothetical relationships between unrelated inputs.

## How the dispatcher chooses

- Unmodified root: reuse its immutable cached spectrum.
- Zero input representation: return zeros.
- Small input: native FFT by default.
- Known rank ≤ 2 and no residual: linear reconstruction for sufficiently large inputs.
- One known edit at sufficiently large size: phase-based update.
- Multiple edits or expensive states: native FFT unless a hardware calibration has shown another method faster.
- `calibrate(state)` tests `direct`, `pruned`, `linear` when eligible, and `native` on your hardware, validates every candidate against SciPy, and records the best **warm-query** method for matching `(N,k,r,has_shift)` shapes. Passing a state whose output was already materialized with `cache_output=True` is rejected, to avoid measuring cache copies instead of algorithms.

Explicit overrides are available: `state.spectrum(method='direct'|'pruned'|'linear'|'native')`. `pruned` is supported for power-of-two lengths, uses an `O(N)` complex temporary, and can be slower in practice than SciPy. Auto mode is conservative. For unannotated `engine.fft`, the default `cache='auto'` stops hashing after three consecutive misses and periodically probes again, so unrelated inputs aren't all fingerprinted; `cache=True` forces exact lookup every time.

## Numerical accuracy and safety

This is **floating-point** software. It uses the Fourier identities algebraically but comparisons permit numerical tolerance. After many edits or with very large/canceling coefficients, numeric error can accumulate. To reset a state, register its current dense signal again (paying one FFT). All signal inputs are copied and checked for finite values. Cached base arrays are immutable, and materialized outputs are copies unless callers explicitly request a read-only view. The content hash is never accepted without a full equality check.

Memory caps apply to the **engine's internal exact-lookup LRU and phase cache**, not caller-owned live `SpectralState` handles, which deliberately retain their base FFTs. `memory_report()` lists both. `cache_output=True` adds a dense output retained by the caller-held state; by default dense result caching is disabled. The optional pruned algorithm enforces a temporary-memory budget. `fft()` without metadata only searches for exact equality (not arbitrary shifts or rank).

## Limits of claims

This system helps when **the input producer gives known relationships** or the same input repeats. It does not accelerate arbitrary fresh dense FFTs asymptotically beyond the optimized backend, and does not establish an improved integer-multiplication bit bound. #130 is a distinct exact-complex theory with unrestricted arithmetic and huge constants; its implementation is not shipped here. Do not treat reduced arithmetic work as proof of wall-clock speedups unless benchmarked end-to-end.
