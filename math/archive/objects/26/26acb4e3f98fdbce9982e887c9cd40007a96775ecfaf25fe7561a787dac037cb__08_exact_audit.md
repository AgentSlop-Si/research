## Mathematical and operational scope

Finite-field checks for hidden low cut-rank ordering, parity inverse, grid-stage execution and an exhaustive 4-by-4 balanced boundary enumeration. The exhaustive boundary minimum is for one finite grid only, not all grid sizes or a Fourier lower bound.

## Control/dataflow and algebra

rank_mod performs modular forward elimination. Green columns are assembled by tri_solve. verify_hidden_order permutes M and audits every cut, then compares two Fourier blocks. verify_inverse checks six random vectors in each direction. verify_grid compares five dense-vector executions and samples cuts. exhaustive_grid4 visits all C(16,8)=12870 subsets.

## Input/guard and acceptance review

Helpers mostly rely on downstream guards. Generic rank_mod assumes rectangular rows and a field modulus. dense_apply uses zip without vector-width checks. verify_hidden_order assumes valid even N and a primitive Nth root. All exact acceptance checks are assert-based.

## Cost accounting

Dense G uses N tridiagonal solves, O(N^2) time/storage. All dense cut-rank elimination can total O(N^4). Random inverse checks are O(N) each after setup. Grid cut ranks are cubic-scale for fixed sample counts, and exhaustive subset checking is exponential when generalized.

## Test coverage and limitations

This source is itself an audit driver, with fixed seed and explicit sizes. Dense forward executor comparisons share the same tri_solve implementation with the fast path, so they independently check permutation/composition, not the tridiagonal solver from a fully independent oracle. The separately coded inverse recurrence provides another partial cross-check.
