# What each new upload adds

| Input | Useful result | Integration and correction |
|---|---|---|
| Phase 7 persistent convolution | Persistent convolution chains; zero-safe leave-one-out updates; dense/selected-time paths | Preserved and retested. New projected graph removes the requirement to retain dense seeds for frequency-only workloads. Hand-specialized updates remain an essential comparator. |
| Query engine v2 | Arbitrary-output projection, shared mutable relation state, explicit batch fusion | Preserved. Repaired old-history scans and missing-history cost estimates. Classical pruning is attributed. |
| Query engine v3 | Learns synchronous groups and splits asynchronous consumers; bounded observation probes | Useful scheduling research. Fixed group-history scanning and all-member output copying, added group-cache budget and bounded diagnostics, and charged planner work on update boundaries. |
| Phase 8 sum-product research | Complete finite-degree update coefficients handle repeated leaves such as A*A*A | Preserved and retested. Added graph import and projected jet preparation/evaluation. The source's full/selected time kernels remain the relevant path for time-domain outputs. |
| Breakthrough audit | Separates dynamic restricted-input results from fresh-input Fourier and bit-complexity claims | Used as the claim baseline; prior negative results and classical attribution are preserved. |
| Linked integer-mult-kappa | External conditional symbolic-network/finite-tape route | Re-pinned through GitHub. Added exact modular schedule replay and a small CRT/carry reference, with explicit missing steps for exponent transfer. |

V3 is not useless: it introduces automatic consumer scheduling, a different axis of reuse from sharing convolution factors. Its supplied benchmark checks only a scalar checksum of the requested outputs; the new benchmark compares every returned complex value. A matching checksum alone could miss other-bin errors. Its original storage report also omits retained event payload and query-history counters; the revised reports include those numeric fields while still excluding Python object overhead.

The Phase 8 jet result is likewise useful but conditioned on small degree and repeated related updates. The new bridge avoids building dense time kernels when only spectral bins are requested. It does not replace the original dense-output workload with an easier one and call that a universal FFT speedup: the benchmark labels frequency output explicitly and includes a hand-specialized projected formula.

All uploaded baseline sources stay identifiable under `baseline_*`; fixes and adapters are at the package root. Top-level `results/` contains this task's independently rerun results. Nested historical result files describe their original runs, not additional verified speedups in this environment.
