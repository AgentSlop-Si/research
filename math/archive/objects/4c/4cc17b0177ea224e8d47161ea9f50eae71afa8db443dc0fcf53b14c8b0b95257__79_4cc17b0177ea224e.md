# A reusable q-Weyl cache propagation example

This small demo uses the finalized operators in the sibling
`../fft_qweyl_boundary_research` package. It does not edit or replace them.
Run `python3 run_audit.py` from this directory.

**Scope:** a declared family of related vectors, all output coordinates retained.
This is not an arbitrary fresh-input FFT improvement, and no mathematical novelty
is claimed. It demonstrates how the audited conjugation can become an actual
reusable computation graph.

## Graph and proof

Let T be the lower triangular q-factorial convolution and let B and C be the
operators from the sibling package:

    (Bx)[i] = (q-q^(-i))*x[i+1]     for i < N-1,
    (Bx)[N-1] = 0,

    (Cy)[i] = q^(-i)*y[i]+(q-q^(-i))*y[i+1]   for i < N-1,
    (Cy)[N-1] = q*y[N-1]-(q/N)*y[0].

The existing exact theorem is TB=CT, including the final corner term. Therefore
if x_j=B*x_(j-1), after computing y_0=T*x_0 once, update

    x_j = B*x_(j-1),
    y_j = C*y_(j-1).

Induction gives y_j=T*x_j for every j. The demo physically computes and charges
both the B updates and the C updates; it does not assume related inputs appear
for free. The operator family is specified by its producer, without searching
for accidental equality, hashing arbitrary vectors, or assuming numerical
outputs from unrelated inputs can be reused.

The method also gives T*p(B)*x=p(C)*T*x. The audit includes
p(z)=2-3z+5z^2+z^3. Evaluating p(C) on an already available T*x takes O(N).
A single isolated polynomial query does not automatically beat computing
p(B)*x and applying T once; the existing cached result must have a legitimate
use or be charged. The initial transform is fully charged in the chain results.

## Complete cost accounting for this implementation

Both methods pay the same preparation: the sibling `prepare_sparse` and
`fixed_kernel.prepare` routines. The latter prepares extra Fourier-factorization
constants that this demo does not need; that conservative cost is retained in
both totals. For L=log2(N), together they cost

    7N-4+2L multiplications,
    2N-2 subtractions,
    N negations,
    2 constant inversions.

The input supplies a primitive N-th root q. Root search is not included in this
exact-field arithmetic contract. All coefficient arrays and their addressing
cost O(N); the two root-power preparations are charged even though a more
specialized implementation could share them. This is not bit complexity.

The first T is a fully charged direct triangular reference evaluator:
N(N+1)/2 multiplications and N(N-1)/2 additions, with
N(N+1)/2 kernel reads, the same number of input reads, and N output writes.
Every B update costs N-1 multiplications, N-1 coefficient reads, N-1 input reads,
and N output writes. Every C update costs 2N multiplications, N additions,
2N coefficient reads, 2N input reads, and N output writes.

For r updates, **excluding the identical preparation**:

| Method | Multiplications | Additions |
|---|---:|---:|
| Cached propagation | N(N+1)/2+r(3N-1) | N(N-1)/2+rN |
| Independent T on every produced input | (r+1)N(N+1)/2+r(N-1) | (r+1)N(N-1)/2 |

Every method writes (r+1)N transform-output entries and rN related-input entries.
The implementation returns and retains the complete chains: (r+1)N input and
(r+1)N output field elements. It also copies the initial input once, costing
N reads and N writes. Including plans and ordinary temporary arrays, peak
storage is O((r+1)N), not O(N). A streaming consumer could emit each pair and
retain O(N) working storage; that is a possible variant, not what the demo
returns. Traffic figures describe logical array operations, not every Python
interpreter reference or list-construction temporary.

For r=4, including all counted field-operation preparation:

| N | Cached reference graph | Independent reference evaluations | Full transform-output writes |
|---:|---:|---:|---:|
| 8 | 270 | 430 | 40 |
| 16 | 672 | 1,504 | 80 |
| 32 | 1,858 | 5,570 | 160 |

These are exact operation counts against a quadratic reference, not elapsed-time
benchmarks or a comparison against an optimized FFT library.

With a supplied compatible primitive 2N-th root in the working field, replacing
only the initial T reference call by ordinary FFT-based convolution gives
O(N log N+rN) exact field work, including ordinary O(N log N) cold
preparation and every input/output update. Independently applying that fast T
to all r+1 inputs would cost O((r+1)N log N). No sub-N-log-N algorithm for the
initial arbitrary input is implied. The full output volume is already
Omega((r+1)N). Exact roots, coefficient preparation, memory and indexing must
follow the chosen convolution implementation's contract; this demo does not
claim to supply its optimized backend.

## Verification

The audit uses N=8,16,32 over each of F_65537 and F_998244353, with r=4 and
all its prefixes. It checks:

- all 112 basis seed vectors and 24 deterministic random seed vectors;
- 680 complete transformed vectors, each compared with an independent direct T;
- 136 degree-three polynomial identities;
- exact operation-count formulas, also for every shorter r=0,1,2,3;
- an unrelated-input negative control: B*e0=0, so the propagated output is zero,
  whereas reusing it for a fresh e0 would be wrong.

All checks passed. The results are in `results/cache_audit.json`. The all-size
correctness argument is the induction from the sibling package's proved TB=CT;
finite tests audit this implementation and its counts.
