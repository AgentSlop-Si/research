# Phase 4 — Growing-length reuse and lazy, forkable FFT representations

**Date:** 9 October 2026

**Status:** working, correctness-tested exploratory engine and reproducible wall-clock benchmarks. **No novel worst-case Fourier complexity theorem or new exact integer-multiplication bound.**

## Hypothesis

If transform length N increases while the number k of known changed input positions remains small, then the advantage of using a cached spectrum should grow relative to rerunning a full FFT. We can exploit the relationship further by keeping a sparse update log (rather than immediately materializing all frequencies) and by letting multiple variants share an immutable reference spectrum.

The crucial input assumption is **producer-supplied edit metadata**: the algorithm is told which coordinate changed and by how much. It does not solve the difficult problem of finding a cheap relation between two independent random dense signals.

## 1. Exact algebra and adaptive complexity

For DFT length N let `omega = exp(-2*pi*i/N)`. If `X = FFT(x)` is known and the current signal is `x + d`, where only k coordinates of d are nonzero, then

    Y[q] = X[q] + sum_(p in supp(d)) d[p] * omega^(p*q).

This is exact in complex arithmetic. Accumulate changes at the same index in a dictionary (expectation O(1) per known edit). The number of distinct nonzero coordinates is k, **not the event count**. Querying one frequency costs O(k), querying Q distinct frequencies independently O(Qk), and writing all N complex frequency values using the direct sum costs O(Nk). A standard pruned FFT can instead recover a dense spectrum in O(N(1+log(k+1))) arithmetic operations. Choose the cheaper path after charging all metadata, storage, and output costs.

A compressed spectrum is a pair `(base_spectrum, pending_changes)`. Returning this pair does **not** mean explicitly writing N updated complex outputs. An explicit dense output has an Omega(N) output-volume lower bound in the relevant sequential/word model.

### Using OpenAI #130 as a theoretical fallback (conditional on its model)

OpenAI's 2026 exact DFT manuscript claims a uniform `A(b) = O(b (log b)^(1-delta))` algorithm (`delta = 10^-13`) under exact, unrestricted complex arithmetic with a specified Fourier root and word-indexing assumptions. Its sharper bound is `O(b (log b)^theta (log log b)^(4-theta))` with `theta<1`.

For N a power of two, b the least power of two >= k, and m=N/b, an index-residue factorization computes a k-sparse change using m length-b transforms plus O(N) coefficient/routing work:

    T_sparse(N,k) = O(N + (N/b)*A(b))
                  = O(N[1+(log(k+2))^(1-delta)]).

The working decomposition and proof are in the preceding `fft130_adaptive_merge/RESEARCH.md`; this phase does not implement #130's exact-arithmetic primitive. For fresh dense unstructured vectors (k=N) this cannot improve the worst-case exponent beyond #130 itself.

### Many *different* signals sharing a reference

Let M vectors `x_t = x_0 + d_t`, where each `d_t` is k-sparse and its positions and values are supplied. Compute `FFT(x_0)` once. Constructing all M explicit dense transforms via direct updates costs:

    O(A(N) + M*N*k).

For k=O(1), this is O(A(N)+MN), vs O(M*A(N)) for M independent #130 DFTs (comparison of *available algorithms*, not a lower bound). If M grows faster than `(log N)^(1-delta)`, then the **amortized bound per output** is O(N). This is a classical linearity consequence, here made usable through an explicit forkable cache.

The fork() method reuses the **same immutable** base signal and base spectrum and copies only k metadata entries, no FFT. A forked version may be edited and committed without changing siblings.

### Query-only workload

For fixed subscribed frequency indices q_1,...,q_Q, maintain only these Q outputs. A known edit contributes `delta*omega^(position*q_j)` to each. Once the starting Q values exist, each edit costs O(Q) (with known position). This is **not** a dense-output FFT and must not be compared as though it computed the full spectrum.

## 2. Faster O(N) phase-vector generation via small reusable tiles

When only one sample changes, each dense spectrum needs the phase vector

    phase[q] = exp(-2*pi*i*position*q/N),  0 <= q <= N//2.

Naively NumPy's vectorized exponential evaluates a transcendental function for each frequency. Instead choose a small tile width B=1024 and write q=t*B+r:

    phase[t*B + r] = phase[t*B] * phase[r].

Precompute the B local phases once using the doubling rule `phase[r+B0] = phase[B0]*phase[r]`, for B0 = 1,2,4,... . Prepare only ceil(N/(2B)) independent tile-start phases, and fill the whole vector by broadcasted complex multiplication. The algorithm uses O(N) arithmetic and memory; it reduces transcendental calls from Theta(N) to O(B + N/B), but it does *not* lower the overall O(N) cost of writing the phase vector. The periodic starts limit cumulative root-power drift compared with a naive million-step recurrence. It must still be tested for the required numerical tolerance.

`phase.py` implements the tiled method. Its tests compare to direct complex exponentials over multiple lengths, positions, and tile sizes.

## 3. Numerical and structural verification

- `test_lazy_fft.py` checks real rFFT updates, repeated-index coalescing, arbitrary frequency reads, dense materialization, fork isolation, selected-frequency subscriptions, and `phase_tiled` across even/odd lengths.
- `exact_modular_check` independently checks the additive-frequency identity using a prime root of unity in F_998244353 (not a proof of the floating-point implementation or of OpenAI #130).
- Seven test cases pass; phase checks iterate many combinations.
- Tested numerical discrepancies are small, but floating-point streams can accumulate error and periodic rebasing is advisable. The exact algebra and the numerical approximation must not be conflated.

## 4. Benchmarks (local machine, 3-run medians)

Environment: Python 3.13, NumPy 2.3.5, SciPy 1.17.0; 40 known sample updates per length. All adaptive figures **include the initial real FFT and required phase precomputation**. The optimized numerical baseline is SciPy `rfft`, not an unoptimized Python FFT. Each table row was checked numerically.

### Every updated dense spectrum required, same edit position

| N | 40 fresh `rfft` (ms) | Cached prepared 40 updates (ms) | Speedup |
|---:|---:|---:|---:|
| 4,096 | 0.7125 | 0.2072 | 3.44x |
| 16,384 | 3.2156 | 0.5276 | 6.09x |
| 65,536 | 13.3044 | 2.4165 | 5.51x |
| 262,144 | 86.6096 | 9.7975 | 8.84x |
| 1,048,576 | 454.5903 | 52.8969 | 8.59x |

Ratio generally improves with length but **not monotonically**. The O(N) update work eventually encounters memory-bandwidth effects.

### Phase generation and one dense spectrum after one known edit

|---:|---:|---:|---:|---:|---:|
| 4,096 | 0.0476 | 0.0264 | 1.80x | 0.0218 | 0.0431 |
| 16,384 | 0.1973 | 0.0365 | 5.41x | 0.0824 | 0.0937 |
| 65,536 | 0.7786 | 0.0603 | 12.91x | 0.4466 | 0.1293 |
| 262,144 | 3.8180 | 0.4934 | 7.74x | 2.8752 | 1.4834 |
| 1,048,576 | 14.1271 | 1.1280 | 12.52x | 17.2675 | 4.2794 |

The one-edit rows assume the base spectrum already exists. The 40-edit table above charges its original creation. At N=1,048,576, maximum phase-vector difference against vectorized `exp` was about 3.4e-14; maximum spectrum difference vs fresh SciPy rFFT about 9.4e-13.

### 64 distinct complete FFT outputs from one reference

Each signal is a different one-coordinate modification of the same reference; all 64 *full spectra* are written. The shared method includes one reference FFT and never assumes phase vectors for each distinct position were precomputed.

| N | 64 independent `rfft` (ms) | Forks + 64 tiled materializations (ms) | Speedup |
|---:|---:|---:|---:|
| 4,096 | 1.3615 | 2.0879 | 0.65x (slower) |
| 16,384 | 5.8315 | 3.0786 | 1.89x |
| 65,536 | 25.4762 | 7.4199 | 3.43x |
| 262,144 | 189.3319 | 75.1484 | 2.52x |

These benchmarks compare *related, metadata-described signals*, not random independent fully materialized signals. The relative order is hardware- and cache-dependent.

### Only eight fixed frequency bins after each of 40 edits

At N=1,048,576, running 40 full SciPy `rfft`s and selecting eight bins took 434.8 ms; the lazy state took 13.49 ms (32.2x), while a dedicated subscribed-eight-frequency updater took 11.45 ms (38.0x). **This is a different output contract** (eight selected bins, not an updated full spectrum). An appropriately designed selective-frequency updater is itself O(Q) per known edit, so the ratio to a wasteful full-FFT baseline is not a new speedup over optimal prior art.

### Crucial counterexample: only one dense spectrum at the end

For 40 edits followed by **one** final full-spectrum request, at N=1,048,576 the fresh SciPy FFT took 12.77 ms and preparing a separate cached state then rebuilding took 26.72 ms. A cache is wasteful when no intermediate spectra are needed. This justifies a workload-aware dispatcher rather than unconditional reuse.

## 5. Research interpretation

**Verified engineering result:** Tiled phase reuse lowers the cost of preparing an O(N) update vector without exponential lookup tables. It combines productively with a forkable immutable spectral reference; correctness tests and local speedups are reproducible.

**Known mathematical result, newly combined in this project:** An edit log coalesced by changed position gives a useful output-sensitive transform interface: expected O(1) metadata edits, O(k) arbitrary-bin queries, O(Q) subscribed-bin updates, and O(N) explicit dense reconstruction when k is constant. Large M related variants have O(N) amortized output cost after initial preprocessing. Earlier dynamic Fourier results (Reif–Tate, eFFT) demonstrate prior art.

**What is NOT claimed:** No new sub-NlogN worst-case fresh dense complex DFT, no floating-point realization of #130's giant exact circuit, no new integer multiplication bit-complexity exponent, and no guaranteed end-to-end performance improvement for unrelated inputs.

## 6. Next falsifiable milestone

Implement an online dispatcher that gets producer-supplied relations `(base_id, changed_indices, changes)` and chooses among (a) selected-frequency direct updates, (b) cached tiled dense updates when k is small, (c) pruned FFT for intermediate k, and (d) native SciPy/FFTW fallback for unrelated data, with measured dispatch and memory costs. Compare against the existing eFFT implementation on the same event workload. Incorporate basis signals and sparse residuals, with no full-spectrum output unless requested.

A theoretical advance beyond existing dynamic FFT methods would require a better proven tradeoff (time/space, exactness, output model) or a genuinely faster general fresh-transform construction. Merely observing growing empirical speedups does not prove the latter.
