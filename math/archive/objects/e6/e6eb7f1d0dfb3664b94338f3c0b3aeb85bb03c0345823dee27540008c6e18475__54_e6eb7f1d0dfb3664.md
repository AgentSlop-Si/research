# Research notes: sharing FFT computations without inventing free work

**Date:** 2026-10-08  
**Status:** Correctness-tested exploratory software; not a new sub-`N log N` theorem.

## 1. Problem and baselines

For a real vector `x` of length `N`, `X[k] = sum_{j=0}^{N-1} x[j] exp(-2πijk/N)`. Standard fast algorithms evaluate this in `O(N log N)` arithmetic. An optimized `rfft` returns only `floor(N/2)+1` nonredundant spectral bins due to Hermitian symmetry.

The aim is to reduce the **total cost across related FFT requests**, including detecting reuse, looking up and validating cached entries, reconstructing spectra, and accessing memory.

## 2. Reuse identities and derivations

1. Exact equality: `x=y => F(x)=F(y)`. A byte-exact hash lookup is safe only after verifying the complete input bytes; this implementation performs that verification. Reading/copying an `N`-element spectrum is `Θ(N)`.
2. Linearity: `F(alpha*x+beta*y) = alpha*F(x)+beta*F(y)`.
3. Right circular shift: `y[j]=x[(j-s) mod N]`. Substitute `t=j-s` into the DFT to get `F(y)[k]=exp(-2πiks/N)F(x)[k]`. Phase reconstruction is `O(N)`.
4. Sparse edits: `y=x+sum_{t in edits} delta[t]*e_t`. Therefore `F(y)[k]=F(x)[k]+sum_t delta[t]*exp(-2πikt/N)`, `O(N * #edits)`.
5. One complex FFT of `z=a+i*b` yields `Z=A+iB` for real inputs. Via Hermitian symmetry, `A[k]=(Z[k]+conj(Z[-k mod N]))/2` and `B[k]=(Z[k]-conj(Z[-k mod N]))/(2i)`. But an optimized pair of real FFTs may beat this in wall-clock time.

### Linear family

Let `basis` have shape `(r,N)` and real `C` have shape `(M,r)`. The actual signals are `X=C @ basis`. Fourier linearity yields

`F(X) = C @ F(basis)`.

Cost: `O(r N log N + M r N)` operations. If `r` is small and supplied directly, the additional spectra cost `O(N)` each. A full dense representation costs `Θ(MN)` to materialize; the benchmark for `fft_family` assumes the compressed representation already exists. Detecting rank from arbitrary dense signals adds its own cost and may not be profitable.

### Reused computation DAG

Hash-consed radix-2 nodes are keyed by `(length, canonical_even_child, canonical_odd_child)`. Every pair of equal subproblems has the same node ID and the same FFT. If `U_m` is the number of unique subproblems of size `m` in a single transform, its *butterfly* count is

`B(N) = sum_{m=2,4,...,N} (m/2) * U_m`.

Ordinary radix-2 FFT has `U_m=N/m`, giving `(N/2)*log2(N)` butterflies. For input with fixed period `p`, `U_m <= p`, so `B(N) < pN` butterfly operations. This **does not show O(N) for arbitrary inputs**, nor does counting only butterfly operations prove Python wall-clock speedups.

For iid binary blocks of size `m`, exact equality occurs between a given pair with probability `2^-m`. At block sizes larger than a constant multiple of `log N`, collisions between large disjoint blocks are extremely unlikely. This explains why DAG savings concentrate near the leaves for high-entropy inputs.

## 3. Practical design

- A bounded LRU cache stores immutable copies of normalized real inputs, their exact raw bytes and their nonredundant spectra. A salted in-memory hash speeds dictionary lookup; we compare full bytes before accepting a hit, so collisions never change the numerical result.
- Mode `auto` is conservative because compiled FFT backends are fast. Consecutive unrelated inputs trigger periodic cache probing rather than costly scanning on every call.
- Mode `aggressive` exposes rotation- and sparse-update-based reuse for correctness experiments even when lookup work costs more than recomputation.
- Small sampled-coordinate comparisons reject unsuitable sparse candidates before scanning all `N` values. Rotation-invariant numerical signatures reject most impossible shifts before byte-based circular search. Positive matches are checked exactly, so a screening collision only costs time, not correctness.
- FFT shift phase sequences use a single complex exponential followed by `O(N)` complex multiplications (`numpy.cumprod`), rather than an expensive exponential for every frequency. Phase recurrence can accumulate small floating-point error for huge transforms; validate tolerances when scientific precision matters.
- FFT batches primarily use optimized vectorized `rfft` rather than Python-level DAG evaluation. Forced rank-2 detection validates the candidate relationship against all input coordinates.
- Optional SciPy backend provides speed; NumPy backend is supported and tested.

## 4. Interpretation of reproducible benchmarks

Run `OPENBLAS_NUM_THREADS=1 python benchmark.py`, which writes `benchmark_results.json`. The benchmark compares against the *same optimized real-input FFT backend* selected for the engine. It includes Python dispatch, hashing, reconstruction, rank detection when used, result copying and cache bookkeeping; it reports medians across seven runs. Numbers depend on CPU, library versions, memory contention and batch shapes. These are engineering benchmarks, not asymptotic proofs.

Expect:
- Exact repeated medium/large arrays can be faster with caching.
- Unrelated inputs generally need a fast fallback; even conservative cache probing has a cost.
- Unconditional shift/sparse detection in Python is often slower than optimized SciPy, despite `O(N)` arithmetic identities. Turn on aggressive reuse to study those relations.
- Known bases can give large amortized savings on a family of many different signals.
- Ordinary DAG butterflies decline for periodic inputs, but a pure-Python graph is not a performance substitute for compiled FFT libraries.

## 5. Correctness and verification

`python -m unittest -v` exercises random real arrays and lengths including non-powers of two, NumPy/SciPy comparisons, exact cache identity, immutability of returned results, every attempted circular shift, sparse changes, known and auto-detected linear families, cache eviction, convolution, packing, DAG reuse, bad inputs and the check `1234 * 5678 = 7006652`.

Numerical rank inference and finite precision make these algorithms **numerical**, not exact for all real numbers. Real floating-point transformations may accumulate small reconstruction errors. Extremely large-coefficient exact integer multiplication requires different precision handling or modular NTTs.

## 6. Research directions, ranked

**A. Symbolic graph sharing independent of input collisions.** Intern equivalent *linear expressions* (not merely equal numerical values) across butterfly networks; count rank and operation requirements after all rewrites. This is more directly related to CrocSwap's finite-circuit shared sums than value caching.

**B. Discover structured spans cheaply.** Instead of validating all of a dense batch independently, maintain certified low-rank models from earlier batches or obtain coefficients upstream from a signal generator. Bound amortized lookup and model maintenance cost.

**C. Packed lookup tables for finite fields.** Research a *finite-field* transform on word-packed vectors using small precomputed blocks with complete memory and access accounting. Josh Alman's [lookup-table Walsh-Hadamard transform](https://arxiv.org/abs/2211.04643) obtains `O(N log N / log log N)` bit complexity over constant-size fields. Do not transfer that theorem directly to arbitrary complex FFTs.

**D. Limitations.** Morgenstern's [bounded-coefficient linear FFT lower bound](https://doi.org/10.1145/321752.321761) rules out a sub-`N log N` algorithm *in that circuit model*, but does not address all data-dependent lookup models. An unlimited, free oracle containing all inputs and FFT outputs can trivially deliver answers in `O(N)` output time, but does not constitute a uniform algorithm with accounted preprocessing.
