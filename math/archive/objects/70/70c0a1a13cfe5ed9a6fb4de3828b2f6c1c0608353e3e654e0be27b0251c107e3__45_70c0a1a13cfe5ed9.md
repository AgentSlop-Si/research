# Adaptive FFT Research — Theory Update

**Date:** 2026-10-09  
**Status:** We have genuine sub-`N log N` bounds for structured/dynamic Fourier updates, **not** a universal sub-`N log N` algorithm for an arbitrary fresh dense DFT.

## 1. Precise answer

Let `F_N` be the length-`N` DFT. A conventional fresh transform costs `O(N log N)` arithmetic operations.

Our adaptive engine changes the problem: a previous transform, basis spectra, or relation metadata may already be available. In that setting, several exact update classes have asymptotic cost `o(N log N)`.

This does **not** imply that an arbitrary unseen dense vector can be transformed in `o(N log N)`.

## 2. Dynamic k-sparse update theorem

Assume the spectrum

`X = F_N(x)`

is already known. The new signal is

`x' = x + delta`,

where `delta` has at most `k` known nonzero coordinates. By linearity,

`F_N(x') = X + F_N(delta)`.

A radix-2 FFT of the sparse delta can prune every recursive subtree containing no nonzero input.

At recursion depth `d`, there are at most

`min(2^d, k)`

active nodes, each with transform size `N / 2^d`. The combine work at that depth is therefore bounded by

`(N/2) * min(1, k / 2^d)` butterflies.

Let `h = ceil(log2 k)`. Summing depths before and after `h` gives

`B(N,k) <= (N/2) ceil(log2 k) + N`,

so

`T_delta(N,k) = O(N (1 + log(k+1)))`.

Adding the delta spectrum to the cached spectrum costs another `O(N)`, leaving the same asymptotic bound:

`T_update(N,k) = O(N (1 + log(k+1)))`.

### Little-o condition

We have

`T_update / (N log N) = O((1 + log(k+1))/log N)`.

Therefore

`T_update = o(N log N)`

whenever

`log k = o(log N)`, equivalently `k = N^{o(1)}`.

Examples:

- `k = O(1)`: `Theta(N)`.
- `k = (log N)^c`: `O(N log log N)`.
- `k = exp(sqrt(log N))`: still `o(N log N)`.
- `k = N^alpha` for fixed `alpha > 0`: still `Theta(N log N)` asymptotically, though it may save a constant factor.

For `k=1`, a point edit changes every DFT coefficient in general. If a dense spectrum must be explicitly written, `Omega(N)` output work is unavoidable, so the `Theta(N)` update is output-optimal up to constants.

## 3. Exact operation-count prototype

The cached-layer C++ prototype stores radix-2 intermediate stages and propagates only dirty butterflies.

For `N=65536`, one changed sample invalidated exactly `131070` complex stage outputs, approximately `2N`, versus `N log2 N = 1,048,576` stage values for a full radix-2 traversal. Numerical agreement with FFTW was around `1e-12`.

For `N=262144`, one edit invalidated `524286` complex stage outputs, again approximately `2N`.

The first implementation is slower than FFTW in wall-clock time because its dirty-node traversal and memory accesses are irregular. This is an implementation issue, not a contradiction of the operation-count bound.

A second standalone input-pruned implementation was also built. It has the expected butterfly counts; for power-of-two `k` in a maximally dispersed support pattern, the measured counts follow approximately

`N * (1 + 0.5 log2 k) - k`

complex butterflies. A fair dynamic wall-clock benchmark shows that a naive recursive implementation is not yet consistently faster than FFTW; allocator/memory costs dominate for most `k`.

## 4. Other structured classes

### Exact repeat

If an input exactly matches a cached signal, no transform arithmetic is needed. Explicitly returning a fresh dense spectrum still costs `Theta(N)` to copy; returning an immutable handle/view can be `O(1)`.

### Circular shift

If `x'[j] = x[(j-s) mod N]`, then

`F(x')[q] = exp(-2 pi i q s / N) F(x)[q]`.

With `s` known, materializing the full spectrum is `Theta(N) = o(N log N)`. Exact shift detection against a constant number of references can itself be linear, so the theoretical bound can remain `Theta(N)`, although memory scanning may make it unattractive in practice.

### Low-rank/basis family

Suppose signals are represented as

`x_t = sum_{j=1}^r c[t,j] b_j`.

Once the `r` basis spectra are cached,

`F(x_t) = sum_j c[t,j] F(b_j)`

costs `O(rN)` to materialize. This is `o(N log N)` per signal whenever `r=o(log N)`.

For `M` signals including basis preprocessing, total cost is

`O(r N log N + M r N)`

versus `O(M N log N)` independently. The ratio is approximately

`r/M + r/log N`.

Hence the total batch cost is little-o of independent FFTs when both `r/M -> 0` and `r/log N -> 0`.

If outputs remain compressed as `(coefficients, basis_spectra)`, materialization can be postponed, but this is an implicit-output model and should not be compared directly with a standard dense DFT API.

### Low-rank + sparse residual

A useful unified class is

`x = B c + e`, with `rank(B)=r` and `||e||_0 <= k`.

After basis spectra are available, a dense spectrum can be produced in

`O(N [r + 1 + log(k+1)])`.

Thus it is `o(N log N)` whenever

`r + log(k+1) = o(log N)`.

This parameterized form is a promising way to describe the adaptive engine.

## 5. Prior-art boundary

These sub-`N log N` dynamic results are not, by themselves, a new universal FFT theorem.

- **Reif & Tate (1997)** studied dynamic algebraic problems with requests that change one input or query one output and gave an `O(sqrt(N))`-time-per-request incremental DFT algorithm. This request model does not materialize all `N` outputs after every request.
- **Pruned FFTs** are classical. FFTW's documentation states `O(N log K)` complexity when only `K` inputs are nonzero (or only `K` outputs are wanted), versus `O(N log N)` for a full transform.
- **eFFT (Tapia, Martínez-de Dios, Ollero, 2024; C++ release 2026)** is especially close to our cached-layer idea. It stores radix-2 intermediate matrices in a tree and updates only affected branches for exact asynchronous event changes. For a single event in an `N x N` image, its operation count is linear in the number of pixels, rather than pixel-count times its logarithm.
- Known Fourier lower bounds remain model-dependent. For example, Ailon gives `Omega(N log N)` in well-conditioned linear computation models, while matching unrestricted lower bounds remain a long-standing issue.
- Lookup-table speedups over finite fields also exist: Alman obtains `O(N log N / log log N)` bit complexity for Walsh-Hadamard transforms over constant-sized finite fields. This is not the same as arbitrary floating/complex DFT.

## 6. What may still be research-worthy here

The likely contribution is **not** “we discovered the first sub-`N log N` dynamic FFT.” That would be false.

The more defensible research target is a general adaptive Fourier runtime that treats transform requests as relations to cached state and chooses among several exact representations:

1. exact reuse;
2. phase/shift reuse;
3. `k`-sparse delta pruning;
4. low-rank/basis reconstruction;
5. low-rank plus sparse residual;
6. shared symbolic/canonical computation graphs;
7. packed real transforms;
8. lazy or partial spectrum materialization;
9. optimized full FFT fallback.

A useful abstract parameter is a **relation complexity** `rho(x | cache)`: the cheapest certified representation of the new signal relative to cached state. The goal becomes an engine whose transform work is roughly

`O(N * min(log N, rho))`

plus relation-discovery/metadata cost, with the full FFT as a safe fallback.

This framing is conditional/parameterized complexity rather than a claim about worst-case fresh inputs.

## 7. Best next experiments

1. Replace recursive allocations in the pruned sparse prototype with arenas/preallocated contiguous buffers.
2. Specialize `k=1,2,4` with phase recurrences/SIMD and compare against both FFTW complex and rFFT baselines.
3. Add upstream relation metadata so detection does not scan dense arrays.
4. Implement a hybrid policy: direct sparse sum for tiny `k`, pruned FFT for medium `k`, full FFT for large `k`.
5. Add the low-rank + sparse-residual representation and benchmark real streams.
6. Implement lazy frequency queries using a configurable FFT cut, then compare with Reif–Tate-style update/query tradeoffs.
7. Benchmark against the public eFFT implementation where the problem classes overlap.
8. Formalize the parameterized theorem and clearly separate dense-output, lazy-output, preprocessing, and discovery costs.

## 8. Relation to the 2026 integer-multiplication result

OpenAI's September 23, 2026 preprint claims exact deterministic integer multiplication in

`O(n (log n)^(1-kappa))`, `kappa=2^-182`,

on a fixed finite-alphabet multitape Turing machine. That is a true `o(n log n)` claim for **integer multiplication in that bit model**, not a claim that arbitrary DFT itself has an `o(N log N)` algorithm. The constructions and cost model are different. Our adaptive FFT research should not conflate these statements.

## Bottom line

**Yes:** the adaptive/structured problem contains exact regimes with `o(N log N)` work, including `Theta(N)` single-edit/shift updates and `O(N log log N)` for polylogarithmically many changed samples.

**No:** we have not shown that a completely arbitrary fresh dense Fourier transform can be computed in `o(N log N)`.

The strongest direction now is to make the parameterized adaptive bound practical and general, rather than to claim a universal FFT breakthrough.
