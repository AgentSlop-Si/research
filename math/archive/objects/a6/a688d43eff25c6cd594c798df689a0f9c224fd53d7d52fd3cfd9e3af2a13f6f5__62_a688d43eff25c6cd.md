# Adaptive FFT reuse engine (research prototype)

This is a runnable, experimentally benchmarked prototype for **reuse among multiple real-input FFTs**. It is not a new general sub-`O(N log N)` FFT algorithm.

Core ideas:

- Cache entire FFTs by **bit-exact input identity**, with a bounded LRU memory budget and full-input verification of hash matches.
- Recognize **cyclic shifts** and **sparse edits** relative to recent cached inputs (research mode). Both have an `O(N)` spectral reconstruction formula.
- Detect some **rank-one/rank-two input families** from dense batches, and reuse their basis transforms (research mode).
- Accept a **known linear family** directly: compute `r` basis FFTs and reconstruct `M` distinct FFTs from linear coefficients, in `O(r N log N + M r N)` arithmetic.
- An optional **canonical shared computation DAG** computes identical radix-2 subproblems only once and reports butterfly savings. It is deliberately not used on the optimized fast path: Python DAG management can cost much more than compiled FFTs.
- An educational **two-real-FFTs-in-one-complex-FFT** packing function.
- Efficient real-input `rfft` storage using only `floor(N/2)+1` nonredundant spectral values.
- Ordinary real FFT and convolution fallback through SciPy (preferred) or NumPy.

## Requirements

Python 3.10+ and NumPy; SciPy is optional but highly recommended for fast FFTs.


The test suite uses Python's built-in `unittest`. Benchmarks produce `benchmark_results.json` and cover **all processing costs**, not just butterfly counts. Timings will depend on CPU and FFT backend.

## Quick start

```python
import numpy as np
from adaptive_fft import AdaptiveFFT

engine = AdaptiveFFT(max_cache_bytes=64_000_000)
x = np.random.default_rng(1).standard_normal(65_536)

first = engine.rfft(x)    # backend computes and caches
second = engine.rfft(x)   # exact cache hit, verified
assert np.allclose(first, second)
print(engine.summary())
```

`.rfft(x)` returns `floor(N/2)+1` complex values, `.fft(x)` returns the full `N`-element spectrum. Returned arrays are **fresh**, so modifying one cannot corrupt cached results.

### The strongest reuse opportunity: known families

If signals are generated from a small number of basis signals, you can skip most FFTs.

```python
rng = np.random.default_rng(2)
N = 16_384
M = 128
basis = rng.normal(size=(2, N))
coefficients = rng.integers(-3, 4, size=(M, 2))

engine = AdaptiveFFT()
spectra = engine.fft_family(basis, coefficients)

# The signals are implicitly: signals = coefficients @ basis
reference = np.fft.rfft(coefficients @ basis, axis=1)
assert np.allclose(spectra, reference)
```

`fft_family()` is most useful when the **basis and coefficient representation already exists**. Discovering that decomposition from arbitrary dense arrays may cost more than using SciPy FFT directly. The results are still `M` different transforms.

For cross-request reuse from one or two registered basis signals:

```python
engine = AdaptiveFFT(mode='aggressive')
engine.register_basis(basis)          # basis must have 1 or 2 independent rows
query = 3 * basis[0] - basis[1]
result = engine.rfft(query)
assert engine.last_strategy == 'span'
```

### Shift and sparse-update identities

```python
engine = AdaptiveFFT(mode='aggressive')
engine.rfft(x)

shifted = np.roll(x, 37)
Y = engine.rfft(shifted)
assert engine.last_strategy == 'shift'

edited = shifted.copy()
edited[11] += 5
Z = engine.rfft(edited)
assert engine.last_strategy == 'sparse'
```

In `auto` mode, structural checks are intentionally conservative, because for ordinary sizes SciPy's FFT is often **faster** than Python recognition + complex phase reconstruction. Force research behavior with `mode='aggressive'` or with `.rfft(x, reuse=True)`. **Don't claim O(N) wall-clock speedups for these paths based only on their formula.**

### Linear convolution / integer multiplication

```python
engine = AdaptiveFFT()
c = engine.convolution([4,3,2,1], [8,7,6,5])
digits = np.rint(c).astype(int)
value = sum(int(d) * 10**j for j,d in enumerate(digits))
assert value == 1234 * 5678
```

Floating-point FFT convolution is not automatically exact for arbitrarily large integers. Exact large-integer algorithms need careful coefficient splitting, precision analysis, or modular NTTs.

### The shared computation DAG

```python
from adaptive_fft import CanonicalFFTGraph

G = CanonicalFFTGraph()
N = 4096
x = [1,0,1,1,0,0,1,0] * (N//8)
id_1 = G.add(x)
id_2 = G.add(x[:])
assert id_1 == id_2
Y = G.evaluate(id_1)
print(G.summary())
```

This is a reference and operation-count tool. It is not faster than SciPy on arbitrary inputs. The DAG accepts positive power-of-two lengths; the optimized `AdaptiveFFT` methods accept any positive length.

## API reference

| Method | Purpose |
|---|---|
| `AdaptiveFFT.rfft(x, reuse=None)` | Compact real-input transform; cache and optional structural reuse |
| `AdaptiveFFT.fft(x, reuse=None)` | Full spectrum, expanded from real-input symmetry |
| `AdaptiveFFT.fft_batch(signals, return_info=True)` | (M,N) real batch; optional rank-2 detection |
| `AdaptiveFFT.fft_family(basis, coefficients)` | **Known** low-dimensional input family; no detection necessary |
| `AdaptiveFFT.register_basis(basis)` | Register 1 or 2 reference vectors as a model |
| `AdaptiveFFT.convolution(a,b)` | FFT-based linear convolution |
| `AdaptiveFFT.summary()` | Counts and memory usage |
| `AdaptiveFFT.clear()` | Clear cache and stored bases |
| `two_real_ffts_packed(a,b)` | Educational complex packing of 2 real inputs |
| `CanonicalFFTGraph` | Hash-consed, exact-input DAG for radix-2 FFTs |

### Modes

- `auto` (default): exact hits, large-input structural probing, optimized fallback, no blind per-row candidate search in large cold batches. Uses a probe/bypass policy after successive misses. Automatic rank detection is limited to large batches.
- `aggressive`: attempt all available reuse relationships even when recognition costs exceed an ordinary optimized FFT.
- `plain`: optimized backend directly, without reuse or caching.

The LRU budget covers stored input arrays, input bytes and Fourier results, plus registered basis models; small auxiliary sample-index caches are not included. The cache is per-process and is not thread safe.

## Scope and theory

For a fixed real reference vector `a` of length N:

- Exact repeat: lookup plus output copy `O(N)`.
- Circular shift by `s`: `FFT(roll(a,s))[k] = FFT(a)[k] exp(-2πisk/N)`, reconstruction `O(N)`.
- `d` edited coordinates: update the cached spectrum with `d` phase sequences in `O(dN)`.
- `M` signals from `r` known bases: `O(rN log N + MrN)` arithmetic. For fixed `r`, the marginal cost per additional signal is `O(N)`.
- Binary inputs with fixed period p: a canonical DAG can use `O(pN)` butterfly operations but only for the restricted input class.

These assumptions do **not** imply general `O(N)` FFT for arbitrary independent dense inputs. Mathematically, `O(N)` output is still necessary when the full spectrum must be explicitly produced; what we achieve is an `O(N)` *update or extra transform given prior information*.
