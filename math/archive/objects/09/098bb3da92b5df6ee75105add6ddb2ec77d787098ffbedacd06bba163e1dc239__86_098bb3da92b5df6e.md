# Phase 12: internal product rewrites that expose cached subgraphs

The user's proposed transformation is implemented inside the supplied
sum/convolution DAG:

\[
S_A S_B = U S_B + (S_A-U)S_B,\qquad U=S_A-k.
\]

The planner searches already cached products with the same factor `S_B`,
derives `k` by exact symbolic cancellation, and accepts a replacement only
when its estimated missing vector work is lower. Reuse can occur between
queries or between branches of one initially cold evaluation.

**Result:** this is a working cache-aware optimization for related product
graphs. It does **not** establish a sub-`N log N` FFT or an integer
multiplication exponent. Small graphs and unrelated operands can run slower.
Read [BENCHMARKS.md](BENCHMARKS.md) for all measured wins and losses.

**Numerical limitation:** the identities are exact in a commutative ring,
but the execution backend uses floating-point FFTs. Reassociation can worsen
rounding. A recorded example changes `2.220446049250313` to `2.0`; this
prototype does not automatically detect numerical instability. The finite-field
oracle is a correctness audit, not a fast exact production backend.

## Reproduce

Python with NumPy and SciPy is required. The measured versions are recorded
in `results/benchmark.json`.

```bash
python3 -m unittest discover -s tests -v
python3 research_audit.py
python3 benchmark.py --repeats 7
```

The delivered run has 20 passing tests and 48 exact finite-field witness
checks. The benchmark records seven runs per mode per case, alternating mode
order, with a fresh engine for every run. It times input copying and FFTs,
construction, cache preparation, search, evaluation, and all full outputs.
Input array generation is shared and excluded.

## Minimal use

```python
import numpy as np
from cache_rewrite import CacheRewriteFFT

n = 4096
e = CacheRewriteFFT(n, rewrite=True)
rng = np.random.default_rng(123)
arrays = rng.normal(0, .02 / np.sqrt(n), (9, n))
arrays[:, 0] += 1
x = [e.signal(a) for a in arrays]   # these nine rFFTs are real costs
g, b = e.mul(*x[:-1]), x[-1]
p = e.mul(g, b)
q = e.mul(e.add(g, e.one), b)
y = e.evaluate_time(e.add(p, q))   # empty cache at call entry
print(e.proof_records())          # q becomes cached(p) + b
print(e.last_stats)
```

`*` in the graph means length-`n` **circular convolution**. In the spectrum
it means pointwise multiplication. `e.one` is the unit impulse at index zero,
not an all-ones time-domain array. There are no integer carries in this engine.
Each node represents a full half-spectrum at the same length; this experiment
does not rewrite the butterflies inside SciPy's FFT implementation.

`rewrite=False` uses the same evaluator and cache but disables the new rule.
This is the primary comparison baseline. Both modes check a cached parent
before traversing its descendants; the supplied older evaluator did not.

## Bounds and limitations

The defaults allow 8 candidate probes per target, 128 probes per evaluation,
64 terms in a linear signature, 256 newly created graph nodes per evaluation,
and 10,000 signature/cost/frontier node visits. Product indexing is restricted
to arity at most 32. Search budget exhaustion falls back to ordinary evaluation.
Other per-node dispatch, constructor bookkeeping, and cache index maintenance
are additional work and are included in wall-clock measurements.

Certificates support bounded integer symbolic coefficients (absolute value at
most `2**40`); seed arrays may contain arbitrary finite real numbers. Noninteger
coefficients, unsupported forms, and unprofitable proposals fall back. The
optimizer is deliberately incomplete and does not do full equality saturation.

The cache byte limit bounds persisted **result-array entries only**. Input
arrays and seed spectra, the graph, per-evaluation memo, output copies and Python
metadata are separate. Pinning protects the chosen cached frontier from eviction
during evaluation. A single call retains its computed arrays; this is not a
bounded-total-memory evaluator. Aliased cache entries are charged separately,
which conservatively overcounts their shared payload. Graph metadata can grow
over successive calls; the per-call node cap is not lifetime garbage collection.

The integration target for integer multiplication remains an exact backend
with modulus/length/normalization-aware cache keys, precision or CRT accounting,
and carry costs. The external `integer-mult-kappa` repository is unchanged.
