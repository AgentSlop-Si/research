# Exact blocked rational-series Fourier synthesis: baseline prototype

This is an independently written baseline, not a new algorithm and not an adaptation of uploaded code. It demonstrates a charged, streaming implementation of a standard rational-generating-function recurrence. It makes **no floating-point, complex-number, numerical-stability, bit-complexity, practical speedup, or novelty claim**.

## Result and reproduction

Run `python streaming_fourier.py` with standard-library Python. The deterministic seed is 20261009. `results.json` records **184 passing cases**, all compared coefficient-for-coefficient against a full length-N forward NTT using the same independently written radix-two kernel. **76 cases** also match direct Fourier evaluation. Tested N ranges from 1 to 4096; tested active support sizes extend to 64. Coverage includes empty/all-zero input, duplicate positions including cancellation and positions reduced modulo N, k=1, k=N for N<=64, random supports, subgroup cosets, and final partial blocks when k does not divide N. Every nonzero block also checks the divisibility invariant described below.

The fixed field is F_p for p=998244353, with primitive root 3. Dyadic N divides p-1 exactly when N<=2^23. The convolution length F must also divide p-1, so this implementation requires F<=2^23 (in particular k<=2^22 with this padding rule). Tests are far below these limits. This fixed-modulus experiment is **not an unbounded asymptotic bit-complexity theorem**. Zeros of coefficients in this finite field say nothing contradictory about a nonvanishing lemma over complex prime-order roots.

## Mathematical specification and correctness

Normalize and merge input pairs (j,a), reducing j modulo N and a modulo p. Remove zero merged entries. Let k be the resulting support size, zeta=3^((p-1)/N), and z_s=zeta^j_s. The intended output is

    f_m = sum_s a_s z_s^m,  0 <= m < N.

Define

    Q(t) = product_s (1-z_s t),
    P(t) = sum_s a_s Q(t)/(1-z_s t),
    R(t) = Q(t)^(-1) modulo t^k.

Then the formal generating series is P/Q. Q(0)=1, so every inverse and series coefficient is well-defined. Prepare P and Q with straightforward quadratic arithmetic and R with its quadratic coefficient recurrence. Start with P_0=P. For each output block, calculate

    A_r = (P_r R) modulo t^k,
    P_(r+1) = (P_r-Q A_r)/t^k.

The first k coefficients of Q A_r equal P_r; the code asserts this exactly. Since deg(P_r)<k and deg(Q A_r)<=2k-1, the next numerator has degree <k and is exactly the negated high half of Q A_r. The identity

    P_r/Q = A_r + t^k P_(r+1)/Q

proves by induction that concatenated blocks give the desired coefficients. Compute a full block and transition even for the last block, then discard unrequested output coefficients. k=0 is handled separately by emitting N zeros.

For both multiplications, pad to F, the least power of two >=2k, preventing cyclic aliasing. Precompute the length-F spectra of Q and R. Each block uses two forward and two inverse transforms, and two length-F pointwise products. No FFT is delegated to a library.

## Explicit operation accounting

`results.json` separates input/preparation, generation, and total counters, and the complete padded-input full-NTT baseline. A butterfly is one data multiplication and two additions/subtractions. The implementation also separately counts its twiddle-update multiplications, inverse-normalization multiplications, modular exponentiation multiplications, pointwise multiplications, scalar polynomial preparation multiplications/additions, transition negations, input merge additions, and baseline dense zero initialization/assignments. Modular exponentiation is implemented explicitly and counted; it is not hidden in a unit-cost `pow` call. Integer indexing, bit reversal, allocations/copies, modulo reductions, hash operations, Python interpreter costs, and assertion comparisons are not arithmetic-operation counters. These counts therefore are neither total machine instructions nor bit operations.

For b=ceil(N/k), ell=log2(F), and k>0:

- Polynomial preparation: exactly 3k^2-k modular multiplications, plus recorded additions/subtractions. This includes Q, P, and the truncated inverse R.
- Spectral preparation: 2 transforms, F*ell butterflies.
- Generation: 4b transforms, 2bF*ell butterflies, and 2bF pointwise multiplications.
- Inverse normalization: 2bF modular multiplications.
- Transition: bk negations, including the intentionally unneeded final transition.
- Full NTT: (N/2)log2(N) butterflies, plus the separately counted twiddle and stage-root setup operations.

The NTT computes stage roots by modular exponentiation anew on every call; those charges are included in the JSON. In a scalable arithmetic-complexity treatment one would precompute and reuse stage roots to obtain the conventional O(F log F) transform bound without repeatedly charging root construction. Establishing and constructing suitable fields/roots, field-element bit lengths, and arithmetic bit costs require separate analysis. For the fixed field here the exponent lengths are bounded, and every such multiplication is still counted.

## Complexity and storage interpretation

In the conventional unit-cost field-arithmetic model with suitable available roots and cached transform plans, this baseline has O(k^2) polynomial preprocessing and O(N log(2k)) synthesis, together with input normalization and root construction. Crucially, **this implementation does not remove the O(k^2) preprocessing cost**. It is not an O(N log k)-total-work solution when that preparation dominates, and log(2k) is used to include k=1 correctly. Root construction, duplicate normalization, and stage roots are additional explicitly recorded work in this implementation.

The generator retains O(k) field-element workspace after normalization, because F<4k and only a constant number of length-F arrays are live. Consuming the generator immediately does not require retaining all N outputs. The verification harness deliberately materializes N outputs and comparison arrays, using O(N+k) space. Raw duplicate normalization has peak storage O(u), where u is the number of distinct positions before cancellation; u can exceed the final active k. Holding an input list of r entries also costs O(r). Thus preprocessing storage with arbitrary duplicate/cancelled input should be described as O(r+u+k), not blindly O(k). These are asymptotic live-object bounds from the code, not measured peak byte allocations.
