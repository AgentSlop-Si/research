# A deterministic full-prefix surrogate planner

9 October 2026. This implements the stronger planner proposed in the newly
supplied corrected derivation. It replaces the previous geometric-candidate
planner's library partition with deterministic median-of-medians selection,
evaluates every head prefix at the same asymptotic preprocessing cost, and
constructs the surrogate without selecting a head again.

This is an implementation and accounting improvement, not a new exact FFT or
a novelty claim for importance sampling, linear selection, or pruned FFTs.
The corrected attachment contained mathematical documents, not executable code;
these new source files implement the planner and surrogate construction only.

## Objective and behavior

For m nonzero entries, cap H<=m, total magnitude L, and residual mass L*rho_s,
the mathematical objective is

    k_s = 0                            if rho_s<=epsilon,
          ceil(4 log(4N/delta) rho_s^2 / epsilon^2) otherwise,
    B_s = min(m, s+k_s).

The planner evaluates all s=0,...,H, minimizing B_s. Ties prefer fewer actual
random draws and then the smaller head. Exact-input bypass has zero actual
draws, even if its theoretical requested sample budget is huge. This tie rule
is about operational draws, not the unused theoretical request.

The selected indices are stored once in descending magnitude order, with input
index breaking ties. Construction reuses these indices. It never runs another
partition or magnitude selection. A plan is bound to its complete input value
snapshot and epsilon/delta; construction rejects stale or mismatched plans.
The O(N) validation pass is charged and avoids silently reusing old norms or
sample budgets on a different input.

The constructor has three paths:

- **Exact input:** copy all m nonzero entries, draw nothing. This decision occurs
  before the RNG is consulted, even for enormous requested sample counts.
- **Head only:** copy the selected head, draw nothing.
- **Sample tail:** copy the head, draw k sorted uniforms, and merge them with one
  cumulative tail-mass scan. Coalesce consecutive hits without a hash table.

The returned metadata separates `requested_samples`, `actual_draws`,
`copied_nonzeros`, `sampled_distinct_indices`, `support_upper_bound`, and
`realized_support`. Forty-five draws coalescing to one entry remain 45 draws.

## Deterministic preprocessing bound

Selection uses the median-of-five BFPRT construction. Each recursive partition
discards at least a constant fraction of the values; its recurrence is

    T(n) <= T(ceil(n/5)) + T(7n/10+O(1)) + O(n) = O(n).

The fixed index tie-break makes all comparison keys distinct. Only the H chosen
entries are sorted, costing O(H log(H+2)). Prefix masses and all H+1 candidate
evaluations take O(H). Thus planning takes

    O(N + H log(H+2))

arithmetic/comparison work in the corrected source's ideal model, with O(N)
storage. This bound is deterministic; it does not rely on expected quickselect
behavior or an undocumented library partition guarantee. The default cap is
min(m,max(1,log2(N)^2)), so its sorting overhead is o(N) asymptotically.

Every sampled path satisfies s+k<m<=N. Construction takes O(N+k log(k+2)),
including input binding, markers, sorted uniforms, cumulative scanning and
coalescing. If a classical sparse-input FFT evaluates the resulting q-sparse
vector, its O(N log(q+2)) work gives the end-to-end bound

    O(N + H log(H+2) + k log(k+2) + N log(q+2))
      <= O(N + H log(H+2) + N log(B_selected+2)).

This last simplification uses the planned support bound B_selected, rather than
silently replacing it by the smaller realized q and discarding sampling work.
All N output writes must still be charged by the transform caller. This package
does not introduce another transform backend; sparse entries can be supplied
to the project's existing classical sparse-input evaluator. Divide its raw
DFT outputs by sqrt(N) for the unitary convention used in the error theorem.

## Exactness of the planner versus numerical certification

There are two distinct claims:

1. In the ideal mathematical model, evaluating every prefix exactly minimizes
   the stated certified support objective within H. It is at least as good as
   the previous geometric grid and may be strictly better at a cutoff.
2. The Python implementation exactly minimizes its explicitly computed numeric
   objective. Magnitudes come from floating-point `hypot`; the logarithmic
   factor comes from `math.log`. Prefix masses are exact `Fraction` sums of
   those computed magnitudes, avoiding cancellation in tiny residual masses.
   Budget comparisons and ceiling operations then use exact rational arithmetic
   on that numeric factor. Fractions do not certify the preceding magnitudes
   or logarithms against their mathematical values.

The tests prove the second claim against an independent full-sort oracle.
They do not certify the original probability theorem in floating point.
Python's finite-bit uniforms, complex phase calculation, possible underflow,
and any downstream FFT roundoff remain separate numerical issues. Input and
output values outside the supported floating range raise an error where checked.
The ideal-model selection theorem is not a bit-complexity theorem for Python's
Fraction arithmetic or huge integer sample-budget metadata. All such operations
are executed and charged qualitatively; no unit bit-cost claim is made.

## Usage

```python
from prefix_planner import plan_prefix, construct_surrogate
import random

plan = plan_prefix(x, epsilon=0.1, delta=0.01, max_head=64)
entries, info = construct_surrogate(
    x, 0.1, 0.01, plan=plan, rng=random.Random(1234)
)
# entries is a list of (original_input_index, surrogate_coefficient).
# Feed it into the existing sparse-input full-output DFT evaluator.
```

`max_head=None` selects the default cap; nonnegative caps are clamped to the
actual nonzero count. Invalid epsilon/delta are rejected even on zero-input and
exact-return paths. Mutating x or changing requested parameters requires a new
plan and causes the old plan to be rejected.

## Focused verification

Run `python3 run_audit.py` with the Python standard library.

- 144 cases compare selected indices and the complete optimum against an
  independent full sort and separate residual-sum objective oracle.
- 12 selection cases cover ascending, descending and tied magnitudes, with
  small and near-full caps.
- 27 invalid/stale requests are rejected, including zero-input parameter paths.
- An exact rho=epsilon cutoff uses no samples.
- A 602-digit requested budget falls back to four copied entries before RNG use.
- 45 identical sampled locations produce one entry while retaining the true
  requested/drawn counts in metadata.
- A cutoff example achieves support 3, while its geometric grid achieves 4.

No large timing experiment or empirical probability certification is claimed.
