# Static review of three recovered verifiers and their cut dependencies

Five exact source bodies were read completely as inert text. No supplied code was executed, imported, compiled, or syntax-parsed. All original bytes remain unchanged. These are source-package verifiers despite their filenames containing “independent”; the filename alone establishes no reviewer-execution provenance.

## Bruhat verifier: f25fae4c68038444e86a17de9cccc2cd7babb300226b6142b098af810824dd8c

All 104 lines, 3,127 bytes read. The script builds finite prime fields with n-th roots, enumerates determinant-one 2x2 matrices for n=5,7,11, checks the nonzero-b explicit chirp/permutation/Fourier kernel, enumerates all lower-upper-lower shear triples for the Fourier matrix, and compares their operator product projectively. The main calculations use exact integer modular arithmetic and deliberately do not import metaplectic_bruhat. This supports finite diagnostic identities, not all-order representation composition, projective cocycle computation, runtime improvement, or a global FFT construction. The b=0 branch is constructed but not compared to a separate formula in the enumerated-kernel assertion. The tested orders are primes; at composite n a nonzero b need not be invertible, so the branch formula is not a general composite-ring Bruhat routine.

The projective comparator peq permits its proportionality scalar to be zero. A zero A and nonzero B returns True, although projective equality conventionally requires a nonzero scalar. The generated test matrices are invertible under the stated fixtures, so this is an API/negative-control gap rather than evidence those fixtures are wrong. It also uses zip without shape validation; mismatched shapes can be silently truncated. Dense products and enumeration cost at least polynomial work in the fixture size; no linear runtime is claimed here. Primality and primitive-root search are bounded enumeration with a 9,999-candidate field limit, not a general efficient root constructor. Every equality safeguard is an assert; optimized Python removes them. Output is written to the current directory as independent_results.json, and no historical invocation receipt is inferred from that file's existence.

## Three-stage cut path verifier: f9033a9ee7235fb8c9e82651f98d8b98a9e8761fbc5da7c9b53d3e6dda713d20

All 64 lines, 2,183 bytes read. The explicit scalar dependency DAG has three stages with input/output channels and forward/backward state channels; interstage edges use the bit-reversal involution. Removed wires delete the capacity-carrying channel edge without removing incident graph vertices. BFS checks reachability from the prescribed source side to prescribed output side. Its graph construction is independent of max-flow, but its permutation, cut and source/target definitions are imported from research_gate and uniform_cut, so the artifact is not standalone independent of those definitions. Both exact local dependencies were fully read in this review.

The driver tests five sizes 32 through 512. Its two BFS calls occur inside assert expressions. Under Python optimization neither graph traversal occurs, and verify still returns disconnected=True. This is a precise false-positive acceptance path, not evidence that historical logs used optimization. Even ordinary execution supplies only finite reachability controls. The assertion that the graph overapproximates every rank-one quasiseparable realization and the all-length cut proof live in the separate mathematical certificate; this program alone does not prove them. The Fourier minor full-rank argument is not checked here. At N=32 the displayed cut count equals the target rank, so there is no rank deficit; exclusion begins when m=N/32>1. The DAG and BFS are linear-size given the permutation, but literal binary-string bit reversal and sorted cut construction carry additional word/comparison work; these are verifier costs, not an FFT algorithm.

## Two-line Weyl verifier: fee486172b1293d37c98177136a8964a2086dea601abc5c5b7c99544e01a4398

All 82 lines, 2,535 bytes read. Four odd-prime cases generate displacement matrices, chirp-weighted line sums, the scaled second line, then compare their dense matrix product to Fourier and check both ranks. The matrix conventions and exact field arithmetic are internally consistent with the documented finite controls. The tested u values have the admissible nonisotropic geometry required by the factorization. There is no enumeration over all line choices, bad isotropic cases, even orders, or composite-ring strata. Dense line construction and matrix products are cubic-scale fixture calculations and do not implement a faster transform.

The script computes factorization booleans outside the assert, but emits a literal passed=True even if the assertion is removed by optimization and a case failed. Its rank routine and multiplication use rectangular/square input assumptions without robust shape checks. The field search is finite and uses trial division, not constant-time planning. The direct source has no external algorithm imports, but this alone is not execution provenance or a universal proof. It overwrites a sibling independent_results.json when run. This review did not run it.

## Shared dependency research_gate: 6b6258fb81d3e3122ffe755e6df9b78a3704381d7f666fce92f997cdbc58a3cd

All 216 lines, 6,913 bytes read. Contains bit-reversal, dense exact matrices, separated-generator scans, modular determinant/rank/inverse, offdiagonal 2x2-minor tests, Fourier minors, valuation counts, exterior Cauchy–Binet, augmented scan matrices and three-stage composition. The forward/backward scan agrees algebraically with separated lower/upper generators. The augmented block matrix eliminates to that scan via unit triangular recurrences. The quasiseparable rank test enumerates all strictly separated 2x2 minors; it does not assert every such matrix has a single globally separated-generator chart. The explicit block2_stage control correctly calls out that distinction. Fourier's 2x2 formula has the correct exponent/sign convention.

This is a helper module without a main verifier. Its root test checks n-th order and exclusion of n/2-th order, sufficient for documented powers of two, not arbitrary n. The field is assumed prime. Shape and parameter safeguards are sparse and many are asserts; matvec and some products can truncate through zip. Bit reversal uses n binary-string conversions of length log2 n. Dense determinants/products are cubic, full minor enumeration is quartic, and the exterior compound sum is quartic per selected output minor. Counting a returned identity is not an exact machine-cost receipt. The scalar rank-one scan is linear in its supported shape, but initialization and auxiliary dense checks remain distinct. No runtime test of this helper was performed.

All 81 lines, 3,256 bytes read. The explicit domain check requires powers of two N>=32. Sets x1,f1,b1,x2 and two boundary cuts contain 3m+m+(m-1)+7m+2=12m+1 scalar channels. The Boolean forward/backward propagation correctly removes specified x and recurrent channels. Optimized Python removes the stage-equality/disconnection assertions while returning summary statistics. Sorted wire generation and string-based bit reversal should be counted in literal verifier cost. This is a certificate/control package, not a sub-NlogN FFT implementation.
