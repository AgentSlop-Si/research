# Research fusion: two working combinations and the exact worst-case gap

9 October 2026. **Yes, our methods can be fused.** This checkpoint implements
two compatible combinations and verifies gains that neither a simple selector
nor an unchanged approximate pass supplies. **The exact arbitrary-input
o(N log N) goal remains unmet.**

## 1. Exact graph composition with shared work

The prior affine graph method uses a sparse residual from one filter
L=I-lambda M, with a Fourier-conjugate weighted permutation. We now compose
filters before transforming the residual:

\[
u=L_d\cdots L_1x,\qquad
Fx=\widehat L_1^{-1}\cdots\widehat L_d^{-1}Fu.
\]

The code verifies all source rows, computes the final sparse defect's full
transform, then solves the target cycles in the correct reverse order.
Intermediate residuals may be dense. Root tables and the closure inverse
(1+lambda^N)^-1 are shared by filters with the same parameter.

For d filters, r pooled scalar parameters and s final defects, the complete
count is

\[
(1+r+6d+2s)N+r(\log_2N+2)+d.
\]

The exact finite-field witness at N=32 is fully dense. Each of the two
constituent filters individually leaves 32 defects and its one-defect fast
path rejects. Their ordered composition leaves **one defect** and succeeds.
Reversing the order leaves 32 defects. This is an actual gain from combining
noncommuting filters.

For two filters sharing one lambda and one final defect, cost is
16N+log2N+4. At N=8192, that is **131,089 field operations versus 167,936**
for the paid radix-2 comparator on the same input. This is an operation
comparison, not a measured runtime or bit-complexity result.

The graph descriptors and lambda pool are supplied parameters. Discovering
a suitable chain on arbitrary input has not been made free or solved here.
Singular filters and failed residual tests are explicitly rejected; an
all-input wrapper pays for the ordinary exact FFT fallback.

See `fft_composed_graph_fusion_research/` for the proof, implementation,
main audit and independent exhaustive review. The prior affine solver and
exact arithmetic dependency are included unchanged as code dependencies.

## 2. Exact baseline plus approximate residual

This combination uses the user's original correction idea directly:

\[
x=g+r,\qquad Fx=Fg+Fr.
\]

Choose q=gcd(N,4), let n=N/q and fit a q-periodic baseline from the fresh
input. For each component and residue class, the code compares its exact
mean with zero and uses whichever gives the smaller residual l1 mass.
If S_s is the selected integer class sum, the baseline and scaled residual
are

\[
g_j=S_{j\bmod q}/n,\qquad \rho_j=nx_j-S_{j\bmod q},\qquad r=\rho/n.
\]

The baseline transform has only q possible nonzero coefficients. Its roots
are in {1,-1,i,-i}, and the averaging scale cancels, so those coefficients
are Gaussian integers computed exactly. The residual remains integer-valued
after scaling and can use the existing packed sampler/decoder without
mixing exact-complex arithmetic with finite-word assumptions.

The result satisfies

\[
L_\Box(r)\le L_\Box(x),\qquad
\|\widetilde F x-Fx\|_\infty\le\epsilon L_\Box(r)
\]

with the existing high-probability guarantee. For unitary normalization,
divide the error by sqrt(N). All fitting, comparisons, residual construction,
table preparation, scaling and output writes retain O(N) Word-RAM cost at
fixed accuracy and the inherited bounded-input/failure assumptions.

The q quarter-root coefficients of the original input are already available
from its class sums; the code overwrites those output estimates with their
exact values. If r=0, every coefficient is exact and sampling is skipped.
On general inputs, the residual is still approximated. A conservative word
width is reported explicitly; unlimited Python integers are not assumed to
be unit-cost machine words.

At N=256 in the near-periodic test, the certified error allowance is
**3,097.2 times smaller** than the plain decoder's allowance. The observed
maximum errors in that run were 91.73 for the fusion and 279,134.58 for the
plain decoder, in unnormalized coefficient units. These are one controlled
workload and fixed-seed observations, not universal improvement factors.
For every input, the residual-based bound is no worse than the original
bound, but individual random outcomes need not always improve.

This is a control-variate construction, an established Monte Carlo idea;
no novelty is claimed for subtracting a known baseline. The new project
work is its compatible finite-integer integration, cost and error ledger,
exact corner coefficients, implementation and checks. Background:
[Glynn and Szechtman](https://web.stanford.edu/~glynn/papers/2002/GSzechtman02.html).

See `fft_control_variate_fusion_research/`. The previous packed decoder and
integer sampler are included as explicit sibling dependencies.

## 3. Why this does not yet settle exact N log N

The missing step is a universally cheap exact correction. Two precise tests
now delimit these particular fusion mechanisms:

**Sparse surrogate plus graph correction.** If y has at most k nonzero
coordinates and M is a monomial matrix, then

\[
\|(I-\lambda M)(x-y)\|_0
\ge\|(I-\lambda M)x\|_0-2k.
\]

Thus a logarithmic-size surrogate can change a one-step graph defect on
only O(log N) coordinates. An explicit quadratic chirp has at least N-1
defects for every nonzero cyclic shift and every lambda, so its corrected
defect remains at least N-1-2k. Repeated sampling also need not contract
the time-domain residual's l1 norm.

**Composed invertible graph certificates.** For a finite graph dictionary,
r free scalar parameters and s final defect values describe a rational
family of dimension at most r+s. If r+s<N, even adaptive choices of graph
sequence and support cannot cover generic complex inputs. This statement
applies to the specified certificate family; it is not a lower bound on
general Fourier algorithms. Additional independent coefficients or retained
kernel information require new decoding and cost analysis.

The approximate theorem is for fixed global additive accuracy. Tightening
it enough for an exact rounding target changes the sample count and table
costs. Integer-input DFT coefficients are generally not integers themselves.
Consequently an exact-precision bridge cannot be assumed from these results.

The next exact advance must process the missing independent information with
genuine shared work in o(N log N), rather than merely naming it a residual.
`fft_fusion_exact_gate_research/FUSION_GATE.md` gives the complete scoped
proofs and explicit witnesses.
