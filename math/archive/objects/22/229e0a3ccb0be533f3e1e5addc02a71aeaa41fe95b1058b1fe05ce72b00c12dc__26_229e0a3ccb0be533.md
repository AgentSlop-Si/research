# Phase 9 research: reuse at three graph levels

Date: 9 October 2026. The contribution is implementation, integration, correction of cost claims, and reproducible experiments. Fourier linearity, polynomial update identities, persistent trees, semigroup range queries, and materialized-view selection are established techniques. No priority claim is made for their combination.

## 1. A common algebra with explicit output scope

For circular sequences of length N, let R = K[z]/(z^N-1). A signal is an element of R; addition is coefficientwise and multiplication is circular convolution. At any valid Fourier frequency k, evaluation at the selected root is a ring homomorphism:

F(a+b)[k] = F(a)[k]+F(b)[k], and F(a*b)[k] = F(a)[k]F(b)[k].

Thus an addition/convolution expression can be evaluated on only q selected bins, preserving its expression graph. Shifting by t multiplies the selected value by omega^(kt); an impulse at t has exactly that phase. This remains an algebraic identity over appropriate exact fields; the numerical implementation approximates it.

After B immutable bases have been projected, their numeric storage is 16Bq bytes in complex128, instead of retaining length-N arrays and dense spectra. Dense acquisition still reads Omega(BN) input values. Our default cold benchmark uses native real FFT plus gather, so it pays O(BN log N). The optional supplied arbitrary-output plan has classical arithmetic O(B(N log K + qN/K)); for divisor-friendly lengths K on the order of max(1,q), this is O(BN(1+log q)). Temporary plan storage, its construction, and numerical accuracy are additional considerations. No benchmark silently substitutes this arithmetic bound for the default backend's actual cost.

FFTW documents generic pruning and the difficulty of converting arithmetic savings into wall-clock wins. The input audit's q=1 formulas should include a constant term: O(N(1+log q)), not a literal zero from log(1). The external #130 composition in the supplied v2 note remains conditional on its exact-complex model and supplied-root assumptions; it is not implemented here.

## 2. Persistent expression graph and cached frontier

Each immutable node is a basis, impulse, binary sum, binary product, scale, or shift. Hash-consing shares identical *syntactic* nodes with the same ordered children. It does not discover numerical coincidences or establish equivalence modulo distributivity. The uploaded sum-product implementation also normalizes associative/commutative operations; our balanced product version deliberately preserves edit locality.

For a query, stop graph traversal at registered bases and available cached nodes. Let A be the remaining reachable nodes and C the stopping boundary. The iterative topological evaluator costs O(|A|+|C|) graph work plus O(q|A|) numeric work, and copies q values per returned root. With multiple roots, the same reachable node is scheduled once. Child results are released after their last scheduled use, while the persistent LRU may retain them separately. A cache eviction changes A; it does not preserve a warm-query bound by assumption.

For a balanced m-factor tree with p changed factors, at depth l from the root, at most min(2^l,p) internal nodes are affected. For m=2^h,

D <= sum(l=0..h-1) min(2^l,p) = O(p(1+log(m/p))).

Proof: the first ceil(log2 p) levels form a geometric sum O(p); every later level contributes at most p. The p=m case is O(m), and p=1 is O(log m). With unchanged boundary values still cached, numeric evaluation of the replacement expressions plus ancestors is O(q(D+L)), where L counts new leaf-expression operations. Dense metadata acquisition is excluded only when the producer already supplies those operations. `replace_many` also sorts p indices and uses bisection to route them, adding O(p log p + D log(p+1)) conservative metadata work.

A general DAG does not have this tree bound: a changed node can reach essentially every output ancestor. The relevant object is the actual affected ancestor subgraph. This is a standard change-propagation principle, not a new dynamic-algorithm theorem.

## 3. Complement intervals instead of division

For a frozen chain of projected factors X_0,...,X_(m-1), let p distinct positions i_1<...<i_p be replaced by Y_i. Partition the unchanged positions into the p+1 gaps. Then

new_product = product(gap products) * product(replacement factors).

No division occurs, so the identity holds when any old Fourier bin is zero. Computing a quotient of the total product by an old factor would be invalid there.

Two classical structures implement the gap products:

* Segment tree: O(mq) preparation and numeric storage, O(q log m) per interval; O(q(p+1)log m) is a safe per-version bound, in addition to phase generation for the edits and metadata sorting.
* Disjoint sparse table: store left suffix and right prefix products at every binary split. For an interval [l,r), if it has more than one item, the highest differing bit of l and r-1 identifies the split. Exactly one suffix and one prefix cover the interval, yielding O(q) numeric work. Preparation/storage are O(mq log m); a p-replacement query costs O(q(p+1)).

Index construction is never free. For small m or many replacements, compiled `np.prod` on the projected rows can win. In the current experiments the segment-tree control beats the larger disjoint table on complete workloads. The reusable segment API pays extra validation, persistent-row copying, and dispatch overhead over that hand-specialized control. A per-version `auto` choice is a fixed conservative heuristic, not a trained optimal planner; it does not undo the cost of an index already built.

`IndexedVersion` copies only touched rows while sharing unchanged replacement arrays with its parent. Keeping V versions alive costs the base index plus their replacement metadata and unique row arrays; it is not bounded by the node LRU. Long chains of edits can accumulate many replaced rows. All speed claims specify the number p relative to the frozen base.

## 4. New Phase 8 jets are complementary

The uploaded Phase 8 provides all coefficients C_h in the finite polynomial identity F(x+u)=sum(h=0..d) C_h*u^h in R. These are Hasse coefficients, so factorial division is unnecessary and repeated occurrences of x are handled correctly. For u=delta e_t, the full-time formula is sum delta^h roll(C_h,ht). The original implementation prepares dense time kernels to answer those queries.

Our adapter imports the symbolic C_h graphs into the projected engine. Once their q-bin projections are evaluated, the prepared object retains only (d+1)q complex values plus bin indices. For k known impulse edits, build U[k_bin] as a sum of k phases and use Horner evaluation in the degree dimension. The resulting query costs O(q(k+d)) numeric work, plus edit normalization, and emits exactly q frequency values. There is no k^d term expansion and no inverse FFT. The degree bound is checked; exceeding it raises an error rather than dropping high-order terms.

The adapter's cold cost includes upstream seed registration, symbolic jet construction, and projected coefficient evaluation. It does not remove the upstream seed FFTs if those were needed to create the supplied AlgebraFFT state. Only the returned projected jet is independent of that state's lifetime. Frequency bins and time coefficients are different outputs; the adapter cannot emit arbitrary time coefficients from q<N frequency values.

## 5. Query engine v3: useful, with corrected costs

The new organizer learns temporal synchronization and spectral overlap, then groups consumers under a greedy heuristic. This is useful for sequential API calls whose eventual overlap is not supplied as a batch hint. It is a materialized-view scheduling problem, not a Fourier theorem.

Three replay loops (single view, shared view, group) originally iterated over every retained event E and skipped consumed events. A query with only H new events therefore paid O(E+qH), contradicting a pure O(qH) claim when history was retained. The fixed loops read exactly H entries from the deque's right end and reverse this short list to preserve chronological floating-point replay. Counted-iterator tests enforce that behavior independently of elapsed time.

With history available, the single-view bound including its returned copy is O(q(1+min(H,r+k))). With missing history, the code must rebuild at O(q(1+r+k)); the minimum is not valid. The shared and group cost heuristics now account for that condition.

The supplied organizer also republished every member's output on every group cache hit. The repaired organizer publishes only the requested member: a hit needs O(q_v) copying; a refresh needs O(u_G(1+min(H_G,r+k))) with valid history, plus the requested output. A later consumer gets its slice from the current group. Stale member caches can keep more history alive until capacity forces a rebuild; this is charged and tested.

Group cached-spectrum payload is bounded by a byte LRU. This excludes group index maps, basis projections, per-consumer caches, Python objects, and temporary arrays. Query histories are bounded; diagnostic partition snapshots are now bounded too. Zero group-cache budget falls back to individual views. This is a memory safety mechanism for cache retention, **not** a solution to globally budgeted optimal materialized-view selection.

The organizer can execute its greedy planner at a producer-update probe boundary. Therefore an individual wrapped producer update is not always O(1). `planning_ns` measures this work and the benchmark charges it. If planning events have costs P_j across T updates, their contribution is sum P_j/T amortized; no distribution-free small bound is asserted. Planner costs, migration copies, query-history maintenance, and group maps are separate from the Fourier arithmetic bounds.

## 6. Exactness and model boundaries

`modular_bridge.py` replays exported schedules in prime fields with a verified primitive Nth root, for exactly represented integer real scale constants. It uses an independent direct DFT and direct circular-convolution reference. Its signed integer example zero-pads digits, selects enough primes for their product to exceed the nonnegative coefficient bound, reconstructs each coefficient by CRT, and propagates carries.

This code supplies a reproducible algebraic bridge. Its DFT is O(N^2), prime search is elementary, and Python large integers have their own bit costs. It is intentionally not a high-performance NTT or a new multiplication algorithm. Numerical tests and finite modular instances do not prove a uniform floating-point error bound or a new asymptotic theorem.

Our floating products use different associations from the controls. Relative/absolute tolerances and maximum errors are reported; no claim of bitwise-identical outputs is made. Products can be ill-conditioned, overflow, or underflow; finite checks detect nonfinite results, but underflow and cancellation still require application-specific error analysis.
