# Input-independent FFT sharing: a verified research exploration

**Date:** October 9, 2026  
**Status:** Working reproducible implementations, checked identities and algorithm-cost derivations. **Not a new sub-`N log N` algorithm for arbitrary complex FFTs, and not a new integer-multiplication upper bound.**

## Research question

Can the adaptive cached FFT project be extended from *data-dependent collision reuse* to a **compact, input-independent computation network** that saves work on *every* input, including random and unrelated inputs? Can table lookup remove a growing number of recursive levels when all precomputation and memory accesses are included?

### Results at a glance

1. **Complex FFT, any input:** an input-independent split-radix arithmetic graph provably uses asymptotically **1/3 fewer nontrivial generic complex twiddle multiplications** than the baseline radix-2 graph: `(~N/3) log2 N` versus `(~N/2) log2 N`. Both still perform `N log2 N` complex additions/subtractions and take `Theta(N log N)` arithmetic time. This is a classical algorithm, not our discovery.
2. **Compact plan:** execute the same split-radix schedule from an implicit recursive template with `O(N)` precomputed twiddle constants. The explicit diagnostic graph has `Theta(N log N)` nodes; the compact plan need not store those nodes. Both are independent of input values. Test outputs agree with NumPy's DFT.
3. **Two arbitrary real FFTs:** pack `a+i*b`, use **one** compiled complex transform, and recover both spectra in `O(N)` additional arithmetic through conjugate symmetry. Combining this with split radix is correct, but remains `Theta(N log N)` for an arbitrary pair of real inputs.
4. **Tabulated Walsh-Hadamard over F3/F5:** compile **all** possible `b`-symbol transforms for small `b=2^t`, using previously compiled smaller tables. Each online pass replaces `t=log2 b` butterfly stages with table lookups and `O(N)` memory operations. The construction yields `O(N log N / log log N)` online time *and* sublinear preprocessing/extra table space if `b(N)=Theta(log N)`, over a fixed finite alphabet, in a random-access word-RAM model with `Theta(log N)`-bit words. This is related to Josh Alman's **previously established** result; the transform and cost model are distinct from arbitrary complex FFT and fixed-tape integer multiplication.
5. **Negative check:** hash-consing detected **no additional identical symbolic nodes** in the already-factored radix-2 and split-radix graphs tested. Without a different factorization, fresh arbitrary inputs cannot force exact equality of expressions supported on disjoint variable sets.

## A. Proof for complex FFT multiplication savings

Let `N=2^L`, `w=exp(-2*pi*i/N)`, and define the usual forward transform

```
X[k] = sum(j=0..N-1) x[j] * w**(j*k).
```

Split its input by residues modulo 4:

```
E  = FFT(x[0::2])   (length N/2)
O1 = FFT(x[1::4])   (length N/4)
O3 = FFT(x[3::4])   (length N/4)
```

For each `0 <= k < N/4`, define `u=w**k * O1[k]`, `v=w**(3k) * O3[k]`. The four outputs are:

```
X[k]         = E[k]       + (u + v)
X[k+N/2]     = E[k]       - (u + v)
X[k+N/4]     = E[k+N/4]   - i*(u - v)
X[k+3*N/4]   = E[k+N/4]   + i*(u - v)
```

This follows by substituting `j=2t`, `j=4t+1`, `j=4t+3` into the DFT sum. The right-angle `i` factor requires only component swaps and sign changes, not a general complex multiply.

For a **specified cost model**, count generic complex multiplications by roots of unity *excluding multiplications by* `1,-1,i,-i`, which are handled as trivial rotations. Count a complex addition or subtraction as one complex add. Let `R(N)` denote the generic-twiddle count for radix-2 and `S(N)` for split radix. For `N>=4`, with `R(1)=R(2)=S(1)=S(2)=0`:

```
R(N) = 2 R(N/2)             + (N/2 - 2)
S(N) = S(N/2) + 2 S(N/4)    + (N/2 - 2)
```

The first combines `N/2` radix-2 butterflies with two trivial twiddles. The second combines two nontrivial factors per quarter group, except for the `k=0` group. Solving these recurrences for `L=log2 N` gives:

```
R(N) = (N/2)*(L-3) + 2
S(N) = (N/3)*L - (8/9)*N + 1 - ((-1)**L)/9
```

Thus, as `N -> infinity`:

```
S(N)/R(N) -> 2/3.
```

Both graphs have exactly `N log2 N` complex additions/subtractions. On a simplistic real-operation model in which each complex add uses two real arithmetic operations and each generic complex multiply uses six, the leading coefficients are `5 N log2 N` (radix-2) and `4 N log2 N` (split radix), excluding overhead. Classic split-radix analyses exploit still more special twiddles for exact counts; more advanced algorithms including Alman–Rao further improve the constant. **The exponent remains 1.**

### Why a compact *template* matters

The full explicit DAG contains `Theta(N log N)` operations and must pay at least linear time in that size to construct. We compile it to audit actual arithmetic and reuse. The compact plan instead stores the fixed recursive formulas above (constant-size program) and precomputes at most

```
2 * (4/4 + 8/4 + 16/4 + ... + N/4) < N
```

complex twiddle values across all sizes. It therefore takes `O(N)` compilation time/space, with `O(N)` peak data/scratch (besides recursion stack) and `O(N log N)` time per execution. It does not store an expanded graph. The output values still need `N` slots.

### Two real transforms for the price of one complex transform

For real arrays `a,b`, let `z=a+i*b` and `Z=FFT(z)`. If `A=FFT(a)` and `B=FFT(b)`, linearity and Hermitian symmetry yield, at each index `k`:

```
A[k] = (Z[k] + conj(Z[-k mod N])) / 2
B[k] = (Z[k] - conj(Z[-k mod N])) / (2i)
```

The extra decoding work is `O(N)`, and the input-independent compact split-radix plan can compute the one needed complex transform. For `N=4096`, the simple radix-2 graph counts **18,434** generic twiddle multiplications *per complex FFT*, while the packed split-radix graph counts **12,744** to process both real inputs in one transform. The decoding and memory work must also be included; optimized real-input libraries already exploit related structure. This is a comparison against **two full complex FFTs**, not against best production `rfft` algorithms.

## B. Proof for finite-field Walsh–Hadamard tabulation

**Scope: different transform.** Work in `F_p`, for a fixed odd prime such as `p=3`. The Walsh–Hadamard matrix is `H_2=[[1,1],[1,-1]]`, and the length-`N=2^L` transform is `H_2^(tensor L) x` modulo `p`. The ordinary butterfly algorithm uses exactly `N log2 N` modular additions/subtractions.

Choose a block width `b=2^t`. For every one of the `p^b` possible `F_p^b` inputs, store its entire length-`b` transform in a table. Key an input `(x_0,...,x_(b-1))` by its base-`p` encoding:

```
key = x0 + p*x1 + p^2*x2 + ... + p^(b-1)*x_(b-1).
```

For example, `p=3,b=4`, the input `[1,2,0,1]` has key `1+3*2+9*0+27*1=34`; its transform can be fetched as `table[34]`.

**Shared compilation:** instead of computing each table entry from scratch, build length `b/2` tables first. Split each `b`-tuple into even/odd positions, fetch both *already stored* smaller transforms `E,O`, then fill:

```
out[2*k]   = E[k] + O[k] (mod p)
out[2*k+1] = E[k] - O[k] (mod p).
```

That uses exactly `b` modular additions/subtractions per table entry, yielding `O(b p^b)` arithmetic to construct the largest table, plus `O(b p^b)` digit unpacking and writes. Smaller table costs form a dominated sequence. Table storage is `Theta(b p^b)` field elements.

**Grouped online evaluation:** choose `t=log2 b` consecutive address bits at a time. Holding all other index bits constant creates `N/b` independent length-`b` fibers. Fetch each fiber's transform from the lookup table and write the `b` results. Each pass visits `N` input and `N` output field elements, builds keys in `O(b)` per fiber, and thus takes `O(N)` random-access operations, even if no two inputs repeat. The transform requires `ceil(L/t)` passes, giving

```
Online T(N,b) = O(N * ceil(log2 N / log2 b)).
```

If `b` remains a fixed constant (e.g., 8), this is *still* `Theta(N log N)` asymptotically, with a better constant.

For a **family of algorithms**, let `b` be the greatest power of 2 not exceeding `c log_p N`, with constant `0<c<1`. Then `b=Theta(log N)` and

```
p^b <= N^c,
preprocessing = O(b p^b) = O(N^c log N) = o(N),
storage = O(N^c log N),
log2 b = Theta(log log N),
online = O(N log N / log log N).
```

Total initial preprocessing plus the first full transform is therefore `O(N log N / log log N)` in the stipulated random-access word-RAM model. The table code fits in `O(log N)` bits and a table lookup is charged constant random-access word operations, not a free output of `b` values: all `b` returned values are explicitly copied. On a fixed-alphabet sequential-tape Turing machine, the lookup cost is not established to be constant; this proof must **not** be transferred to that model. The full fixed-field bit-operation result is known from Alman (2023); this program independently demonstrates the underlying grouping/tabulation technique.

## C. A rigorous negative result for exact symbolic deduplication

At a given radix-2 recursion depth, distinct FFT subtrees depend on disjoint sets of input coordinates. Each nonzero intermediate linear expression has a coefficient vector supported on its subtree's coordinates. Two nonzero expressions with disjoint supports cannot be identically equal as formal polynomials in independent input variables: setting one input variable to 1 and all others to 0 distinguishes them. Therefore, a value-independent *exact identity cache* cannot merge such disjoint subtrees merely because randomly sampled values sometimes collide.

This does **not** exclude optimizations through alternative factorizations, algebraic identities, linear-rank savings, fixed-field lookup tables, or input-dependent structure. It also does not assert a general FFT lower bound. The executable graph compiler has expression interning; the tested radix-2 and split-radix formulas yielded no extra equal-expression merges beyond their built-in shared intermediates.

## D. Reproducible experiments

Run from this directory:

```
python -m unittest -v
python demo.py
python benchmark.py
```

`benchmark.py` writes `benchmark_results.json`. Measurements are single-process local exploratory Python timings; they depend on CPU, interpreter, allocations and NumPy version. All FFT comparisons use **arbitrary random complex-valued inputs**, not only periodic or binary signals.

At `N=4096`, the expanded split-radix graph has 73,729 nodes (including input nodes) and an approximate Python object footprint of 7.82 MB (excluding some allocator metadata). Compile times in one run were about 60 ms versus 0.92 ms respectively. The implicit plan executed in approximately 5.2 ms, while NumPy `fft` took approximately 0.037 ms. **This prototype is not competitive with optimized native FFT software.**

### Exact tabulated transform, modulus 3

For a fixed `b=8` table, compiler output contains 6,654 entries **across all sizes 1,2,4,8** (6,561 at the largest size), 52,833 stored field elements, and 52,830 modular addition/subtraction operations to build the table. In one run preprocessing took about 0.008 seconds and the shallow Python tuple/list memory estimate was approximately 743 KB. The table is reused across queries.

### Verification

The regression suite checks: two complex FFT circuit variants against NumPy across powers of two, compact-template equality, exact algebraic operation recurrences, unrelated random real inputs packed into one complex FFT, integer product `1234*5678=7006652`, exhaustive length-4 `F3` table correctness, random WHT vectors modulo 3 and 5, the inverse-WHT identity, lookup-table reuse and asymptotic-size inequalities. `benchmark.py` repeats larger-size numerical FFT comparisons and checks WHT outputs before timing.

## E. Connection to OpenAI/CrocSwap and next falsifiable hypothesis

The OpenAI/CrocSwap integer-multiplication construction uses **rank savings in fixed linear networks** (a relation of the form `s < W*m`) to reduce the recursive cost of structured data movement on a particular fixed-tape machine. That's a more demanding invariant than simply reducing floating-point multiplications in an FFT implementation. The present arithmetic improvements cannot be plugged into their theorem without proving the required rank, scratch restoration, precision and tape-layout conditions.

A worthwhile next experiment would automatically synthesize small *input-independent* linear circuits with candidate factorizations and compute their **rank-weighted** cost, not just the number of additions. A successful candidate must have (i) an exact symbolic identity, (ii) a strictly smaller rank budget in the relevant machine model, (iii) restored scratch, and (iv) an end-to-end recurrence including layout, lookup, and write costs. Failing any one of these invalidates a sub-`N log N` integer-multiplication claim.

No general sub-`N log N` complex FFT algorithm, new positive rank-saving network for CrocSwap, or novel integer-multiplication exponent was established here.
