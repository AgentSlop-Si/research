# Experimental results (October 9, 2026)

These checks **do not** establish a new exact FFT speed bound. They test a new-to-this-project *grouped-stage template* for bounded-precision approximation, plus Monte Carlo sampling/pruning as a stronger approximate comparator.

## 1. Exact modular stage-factor identity

Running `python exact_group_audit.py` yielded:

- PASS: 119 random-vector configurations of `(N,s,t)`.
- PASS: 700 basis-vector configurations for complete finite-field input maps.
- Modulus `998244353`; no floating-point acceptance in this audit.

## 2. Full toy tables (all keys physically materialized)

- K=2, component grid `R=4`: 9^4=6,561 lookup rows, 13,122 complex output values.
- K=4, component grid `R=1`: 3^8=6,561 lookup rows, 26,244 complex output values.
- Each checked lookup matched independent normalized small DFT quantization.

These tiny grid precisions are NOT suitable for accurate large FFTs. Tables at useful accuracy are astronomically larger.

## 3. Higher-precision lazy emulation — negative caching result

For one high-entropy complex-valued length-4096 input, `K=4`, `R=256`:

- 6,144 grouped block calls over 6 grouped passes.
- **Zero** repeated table keys during that run, so 6,144 cache misses.
- max observed error in approximating `FFT(x)/N`: about 0.0058.

This validates rounding/algebra but is **not** evidence of faster lookup. The lazy code computes the missing small transform on every cache miss. A *complete* table of all possible grid states would contain `513^8` entries, far beyond practical memory.

## 4. Sampled/pruned approximate full DFT

For one fixed length-4096 pure tone, epsilon 0.3, eta 0.01, 636 samples were chosen by the proved formula. Across 40 different sampling seeds, observed failures: 0; worst maximum frequency error: approximately 0.1535. This is a finite test, not a replacement for the Hoeffding proof.

For a separate pure-tone test at epsilon 0.5, eta 0.01:

| N | Samples | Visited/pruned butterflies divided by ordinary radix-2 butterflies | Observed max abs error |
|---:|---:|---:|---:|
| 4,096 | 229 | 0.7526 | 0.1894 |
| 16,384 | 252 | 0.6630 | 0.1962 |
| 65,536 | 274 | 0.5912 | 0.2417 |
| 262,144 | 296 | 0.5287 | 0.2088 |

This scaling is for **arithmetic work and approximate outputs**, not claimed wall-clock superiority to SciPy. The returned estimate is not the exact Fourier transform.

## 5. Asymptotic accounting — table sizes are enormous

With error epsilon .05, conservative grid R about `8 (log2 N+1)/epsilon`, and table address-space budget `N^0.5`:

| log2 N | Maximum admitted K by cost model | Ordinary stages | Grouped passes | log2(table entries) |
|---:|---:|---:|---:|---:|
| 20 | 1 (no viable >1 group) | 20 | 20 | 0 |
| 256 | 2 | 256 | 256 | 65.3 |
| 1,024 | 8 | 1,024 | 342 | 293.2 |
| 8,192 | 64 | 8,192 | 1,366 | 2,729.2 |
| 65,536 | 512 | 65,536 | 7,282 | 24,905.7 |

These latter `N=2^L` sizes are astronomical. A table of `2^2729` entries is "sublinear in N=2^8192" in an asymptotic sense but is not buildable on any practical hardware. This is why the construction is a model-dependent existence/diagnostic result, not an engineering improvement.

## Scope statement

No new exact uniform `O(N)` algorithm was found. Polynomial-space complete block tabulation cannot reach linear *online* time inside the tested grouped-stage architecture. Monte Carlo sampling/pruning improves the arithmetic growth rate only after accepting additive error on **normalized** DFT outputs and randomized failure probability. The combination and its analyses rely on established techniques; no priority claim is made.
