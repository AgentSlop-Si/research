# Phase37 curvature source: complete static review

All five assigned exact-hash Python programs, totaling 23,118 bytes, were read completely as inert text. No uploaded code was executed or imported. The source implements finite-field projective-curvature diagnostics, a fixed two-mask Green pencil, polynomial Bézout certificates and small characteristic-zero controls. Earlier independent mathematical acceptance and regenerated certificates retain their separate evidence.

## Concrete findings

1. **Zero inversion is silently defined as zero.** `invert(x)` returns `pow(x,P-2,P)` without rejecting x=0 mod P. Thus `cycle_green` with alpha=1 returns a zero matrix even though I−P_cycle is singular and no inverse exists. For compatible zero-sum vectors the online recurrence can even satisfy its final wrap assertion while computing one particular solution rather than an inverse. `gaussian` and `ratio` inherit the same zero-denominator behavior. This is a genuine missing guard for arbitrary API parameters. The separately audited fixed primes, sizes and nonresonant parameters are not invalidated by this API defect.

2. **The large-size application-control flag overstates the executed check.** `two_mask_gate` computes a random-vector application at every N, but only compares it to basis-column assembly for N<=32 (lines389–395). At N=64 and128 no alternative output is computed or compared, despite `exact_application_control=True` at line403 and a comment suggesting a larger-size subset check. For small sizes that control still uses the same apply implementation to construct its dense columns; it checks consistency/linearity, not independent agreement with the declared Green matrix. Separate earlier independent controls are not supplied by this flag.

3. **Cycle generation does not terminate for N<4.** `seeded_cycles` insists on six distinct directed Hamiltonian orders with canonical start zero. Only (N−1)! such orders exist. At N=1,2,3 this loop cannot finish. Intended tests begin at4, but the constructor lacks this precondition check. At larger N it is randomized rejection, not a deterministic bounded-attempt setup guarantee.

4. **Saved verification defaults to polynomial identity checking, not family reconstruction.** `verify_certificates.verify(False)` checks full array lengths, nonzero leading entries, Bézout/GCD and matching N/prime metadata. It does not reconstruct the advertised Green family or plaquette polynomials. That is explicitly optional through `--regenerate`. An empty certificate index returns0 without establishing the expected twelve cases. The returned count must be compared to an independently pinned case list. An arbitrary pair f=X^(2N), h=X^(2N)+1, u=−1, v=1 satisfies the default algebraic checks but says nothing about the claimed Green pencil; correct-looking metadata alone cannot bind it. This is an evidence boundary, not a contradiction to the purpose of an optional algebra-only mode.

5. **Field and state contracts are incomplete at API boundaries.** `set_field` verifies a square root of minus one, not primality, a primitive generator or the exact order of every required root. `root` verifies dyadic length and divisibility, but trusts the generator. CLI restricts the two known fields; arbitrary direct calls do not inherit their validity. Stored circuit closures use mutable module-global P while retaining constants from construction, so switching the field invalidates an earlier plan. Cycle permutation and vector-shape checks are also absent.

6. **The legacy pair gate needs its lifting hypothesis.** `all_lambda_gate` searches for coprime reduced plaquette polynomials without requiring the complete 2N degrees or recording their characteristic-zero leading terms. Modular coprimality alone cannot justify characteristic-zero coprimality when reduction drops a common factor to a constant. For instance (pX−1)(X+1) and (pX−1)(X+2) reduce to coprime linear polynomials modulo p although they share pX−1 in characteristic zero. The main `two_mask_gate` explicitly selects full-degree polynomials and its producer/earlier proof supplies the correct guarded route. The old helper's general docstring must retain the lifting assumptions rather than inherit them from the new helper.

7. **Assertions and runtime costs remain explicit.** All verification assertions vanish under Python optimization. The source's online cycle solve regenerates powers and performs a Fermat inversion on every call, costing O(N+log P) field multiplications, not merely O(N) uniformly in an unrestricted prime parameter. Fixed documented P or a suitably bounded prime keeps the advertised field-operation order. Dense reference assembly, polynomial schoolbook arithmetic and certificate searches are offline superlinear work. Bit-packed GF(2) rows are Python big integers; their operations are not constant-time independent of N.

## Algebra and full source inspection

The nonsingular cycle Green formula and two-pass recurrence agree with the successor-order convention. Parity curvature tests every anchored ratio for membership in the Nth roots before extracting its sign under exponent N/2; this is valid for the stated even-order field subgroup. GF(2) elimination is ordinary highest-pivot XOR reduction. Random anchors can repeat and do not constitute an all-anchor theorem; the all-anchor conclusion depends on the separate proof.

The polynomial routines use ascending coefficients, exact modular schoolbook products, long division and Euclid on canonical nonempty arrays. `verify_bezout` assumes a constant nonzero gcd and then verifies the complete identity. Its normalization by r0[0] is correct under that premise but not a general gcd-normalizing interface. Functions are not hardened against negative exponents, empty polynomial arrays, noncanonical residues, zero divisors or malformed inputs.

The two-mask composition applies the right outer Green sum, the right diagonal, the middle two-term sum, the left diagonal and the left outer sum in the declared order. The column generator shares only the right-stage column and reconstructs the two middle branches consistently. Every plaquette polynomial is numerator^N−denominator^N and has degree at most2N. Its vanishing is necessary for monomial Fourier equivalence on the nonzero support locus. Coprime plaquettes rule out that fixed pencil under a valid characteristic-zero specialization; they do not exclude different cycle choices, masks, coefficients, deeper stages or all FFT algorithms.

`charzero_control.py` separately uses exact Q(i) SymPy matrices and characteristic-zero polynomial gcd for N4 or8, with only selected rows and columns. It imports the same seeded-cycle generator, so it is arithmetically separate but not independent family provenance. No SymPy execution was performed in this review. `make_certificates.py` intends twelve cases from six sizes and two primes and explicitly checks full degrees and Bézout identities. The unittest file includes finite-field shape controls, planted positive cases, online linearity and a Q(i) N4 check. Source test names and historical logs are not fresh execution receipts.
