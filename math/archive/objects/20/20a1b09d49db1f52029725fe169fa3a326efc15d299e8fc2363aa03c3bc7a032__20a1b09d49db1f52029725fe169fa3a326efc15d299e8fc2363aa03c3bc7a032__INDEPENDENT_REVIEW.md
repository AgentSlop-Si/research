# Independent review: exact recovery and structured integer products

**Result: PASS after one input-iterator fix.** Reviewed `structured_integer.py`,
`error_budget.py`, the README proofs, the author audit, and the sampler contract
in `research_inputs/surrogate_corrected/DERIVATION.md`. The exact paths support
the stated restricted structured-input result. They do not improve arbitrary
integer multiplication or establish a general sub-N-log-N FFT.

## Exact direct product and carries

For a repeated digit k, the implementation computes

    k B (beta^ell - 1)/(beta - 1)

by single-digit multiplication, a shift, subtraction, and exact single-digit
division. The numerator is nonnegative and divisible by beta-1. Long division
keeps remainder below beta-1, so its next numerator is below beta squared and
every output digit is canonical. Base two, where the divisor is one, is valid.
Multiplication keeps its carry below beta, and addition/subtraction use bounded
carry/borrow. No hidden whole-operand multiplication occurs in these kernels.

For the baseline-plus-exceptions path, applying negative exceptions in index
order is safe. At every stage the represented left operand has either its
original baseline digit or its already substituted nonnegative target digit
at each position. It therefore remains nonnegative; multiplication by the
nonnegative right operand preserves this. Carries can cross an arbitrarily
long digit run without invalidating this argument. Positive and negative
exceptions both receive explicit shifted single-digit products and full carry
passes. The other paths sum nonnegative constant-run or sparse-digit products.

The majority-candidate scan is only a candidate generator; correctness does
not depend on that candidate being a mode or a majority. The explicit exception
list reconstructs every input digit. Comparing three decompositions in both
orientations is valid, with a deterministic structural-term cap and an explicit
decline on unsupported inputs. Leading zero input digits are trimmed for the
canonical integer product. The separate convolution function preserves the
requested full coefficient length, including leading zero coefficients.

For convolution, each run contributes a prefix-sum window, and signed sparse
exceptions contribute shifted copies. The windows' clipped endpoints and
output positions are correct. One prefix table is shared by all run terms.

## Cost scope

The direct integer path uses O(s(n+m)) digit-kernel work for s selected
structural terms, including bounded carries. Input validation, candidate
discovery, shifts, copies, and output materialization are also executed and
remain within this bound plus the initial O(n+m) scan. Fixed radix and fixed
term cap therefore give linear arithmetic digit work on this restricted input
family. The counters are logical categories, not an exhaustive interpreter
instruction count; index words require O(log(n+m)) bits.

The convolution coefficients and prefix sums are wider than digits. Its stated
linear arithmetic/word count for fixed structure is not a constant-bit-width
claim. The README's separation of these two representations is necessary.
No timing superiority over a tuned native multiplication library is established
by the Python operation counts.

## Conditional approximate-to-exact bound

With the unitary DFT, ordinary convolution has the factor sqrt(N) before the
inverse transform. Expanding the two forward errors and applying the 2-norm
bound yields the README's three terms

    epsilon_a La B2 + epsilon_b Lb A2 + epsilon_a epsilon_b La Lb.

The approximate inverse adds epsilon_i times the l1 norm of its actual input.
Cauchy-Schwarz bounds that norm by
`(A2+epsilon_a La)(B2+epsilon_b Lb)`. The integer ceiling norms used by the code
increase this bound, so the rational certificate is conservative. A separately
certified numerical-error allowance is still needed; the helper itself does
not certify an FFT implementation or a Monte-Carlo success event. Strict error
less than one half is essential and is implemented correctly.

For a nonzero integer other operand, certification implies
`epsilon_a La B2 < 1/2`. Every nonempty integer residual tail has l1 mass at
least its support and at least one. Thus the stated head-only cutoff is
impossible for such a tail, and the current sampler's requested sample count
exceeds its support. Its exact-input bypass follows. This rules out this
particular sufficient-certificate bridge to an exact sparse surrogate; it is
not a lower bound on all approximation or exact-recovery algorithms. The
zero-error limiting case is already exact, rather than a division by zero
case for the sampling formula.

## Fixed review finding and focused checks

Originally `convolution_rounding_bound` consumed iterator inputs during
validation and then reused the exhausted iterators. For two `iter([255,255])`
operands with unit forward allowances, it incorrectly reported zero norms and
a safe zero bound; the corresponding lists correctly give bound 628320. The
helper now materializes each input once before validation and all norm work.
Empty generators are consequently rejected as intended.

`independent_review_checks.py` now passes eight exact product comparisons and
eight independent coefficient convolutions covering every selected path,
negative corrections, both orientations, base-two division, leading zeros,
and zero operands. It also checks iterator/list equivalence, two empty-generator
rejections, three strict rounding thresholds, and two negative closed-interval
controls. `independent_review_checks.json` records the final source hashes.

After this targeted fix, the author audit was rerun and passes 154 accepted
exact products, one decline, 151 full convolutions, and five rational-budget
cases, including products through 4096 digits. No old benchmark was rerun.
