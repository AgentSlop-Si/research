# Phase 8: Canonical Sum–Product FFT Engine

**Status: working numerical research implementation; not a new universal FFT or integer-multiplication complexity result.**

This continues the Phase 5–7 adaptive FFT project. Phase 8 adds **sums of convolution products**, canonical sharing across branches, exact algebraic Taylor-jet updates for repeated appearances of one input, symbolically detected sparse correction kernels, and import of already computed Phase-7 FFTs.

## Quick example

```python
import numpy as np
from algebra_fft import AlgebraFFT

N = 65536
rng = np.random.default_rng(1)
engine = AlgebraFFT(N)
a, b, c = [engine.signal(rng.normal(size=N)/np.sqrt(N)) for _ in range(3)]

# Circular convolution uses * conceptually; engine.mul is convolution.
root = engine.add(engine.mul(a, b), engine.mul(a, a), engine.mul(b, c))

# Compile exactly the coefficients in F(a + delta e_t).
plan = engine.plan_updates(root, a, expected_versions=64, max_degree=3)

full = plan.single(position=100, delta=0.05)        # All N outputs
few = plan.single(position=100, delta=0.05, indices=[0, 5, 19])
print(plan.mode, full.shape, few)
```

`expected_versions` is an expectation, not a guarantee. The dispatcher uses a conservative threshold and memory guard; it does **not** claim optimal hardware calibration. Set `expected_versions=1` for a safe re-evaluation path.

## Design

- `signal`: registers real float64 input and caches its rFFT. Inputs are defensively copied and made immutable.
- `add`, `mul`, `scale`, `impulse`: construct expressions over **length-N circular convolution**. Addition and multiplication are associative/commutative in the graph's canonicalization. Nodes share identical symbolic subexpressions, but **distributive equality is not generally canonicalized**.
- `factor_common`: an optional conservative factoring pass; e.g. `A*B + A*C -> A*(B+C)`.
- `degree_in`: compute the algebraic degree of a chosen leaf in a root expression, including repeated uses.
- `symbolic_jets`: construct the coefficient circuits of a change in one input leaf without expanding the entire original expression.
- `prepare`: compute Taylor coefficient convolution kernels up to a configurable degree. Recognize mathematically sparse impulse kernels **symbolically** (no heuristic numerical zero decisions), skipping their inverse FFT and dense time-domain storage.
- `single`, `many`: produce exact *algebraic* polynomial updates, with floating-point numerical execution. For large edit sets, `many` switches to one frequency-domain evaluation and inverse FFT to avoid enumerating all mixed terms.
- `single_frequency`: evaluate a selected Fourier coefficient without generating a full edited output.
- `frequency`: compute one frequency bin directly through the unique reachable DAG nodes.
- `replace`, `edit_version`: persistent expression rewrites that share unchanged subexpressions. Unlike Phase 7's balanced product tree, the canonical n-ary product key can cost O(m) to rebuild for an m-factor expression; no O(log m) mutation claim is made here.
- `plan_updates`: fallback if degree, estimated preparation memory, or expected reuse make jets inappropriate. Memory estimates are conservative heuristics, **not process-level allocation limits**. A strict LRU byte limit applies only to cached graph spectra; immutable seed arrays and prepared jets have separate memory costs.
- `import_phase7`: consume trusted Phase-7 chain versions using immutable seed spectra, shifted bases and sparse edits. Avoids additional base FFTs, while explicitly copying imported data for immutability.

## Mathematical identity

Let `*` denote circular convolution of length N, `e_t` be the unit impulse at t, and `F(x)` a polynomial expression in x assembled from additions and convolutions. In the ring R^N with cyclic convolution, its exact polynomial expansion is

`F(x+u) = sum_{h=0}^d C_h * u^{*h}`

where `u^{*0}=e_0`. For one known edit `u=delta*e_t`, powers satisfy `(delta*e_t)^{*h}=delta^h*e_{(h*t) mod N}`, hence

`F(x+delta e_t)[q] = sum_{h=0}^d delta^h * C_h[(q-h*t) mod N]`.

This gives O(dN) arithmetic to materialize the full updated output and O(dQ) to return Q chosen output coefficients **after** preparing the kernels. A full fresh arbitrary input does not benefit from this bound without the cached expression and known relationship metadata.

For k edits, the exact update includes cross terms. The engine either expands the at most `sum(k**h for h=1..d)` shifted impulse contributions (aggregating shared shifts) or computes the correction spectrum and performs one inverse transform.

The algorithm is a specialized application of *truncated Taylor polynomial/jet arithmetic* to a convolution circuit. Neither jets, automatic differentiation, algebraic factoring, nor dynamic convolution are claimed as new discoveries.

## Benchmarks and limitations

`benchmark.py` compares three cold-start paths on the **same related-version workloads**: (1) SciPy recomputation of only the modified input transform with unchanged kernels pretransformed; (2) the Phase-8 graph + jet preparation; and (3) a hand-specialized mathematical update formula. All paths generate the same outputs (full or the same selected bins) and charge initial FFTs/preparation. Values in `benchmark_results.json` are noisy local median timings, not universal speedups.

The hand-specialized code is usually faster than the general Phase-8 dispatcher. Also, tests use real double precision, not formally certified numerical error or exact bit arithmetic. Extremely long convolution chains may have numerical overflow/underflow. This work does not implement OpenAI #130's unrestricted-exact circuit, improve the #130 exponent, or produce a new integer-multiplication upper bound.
