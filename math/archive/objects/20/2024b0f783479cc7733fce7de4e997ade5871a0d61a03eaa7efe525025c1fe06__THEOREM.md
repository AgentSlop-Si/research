# Hero #1 Phase 24 — Deferred radix-2 Fourier graph and Green-conjugated probes

**Date:** 2026-10-10. **Scope:** exact finite-field computation for dyadic lengths, with a certified sparse-rational fast path and a native FFT fallback. **Not** an unrestricted sub-`N log N` FFT algorithm. The butterfly DAG, DIF recursion and pruned transforms are standard ideas; the result presented here is a project-specific, end-to-end construction with the Phase 23 Green certificate, a no-recomputation completion guarantee, and complete field-arithmetic/scratch accounting. No claim of historical priority.

## Field and transform

Let `N=2^L>=16`, let `p` be prime with `N|(p-1)`, and let `omega` be a supplied primitive `N`th root of unity in `F_p`. Define the unnormalized DFT `Y_k=sum_{j=0}^{N-1} x_j omega^(jk)`. All field results below are exact; root preparation, modular arithmetic bit costs and Python object operations are outside the field-add/multiply ledger and are discussed separately.

For even `n=2h`, with root `omega_n`, form

```
A_j=x_j+x_(j+h)
B_j=(x_j-x_(j+h))*omega_n^j       (0<=j<h).
```

The **DIF identities** are `Y_(2k)=DFT_h(A)_k`, and `Y_(2k+1)=DFT_h(B)_k`. Their proof is an immediate split of `j` and `j+h` in the Fourier sum; `omega_n^h=-1`, and `omega_h=omega_n^2`.

Each full DIF butterfly uses **two field additions/subtractions and one field multiplication**. The following design computes the Fourier outputs on a requested set `Q` without repeating any of these primitive operations if a later full transform is required.

## Theorem 1: deferred sibling execution and exact no-recomputation completion

At each active recursion node of size `n=2h`:

- If both even and odd output branches contain queries, execute the full butterfly and recurse into both children.
- If only the even branch is queried, save the original first half (`h` field elements), execute only the `h` additions producing `A`, and recurse into `A`. The untouched second half still holds the original `v` values. If needed later, generate `B=(u_saved-v)*omega_n^j` using exactly the **one subtraction and one multiplication** missing from each full butterfly.
- If only the odd branch is queried, save the original second half, execute only the `h` subtractions and `h` multiplications producing `B`, and recurse into `B`. If needed later, generate `A=u+v_saved` using the **one addition** missing from each full butterfly.
- A node receiving no query is left entirely untouched, to be computed only if the full transform is later requested.

Inductively all requested outputs are correct, because every visited child's inputs equal the corresponding ordinary DIF child. On eventual completion, each full butterfly contributes exactly two additions and one multiplication, split between the preview and later completion if necessary. No primitive arithmetic operation is repeated.

Consequently, for *every* query set and *every* input `x`, after `full()` the total DIF counts are **exactly**

```
field multiplications  = (N/2)*log2(N)
field additions         = N*log2(N)
field arithmetic total  = (3N/2)*log2(N).
```

This is an equality **in this particular radix-2 DAG**, not a lower bound on arbitrary Fourier algorithms. Test code compares the complete transform against a separately implemented direct DFT and checks both arithmetic counts exactly.

## Theorem 2: exact linear scratch requirement for this implementation

For any **nonempty** fixed set `Q` of `q` distinct requested Fourier frequencies, the preview stores exactly `N-q` backup field elements at its peak.

Proof: consider the binary frequency-decision tree whose paths are the low-to-high bits of each Fourier index. At every active node with one inactive sibling, the implementation copies one original field element for each leaf of the inactive sibling. These inactive siblings are pairwise disjoint, and together partition all `N-q` unqueried Fourier leaves. At a node with both children active there is no backup. Each backup remains live until full completion. Thus the total number of saved elements is exactly `N-q`.

The working storage is `N` mutable data elements plus at most `N-q` backups, plus at most `N-1` node-state flags. The shared `N`-entry root table is separate. This is **`O(N)` words**, but not negligible or free: memory copies and accesses are separately reported in the code. The `N-q` count is not claimed as an optimal memory lower bound for other architectures.

## Theorem 3: Green-conjugated input-side probes

Retain the project operator identity `L F_N=F_N P` with `L=diag(a+c omega^k)+b S`, where `(S Y)_k=Y_(k-1 mod N)`. Let `r=P x` and `Y=F_N x`. Then the needed residual Fourier samples are

```
R_k=(F_N r)_k=(a+c*omega^k)*Y_k + b*Y_(k-1 mod N).
```

Therefore the `m=2s+2` residual probes used by Phase 23 can be obtained by requesting **`m+1` frequencies of `F_N x`**: `0,...,m-1` and `N-1`. Exactly `2m` multiplications and `m` additions form the probe values once these outputs are available. The residual `r=P x` need not be evaluated until a candidate requires a full cyclic certificate.

The unchanged Phase 23 solver accepts a candidate only after verifying its complete input-side relation on **all N entries**, plus invertibility of the reconstructed spectral denominator. Otherwise the engine finishes the *same* input-side DIF graph, returning `F_N x`. Thus correctness on arbitrary inputs requires neither a successful structural fit nor uniqueness from the short probes.

On the common early-rejection branch, there is **no call to `P.apply` or `L.solve`**. The Fourier arithmetic performed across preview and fallback is identical to native radix-2, plus the parameter-search arithmetic and `3m` Green probe operations. In harder fallback cases, an unsuccessful full certificate may incur an additional `O_s(N)` charge to materialize `P x`, without repeating any FFT butterflies.

## Theorem 4: exact ten-probe operation formula

For `s=4` and any dyadic `N>=16`, set `Q={0,...,9,N-1}` (`q=11`). Classify active nodes at depth `ell`:

- Depths `ell=0,1,2`: every active node requires both children. Total cost over these depths is `9N/2` field operations.
- Depth `ell=3`: three nodes require both children and five require only the even child. Cost `(3*3+5)*N/16=7N/8`.
- All remaining depths `ell>=4`: ten nodes require only even children and one requires only an odd child. Cost `sum_(ell=4)^(L-1) (10+2)*N/2^(ell+1)=3N/4-12`.

Hence the exact preview cost is

```
C_deferred_preview = 49*N/8 - 12.
```

For comparison, eagerly computing both sides of every activated node costs `3*(43*N/16-11)=129*N/16-33`, while Phase 23's sequential ten-probe generator costs `19*N` field operations on `r`.

Including the `3m=30` operations used to convert x-probes into residual probes gives a complete *preview* saving relative to the Phase 23 stream of

```
19*N - (49*N/8-12+30) = 103*N/8 - 18.
```

For a certified candidate following the same Phase 23 structural path, all subsequent compiler, residual-generation, certificate, decoder and Green costs are unchanged. Thus the **end-to-end** saving from Phase 23 on this branch is exactly `103N/8-18`, checked for `N=64,128,256,1024,4096,32768`. On generic fallback the costs differ more substantially because the native input-side FFT replaces a repeated Bluestein forcing FFT, and the residual/Green solve are usually omitted.

## Theorem 5: the structured family cannot cover generic inputs

For fixed support budget `s<N-1`, suppose the certified relation is

```
A(S)r=(I-alpha*S^delta)e_0,
```

where `A` has at most `s` nonzero coefficients, `alpha!=0`, `1<=delta<N`, and `A(S)` and `P` are invertible. For each chosen support, each of its nonzero coefficients, `alpha`, and `delta`, there is at most one input `x`, since

```
x=P^(-1)A(S)^(-1)(e_0-alpha*e_delta).
```

Thus over `F_p` the size of this family is bounded by

```
(N-1)*(p-1)*sum_(t=1)^s binom(N,t)*(p-1)^t.
```

Dividing by `p^N` gives a rigorous upper bound on its probability under uniformly random input. For fixed `s`, the bound becomes extremely small as `N` grows in compatible fields. Over `C`, the corresponding finite union of parameterized algebraic families has complex dimension at most `s+1`, so it is a proper measure-zero subset when `N>s+1`. This is a restriction **only** on the present sparse-rational Green family, not a general FFT lower bound.

## Limits and external prior art

1. No exact arbitrary-input sub-`N log N` algorithm is proved. The fallback is still a complete ordinary radix-2 FFT. Native radix-2 beats the Phase 24 structured branch on every size in our tested range; the Phase 23 Bluestein baseline obscured this comparison.
2. The result requires a primitive dyadic root over a compatible finite field, supplied together with a root table. Root-table construction can be charged `N-1` field multiplications; the sample operation-count comparisons hold the table fixed for every algorithm. Field operations are **not** bounded bit-time as `N` grows because a compatible prime must grow as well.
3. The exact `N-q` backup bound trades arithmetic savings for about one additional `N`-word scratch bank. Python allocation, modulo reduction, bit-index arithmetic and dictionary overhead are not counted in the reported field arithmetic; this is not a wall-clock speedup claim.
4. Over the complex numbers, known restricted-model lower bounds apply: Morgenstern (1973) proves an `Omega(N log N)` bound with bounded coefficients, and Ailon (2014) establishes an `Omega(R^-1 N log N)` bound under a uniformly well-conditioned computation model. Those known results do not establish a general Fourier lower bound across all computational models.

Sources: [Morgenstern, JACM 1973](https://doi.org/10.1145/321752.321761); [Ailon, 2014, arXiv:1403.1307](https://arxiv.org/abs/1403.1307). In-place DIF and pruning are classical algorithms; no priority claim for the scheduling primitives.
