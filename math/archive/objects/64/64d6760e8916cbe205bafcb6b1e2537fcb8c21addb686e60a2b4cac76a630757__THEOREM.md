# Hero #1 — Phase 27: CRT-15 all-input Fourier circuit and cross-ratio gate

**Date:** October 10, 2026. **Status:** exact finite-field circuit, full-basis checks and explicit cost identities. **Not** a new `o(N log N)` result, `O(N)` result, optimal circuit, floating-point algorithm, or historical priority claim.

## 1. The underlying computation model

Take a prime `p`, a length `N=15G`, `G=2^t`, satisfying `N | (p−1)`, and an element `omega` of multiplicative order exactly `N`. The unnormalized DFT is

\[
(F_N x)_k=\sum_{j=0}^{N-1} \omega^{jk}x_j.
\]

Each addition/subtraction costs one field operation; each nonidentity multiplication by a fixed field scalar costs one. In particular, multiplication by a square root of `-1` is **not** declared free. Data field arithmetic is counted separately from cold scalar preparation, integer indexing, word traffic and modular-bit cost. The exact implementations over `F_2013265921` and `F_754974721` have independent roots of the requested orders.

## 2. Fully expanded 15-point codelet

A length-3 transform is evaluated in **6 additions + 2 scalar multiplications** using the prepared coefficients `(omega3+omega3²)/2` and `(omega3−omega3²)/2`.

For a length-5 DFT with primitive root `z`, prepare

\[
 c_1=(z+z^4)/2,\quad c_2=(z^2+z^3)/2,\quad
 h_1=(z-z^4)/2,\quad h_2=(z^2-z^3)/2,\\
 c_a=(c_1+c_2)/2,\qquad c_d=(c_1-c_2)/2.
\]

For `x=(x0,...,x4)`, use

\[
\begin{array}{ll}
 s_1=x_1+x_4, & s_2=x_2+x_3,\\
 d_1=x_1-x_4, & d_2=x_2-x_3,\\
 s=s_1+s_2, & t=s_1-s_2,\\
 m=x_0+c_a s, & v=c_d t,\\
 e_1=m+v, & e_2=m-v,\\
 f=d_1+d_2, & k_1=h_1f,\\
 k_2=(h_2-h_1)d_2, & k_3=(h_1+h_2)d_1,\\
 o_1=k_1+k_2, & o_2=k_3-k_1.
\end{array}
\]

The outputs are `y0=x0+s`, `y1=e1+o1`, `y4=e1−o1`, `y2=e2+o2`, `y3=e2−o2`. This is exactly **17 additions + 5 field multiplications** with the constant coefficients prepared once per plan. The three-multiply odd-part identity is a standard Winograd/Gauss reduction and is **not new**.

Use the Good–Thomas `(3,5)` permutation to calculate five 3-point DFTs and three 5-point DFTs. Its complete data-arithmetic cost is

\[
\boxed{C_{15}=5(6+2)+3(17+5)=106}
\]

consisting of exactly **81 additions and 25 scalar multiplications**. The corresponding conventional `(3,5)` Cooley–Tukey composition with these same short codelets requires eight additional nonidentity cross twiddles, or **114** data-field operations. Both actual kernels are present in `crt15_engine.py`, and every output is cross-checked.

## 3. Coprime Good–Thomas factorization and charged savings

Let `A,B` be coprime and `N=AB`. Define the CRT idempotent representatives

\[
 e_A=B(B^{-1}\!\pmod A),\qquad
 e_B=A(A^{-1}\!\pmod B).
\]

Index the input and output by

\[
 j=e_Au+e_Bv\pmod N,\qquad
 k=Br+As\pmod N,
\]

where `u,r` range over `A` indices and `v,s` over `B` indices. Since `e_A ≡ 1 (mod A)` and `e_A ≡ 0 (mod B)` (and conversely for `e_B`),

\[
\boxed{\omega^{jk}=(\omega^B)^{ur}(\omega^A)^{vs}.}
\]

Therefore the length-`N` DFT equals `B` length-`A` DFTs followed by `A` length-`B` DFTs, with **no data-dependent twiddle multiplications** between them. Only permutations are required. By contrast, the canonical Cooley–Tukey decomposition with input `j=u+Av` and output `k=q+Br` contains the cross coefficient `omega^(uq)` and thus `(A−1)(B−1)` nonidentity cross multiplications. None of these factors is one: `0<uq<AB` for the relevant `u,q`.

With `A=15`, `B=G=2^t`, the same length-`G` dyadic transform and the same `15`-point codelet are used on both sides. The external CRT step saves exactly `14(G−1)` field multiplications. A second CRT step *inside* each of the `G` length-15 codelets saves another `8G` multiplications relative to the fully conventional `(3,5)` inner composition.

Let `t=log2 G`. An optimized radix-2 DIF transform of length `G` uses

\[
 A_2(G)=Gt,\qquad M_2(G)=\frac{Gt}{2}-G+1.
\]

The resulting length-`15G` computation, valid for **every input**, uses

\[
\boxed{
A_{GT15}(N)=15Gt+81G,\quad
M_{GT15}(N)=\frac{15Gt}{2}+10G+15,
}
\]

and hence

\[
\boxed{C_{GT15}(N)=\frac{45}{2}Gt+91G+15.}
\]

Against the **specific fully conventional nested Cooley–Tukey comparator**, the exact data-field saving is

\[
\boxed{C_{CT}(N)-C_{GT15}(N)=22G-14.}
\]

There is no claim this comparator is the globally optimal mixed-radix FFT. The saving is `Theta(N)` for this class of lengths; the total work on both sides remains `Theta(N log N)` as `G→∞`.

## 4. Exact impossibility of twiddle-free *monomial* equivalence for noncoprime splits

This is an elementary project-specific diagnostic, **not** a universal FFT lower bound.

**Proposition.** Over a field containing a primitive `AB`-th root `omega`, the matrix `F_AB(omega)` can be converted to a tensor product `F_A(zeta_A) ⊗ F_B(zeta_B)` using **only row/column permutations and nonzero row/column scalings** if and only if `gcd(A,B)=1` (where the tensor factors use primitive roots of orders `A,B`).

*Proof of sufficiency.* The CRT permutation identity in §3 explicitly constructs the conversion when `gcd(A,B)=1`.

*Proof of necessity.* For any nonzero-entry matrix `H`, consider the invariant cross-ratios

\[
\mathcal R(H)=\left\{\frac{H_{j,k}H_{j',k'}}{H_{j,k'}H_{j',k}}\right\}.
\]

This set is unchanged by nonzero diagonal row/column scalings and row/column permutations. For `F_AB`, taking `j−j'=k−k'=1` produces the primitive `AB`-th root `omega`, so `R(F_AB)` contains an element of order `AB`. For `F_A ⊗ F_B`, every cross-ratio is a product of an `A`-th root and a `B`-th root, hence has order dividing `lcm(A,B)`. If `gcd(A,B)>1`, then `lcm(A,B)<AB`, a contradiction. QED.

This rules out **only** reindexing/scaling routes to a twiddle-free tensor factorization for noncoprime lengths. It does **not** prohibit more general globally shared linear circuits or arbitrary high-arity kernels.

## 5. Actual verification and runtime accounting

- `test_phase27.py`: 7 focused tests pass.
- `audit_phase27.py`: across two prime fields and lengths `15,30,60,120,240,480`, **614,250 distinct Fourier matrix entries per circuit** and **1,842,750 independent entry-equality checks** across three implementations. Every matrix column (basis input) is verified against the closed-form DFT, which proves correctness of these specific finite linear maps for arbitrary input vectors at those sizes.
- `benchmark_phase27.py`: executed all three exact circuits through `N=61,440`; small sizes checked against a direct DFT, large sizes checked between distinct implementations and selected direct output rows. Their executed addition/multiplication counters match all formulas.
- The cold setup implementation counts modular field powering, root-table construction, and reusable 3-/5-point coefficient preparation. Root order checks, primality/generator proofs, integer CRT indexing, allocations and bit complexity are **not** included in the field-operation total; the supplied-root and warm-data models remain separate.
- At `N=1,920` (`G=128`): `31,823` GT data operations vs `34,625` fully conventional comparator. At `N=61,440` (`G=4096`): `1,478,671` vs `1,568,769`. The relative improvement declines as `G` grows.
- The specific implemented cold setups use `G` cached dyadic roots for GT but additional full `N`- and 15-entry root tables for CT. Their cold setup difference is exactly `N+13` charged field multiplications, not a universal lower bound on CT root preparation. Both circuits have `O(N)` working storage; CRT gathers and output scatter incur additional `O(N)` indexing/data movement.

The project-specific contribution here is the **fully expanded, audited finite-field fusion** and a precise monomial-equivalence rejection test.
