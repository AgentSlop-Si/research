## Result

All 12 assigned source hashes, 71,189 bytes and 1,830 lines, were read completely as inert text. None of the uploaded programs was executed, imported, compiled, or syntax-parsed in this review. The original files and archives were not modified. Source coverage is now complete for this queue; software correctness and execution coverage are not.

The central finite-field Fourier/filter and rational-series identities remain sound under their stated admissibility assumptions. The literal adaptive implementation has a newly identified valid-input failure at N=2, plus two public decoder length-validation gaps. Existing zero-diagonal, root-availability, operation-counter, floating-point and test-scope restrictions remain. These findings qualify implementation claims without overturning the conditional structured-input mathematics.

### Most important findings

1. **Valid tiny input raises before fallback.** The default adaptive transform can propose a polynomial longer than its own validator accepts. At N=2, residual [0,1] produces BM polynomial [1,0,-1], then raises instead of reaching Bluestein. A fully admissible input witness is provided below.
2. **Two low-level decoders silently mix lengths.** `decode_binomial` and `decode_graph_polynomial` do not require `len(r)==engine.n`. A two-entry residual with a four-point engine produces mathematically incorrect four-point output rather than rejecting the call.
3. **“All length” remains conditional.** A primitive N-th root does not guarantee the auxiliary convolution roots or an admissible Green diagonal. Both conditions can fail even with nonsingular L and P.
4. **Source PASS/basis/benchmark artifacts are bounded evidence.** Basis checks of an adaptive program are not an all-input certificate; the so-called exhaustive random test contains 60 samples; arithmetic counters omit operations and machine costs; the checkpoint script can report success after skipped assertions under optimized Python.

## Findings and concrete boundaries

### H18-01: default adaptive BM can raise on a valid N=2 input

Location: `annihilator_engine.py:78–114, 333–362, 411–458`.

Take p=2013265921, N=2, the default Green coefficients, and

- x = [1875997790, 1235413179]
- omega = −1 modulo p
- P = [[9,1],[1,5]], so Px = [0,1]
- det(P)=44, and L=[[8,2],[2,6]] also has determinant 44
- direct DFT(x) = [1098145048,640584611]

The source path is determined exactly:

1. `majority_long_shift` returns None because the residual contains zero.
2. BM reads [0,1]. Its first discrepancy is zero, advancing delay to 2. Its next discrepancy is 1, extending C to [1,0,−1] and setting L=2, which is within the default max_degree=3.
3. `graph_bm_candidate` returns this length-three candidate.
4. The selector calls `graph_polynomial_apply` before checking candidate suitability. That function requires `len(q)<=len(r)=2`, so it raises `ValueError('invalid graph polynomial')`.
5. The fallback at lines 457–460 is never reached.

This is an actual valid-domain exception inferred from complete source control flow; it was not reproduced by running the source. Independent explicit matrix arithmetic verifies x, Px, both invertibility conditions and the expected DFT. The same boundary can arise whenever BM proposes degree N and the configured maximum permits it. The current tests do not exercise the adaptive path at N=2 or N=3.

Recommended repair: reject or normalize inadmissible proposals before calling the full-vector validator and proceed to the ordinary fallback. Add exact regressions for N=2, N=3, leading-zero residual prefixes and max_degree>=N. No source was patched.

### H18-02: low-level residual/engine length mismatch can silently return wrong values

Location: `annihilator_engine.py:254–295, 365–408`.

Unlike `decode_annihilator` at lines 174–176 and `decode_factor_union` at 489–490, these two public decoders omit the equality check. Their filter uses `len(r)` for cyclic wrapping while denominator and output loops use `engine.n`.

Witness: engine N=4, p=97, generator 5, omega=22, residual r=[0,1], delay=1, and q=[1,−2], equivalently a=2,b=1. The short two-cycle filter is [−2,1]. At the engine's frequency k=1, the decoder's formula gives

(−2+22)/(1−2·22) = 83 modulo 97.

The zero-padded four-point DFT of [0,1,0,0] gives 22. The proper two-point DFT also differs. Nothing declares padding or a length conversion; this call should be rejected. High-level transforms validate their input lengths, so the defect does not refute their valid-length identity. Add the same residual-length check used by the other decoders.

### H18-03: inherited Green and field admissibility is stronger than N-root existence

Locations: `green_sparse.py:36–49,168–183`; `rational_forcing.py:59–66,91–94,147–171,183–197,304–317,348–381`.

The cyclic solver inverts every diagonal entry before checking closure. At p=17,N=16,omega=3, L has a zero diagonal at index 3 and P at index 11, although both determinants are 16 modulo 17. It therefore rejects nonsingular operators. This previously documented limitation is preserved, not rediscovered as a new mathematical contradiction.

A second concrete boundary: p=31,N=15,generator=3 gives omega=9, nonzero L/P diagonals and determinants 3. N and 2N both divide p−1, but Bluestein needs a power-of-two convolution of length 32, which the field cannot support. Thus an initialized engine may later raise on fallback. The rational branch separately needs sufficiently long power-of-two convolution roots. “Any N dividing p−1” is not a complete public implementation contract.

The caller must supply a prime field and genuinely suitable generator. `general_root` checks the requested N-order, but does not independently establish primality or all auxiliary NTT orders; some checks are assertions and disappear with optimization. Invalid field/generator inputs may fail inversions or produce invalid NTT behavior. N=1 is excluded. Empty cyclic diagonals can reach an indexing exception. These inputs are not silently promoted to supported cases.

### H18-04: arithmetic and memory counters are proxies, not complete runtime certificates

Locations: `green_sparse.py:52–76,84–165,264–294`; `rational_forcing.py:20–44,91–143,227–300,318–344`; `annihilator_engine.py:13–27,49–114,216–229,411–473,534–563`; `operation_benchmark.py:13–19,49–64`.

The benchmark methodology string claims “Exact per-call field operations for PolyStats.” That is too strong:

- Rational denominator sign formation, Newton sign flips/correction and block remainder negations are not all in PolyStats. The omitted arithmetic remains O(N+K log(K+1)), so this does not destroy the accepted asymptotic form.
- Bluestein's `4*n` chirp charge is a proxy: the loop executes four multiplications for each of n−1 iterations plus two explicit square products, before other counted work. It is not an exact statement-by-statement scalar total.
- Some power costs are charged by upper bounds, and comparisons, preliminary zero scans, support dictionaries, repeated scans, allocation, indexing and list-copy costs are not comprehensively counted. `bm_operations` is never incremented. Output-write counters do not count all initialization, permutation and butterfly writes.
- `green_sparse.transform_adaptive` does not enforce a nonempty homogeneous candidate list; it assumes shared length, modulus and Fourier roots. Its support counter omits the repeated best-support scans. Supplied inconsistent candidates are outside the validated contract.
- Fallback metadata sets K=N even if the actual residual is sparse. That value is a fallback sentinel/upper bound rather than a measured support count. Arbitrary `method` strings in `transform_recurrence` are effectively treated as auto unless equal to “bluestein.”
- The benchmark baseline performs P, Bluestein and L on the same data. It is not a comparison with the best implementation of every Fourier algorithm. Input construction via P inverse and graph inverses is outside timed/charged transforms and is acknowledged as test preparation.

Root and Green setup is shared and omitted by the Phase18 benchmark. Computing short NTT roots independently at multiple stage lengths incurs an additional growing-field planning term unless suitable short roots are supplied; p-dependent bit cost and trial-division root-order checking are separate. Dictionary hashing is ordinary Python support/lookup work, not a cryptographic certificate, and it is not counted by the field-operation proxy.

Within each high-level call a fresh Work/PolyStats object is created. Twiddle keys include modulus, generator, stage length and direction; inverse-scale keys include modulus and size. Fixed denominator and inverse-series kernels are rebuilt from the current sparse input and reused only across its blocks. I found no hidden reuse of a prior input's answer. Direct low-level callers may deliberately reuse a PolyStats object and thereby reuse its root plans; that changes setup accounting and is not the benchmark's fresh-call contract.

For a fixed candidate bank/degree and supported roots, the implementation retains O(N+K) field-sized storage up to Python/container constants, plus small candidate descriptions. Full fallback uses O(N) buffers; roots, L/P arrays, denominator/inverse lists, outputs, and recursion temporaries are real allocations. No measured peak-memory or machine-time claim was verified. Source NTT recursion and dictionary/list traffic cannot be replaced by the arithmetic counter.

### H18-05: exact identities do not imply complete test coverage or precision certification

Locations: all test/audit programs; specific boundaries below.

- `exact_basis_audit.py` uses q=[1,−2], one coprime delay per length, two fixed primes and 13 lengths. It checks the fixed graph decoder on every basis vector; the full adaptive Green transform is checked only when N<=128. Since the adaptive selector depends on x, passing basis inputs alone is not an all-input proof of its implementation. Linearity of the mathematical DFT cannot be assumed for a potentially buggy selector to justify that inference.
- `union_audit.py` covers two supplied factors, one fixed pair per length, in 11 cases. Expected columns are computed directly, but the tested implementation is imported from the supplied package. This is a source-authored audit, not independent reviewer execution. It does not exhaust all factors, overlaps or resonance strata.
- `test_phase18.py` contains 15 test methods. It checks useful geometric/BM/long-delay, one- and two-degree resonance, noncoprime, union, mutation and fallback cases. Its `test_exhaustive_small_random_field` is 20 random vectors at each of three lengths, not exhaustive enumeration of a field. A wrong filter is shown to have large defect in the mutation test; this alone is not an end-to-end adversarial certificate rejection test.
- Tests predominantly use 2013265921 and 998244353 with admissible roots. They miss the N=2 candidate-size exception, mismatched decoder length, zero-diagonal-but-invertible fields, unsupported auxiliary roots, all-zero high-level input, and explicit rational/cached-kernel branch equivalence in this Phase18 suite. Prior Phase17 tests may cover some kernels, but those unassigned tests were not read or run here.
- `generic_gate.py` really enumerates 17^4 vectors and the 17 polynomials 1+c z. Its early exit cannot lower the best support incorrectly: it stops only when the current support cannot improve the minimum. It is a finite diagnostic for N=4,d<=1, not a characteristic-zero dimension proof or an FFT lower bound.
- `precision_gate.py` computes one N=128 near-resonant scalar quotient for five epsilons and compares it with an mpmath 90-digit geometric sum. It illustrates cancellation in complex double and phase representation. It does not run the full modular engine in complex arithmetic, establish a uniform forward/backward error bound, or pin an mpmath/runtime version.

### H18-06: archive integrity and runner success have narrower meaning than certification

Locations: `build_checkpoint.py:9–39`; `run_all.py:7–40`.

The builder hashes current files, creates a ZIP, tests its CRC, reextracts, runs sha256sum, and runs only `test_phase18`. Integrity and tests are separate; a matching manifest establishes neither truth of embedded claims nor independent review. Its test/manifest return-code gates and CRC check use `assert`. Running the builder with Python optimization can skip those checks and emit the hard-coded success booleans even after a failed child return code. This is a static false-positive route, not a claim that the supplied receipt was produced that way.

The builder writes the manifest and overwrites the final ZIP before completing validation. Output is not atomic. “Reproducible ZIP” means a rebuilding procedure here: `ZipFile.write` retains filesystem timestamps/metadata and files can contain elapsed times, so byte-for-byte determinism is not established. An untracked file under the source directory is included by rglob; there is no fixed content allowlist. Hashing does not authenticate the author or pin the Python environment.

`run_all.py` is stronger about child exit status: it explicitly aborts on nonzero status and captures logs. It still does not itself check the main manifest, pin sibling/module resolution or mpmath, or certify external process provenance. Its optional Phase17 replay extracts a nested archive only after resolved-path containment checks; it runs inherited tests when explicitly selected. The builder does not use that guarded helper, although its normal archive is self-created. No nested prior program was executed in this review. Python's default module path/environment is a runtime boundary; bare sibling imports are not cryptographically pinned.

## Detailed semantic acceptance

### Green recurrence and sparse DIT

For positive-sign Fourier, S is the backward cyclic shift and D has entries omega^j. The implemented L=aI+bS+cD and P=aI+cS+bD^{-1} satisfy LF=FP. On the admissible diagonal/closure domain, the cyclic solve's affine forward recurrence followed by the homogeneous closure correction is algebraically correct. `inv_all` uses one inverse and a prefix/reverse product sweep; zero and nonunit cases fail rather than granting a valid inverse.

Sparse DIT separates even/odd indices, uses the correct stage stride n/m, duplicates even-only output, and applies the correct signs to odd-only output. Its public constructor assumes the radix-two/primitive-root contract rather than validating it itself. `from_entries` validates nonzero support indices, but zero-valued out-of-range entries are dropped first. `direct_sparse` and the structured input constructors use direct indexing and do not have the same guard, so negative indices can follow Python indexing conventions. High-level generated support stays in range.

### Rational forcing and convolution

The balanced fraction tree forms the numerator and denominator of sum_j r_j/(1−omega^j t). Denominator constant one permits Newton inversion. With H the next power of two >=K, the block recurrence takes the last K outputs, convolves with the denominator, negates coefficients K through 2K−1 and convolves with the inverse series modulo t^H. The indexing, initial block, zero support, K=1, and final truncated block are consistent. For valid generators/roots, NTT butterflies, inverse scaling and Bluestein signs match the positive Fourier convention.

These are exact finite-field identities. Prime/generator discovery, auxiliary-root availability, scalar cost and complex stability remain independent conditions. No source transform or benchmark was executed to supplement the static conclusion.

### Annihilator, resonance, discovery and unions

For q(S^delta), each Fourier coordinate is multiplied by q(omega^{k delta}). Every decoder divides only at nonzero spectral denominators and recomputes the erased coordinates by direct Fourier summation on the original residual. Zero defect does not mean zero Fourier data. At gcd(N,delta)=g, a degree-d polynomial has at most min(N,dg) erased coordinates; the decoder still works when every coordinate is erased, but direct repairs can then be quadratic. The binomial count separately handles a=0 and requires b!=0.

Projective majority uses cross-products with nonzero residual entries. A strict majority yields a proposal, and the full defect scan controls acceptance. BM inspects a bounded sample along one orbit and is only a proposal mechanism. The selector charges attempted full scans, repeats accepted filter computation inside the decoder and limits noncoprime repair exposure. The new candidate-length bug is an exception before that fallback guarantee, not a defect in the Fourier quotient identity.

Supplied factors are applied successively, without expansion into 2^m monomials; their scalar eigenvalues are multiplied and each distinct zero frequency is repaired once. The factors commute as polynomials in S; the outside Green L/P operators provide the noncommuting structure. Dense defects trigger a full transform. The factor description is input information and no efficient search over arbitrary hidden factor sets is implemented. For constant factor count, sparse defect and bounded actual resonance count the structured arithmetic bound remains conditional and sound.

The prior dimension qualification stays essential: d+K applies to one full cyclic orbit, including coprime long shifts. A noncoprime shift has g-dimensional eigenvalue multiplicities, so that bound does not transfer unchanged. None of this yields a generic-input sub-N-log-N transform.
