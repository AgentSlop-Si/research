# Phase 7 implementation audit and local hardening

Audit date: 2026-10-08 UTC. No publication or original-source modification.

## Bottom line

The supplied 57 tests and 1,600 independent finite-field cases pass, but they miss several implementation defects. A separate, narrowly hardened derivative passes 80 tests, including recovered Phase-5 regressions and new adversarial checks. Ordinary randomized convolution results were also correct in the original; the failures are specific edge cases, API consistency, resource accounting, and deep composition.

The finite-field checker validates identities independently; it does not validate the floating-point implementation, numerical conditioning, memory limits, or speed.

## Reproduced findings

1. **Spectrum-only `auto` silently loses the reference signal.** In `cost_aware_fft.py:518`, `sparse_from_known_changes(rfft(arange(8)), 8, [(1, 2)], 'auto')` returns DC 2 instead of 30. The placeholder time signal is zero; auto may dispatch to native recomputation using that placeholder. The derivative maps auto to direct reconstruction. This is a recovered earlier fix, absent from the new package.

2. **Rejected convolution-subscription edits corrupt the subscription.** In `relational_convolution.py:421-424`, subscribed values change before accumulated-delta overflow is checked. A left delta of `1e308` convolved with `[1e-308, 0]` starts near 1. A second left edit of `1e308` raises `ValueError`, but the reported subscription becomes near 2, while its unchanged snapshot remains near 1 and its event count remains zero. The derivative validates accumulated edits before modifying the output; both operand directions are tested.

3. **Repeated composition breaks valid chain operations.** `convolve_with` joins roots without balancing. At 1,100 repeated factors, `factor(0)` and `edit(0, 0, .25)` raise `RecursionError`. Building the same chain with `chain([...])` works. Recursive factor lookup, rewriting, and frequency-bin evaluation are replaced by iterative equivalents. Tests cover two edited factors and bin cache budgets 0, 1, and 10,000. This avoids the recursion failure, but intentionally does not rebalance the tree.

4. **An output-cache hit bypasses explicit method validation.** An edited state correctly rejects `reuse`, `zero`, and `linear` before caching, but accepts all three after `spectrum('native', cache_output=True)`. Cached odd-length states also bypass pruned compatibility checks. The derivative validates the explicit request before returning cached output.

5. **Calibration admits an ineligible pruned candidate.** At length 16 with `max_temp_bytes=256`, calibration's old admission estimate accepts pruned, whose execution rejects its memory requirement. Calibration aborts despite working native/direct alternatives. The recovered patch shares a conservative estimate between admission and execution and skips backend `MemoryError` failures. A separate deterministic test supplies a pruned-winning profile, shrinks the public budget, and checks that automatic dispatch no longer selects the now-ineligible method. That last test models a previous calibration winner rather than relying on noisy host timing.

6. **Memory limits undercount retained or temporary arrays.** A tiled phase view reports 32,784 bytes but retains a 49,152-byte backing array and is cached under a 32,784-byte budget. For N=65,536 and eight edits, pruned admits a 1,114,112-byte budget while tracing approximately 4.33 MB of peak allocations (about 3.80 MB after subtracting the returned output). These measurements are allocator observations, not an RSS guarantee. The derivative charges backing allocations and uses a deliberately conservative visible-work-array estimate. Hidden backend/runtime allocations are still outside a hard process-memory guarantee.

7. **Complex seed input is silently projected to real values.** A NumPy array `[1+2j, 3+4j]` is accepted as `[1, 3]`, with only a warning, despite the real-input API. The derivative rejects complex and nonnumeric seed data before casting.

8. **The structural-sharing diagnostic confuses engine-local identifiers.** Two distinct one-factor chains in separate engines both have local node UID 1. `count_reused_nodes` reports one shared node despite different objects. The derivative counts object identities, as its docstring promises.

Cross-engine `RelationFFT.combine`, Phase-7 factor replacement, and Phase-7 composition already reject incompatible engines. Those controls passed; no cross-engine numerical-combination defect was reproduced.

## Local benchmark rerun

The supplied benchmark was run against the derivative, with setup charged according to its existing definitions. Full-output workload ratios versus prepared-kernel FFT recomputation were 1.31x at N=4,096, 2.90x at N=65,536, and 3.28x at N=262,144. These are medians of three local repeats for that workload.

The strongest included analytic frequency comparator took 8.17 ms, while the generic persistent engine took 15.74 ms. The analytic implementation was approximately 1.93x faster. The package's negative result therefore remains.

Important coverage limit: the supplied many-version full-output benchmark materializes all coefficients but compares only three sampled coefficients per output. The audit's independent tests compare complete small outputs. No timing claim is made for arbitrary inputs, another host, eFFT, or a native backend.

## Remaining limitations and deliberately unmodified behavior

- Concatenated roots remain unbalanced. Iterative traversal prevents stack overflow but cannot provide logarithmic update time on a linear-height chain. Joining also copies the seed-ID tuple; retaining all appended versions can have quadratic aggregate tuple storage.
- Warm single-factor frequency lookups hash keys containing the entire length-m seed tuple. Ordinary Python tuple hashing is linear in m, even on cache hits. Seed membership tests scan the engine's seed list; these costs prevent claiming the implementation achieves the ideal logarithmic bound end to end.
- Sparse edit tuples are copied/sorted, and modified-factor sets can grow. Registering immutable seeds keeps their arrays for the engine's lifetime. Budgeted dense cache arrays are not a complete total-memory bound.
- The iterative multi-factor bin evaluation uses a per-query map of visited-node values. Its temporary storage is O(visited nodes), separate from the persistent bin LRU budget.
- No comprehensive numerical-stability fix is attempted. Long products, cancellation, extreme scales, overflow, and underflow remain float64 limitations. Direct manipulation of internal metadata or resetting ndarray write flags is outside the supported API.
- The patch does not add a balancing algorithm, stronger cost model, a hard allocator limit, native optimization, exact integer convolution, or a new transform theorem.

## Bounded next experiment

Measure N=64 with m=16, 64, 256, 1,024, and 4,096 factors, Q=1 and 4 bins, and 200 one-edit forks per configuration. Compare balanced construction versus repeated append construction, cold versus warmed caches, and a specialized leave-one-out formula. Charge construction, tuple copying/hashing, edits, queries, and retained storage separately; verify every requested bin. This small grid directly tests the remaining claimed logarithmic behavior before a larger rewrite or native implementation is justified.
