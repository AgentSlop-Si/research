# Exact product reuse through a correction graph

This package turns A_i B=A_j B+(A_i-A_j)B into an executable graph schedule.
It improves related same-B batches in a declared arithmetic model, with the
first product, root preparation, relation discovery and all output digits paid.
It does not improve the asymptotic cost of a single fresh arbitrary product or
an arbitrary exact FFT.

## Semantics and the two verified correction representations

Inputs are n canonical base-beta digits for each nonnegative integer A_i and B.
The first product uses a radix-2 NTT of length m>=2n-1 over p=65537. The program
requires n(beta-1)^2<p and m dividing p-1. Therefore every true nonnegative
convolution coefficient is uniquely recoverable from its residue; no modular
aliasing is possible. Root generation, order checks, the root table, inverse
normalization and B's shared transform are all executed and counted.
The fixed-modulus implementation is a finite-size experiment: at base 16 its
coefficient bound permits n<=291. Extending to unbounded sizes requires suitable
moduli/root preparation or CRT reconstruction, with those costs charged; the
spanning-tree scheduling theorem itself is independent of this backend.

The default correction is a list of nonzero signed coordinate differences
between the two digit vectors. A patch with s entries is convolved with B by
exact integer multiply-adds, then merged with the cached coefficient vector.
The uncarried coefficient cache has length 2n-1. Each output undergoes a full
base-beta carry pass and returns exactly 2n digits, including leading zeros.

With `numeric_patches=True`, the program also computes canonical signed digits
of the actual integer difference A_i-A_j by bounded block subtraction, with
borrows charged. It chooses whichever verified representation has fewer
nonzero blocks. This matters for A_i=A_j+1 through a long carry chain: coordinate
differences can be dense while the actual difference is one block.

In this mode the cache stores canonical 2n product digits after the carry pass.
Both correction representations satisfy

    sum_j patch[j] beta^j = A_i-A_j.

Consequently the updated coefficient vector evaluates at beta to A_i B, even
when it is not the canonical digit-polynomial convolution. Carry normalization
then gives the unique canonical product digits. Negative intermediate
coefficients are allowed; the final integer is nonnegative and below beta^(2n).
The program never assumes a numerically small k is cheap without constructing
and checking its digit representation.

## Restricted optimality theorem

Build a graph with one vertex per requested product and an extra root R.
An R-to-i edge has the cost of computing A_i B freshly with the common prepared
B transform. An i-to-j edge has the exact scalar arithmetic cost of the chosen
verified correction kernel. These weights are fixed once the patches are
prepared. Each product may be computed freshly or from one previously computed
parent product. All requested outputs must be produced.

**Theorem.** In this single-parent model with symmetric correction costs, a
minimum spanning tree rooted at R minimizes product-kernel scalar arithmetic.
Previously paid cached products are represented by zero-weight root edges.

**Proof.** The first production of each query has one parent, either R or an
earlier query. Parent pointers are acyclic by execution order and every vertex
reaches R. They therefore form a spanning tree whose weight is that schedule's
product-kernel cost. Conversely, every rooted spanning tree can be executed in
parent-before-child order, with exactly its edge costs. Minimizing over trees
is therefore exactly minimizing over these schedules. With directed costs the
analogous object is a rooted directed arborescence, not an undirected MST.

This does not optimize over multi-parent linear combinations, new auxiliary
anchors, a different correction kernel, cache eviction, parallel time, numerical
conditioning or machine memory traffic. Patch preparation, planning and output
normalization are common charged terms outside the tree objective. It is not a
general lower bound or a claim that this is the fastest integer multiplier.

## Cost ledger

The exact scalar counter charges each modular add/subtract/multiply, ordinary
integer add/subtract/negate/multiply, and bounded-word divmod as one operation.
Modulo reduction is included in a modular operation. This is a declared
arithmetic/word model, not a CPU instruction or bit-complexity benchmark.

| Operation | Charged work |
|---|---|
| Common preparation | Actual root powers/order checks, inverse constant and one B transform |
| Fresh product | 3m log2(m)+2m scalar operations; two transforms and pointwise product |
| Nonempty default correction | 2ns+(2n-1) scalar operations |
| Nonempty numeric-mode correction | 2ns+2n scalar operations |
| Identical product | Zero arithmetic, but copying and full output remain |
| Carry normalization | 2n additions and 2n divmods per requested product |
| Coordinate edge discovery | n subtractions plus reverse-patch negations per tested pair |
| Numeric edge discovery | Additional O(n) block subtraction/comparisons per tested pair |
| Input/output | O(Qn) validation/reads and exactly 2nQ output-digit writes |
| Current Prim planner | O(Q^2) bookkeeping, with comparisons and edge-cost evaluations recorded |

Default discovery tests all Q(Q-1)/2 pairs, hence costs O(Q^2 n). Passing
`candidate_edges` restricts this to E supplied or cheaply generated pairs and
O(En) verified discovery; root edges always retain a fresh-product fallback.
Candidate graphs are hints, not trusted relations: the program still computes
their differences. Generating a difficult candidate graph is not free.

Root/index work, validation, cache-key checks, copies and output writes are
reported as separate logical categories. They are not an exhaustive trace of
Python/interpreter memory traffic: remaining list allocation/slicing and
metadata work are covered by the stated asymptotic terms. In particular,
`total_arithmetic` is not total machine work. Live storage includes O(Qn)
cached products and outputs, O(n) transform state, and all stored patches
(up to O(En)); discarded candidate representations also incur allocation work.

The baseline already reuses B's transform. Comparing against Q entirely cold
two-input transforms would overstate this package's additional saving.

## Cold and warm results

Eight queries, n=128, base 16. Counts include setup, edge differences, product
arithmetic and carry normalization; separate metadata counters are in JSON.

| Family and discovery | Fresh-product baseline | Graph schedule |
|---|---:|---:|
| Related three-block variations, all pairs | 60,728 | 21,345 |
| Unrelated dense controls, all pairs | 60,728 | 67,636 |
| Integers near beta^127, verified consecutive-query edges | 60,728 | 20,927 |

The dense control selects eight fresh products: it exposes the cost of an
unsuccessful search for reusable corrections. The last row uses the numeric
patch mode; coordinate patches alone cost 43,704 on the same supplied chain.
This is an exact carry-chain test of the user's A-k idea.

For the first row, the warm graph count is 11,305, but its raw anchor cache and
shared preparation previously cost 10,040. Their sum is the cold count 21,345.
For the numeric carry-chain row, warm work is 10,887. Preparing its canonical
anchor cache costs 10,552 including the first carry pass; seed plus warm counts
one extra 512-operation normalization because the warm batch rematerializes
the anchor output. Warm counts are never presented as a cold-input result.

Cache tuples are trusted state produced by this implementation. A/B/base/index
and representation-length guards prevent accidental stale reuse; they do not
authenticate adversarially corrupted cached coefficients. Coefficient integrity
would need separate provenance or verification, with its cost charged.

## Coverage constraint and constructive escape conditions

For a q-symbol digit alphabet of dimension n, a cache of M fixed centers and
coordinate corrections of support at most s covers at most

    M V_q(n,s),  where V_q(n,s)=sum_(j=0)^s binom(n,j)(q-1)^j.

Thus universal coverage requires M>=q^n/V_q(n,s). This follows by counting
each center's Hamming ball and taking a union bound; overlap only worsens
coverage. For fixed q and s=o(n), the necessary cache is exponential in n.
It is a constraint on this fixed-center coordinate-patch model, not on arbitrary
integer multiplication. Numeric difference patches and other structured
corrections require their own coverage analysis.

Over an infinite field, finitely many centers plus corrections in finitely many
proper linear subspaces cannot cover the whole input space. Each translated
subspace lies in a nontrivial affine hyperplane; the product of their defining
linear polynomials is nonzero and cannot vanish everywhere. Allowing a center
chosen freshly from the query avoids this coverage statement, but its first
product must then be paid.

Useful escape conditions are concrete: many same-B queries; cheaply obtained
graphs with genuinely sparse verified differences; existing anchors whose
creation has already been amortized; or additional proved fast correction
families. For large Q, use a sparse candidate graph and a standard efficient
MST implementation instead of this transparent O(Q^2) Prim audit. If B also
changes, A0B0+deltaA B0+A0 deltaB+deltaA deltaB must all be accounted for.

## Reproduce

Run `python audit.py` and `python audit_numeric_shifts.py`. The audits pass
195 and 96 exact integer-product comparisons respectively. They also verify
125 spanning trees exhaustively for a small graph, exact coverage counts,
duplicate queries, invalid arguments, and stale cache rejection. Independent
review checks cover modulus-boundary cases and trusted-cache limitations.
The tests substantiate the implementation; the all-size schedule theorem and
coverage statement are proved above.

`LITERATURE_BRIEF.md` records the separate Fourier literature and current
exact-FFT baseline. No mathematical priority or practical speedup is claimed.
