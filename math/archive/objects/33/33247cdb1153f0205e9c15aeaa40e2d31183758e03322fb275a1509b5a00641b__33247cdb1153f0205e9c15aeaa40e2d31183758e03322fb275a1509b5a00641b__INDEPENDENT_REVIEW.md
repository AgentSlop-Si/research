Reviewed on 2026-10-09 by the exact-factorization research agent, separately
from the compiler author. Reviewed `port_feedback.py`, both helper modules,
the final README, audit code and captured results.

**Verdict:** the rank-d closure, rank-one coupling update, arbitrary-state

## Algebra and state guarantees

The observation variable satisfies `c=g+G Lambda c`. Thus
`S=I-G Lambda` gives the solution through `U Lambda S^-1 g`. The proof also
correctly handles dependent columns of U, duplicate observation ports, repeated
injections and several independent source banks. If S is singular, its nonzero
null vector generates a nonzero homogeneous graph solution, so rejection is
appropriate even when the port representation is redundant.

For an edit `Lambda_new=Lambda+a b^T`, set `z=S^-1 G a`,
`v^T=b^T S^-1`, and `theta=1-b^T z`. Direct expansion confirms both

    S_new^-1 = S^-1 + z v^T / theta
    F_new-F = (a+Lambda z) v^T / theta,  F=Lambda S^-1.

The code assigns the factor `1/theta` exactly once, to the output direction.
Its updated inverse, coupling and effective U factor are mutually consistent
and can be used in later edits. A zero a or b leaves the prepared state and
target map unchanged, although the advertised preparation remains charged.
An edit with theta=0 is rejected before any gates are emitted.

The descending and ascending graph passes cancel the original target state.
Each rank-one correction depends only on original source banks; its pivot
uncompute restores every source before the next correction. Targets and the
unused workspace need not start at zero. The pivot's coefficient is inverted,
not its value. The edit's interpretation as a new solution requires the same
sources/injection pattern and an already accumulated old solution, as the README
explicitly states. Arbitrary unrelated target background is preserved.

Both public compilers validate source/vertex indices and use the same layout.
Prepared plans now check N, p and q compatibility, preventing reuse against a
different Fourier root in the same field and dimension.

## Preparation and instruction accounting

I independently expanded the operation counts for the paired J^T/K^T walks,
G formation, the two d-by-d products, pivoted Gauss-Jordan, and the effective
U product. They match the initial preparation formulas in the README and the
code's assertions. Pivot scans and row-reference swaps cost O(d^2) additional
control work; no input-dependent source inversion occurs.

I also expanded every coupling-edit step, including recombining source rows,
the response walk and refreshing all three cached factors. The totals are

    mul = 7d^2+2d+2Nd+2N(R-1)+dQN
    add = 6d^2-2d-1+N(2d+R-2)+dN(M+Q)
    sub = 1; constant_inverse = 1.

Here M counts injection entries and Q counts distinct referenced source banks.
Repeated source banks are combined once per coordinate in the final functional,
which is why the edit's last multiplication term uses Q rather than M.

The complete first circuit retains one quadratic ADD_T per supplied injection.
The rank-one instruction formula `6m+3k-4`, the zero-update omission, both graph
sweeps and all RN edit outputs are accounted for correctly. Source-pivot inverse
construction and scalar-expansion reciprocals are separate recorded setup costs.
The README also correctly charges q-plan setup, orbit storage and root checking.

## Local correction and inherited-checkpoint caveat

The copied `rank_one_add` originally sorted all source-register IDs before
emitting its source-to-pivot shears. For arbitrarily ordered, unbounded source
banks, this can add superlinear sorting work not covered by the claimed linear
gate-construction bound. The author removed that sort **only in this package's
`prior_feedback.py`**. The pivot is still selected by a linear `min` scan;
remaining shears follow insertion order. These shears commute, so the map,
inverse recovery and instruction counts are unchanged.

Older saved feedback checkpoints still contain the sorting step. Their algebra
and online scalar counts remain valid, but their gate-construction cost claims
need that additional sorting overhead for unbounded source order. They were not
modified during this review. The new README accurately identifies the local
helper modification rather than describing every dependency as unchanged.

## Verification scope

The final captured audit passes 216 configurations, 4,704 full-register basis
vectors for each of closure and edit, 648 mixed states and 648 second edits.
It also reports two singular rejections, ten invalid-injection rejections, two
different-root-plan rejections and an invertible small system requiring a row
swap. The full RN-by-RN inverse oracle is independent of the port reduction.

During review I additionally ran one focused case with shuffled source banks
`2,0,1`, repeated injections, duplicate coordinate ports, arbitrary dirty state
and a zero-valued source coordinate. Both closure and edit agreed with the dense
oracle. Both zero edit factors also left the map and cached factors unchanged.
No unrelated research suites were rerun.
