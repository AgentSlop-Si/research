# A prime-free exact backend for the A-k correction graph

**Result:** the correction graph can now multiply arbitrary finite-length
canonical digit vectors exactly, without the previous p=65537 digit limit,
prime search, or a precomputed prime bank. Tests cover up to 4096 base-256
digits (32768-bit input integers). This elementary backend is deliberately
not claimed to beat modern multiplication or improve its worst-case order.

The folder name retains the task's CRT label, but the implemented construction
uses one explicitly constructed, possibly composite Fermat-like ring. No CRT
reconstruction or primality assumption is hidden in the implementation.

## Exact ring construction

For n base-beta digits let C=n(beta-1)^2 bound every ordinary convolution
coefficient. Let m be the next power of two used by the program, with
m>=2n-1, and set

    h=m/2,
    t=h ceil(max(1,bit_length(C))/h),
    P=2^t+1,
    omega=2^(2t/m) mod P.

Then P>C, t is a multiple of m/2, and

    omega^m=1,     omega^(m/2)=-1 mod P.

P need not be prime. For any nonzero exponent d mod m, write d=2^s u
with u odd. Translating the root-sum index by m/2^(s+1) multiplies
every term by -1 without changing the sum. Thus S=-S; since 2 is
invertible modulo the odd P, S=0:

    sum_(j=0..m-1) omega^(jd)=0.

This proves Fourier orthogonality over the ring. Since P is odd, m is
invertible. Inverse normalization is multiplication by 2^(-log2 m), itself
an exact signed binary rotation. The usual forward/pointwise/inverse identity
therefore computes cyclic convolution over Z/PZ. Zero padding removes cyclic
aliasing, and P>C recovers the true integer coefficients from their canonical
residues. The ordinary signed carry pass returns all 2n canonical product
digits.

There is no unknown constant to discover: the modulus, root exponent, inverse
scale, and index permutation are constructed directly. Their construction is
executed and recorded. No table of m large twiddle coefficients is stored.

## Exact arithmetic without large modular division

Multiplication by a twiddle 2^r is performed using shifts, masks, a subtraction,
and an optional sign change, exploiting 2^t=-1. This costs O(t) bit operations.
Canonical residues are in [0,2^t]. For a pointwise product z=ab<=2^(2t),

    z mod P = (z & (2^t-1)) - (z >> t),

followed by adding P if the result is negative. One fold suffices, including
the endpoint a=b=2^t. Ring additions/subtractions use one conditional reduction.

The default pointwise product calls Python's exact multiplication on at most
t+1-bit operands. That call is explicitly charged as M(t+1), not considered
free and not mistaken for a new multiplication algorithm. An optional
shift/add schoolbook pointwise path is implemented and tested; it supplies
a self-contained O(t^2) bit upper bound independent of Python's internal
multiplication method.

## Bit cost, setup, and memory

Let M(t) denote the cost of the chosen t-bit multiplication subroutine. One
cold same-B preparation and one fresh product use three length-m transforms
and m pointwise products. Their arithmetic bit cost is

    O(m t log m + m M(t) + n K^2),
    K=O(log(n+1)+log(beta)).

The final term conservatively charges carrying with elementary bounded-integer
division. Modulus construction, index preparation, input validation, padding,
coefficient copies and all output digits are performed. O(m log m) explicit
index operations are also required; even charging O(log m) bit work per index
operation is absorbed by the displayed transform term because t>=m/2.
Computing the size bound itself uses arithmetic on O(log n+log beta)-bit
parameters and is not an oracle.

For fixed beta, m=Theta(n) and t=Theta(n). With schoolbook pointwise products,
the conservative bound becomes O(n^3+n^2 log n); with another multiplier it is
O(n^2 log n+n M(n)). This is not asymptotically competitive. Its purpose is
a transparent unbounded exact backend and reference for graph reuse.

Ring workspace and stored transformed B require O(mt) bits, which is
quadratic in n for fixed beta. In default numeric_patches=True mode, cached
canonical products require O(Qn log beta) bits for Q queries. Coordinate-only
numeric_patches=False mode instead caches raw convolution coefficients and
requires O(Qn(log beta+log(n+1))) bits. Candidate-patch and index storage are
additional in both modes. No linear-bit-space claim is made.

The reused graph scheduler retains its original scalar-operation objective.
One large-ring multiplication and one small digit multiplication both count
as one scalar operation in that inherited objective, despite their different
bit costs. Its MST is consequently not a bit-cost optimum. Returned counters
separate ring twiddles, pointwise products, operand widths, carry work,
digit corrections, metadata, and outputs. `total_scalar_arithmetic` must not
be presented as total runtime or total bit work. The schoolbook bit-budget
counter is an upper-bound proxy, not measured work of Python's multiplier.

## Reuse and signed sparse differences

The same two verified patch families remain available: coordinate differences
and signed canonical digits of the numerical difference A_i-A_j. Numeric mode
caches already normalized product digits. Each patch preserves evaluation at
the base, so adding patch*B and carrying yields A_i B, even through long carry
chains. All candidate differences are computed and checked. A supplied chain
is a search hint, not a supplied answer.

For support s and D=ceil(log2 beta), a sparse correction has at most ns products
of D-bit digits. In default numeric_patches=True mode, the parent consists of
normalized digits, so intermediate signed coefficients have
K_s=O(D+log(s+1)) bits. A conservative arithmetic bit bound is

    O(ns(D^2+K_s) + n K_s^2).

It also uses O(ns+n) explicit indexed operations. Charging full index-word
bit manipulation separately adds O((ns+n) log n) as a simple upper bound.
Coordinate-only numeric_patches=False mode retains raw parent coefficients up
to n(beta-1)^2, so the same displayed arithmetic bound instead uses
K_s=O(D+log(n+1)). For fixed radix and fixed s in normalized mode, the digit
arithmetic and indexed-operation counts are linear, and all product digits
are returned. Relation discovery and
planning remain additional costs: O(En) digit visits for E candidate edges
and O(Q^2) bookkeeping in the inherited transparent Prim implementation.

Cold batches pay B's transform and the first anchor product. Warm batches
assume these were paid previously and retain the same trusted-cache provenance
contract as the prior graph. Warm input/base/index and raw/canonical format
checks prevent accidental stale reuse; arbitrary corrupted cache contents are
not authenticated by those key checks.

## Numeric sparse offsets still have a coverage limit

Let V_beta(n,s)=sum_(j=0..s) binom(n,j)(beta-1)^j. For one fixed anchor,
there are at most

    1+2 sum_(j=1..s) binom(n,j)(beta-1)^j = 2V_beta(n,s)-1

signed canonical numerical differences with at most s nonzero digits. Clipping
targets to [0,beta^n) can only reduce this count. A fixed cache of M anchors
covering every n-digit input therefore needs

    M >= beta^n / (2V_beta(n,s)-1).

If either coordinate-sparse or numeric-sparse patches are allowed, the union
has size at most 3V_beta(n,s)-2 per anchor (the two sets at least share the
anchor), giving the corresponding denominator. For fixed beta and s=o(n),
these bounds still require exponentially many fixed anchors. This extends
the counting argument to the A-k representation; it is not an impossibility
theorem for algorithms that compute new anchors or use different corrections.

## Verification and reproduction

Run `python3 run_audit.py`; only Python's standard library is required.

- 280 signed-rotation comparisons against independent modular exponentiation.
- Direct DFT and inverse checks over five rings, including composite moduli.
- Explicit composite example P=2^32+1, divisible by 641.
- Pointwise folding checks at random and endpoint residues, plus independent
  shift/add pointwise products.
- 77 exact integer products checked against Python's whole-integer oracle.
- Cold/shared-B, graph-reuse and warm batches at 300, 512, 1024 and 4096 digits.
- A dense-difference control and finite numeric-offset coverage checks.

The verifier's whole-integer conversions and products are oracle work, not
called by the counted algorithm. For six-query related batches the full-product
baseline performs 6m pointwise ring products; the cold graph performs m and the
warm graph performs zero. This is an exact same-backend reuse comparison, not
a comparison against an optimized general multiplier. Recorded elapsed times
are one audit run and are not statistical performance claims.

`graph_kernels.py` is an unchanged copy of the earlier `correction_graph.py`
(SHA-256 973608410eb3a81e71b3b1357201a05c759ba4508b5fafd5fa8d91cc264ecbde).
Its validation, patch discovery, scheduling, correction and normalization
helpers are reused. Its old 65537 preparation/FFT functions are never called
by this adapter. The original research files were not modified.
