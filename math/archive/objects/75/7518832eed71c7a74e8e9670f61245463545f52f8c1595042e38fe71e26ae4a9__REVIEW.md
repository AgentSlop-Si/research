# Phase31 exact-version code and dependency review

All twelve assigned exact-hash sources (35,424 bytes: ten Python files and two C++ files) were read completely as inert text. No uploaded code was executed, imported or compiled. The code constructs fixed-seed Green pencils, rectangular polynomial equations, bounded modular rank checks and linear online Green applications. This review is distinct from the already accepted bounded mathematical Phase31 audit.

## Substantive defects and qualifications

1. **Cold setup is not literally linear as implemented.** The changed `phase28_executor.py` validates each cycle with `sorted(self.order) != list(range(n))`. On arbitrary supplied/random permutations the comparison-sort validation has O(N log N) worst-case work. `FourGreenExecutor` and `FiveGreenExecutor` inherit it, so their initialization-O(N) wording is not established by this implementation. Replace validation with a paid visited-array permutation scan to obtain linear validation; original files are unchanged. Root powering and modular inversion costs remain separate from this sorting term. Online application after preparation uses a constant number of linear recurrences and is O(N) in the stated field/address model.

2. **The indexed native checker misses a truncated final index.** `rectangular_seven.cpp` loops while an eight-byte `ids.read` succeeds, then tests only `!ids.eof()`. A file containing complete indices followed by one through seven bytes fails the final read with both failbit and eofbit, so the purported “truncated sample indices” check does not reject it. An empty index file likewise gives a successful zero-sample result. Validate total byte size modulo eight or distinguish an EOF with nonzero gcount. This is a direct C++ stream-state argument; no uploaded binary was run.

3. **Stored-rank tests have limited evidence strength.** The N8 test pins length, all-35 rank bytes and an expected SHA, but does not recompute all 564,480 matrices. The N16 stored-sample test checks lengths, unique indices and all-35 bytes, but does not require each index to be below 146,764,800 or bind those 100,000 ranks to freshly recomputed corresponding matrices. The later 100 independently sampled determinant tests are separate controls. A list of 100,000 distinct out-of-range uint64 values plus all-35 rank bytes satisfies the former predicates in isolation. Thus saved-byte checks are provenance/shape checks, not full portable mathematical verification.

4. **Runtime dependencies must be pinned as a set.** The unchanged Phase30 certificate modules import the changed `phase30_four_parameter.py`, `phase29_executor.py` and `phase28_executor.py` in this source package. File identity of a certificate module alone does not pin its executed meaning. `phase30_four_parameter.py` additionally prepends a sibling `fft_green_phase29_two_parameter` directory to sys.path, allowing an existing sibling to take precedence over the bundled same-name modules. An isolated dependency manifest/environment is needed for reproducible execution. No external sibling was imported here.

5. **Native I/O and field contracts need retention.** The native programs read native-endian uint32/uint64 streams whereas the Python exporter writes little endian. This is consistent on the usual little-endian machine, not a cross-endian format decoder. They check input header and short matrix payload, but do not check final output stream status after writes; a partial write can still precede a success summary. Default modulus 998244353 keeps two-residue additions inside uint32. A generic `MODULUS` override above 2^31 can overflow that addition; primality and root compatibility are also not automatically validated by a macro override.

6. **Supplied valid lengths remain a premise.** The executors assume a positive N dividing P-1, valid field roots and nonzero cyclic closure denominators. They do not all validate those contracts as public APIs. The expression `-(P-1)//n` agrees with the intended negative exponent at admitted divisors; outside that contract it is floor division of a negative number, not root validation. Fixed P also does not supply an unbounded-length bit-complexity family.

## Implemented mathematics and loops

The rectangular quadratic formula correctly cross-multiplies target cross ratios without dividing by an unknown pencil entry. Homogeneous multiplication by each of five variables gives 35 cubic monomials. Full cubic-column rank excludes a nonzero common solution because every degree-three monomial would vanish; in characteristic zero this uses a correctly bound rational/cyclotomic specialization with all denominator guards. A full modular rank does not by itself certify a different family, free variable cycle orders, arbitrary matrix sizes or an unrelated characteristic-zero lift.

The seven-minor and eight-minor C++ variants enumerate the same monomial order as the explicit five-variable degree-two/three construction. Their incremental row reduction retains the required pivot-zero invariant; at rank 35 the selected source rows give a square nonsingular minor. Lower-rank witness arrays contain padding and must be interpreted with the stored rank. Neither binary rank-only output nor witness row indices alone bind the source matrices, equation ordering, range or modulus without an accompanying manifest. The code's range iteration is well bounded; unlike the earlier Phase30 limit bug, these two programs use a flat begin/end loop.

The source executors' two-pass cyclic recurrence is algebraically correct: the first pass computes the complete affine cycle numerator, division by 1-alpha^N determines the preceding boundary value, and the second pass emits the cycle solution. Constant diagonal phases and scalar pencil coefficients are then applied. Matrix generation is dense offline research work, separate from online vector application. FourGreenExecutor reconstructs its fourth cycle order per call, which is another O(N) term, and mutates two stored coefficients. Its interfaces are not advertised here as concurrent/reentrant. FiveGreenExecutor normalizes the first coefficient to one; the homogeneous certificate equations allow the larger full five-coefficient vector. Executor agreement in the affine chart does not validate all homogeneous parameter charts, though the symbolic full-rank certificate covers them when correctly reconstructed.

The five-term N4 mapping count is 24*24=576. N8 has 336*1680=564480 mappings; N16 has 3360*43680=146764800. The six-term control is exhaustive only at N4 and sampled otherwise. The seven-term control is explicitly sampled. The independent_audit.py label does not mean independent family construction: it imports the same generator, lifting and determinant helpers. Its selected set includes mandatory indices plus a random set, so actual sample count is explicitly recorded rather than guaranteed equal to its count argument. The build_input wrapper has argument parsing and file writes at top level, another reason not to import it during inspection.

## Evidence boundary and corrections

This pass establishes complete static reading of these twelve exact source versions and identifies concrete validation, cost and portability gaps. No historical C++ run, large-rank file, reported timing or uploaded unittest suite was rerun. No newly accepted all-input FFT, generic nonexistence theorem, asymptotic speedup or publication novelty follows. Previously independently reconstructed Phase31 mathematical exclusions retain their own narrower seals; these code defects must not silently invalidate or certify them.

A reproducibility repair would pin every imported module, validate permutations in linear work, reject incomplete index records, validate index ranges, and either recompute every claimed certificate or supply fully bound independently checkable determinant witnesses. Such repairs are recommendations; the preserved source bytes are unchanged.
