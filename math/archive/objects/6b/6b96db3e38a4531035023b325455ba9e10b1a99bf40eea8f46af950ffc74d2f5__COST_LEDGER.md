# Phase17 — Full computation ledger and accepted complexity model

All statements distinguish **finite-field unit arithmetic**, **exact complex arithmetic**, **floating-point rounding**, and **bit complexity**. No free long FFT or uncharged input-dependent cache exists.

## Graph preconditioning and inverse

- Read all `N` fresh input entries: `N` field-word reads.
- Produce residual `r=Px` where `P=7I+S+2D^-1`: direct implementation at most `2N` multiplications and `N` additions, plus `N` output writes, `N` root-power accesses, support detection `O(N)`.
- Primitive root `omega`: one provided primitive root or exact root setup in an appropriate field; generating the table `omega^j` for `j=0..N-1` requires `N-1` multiplications. Prime search / roots of unity availability and bit lengths are **not** waved away as `O(1)` in a bit-complexity claim.
- Green `L=7I+2S+D`: precompute inverse diagonal in `O(N)` multiplications using a product tree/batch inversion plus one field inversion. Compute the affine homogeneous multiplier sequence in `O(N)`, including closure inverse. This setup is charged even for a single invocation.
- Given forcing `z`, cyclic Green solution is approximately `3N+1` field multiplications and `2N` additions with `O(N)` writes and memory (as recorded in the Phase16 exact ledger). Using a batch inversion and evaluating diagonal polynomials gives `O(N)` setup. The explicit code performs the same operations, though these are currently described by an upper-bound ledger rather than included in `PolyStats`.

## Rational forcing when `K=|supp(Px)|>=1`

- `K` source-index reads; `omega^j` may be formed by repeated squaring in `O(log N)` multiplications each or by a globally charged `O(N)` root table.
- Balanced product/sum tree of `A(t)/B(t)` from sparse source entries: `O(K log^2(K+1))` field operations. Denominator and numerator are rebuilt for every **new** source support; never assume a cache across unrelated inputs.
- Newton inverse `U=B^-1 mod t^H`, `H=2^ceil(log2 K)<=2K`: `O(K log K)` field operations. Setup is explicitly charged.
- Fixed-kernel NTT transforms of `B` and `U` are calculated **once per input** and recorded by `cached_kernel_transforms`. NTT stage twiddle powers are likewise precomputed once per call using charged modular exponentiation and root multiplications (`twiddle_tables_built`, `twiddle_plan_setup_mults`), and reused across short NTT calls (`twiddle_table_hits`). Every subsequent block incurs `cached_kernel_hits`, its own variable operand forward transform, its pointwise multiplication, inverse transform and output writes. There are `ceil(N/H)` blocks, each of cost `O(H log H)`. The first block uses the numerator; subsequent blocks each have **two** fully charged convolutions.
- Integer indexing, block past windows, support index splitting, cache invalidation and temporary space: `O(N+K log K)` operations/words in a conservative implementation, subsumed in the sparse branch arithmetic bound for word-index RAM with `K<=N`.
- The main `N`-length DFT is **not** executed on the sparse branch. Short NTTs of sizes `O(K)` are executed and charged. This is a *conditional* `O(N log(K+1)+K log^2(K+1))` algorithm, not unrestricted `o(NlogN)`.

## Generic fallback

- When `K` is large, use exact Bluestein over suitable finite fields. Build the chirp phase and inverse chirp in `O(N)` scalar arithmetic (using successive-square exponent recurrence). Require `2N | p-1` for the implementation's chirp-root convention. Its three length-`M` power-of-two NTT calls, pointwise products and inverse scaling are charged; `M=2^ceil(log2(2N-1))=Theta(N)`.
- Field arithmetic bound `O(NlogN)` with `O(N)` scratch. For arbitrary exact complex transform lengths, Bluestein's usual algebraic identity similarly gives an `O(NlogN)` arithmetic routine under an appropriate root-of-unity model. Establishing an all-size fast **bit** algorithm requires separate work.
- `AllLengthGreen.transform(method='auto')` selects the sparse branch only when `K<=max(2,floor(N/max(4,floor(log2 N)^2)))`. This conservative finite-size heuristic is not an optimizer for wall-clock performance. Explicit `method='rational'` still works for all `K`; asymptotically any polylogarithmic `K` enters this sparse branch.

## Precision and limits

The complex Green operator has `cond_2<=2.5`; this bounds error propagation through `L^-1`, **not** the intermediate coefficient growth of the rational generating function. Clustered phases can produce `B(t)` coefficients approaching `binom(K,K/2)`. Do not claim a bit-complexity breakthrough from the finite-field gate counts. The finite primes and selected lengths do not imply existence of uniformly small suitable primes for every large N. Adaptive support selection is data-dependent and fully charged, and generic inputs have full residual support.
