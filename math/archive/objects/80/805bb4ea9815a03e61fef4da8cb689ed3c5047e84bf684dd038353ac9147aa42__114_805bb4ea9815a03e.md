# Phase 11: Fresh-input structured convolution research

Unlike Phases 5–10, Phase 11 **does not require an earlier transform or known edits**. It tests the user's idea `AB=(A−k)B+kB` by automatically looking for short recurrence / annihilating filters and multiplying sparse transformed operands.

**Outcome:** exact `O(N)` field-arithmetic convolution for an identified class of *fresh structured* inputs. Correct O(N log N) NTT fallback for general modular inputs **within the supported root-of-unity lengths of the selected prime**. No universal DFT bound, no special OpenAI #130 implementation, no claim of new research priority.

## Install and run

The exact algorithms and tests use **Python 3.10+ standard library only** (no NumPy or SciPy needed).

```bash
cd fft_phase11_fresh_factor
python -m unittest discover -s tests -v
python barrier_audit.py
python benchmark.py --sizes 256 1024 4096 8192 --repeats 3
python benchmark_near_power.py
```

## Use

```python
from fresh_factor import convolve, multiply_near_power, multiply_int

p = 998244353
A = [7]*1024
B = [1, 4, 8, 2] * 256
output, plan = convolve(A, B, mod=p)
print(plan.method, plan.qa, plan.nnz_a) # structured, (1,-1), 2

# Exact signed integer convolution, no modulus:
coeff, plan = convolve([3,3,3,3], [2,1,4])
assert coeff == [6,9,21,21,15,12]

# Integer multiplication, near a power of two:
a=(1<<1024)-1
b=(1<<1000)+17
prod, explanation = multiply_near_power(a,b)
assert prod==a*b
print(explanation)

# Integer multiplication via digit convolution (research/demo API):
prod, plan = multiply_int(1234,5678)
assert prod == 7006652
```

`convolve(..., mod=998244353)` uses exact modular NTT for fallback. `convolve(..., mod=None)` uses multiple NTT primes and CRT for bounded outputs and exact schoolbook fallback for coefficients outside its CRT budget. The bounded-degree candidate library and BM discovery are verified algebraically; screening samples can miss speed opportunities but cannot produce incorrect answers.

## Files

- `fresh_factor.py` — canonical polynomial-filter identities, sparse product, inverse recurrence, Berlekamp–Massey finder, exact modular NTT, CRT, integer shift shortcut, cost-aware planner
- `tests/test_fresh_factor.py` — correctness on arbitrary random inputs, structured recurrences, full signed integer results, modular results, inversion identities
- `barrier_audit.py` — exhaustive small-size bijection and sampled random-input obstruction
- `benchmark.py` and `benchmark_results.json` — identical-output exact finite-field performance comparisons
- `benchmark_near_power.py` and `benchmark_near_power_results.json` — integer shift shortcut versus built-in integer multiplication
- `RESEARCH.md` — full proof, limitations, worst-case analysis, literature links

**Read `RESEARCH.md` before claiming a breakthrough.** The asymptotic savings are restricted to low-recurrence inputs and are established consequences of known algebraic methods.

## Important benchmark boundary

`python benchmark_native.py` optionally compares the research Python implementation against highly optimized SciPy on small, exactly roundable integer data. It confirms that SciPy is much faster in wall-clock time. The exact modulo-prime NTT baseline is the proper equal-arithmetic-model reference; neither benchmark establishes a fresh arbitrary FFT improvement or superiority to native FFT libraries.
