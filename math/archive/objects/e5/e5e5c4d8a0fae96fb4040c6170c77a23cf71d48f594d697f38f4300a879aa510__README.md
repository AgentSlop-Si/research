# Selective binary FFT caching experiment

Measured 8 October 2026. This bundle contains runnable experiments and raw timing
samples for replacing full FFT hash-consing with fixed small binary-input leaf
lookup tables.

## Start here for the runnable implementation

The reusable C/Python API is in c_experiment/adaptive_fft.py. Read
c_experiment/ADAPTIVE_README.md for complete examples. For one-off or short
workloads, use the explicit no-calibration arithmetic plan first. From
c_experiment (or after adding it to your Python path):

```python
import numpy as np
from adaptive_fft import BinaryFFTPlan
x = np.random.default_rng(7).integers(0, 2, 65536, dtype=np.uint8)
with BinaryFFTPlan(len(x), x.dtype, method="codelet8") as plan:
    y = plan.execute(x)
    assert plan.calibration_count == 0
```

For heavy repeated use, get_plan(len(x), x.dtype) calibrates once and caches the
choice; subsequent plan.execute(x) calls do not retune. Autotuning is optional
and expensive: about 0.44–0.81 seconds for smaller tested sizes, 4.02 seconds at 1M.
At N = 4096 its measured saving versus fixed arithmetic8 needed roughly 317,000
transforms to repay calibration. At N = 65536 the selector chose arithmetic8, so
there is no demonstrated payback over choosing that kernel directly.

The selector chose the fastest held-out kernel at 3 of 5 sizes. Its conservative
8% lookup margin intentionally missed a 6.4% held-out gain at 16k and a 0.6% gain
at 65k. It is not guaranteed to choose the fastest kernel on future workloads.
All numerical, input-guard, cache/lifetime, buffer-ownership and native safety
tests passed. Raw held-out and API measurements are included.

## Main conclusion

The 8-bit table improved the Python prototype by 1.53–1.65x over the matching
warm-plan uncached FFT. In compiled C with stronger arithmetic codelet controls,
it improved small transforms (1.20x at N=4096 and 1.08x at N=16384). At N=65536
the small difference changed sign between runs; at 262144 and 1048576, arithmetic
codelets were faster. Full 16-bit lookup tables were too expensive in memory
traffic for larger transforms. These are implementation-specific measurements,
not a claim of a general FFT speedup or a new asymptotic bound.

## Reproduce

Requires Python 3 with NumPy and SciPy, and GCC for the C experiment. No script
installs packages or accesses the network. Scripts locate source files relative
to their own locations, so the extracted folder can be placed anywhere.

Python comparison (three sizes, three random seeds, five samples per seed):

    python3 python_experiment/benchmark_python.py

Native initial run, including practical NumPy/SciPy comparisons:

    python3 c_experiment/benchmark.py --output c_experiment/results.json

Native longer confirmation:

    python3 c_experiment/benchmark.py --rounds 21 --target-ms 100 --skip-practical --output c_experiment/results_confirmation.json

Quick native correctness/timing check:

    python3 c_experiment/benchmark.py --quick

Existing result files are the observed runs. The commands may replace them; copy
those JSONs elsewhere first if you want to retain the original measurements.

## Boundaries

All inputs are independently generated binary values; all full FFT variants
return all complex128 bins. Actual permutation/gathering, key packing and table
output copying are inside timed execution. Reusable plans and table creation
are measured separately. The compiled experiment preallocates output; NumPy and
SciPy calls allocate, so cross-library numbers are not matched kernel comparisons.
Real rfft returns only half a spectrum and is labeled separately.

The native harness verifies all 65,536 possible 16-bit table rows and 630 complete
FFT cases through N=1048576. ASan/UBSan passed. LeakSanitizer could not operate
under sandbox tracing; leak detection remains unverified. Python correctness
checks cover every timed method and exhaustive 4/8-bit tables.

Run on your intended hardware before choosing a production cutoff. This was a
single virtualized AMD EPYC system with uncontrolled neighboring load. A packed
16 KiB Hermitian 8-bit lookup table is a possible next experiment, not a measured
result included here.
