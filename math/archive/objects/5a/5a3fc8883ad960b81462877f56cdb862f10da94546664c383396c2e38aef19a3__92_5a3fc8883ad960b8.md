# FFT research checkpoint — 2026-10-09

## Confirmed baseline

1. Adaptive Python engine supports exact repeats, shifts, sparse edits, low-rank families, shared DAGs and packed real FFT tricks.
2. C++/FFTW port showed Python bookkeeping was only part of the cost. Exact repeats win at large N; shift/sparse reconstruction is often memory-bound.
3. Dynamic known-k sparse updates admit pruned work `O(N(1+log(k+1)))`; for `k=N^{o(1)}` this is `o(N log N)`. Single known edit is Theta(N) for a materialized dense spectrum.
4. This dynamic result is not a universal fresh-input DFT breakthrough; related incremental/pruned FFT prior art exists.
5. Current OpenAI exact-DFT work (Sep 25 2026) already gives a universal exact complex-arithmetic all-length bound below `N log N`, with published exponent decrement `1e-13` and enormous constants.

## Small finite-win search

A finite win is a word computing `A^(tensor b)` with fewer than `b q^(b-1)` calls to `A`, with monomial maps free between calls.

For dense `q=2`, support propagation is the telephone/gossip process. Full 16x16 support at `b=4` needs at least 28 calls; the ordinary tensor network uses 32. Therefore b=4 is the first combinatorially possible exponent for a small win.

### Fixed Fourier kernel C, b=4

- 28-call support-optimal schedule: repeated optimization stalls at relative Frobenius error about `0.787225834`.
- Best support-complete 31-call near-hypercube schedule initially reached `0.668891845`.
- Outer topology sweep found a better 31-call schedule with error `0.6128978600864178`.
- Long Adam + L-BFGS refinement reproduced exactly `0.6128978600864178`; max intermediate condition about `4.04`.
- Thus no tiny certificate was found; these are computational failures, not impossibility proofs.

### Arbitrary 2x2 kernel reduction

Any dense 2x2 matrix is diagonal/permutation-equivalent to

`A_t = [[1,1],[1,t]]`.

Every allowed local call in the same double-diagonal class obeys

`B11*B22 = t*B12*B21`.

This reduces the entire dense 2x2 finite-win family to one complex cross-ratio parameter `t`, plus topology and gate weights.

Large-|t| Frobenius fits looked artificially good (e.g. ~0.188 at t=-8) because the target becomes entry-imbalanced. Entrywise-relative objectives removed this false signal; no near-exact certificate emerged.

### Fixed C, b=5

- Standard: 80 calls.
- A support-complete 79-call topology was found.
- Quick optimization stalled near `0.77665124`.
- Again: failure, not proof of impossibility.

## Strongest new candidate: retune the published explicit network

The published explicit construction fixes `h=100`, but its own proof gives the general margin

`Delta(h) = 2*C(h,3)^2 * ( C(h,3) - 3 h(h+1) )`.

Positive margin starts at `h=22`.

The physical role count for general h is

`v=C(h,3)`

`d_nbr=C(h-3,3)+3(h-3)`

`N0=v^3`

`I0=3v^2`

`W=2N0 + I0*(v*d_nbr+h+1)`

`m=h^3`.

Pad to `W_*=2^p`, where `p=ceil(log2 W)`, and use

`lambda = m - Delta/W_*`, `theta=log_m(lambda)`.

### h=24 candidate

- `h=24`
- `v=2024`
- `m=13,824`
- `W=34,666,942,577,344`
- `W_*=2^45=35,184,372,088,832`
- `Delta=1,835,266,048`
- `lambda=13,823.9999478386...`
- `theta=0.9999999996042389976...`
- `1-theta=3.9576100...e-10`

This is about **1,879x larger raw exponent saving** than the h=100 constants in the manuscript.

The manuscript-wide audit found no later intrinsic use of h=100. The hard-coded `71` elsewhere is `log2(W_*)`; for h=24 it becomes 45. The synthesis certificate changes from `b=mf+71` to `b=mf+45` with the same inequality form. The tensor recursion base threshold becomes

`K=m*(45+1)=635,904`.

A conservative retuned all-length corollary is therefore a candidate

`T(n)=O(n (log n)^(1-3e-10))`.

This is still an exact-unbounded-complex-arithmetic theorem, not a practical stable FFT. It also has not been separately Lean-formalized or peer-reviewed. Existing formalization corresponds to the published constants.
