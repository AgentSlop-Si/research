# Direct cold recurrence evaluation, including zero and singular shifts

This checkpoint replaces the previous cold target's generic preparation and
cyclic solve with a direct recurrence. It also removes both excluded-shift
cases: lambda=0 and lambda^N=1. Complete exact Fourier outputs are returned,
and automatic shift discovery, residual verification, coefficient preparation,
and every output are paid.

The result remains a **verified structured-input algorithm**, not a faster
FFT for every fresh input. It does not satisfy the new material's global gate
of an input-independent sub-N-log-N evaluator for arbitrary complex vectors.
The rectangular-support material also remains compatible with this result:
the implementation still pays for every sparse-defect Fourier contribution;
it does not improve arbitrary support expansion.

## Exact accepted family

Supply dyadic N>=4, a primitive Nth root q in an exact field, a complete fresh
input x, and a nonnegative support cap s. Define the previously verified
intertwining pair

    E[i,i]=-q^i,
    E[i,i+1]=-q^i(q^(i+1)-1),  i<N-1,
    (J y)_i=(q^(-i-1)-1)y_(i+1)-q^(-i-1)y_(i+2),

with cyclic output indices and positive-sign Fourier matrix F. Then FE=JF.

Automatic `try_extended_fourier` accepts exactly the union of:

- inputs with at most 2s nonzero coordinates;
- inputs for which some field scalar lambda, now **including zero and roots
  of unity**, gives at most s nonzeros in u=(E-lambda I)x.

If m, the number of nonzero input coordinates, is at most 2s, direct sparse
evaluation returns all outputs. Otherwise any such lambda occurs at least
m-s>m/2 times among `(E x)_i/x_i` on nonzero coordinates. The existing exact
Boyer-Moore ratio comparison therefore discovers it in O(N) work, using
cross-products and at most one paid inverse. Every residual coordinate is
then checked, including positions where x_i=0. Failed discovery or excessive
residual support causes an O(N)-work decline. Outside the independent sparse
fallback, a supplied shift can instead be verified through the same interface;
it is not trusted as a valid relation.

The residual Fourier vector b=F u costs O(N(s+1)), using the already generated
q-power table. The remaining task is to recover F x from

    (J-lambda I)y=b.

The algorithm below solves this equation together with explicit information
from the actual input. That information is essential when the shifted
operator is singular.

## Zero shift: one scan, no inverse

For lambda=0 let v_i=y_(i+1). The target equation becomes

    v_(i+1)=(1-q^(i+1))v_i-q^(i+1)b_i.

At i=N-1, q^N=1, so cyclic closure sets `v_0=-b_(N-1)`. Starting from that
value and scanning i=0,...,N-2 produces every y coordinate. This uses exactly
4N-3 field operations, including all transition coefficients. There is no
triangular source inverse, closure-matrix preparation, or field inversion.

## Nonzero shift: scalar closure, then a missing-coordinate constraint

First compute the actual Fourier coordinate `y_0=sum_i x_i` in N-1 additions.
For every remaining row, the target equation gives

    y_(i+2)=(1-q^(i+1))y_(i+1)
              -lambda*q^(i+1)y_i-q^(i+1)b_i.

With y_1 still unknown, propagate `y_i=p_i+h_i*y_1`, starting from
`p_0=y_0, p_1=0, h_0=0, h_1=1`. Two exact scalar closure equations remain:

    h_N*y_1 = y_0-p_N,
    (1+lambda*h_(N-1))*y_1 = -b_(N-1)-lambda*p_(N-1).

If either coefficient is nonzero, it determines y_1. Both closure equations
are checked before output, and all y_i are then emitted. The complete target
cost is exactly 13N-5 field operations, including coefficient preparation,
the y_0 input sum, one inverse, both checks, and every output value.

If both coefficients vanish, consistency requires both right-hand sides to
vanish. The nonzero vector h is then a null vector of J-lambda I. Because F
is invertible and E is triangular with distinct diagonal entries -q^t,
there is a unique t with `lambda=-q^t`; its source eigenspace has dimension
one. If z=F^-1 h, backward substitution in `(E-lambda I)z=0` gives z_i=0
for i>t, and z_t cannot be zero without making z identically zero. Therefore

    sum_i q^(-it)h_i = N z_t != 0.

The **known input coordinate** x_t supplies the missing equation

    sum_i q^(-it)y_i = N x_t.

Two geometric-progression dot products give its coefficients on p and h;
one paid inverse determines y_1. Finding t scans the paid q-power table.
The field constant N is constructed with log_2 N doublings. This exceptional
target branch costs exactly `18N+log_2 N-3` field operations plus O(N) equality
and indexing work. It performs one inverse-Fourier coordinate sum, not a
complete hidden inverse transform.

For a singular shift, u=0 does not imply x=0 or F x=0. The input constraint
recovers this missing kernel component. The audit includes every source
eigenvector in each small configuration, and a finite-field case forcing the
exceptional branch: F_5, N=4. Simply inverting a zero denominator or returning
zero for a zero defect would fail these tests.

## Cold work and measured gate ledgers

All accepted inputs take O(N(s+1)) exact field/word work and O(N) live field
elements. No source inverse data, dense matrix, Fourier anchor, or ordinary
FFT is prepared by the new evaluator. The ordinary FFT appears only as an
independent same-input audit comparator.

For a dense one-defect input in the nonzero ordinary-closure branch, the
automatic cold count is exactly `25N-10`, versus the previous detector's
`42N+log_2 N+3`. For a dense one-defect input whose detected shift is zero,
the new count is `14N-10`; the previous detector declined that family.

| N | New nonzero-shift route | Previous detector | Ordinary radix-two comparator |
|---:|---:|---:|---:|
| 128 | 3,190 | 5,386 | 1,479 |
| 512 | 12,790 | 21,516 | 7,433 |
| 2,048 | 51,190 | 86,030 | 35,851 |
| 8,192 | 204,790 | 344,080 | 167,949 |
| 131,072 | 3,276,790 | 5,505,044 | 3,473,425 |

The new zero-shift route at N=8192 costs 114,678 field operations versus
167,949 for the ordinary comparator on the exact same fresh dense input.
Both comparisons charge full discovery/preparation and return the same full
output. Inputs are provided identically; fixture generation is outside both
evaluation ledgers. Smaller nonzero-shift examples still lose to the ordinary
FFT. These are instrumented scalar counts, not timings or a comparison to
every optimized FFT implementation. A restricted family beating this selected
comparator does not establish a worst-case improvement.

Every counted add, subtract, multiply, negate and inverse is a unit exact-field
operation. The inherited name `constant_inverse` includes paid input-dependent
inverses here. This is an adaptive rational algorithm with exact equality tests,
not an input-independent linear circuit. Field-element bit size, root discovery,
and numerical conditioning are separate. Root and field validity are supplied
preconditions. Logical scans, copies, comparisons, addressing, and all output
writes are covered by the work bounds, not represented as exhaustive physical
memory or Python instruction counts.

## Files and verification

Run `python audit.py`. The audit checks 368 exact complete outputs, 13 dense
declines and four invalid-argument controls over 13 prime/cyclotomic
configurations and larger prime-field comparisons. It exercises zero shift,
each closure choice, and the singular missing-coordinate branch. Every returned
field ledger is independently matched by an outer counted-field wrapper and
by its stage sums. Small outputs use a dense DFT oracle; large outputs use an
ordinary radix-two DFT. The finite checks audit the program; the formulas above
prove the all-size conditional identities and complexity.

`extended_recurrence.py` is new. It reads the earlier exact-field counting and
sparse Fourier helper through the sibling `fft_rational_reuse_research/`;
that folder's established helper dependencies must remain present. The audit
also reads the earlier ordinary FFT comparator in `fft_qbasis_research/`.
No old checkpoint was modified. `results.json` retains all stage and comparator
ledgers. Mathematical ingredients—recurrences, majority voting, linear-system
closure, and Fourier coordinate constraints—are standard; no priority claim
is made for them.
