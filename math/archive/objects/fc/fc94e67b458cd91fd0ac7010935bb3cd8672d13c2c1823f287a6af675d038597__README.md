# Relation-Aware Fourier Research — Phase 4

This package continues the FFT / shared-computation-graph investigation.

**Goal:** test whether caching becomes more useful as transform length grows when different requests share a reference input and are described by a small number of known edits. Experiment with postponing full-spectrum output and reusing phase-vector computations.

## Files

- `lazy_fft.py` — lazy delta log, constant-metadata-time edits, one-frequency queries, selected-frequency subscription, forked shared-reference transforms, dense-output path, exact modular identity check
- `phase.py` — FFT phase-vector preparation with one local tile and a vector of tile starting phases
- `test_lazy_fft.py` — automated correctness tests
- `benchmark.py` — 40-update workloads: full spectra, 8 bins, and only one final spectrum
- `benchmark_phase.py` — direct vector exponentials vs tiled phases and full FFT
- `benchmark_branches.py` — 64 distinct variants from one cached transform
- `RESEARCH.md` — mathematical bounds, cost assumptions, measurements, limits, prior art
- `benchmark_results.json`, `phase_benchmark_results.json`, `branches_benchmark_results.json` — logged benchmark data

## Example

```python
from lazy_fft import LazyRealFFT

root = LazyRealFFT([3, 1, 4, 1, 5, 9, 2, 6])
version_a = root.fork()
version_b = root.fork()
version_a.edit(2, +7)
version_b.edit(5, -3)

# Each version shares the original cached FFT.
print(version_a.frequency(1))
print(version_b.frequencies([0, 1, 2]))
print(version_a.materialize_direct())  # explicitly compute all outputs
```

All FFT computations using SciPy are numerically approximate, unlike the #130 exact field-operation claim. Expected O(1) edit cost assumes standard dictionary hashing and producer-supplied edit metadata; hashing unrelated full signals is not free. No claim of a new universal sub-NlogN FFT or integer multiplication bound is made.
