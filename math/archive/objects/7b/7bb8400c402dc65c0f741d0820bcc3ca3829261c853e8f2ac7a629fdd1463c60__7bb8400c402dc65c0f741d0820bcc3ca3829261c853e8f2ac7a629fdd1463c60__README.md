# Exact aggregation for a high-degree q-Weyl tail

9 October 2026. This package gives a constructive restricted improvement:
for every fresh N-vector x, it evaluates all N coordinates of

\[
L_{N,r}x=C^{N-r}p(C)x,\qquad \deg p<r,
\]

using **O(N log(r+1)) field operations including cold preparation**, and
O(N) field storage. Only FFTs of length 2r occur. The operator has rank at
most r; it has rank exactly r when p(0) is nonzero. In particular, the last
r terms of H_q(C) can be evaluated this way, but this is **not** an
O(N log(r+1)) algorithm for the complete, invertible operator H_q(C).
It does not establish an exact sub-N-log-N FFT for arbitrary fresh inputs.

The reusable mechanism is a projected inverse convolution, an r-dimensional
polynomial action, and a full decoding convolution. The projection sums
block spectra before one inverse transform. The decoding transforms its
small input only once and shares it across all output blocks. These are
standard block Toeplitz/middle-product and FFT reuse techniques, applied
here to the existing q-Weyl similarity. No general novelty is claimed.

## Exact assumptions and operators

N and r are powers of two, N>=2 and 1<=r<=N/2. Arithmetic is over a field
containing a **supplied primitive Nth root q**, with N nonzero in that field.
Root finding and the bit cost of representing field elements are outside
this unit field-operation model. There is one charged inversion of the
constant 2; no input-dependent division occurs.

Since 2r divides N, every small transform uses the available root
q^(N/(2r)). The fast tail implementation does not require a primitive 2Nth
root. The endpoint r=N is deliberately excluded: this particular cyclic
embedding would require a length-2N transform and an additional root or a
different multiplication backend. Even such an extension would cost
O(N log N), not improve the full-operator exponent.

Recall the already verified operators from `fft_qweyl_boundary_research`:

\[
f_j=\prod_{a=1}^j(1-q^a),\quad
t_j=1/f_j,\quad
d_j=\frac{(-1)^j q^{j(j-1)/2}}{f_j},\qquad f_0=1.
\]

Let A be the lower shift, T=H_q(A), H_q(z)=sum_(j=0)^(N-1) t_j z^j.
T is lower triangular Toeplitz with kernel t; its inverse is lower
triangular Toeplitz with kernel d. The weighted upper shift B has entries

\[
B_{i,i+1}=b_i=q-q^{-i}\quad(0\le i<N-1).
\]

The actual boundary-corrected sparse operator is

\[
C=B+\operatorname{diag}(q^{-i})-\frac qN A^{N-1}=TBT^{-1}.
\]

In particular C is similar to one nilpotent Jordan block: C^N=0 and
rank(C^k)=N-k for 0<=k<=N. The corner term is retained throughout.

Set g_0=1 and g_j=product_(a=0)^(j-1) b_a. Every g_j is nonzero and

\[
g_j=(-1)^j q^{-j(j-1)/2}f_j,\qquad
g_j^{-1}=d_j,\qquad B=G^{-1}A^T G,
\]

where G=diag(g). Thus no separate inversions are needed for the g table.

## Projection, small action, and decoding

Put z_j=(T^-1 x)_(N-r+j) for 0<=j<r. Directly from the similarity,

\[
v_j=g_{N-r+j}z_j,\qquad
u_i=d_i\sum_{k=0}^{r-1-i}p_k v_{i+k},\qquad
y=T(u_0,\ldots,u_{r-1},0,\ldots,0)^T.
\]

These equations are exactly y=L_(N,r)x. The middle expression follows
from applying (A^T)^(N-r)p(A^T) to G T^-1 x: only the last r input
coordinates and first r resulting coordinates can participate.

There are b=N/r input/output blocks. For a kernel a and an r-by-r Toeplitz
window a_(h+i-j), form a length-2r cyclic kernel with entries

- c_k=a_(h+k), 0<=k<r;
- c_(2r-k)=a_(h-k), 1<=k<r;
- c_r=0, and out-of-range kernel indices interpreted as zero.

The first r entries of the cyclic convolution with an input block padded
by r zeros are the required window action. Indices i-j lie strictly
between -r and r, so the positive and negative embeddings cannot alias.

For the projected inverse convolution, input block b0 has center
h=(N/r-1-b0)r in kernel d. Compute each input block's length-2r FFT and
multiply by its prepared window spectrum. Sum all those spectra and
perform **one inverse FFT** to recover the entire r-entry projection.

The small upper triangular polynomial map is one length-2r cyclic
convolution, with p_k stored at cyclic index -k. Its first r coordinates
give the sum in the displayed formula for u.

For decoding, output block b0 has center h=b0*r in kernel t. One FFT of
the padded u serves all blocks; each window needs a diagonal product and
one inverse FFT. Each block returns its first r coordinates, writing all
N coordinates of y. No length-N FFT is hidden in either phase when 2r<N.

This also proves the rank claim. If p_0!=0, p(C) is invertible and
rank(L_(N,r))=r. More generally, if p has valuation v, the rank is r-v;
the zero polynomial has rank zero. The default p_k=t_(N-r+k) has p_0!=0.

## A weighted aggregate of all N resolvents

The same map is the exact aggregate

\[
\boxed{
C^{N-r}p(C)=\frac1N\sum_{\lambda^N=1}
\lambda^{1-r}p(\lambda)(\lambda I-C)^{-1}.
}
\]

To prove it, expand (lambda I-C)^-1 as
sum_(k=0)^(N-1) C^k lambda^(-k-1). The coefficient sum contains
lambda^(j-r-k); averaging over the N roots is zero unless
k=N-r+j, where it is one. The bounds 0<=j<r ensure no second survivor.

Thus the algorithm genuinely aggregates N resolvent actions without
performing N vector scans. All N weights can be nonzero: choose any
nonzero constant p, which gives weights p_0 lambda^(1-r)/N. For fixed r,
the whole fresh-input/full-output aggregate costs O(N). For r=N^o(1),
it costs o(N log N). These statements concern this rank-at-most-r
aggregate only. The original H_q(C) has nonzero constant coefficient and
rank N; its complete resolvent weights do not have this high-degree-tail
restriction. The already known r=1 case is included as a consistency
check, rather than claimed as a new discovery.

## Full arithmetic ledger

Put L=log2(N), s=log2(2r), b=N/r,

\[
P=(2N+r)s,\qquad V=(2N+4r)s.
\]

The implementation charges ordinary radix-two butterflies even when a
twiddle equals one. Every inverse FFT's normalization is charged.

| Operation | Cold preparation | One fresh-vector action |
|---|---:|---:|
| Field multiplications | 8N+L-5+P | V+6N+8r |
| Field additions | L-s+P | V+2N-2r |
| Field subtractions | 2N-2+P | V |
| Field negations | N-1 | 0 |
| Constant inversions | 1 | 0 |
| Forward length-2r FFTs | 2b+1 | b+2 |
| Inverse length-2r FFTs | 0 | b+2 |

Preparation includes the complete earlier q-factorial table preparation,
including a few unused constants, a new root table, all g prefix products,
all window spectra, the p spectrum, and the bit-reversal permutation.
The inverse transform length is obtained as (N/(2r))*(1/N), using L-s
doublings and one multiplication, without a second inversion.

Two window-spectrum banks store 4N values, and the middle spectrum stores
2r values. The other permanent arrays and peak live temporary space are
O(N). Every input coordinate is read and every output coordinate written.
Window construction, padding, copies, spectrum accumulation, integer
indexing, bit reversal and all butterfly traffic take O(N log(r+1)) word
operations. The explicit traffic metadata describes logical arrays, not
every allocation/reference operation of Python list expressions; those
extra operations satisfy the same asymptotic bound. No floating-point
stability or bit-complexity result is implied.

## Comparators for the same target

`full_similarity.py` evaluates **the same** C^(N-r)p(C) by the ordinary
full-length identity T G^-1 (A^T)^(N-r)p(A^T) G T^-1. Three full
convolutions need three forward and three inverse length-2N FFTs.
This comparator takes a separately supplied primitive 2Nth root eta
with eta^2=q; no free construction of this extra root is assumed.

Its online counts are 6NL+20N multiplications and 6N(L+1) each of additions
and subtractions. Its cold counts are 3NL+12N+2L-4 multiplications,
3N(L+1)+2N-2 subtractions, 3N(L+1) additions, N-1 negations and two
constant inversions. The extra inversion is a conservative duplication
between imported preparation routines. This is a straightforward general
polynomial comparator, not a best-constant implementation.

For N=64, sums of the separately listed field operation types are:

| r | Tail FFT length | Tail preparation | Tail online | Full similarity preparation | Full similarity online |
|---:|---:|---:|---:|---:|---:|
| 1 | 2 | 1095 | 914 | 4807 | 8960 |
| 2 | 4 | 1487 | 1340 | 4807 | 8960 |
| 4 | 8 | 1894 | 1832 | 4807 | 8960 |
| 8 | 16 | 2337 | 2480 | 4807 | 8960 |
| 16 | 32 | 2864 | 3488 | 4807 | 8960 |
| 32 | 64 | 3583 | 5312 | 4807 | 8960 |

These are exact instrumented field-operation totals, not wall-clock
benchmarks or arithmetic weights for a native implementation. Direct
degree-(N-1) C-Horner evaluation is also included as a correctness oracle;
it is quadratic and is not the best asymptotic comparator. The complete
H_q(C) Fourier comparator in `fft_qweyl_resolvent_research` computes a
different operator and is therefore not used for a numerical speedup
claim here. Ordinary full similarity already caps the same-target cost
at O(N log N); the contribution here is its dependence on r.

## Prior work and remaining problem

The middle-product and FFT-reuse ingredients are established techniques.
Hanrot, Quercia and Zimmermann, *The Middle Product Algorithm I*, AAECC 14,
415-438 (2004), DOI [10.1007/s00200-003-0144-2](https://doi.org/10.1007/s00200-003-0144-2),
develop efficient computation of selected product coefficients.
Joris van der Hoeven, [*Newton's method and FFT trading*](https://www.texmacs.org/joris/fnewton/fnewton_bis.html),
sections 2.4 and 6, discusses middle products and multiplication in smaller
FFT blocks; its introduction also explicitly discusses reuse of transforms
when one argument serves several products. The present package supplies a
checked application and complete cost accounting for our exact C operator,
not a claim to have invented block convolution or transform caching.

The outstanding full-operator problem is to handle the degree-zero through
degree-(N-r-1) part of H_q(C) at a correspondingly reduced cost, while
sharing the projected and decoded states across scales. Evaluating the
top tail faster does not provide that step, and recursively summing
independent tails cannot be assumed to improve the total without a new
shared computation and a complete recurrence.
