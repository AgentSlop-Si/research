# Coalesced single-view projected Fourier experiment

## Conclusion

This is a bounded, independent derivative of the supplied query-v2 projected view. It removes lifetime event-log retention/scanning for one fixed-bin consumer and changes the arithmetic crossover from update count H to distinct currently changed keys u. It does **not** improve arbitrary dense FFT complexity, discover the relation, or establish novelty.

In the final runtime measurements, coalescing beat the fastest tested alternative in **0 of 8 setup-inclusive workloads**. It still beat compacted original replay in some cases. Always-rebuild or eager updating was faster in every setup-inclusive comparison. Excluding setup, repeated-wide had a small 1.03× measured stream advantage (6.020 versus 6.198 ms); all other stream comparisons were losses. That small margin is not a robust established speedup. This final run supersedes the preliminary 1-of-8, 1.13× result: that version did not account adequately for dictionary tombstones after cancellations. The final implementation adds amortized update-side compaction and charges its cost. Seven-trial medians are measurements, not statistically established or universal guarantees.

## Contract and exact-arithmetic argument

The producer supplies x = sum_i c_i b_i + e, a fixed list of q requested bins, and the r-by-q projection P of the basis. Updates are trusted finite numeric relation metadata; keys are valid integer indices. Bins may repeat, q must be positive, rank r may be zero, and n must fit positive signed int64. Direct external mutation of internal arrays/dictionaries is unsupported. This version serves one view; it is not a multi-consumer replacement.

At the previous query let the state be (c0,e0), with cached projected value y0. On the first post-query edit of key a, save its prior value. Later edits replace only current metadata. If the current value returns exactly to the saved baseline, remove that pending entry. Re-editing a removed key correctly starts from its query-time baseline again.

In exact arithmetic, linearity gives y = y0 + sum_pending (current(a) − saved(a))·column(a). A coefficient column is a row of P; a point column is its q-vector of Fourier phases. Thus applying u pending differences and rebuilding from current r coefficients and k residual points are algebraically equivalent. Choose replay when u ≤ r+k, otherwise rebuild. Clear snapshots after answering. This induction relies on exact arithmetic; the implementation does not satisfy exact arithmetic.

## Honest costs and memory

- Expected amortized update work is O(1), using Python hash maps and fixed-word arithmetic. To prevent tombstones from hiding a larger query-time cleanup, updates rebuild the pending map when live size falls below one quarter of its previous high-water size, or clear it when empty. Those copies and old-map deallocations are charged to updates; geometric shrink costs amortize over preceding removals. Hash-table resizing and compaction mean this is not a worst-case latency guarantee for every edit.
- Projected arithmetic and output copying take O(q·[1+min(u,r+k)]).
- The implemented Python query additionally destroys u snapshot entries. Its full bound is **O(q·[1+min(u,r+k)] + u)**. Dictionary swapping would still decrement references and would not erase this cost.
- In particular, deleting a previously large residual can yield u≫r+k: q=1 and r=k=0 still require O(u) reclamation. The diagnostic measures this explicitly; no pending objects are parked for untimed future cleanup.
- Live numeric buffers and entries use O(rq+Pq+r+k+u+q), where P here denotes the number of prepared point positions (distinct from the projection matrix notation above). Actual Python allocation also has dictionary/tuple/scalar overhead and historical hash-table capacity. Pending-table capacity is reset on query and geometrically compacted during cancellations, keeping it proportional to current live u up to constant-factor hash-table slack. The sparse dictionary may retain capacity from an earlier larger support. Consequently the live-entry formula is not a strict resident-memory bound in current k alone.
- The projection is unconditionally copied into an owned contiguous r-by-q buffer. This fixes the inherited ascontiguousarray case that could retain a large r-by-N backing allocation. Inputs and returned query arrays are copied appropriately. Prepared point phases cost O(Pq) storage; they are not an O(N)-independent free resource if P grows with N.
- Initial projection construction is external to the data structure. The benchmark obtains it by a full NumPy basis FFT, charges that setup, and makes no improved preprocessing claim.
- Integer phase products are reduced modulo n before conversion to float. An int64-safe vector path is used when multiplication cannot overflow; otherwise Python integers compute residues. The latter is safe from int64 wraparound, but arbitrary-precision bit costs are outside the fixed-word complexity claim.

## Floating-point behavior: improvement and counterexample

Snapshot differences avoid blindly replaying requested deltas that did not change represented metadata. With identical unit projection rows, coefficients [1e16,−1e16], and a +1 edit to the first coefficient, represented state stays at zero. Original replay returns 1; the coalesced path returns 0.

**This does not make the coalesced path numerically exact.** Start one coefficient at 1e16, add −1e16, then add +1 before querying. Current metadata is 1, but subtracting the snapshot rounds (1−1e16) to −1e16. Cached replay returns 0; explicit rebase returns 1. This adversarial regression is deliberately included in the passing suite to record the limitation, not to disguise it as correct NumPy agreement.

Long-running incremental replay also drifts. The 20,000-query diagnostic observed maximum absolute error 3.21e-11 and final error 3.02e-11 against the FFT of current represented metadata; an explicit rebuild reduced final error to 1.82e-12. No certified forward-error bound or automatic stability-triggered rebuild is implemented. For ill-conditioned cancellation, use explicit rebasing/always-rebuild and assess error on the application’s scale.

For a single point at j=N−1 with N=2^20 and high requested bins, modular reduction reduced measured phase error from 4.25e-10 to 4.33e-16 relative to NumPy. This fixes the phase generator in this derivative and its comparator classes only; the supplied original remains unchanged.

## Matched-q benchmark methodology

Python 3.12.14, NumPy 2.3.5, Linux-6.18.44-x86_64-with-glibc2.41. OPENBLAS_NUM_THREADS=OMP_NUM_THREADS=MKL_NUM_THREADS=1. Input seed is fixed per workload. Seven matched trials use randomized method order after one warm-up/correctness pass per method.

All four methods receive the same precomputed basis projection, same prepared modular phase table, same coefficients/residual and same precomputed update sequences. The original engine source is unmodified. Its existing preparation fields and normalized initial sparse state are configured by the harness, and compact() is charged after **every** query. No stale-history scan is manufactured by withholding compaction. All methods return the same q bins, including a copy of each answer.

The common basis FFT and phase preparation are timed once per matched trial and charged equally to each method. Each method’s constructor, owned phase-table copy and initial reconstruction are timed. API-specific projection-copy overhead is retained: the derivative owns its projection; original may share the already-prepared projection. Stream totals include every metadata update, query, compaction/clear, answer retention and loop/timer overhead. Input RNG and NumPy correctness oracles are excluded for all methods. This is a small Python implementation comparison, not a compiled-kernel lower bound.

Every answer in the untimed warm-up streams is checked at its requested bins against np.fft.fft of current represented metadata: 24924 output-array comparisons across all methods, rtol=3e−10 and atol=3e−9. The maximum observed absolute error across these normal-scale workloads is 4.18e-10. The severe-cancellation counterexample above is separate and is not covered by this tolerance claim.

## Validation and scope

16 unit tests pass. They cover requested-all-bin random streams; repeated keys; exact cancellation; 20,000-query history without a retained event log; mass support deletion with reclaim accounting; cancellation-driven pending tombstone shrinking; duplicate bins, rank zero and q=1; input/output/projection ownership; sub-ULP metadata no-ops; high-index modular phases; int64 multiplication overflow fallback; prepared/on-demand phase equivalence; explicit rebasing; and basic shape/bounds. One test explicitly records the known severe-cancellation limitation. Thus “16 pass” does not mean universal numerical equivalence.

Only this new derivative and its tests/benchmarks were created. The copied original source is byte-for-byte preserved with SHA-256 provenance. No shipped binaries were executed. No dependencies were installed, external code fetched or repositories published. The report does not audit or replace the other files in the user’s archives.

Potential next work, not implemented here: a stable error-aware or periodic rebuild policy charged in total cost; compiled coalescing with honest reclamation; and multi-view ownership semantics. The present evidence supports a small specialized optimization and clearer accounting, not a new unconditional FFT bound.
