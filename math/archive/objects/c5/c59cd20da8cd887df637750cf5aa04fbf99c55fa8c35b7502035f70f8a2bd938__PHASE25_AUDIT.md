## 2. CRT factorization and output orientation

Let N=3G, G=2^t≥2, p prime, and ω have exact order N. Set a=3⁻¹ modulo G, b=G⁻¹ modulo 3, e_G=3a, e₃=Gb. The input indexing is

    j = e_G j_G + e₃ j₃ modulo N,

while the output indexing is

    k = 3k_G + Gk₃ modulo N.

Both maps are bijections. Expanding jk, the cross terms are multiples of N; the remaining coefficients satisfy 3e_G≡3 and Ge₃≡G modulo N. Hence

    ω^(jk) = (ω³)^(j_G k_G) (ω^G)^(j₃ k₃).

This proves the three dyadic transforms followed by G triple transforms, with no interstage twiddles. The inverse output map is k_G=a(k mod G) mod G and k₃=b(k mod 3) mod 3. The input CRT map must not be substituted for the output map. Eleven wrong-layout controls distinguish them explicitly.

This is established Good–Thomas/prime-factor FFT structure. [Burrus's own FFT notes, mirrored by FFTW](https://fftw.org/burrus-notes.html), identify the Thomas/Good index-map lineage and the developed prime-factor algorithms. The derivation above independently verifies this source's precise conventions; it makes no historical priority claim.

## 3. Triple codelet and exact graph arithmetic

Write η=ω^G. With t=b+c and d=b−c, the codelet uses

    y₀=a+t,
    mid=a−t/2,
    z=(η−η²)d/2,
    y₁=mid+z,  y₂=mid−z.

Since η+η²=−1, all three outputs equal the defining DFT₃. Characteristic 2 or 3 is excluded by the field/root hypotheses. With both fixed scalar products retained, the full graph uses six additions/subtractions and two multiplications. The partial costs are 2 for {0}, 6 for either singleton {1} or {2}, 7 for any two outputs, and 8 for all three. Memoization makes these costs independent of request order. All six orders are checked on 25 fresh triples across five field/root choices.

For G=2^t, each dyadic internal node has exactly one identity twiddle, at j=0. There are G−1 internal nodes, so omitting those products gives

    C₂(G) = Gt + Gt/2 − (G−1).

Thus the source's literal complete graph has

    C_GT3 = 3C₂(G)+8G = (9/2)Gt+5G+3.

The CT reference uses input rows x_(j₃+3j_G), the same row transforms, then factors ω^(j₃k_G) before the same triple codelet, with output k_G+Gk₃. Exactly two nonidentity twiddles occur for each 1≤k_G<G. Neither exponent k_G nor 2k_G is a multiple of N. Therefore

    C_CT3 − C_GT3 = 2(G−1).

These are costs of these particular programs, not optimal mixed-radix arithmetic counts. The ratio tends to one; no superconstant saving follows.

### Identity-coefficient exception

For N=6, p=7 and supplied generator 5, ω=5 and η=4. Then (η−η²)/2=1 in GF(7). `TripleCodelet` still performs and counts `self.w*self.d`. Consequently its literal cost is 8, whereas a policy that really omits *all* multiplication by 1 gives 7. The full literal GT graph costs 22; an additional codelet identity optimization would give 20. Both outputs are exact. The CT/GT difference of 2 remains, since both use the same codelet.

Proposed correction: define the current ledger as “skip j=0 dyadic and zero-exponent interstage twiddles, retain both triple scalar products,” or implement/check the extra coefficient-equals-one optimization and adjust the exceptional formula. The source's tested large fields do not encounter this exception.

## 4. Deferred mixed-radix queries

Map a fixed nonempty Q to grid indices and let J be its distinct dyadic k_G values. Each row-DIF graph requests J; each triple at j∈J computes only requested cube-coordinate outputs. The row theorem from Phase24 remains valid after dropping identity multiplications: an operation absent from the full graph is absent from both preview and completion. The triple DAG likewise memoizes each scalar intermediate. Thus preview followed by full completion executes each full arithmetic node once and totals C_GT3.

At the end of preview each row retains G−|J| backup scalars, so the three rows retain exactly N−3|J|. Triple caches add O(|J|) scalar/metadata words. This is the graph's fixed-batch backup count, not a general memory lower bound. Empty previews are rejected; duplicate requested indices are deduplicated.

At depth ℓ at most min(2^ℓ,|J|) dyadic nodes are active. Summing their sizes proves O(N log(q+1)) field work for q=|Q|, with O(N) for fixed q. The remainder still completes a Θ(N log N) graph.

The independent scheduler labels primitive operations and rejects any repeated label. It verifies every nonempty query subset at N=6 in two fields, larger selected query sets, singleton/full batches, and complete basis responses through N=96. All 372 basis columns match roots directly, without relying on the CT oracle. Repeated full completion keeps arithmetic counts unchanged on the intended lifecycle.

The inherited scheduler still needs a lifecycle guard if preview is called after full completion. The outer GT object's already cached triples may conceal corrupted row previews by returning old correct outputs, but arithmetic can be repeated and its fixed no-repetition count no longer describes that call sequence. The theorem is accepted for the declared preview-then-complete use, or a full-only use, not arbitrary reordered API calls. Reject post-completion preview or serve it purely from completed caches.

## 5. Cold setup, memory and ledger corrections

The GT root progression itself costs G−1 multiplications; its two triple constants can be prepared with the stated two multiplications and one subtraction under the source's ring-constant convention. Root derivation, exact-order checks, CRT integer inverses/indexing and bit costs are separate. However the actual implementation has further setup behavior worth retaining:

1. `ct3_baseline` builds a 2G-entry ω table, costing 2G−1 multiplications. It then calls `base_radix2_full` three times. Each call separately builds `roots=[pow(omega_G,k,p) for k in range(G)]`. These three dyadic tables are not part of the advertised CT cold-table figure. Under a standard leading-bit binary ladder their exponentiation work is three times Σ_(k=1)^(G−1)(bit_length(k)+popcount(k)−2), which is Θ(G log G). A shared recurrence-built G-root table would repair that schedule.
2. `transform_deferred_conjugate_gt3` constructs a new `DeferredGT3` each time, so it actually repeats the G-root progression and coefficient preparation even when the supplied Green engine already holds all N roots. Those operations are excluded from `work.arithmetic()` as setup. A cold/per-call total must add them, or explicitly implement a reusable plan/supplied-table API.
3. GT also derives ω³ and ω^G and validates the supplied generator-derived root. Those costs are outside the displayed graph formulas; primality is assumed, not proved by the code.
4. The copied Green compiler still has the previously identified counter omissions and root-extraction/nonresidue-search qualification. This phase does not fix them. The positive graph difference remains valid, while the Green “total_field_ops” column remains a partial proxy.

The source acknowledges startup input-row storage, N dyadic working values, G roots, backups, output storage and O(G) codelet/node caches. The codelet caches contain field scalars as well as metadata. `stats()` is not a complete count of all live Python references, allocations, input/output traffic or word operations. Per-row output bit reversal still does O(G log G) integer work in its literal implementation. These facts do not break the O(N)-word graph representation, but preclude reading the reported field columns as wall-clock or complete machine-cost measurements.

Seven benchmark graph/preview rows, through N=49,152, are independently reproduced as combinatorial arithmetic counts. The preview count is three optimized row-query counts plus the exact partial triple costs. ## 7. Unitary entropy theorem: accepted restricted model

Over C, let A be N×N unitary, accumulated by gates that apply a 2×2 unitary transformation to two rows, on N registers without extra workspace. Define Φ(A)=−Σ_ij |A_ij|² log₂|A_ij|².

For the two affected rows, set r_j=|u_j|²+|v_j|². A gate preserves r_j and Σ_j r_j=2. Their entropy contribution can be written

    −Σ_j r_j log₂r_j + Σ_j r_j H₂(|u_j|²/r_j),

with zero-mass terms omitted. Since binary entropy is in [0,1], the change is at most Σ_jr_j=2 bits in absolute value. Starting from identity gives Φ=0; a normalized Fourier matrix has Φ=N log₂N. Thus at least N log₂N/2 pairwise unitary gates are necessary.

This is precisely the established restricted model of [Ailon, Theorem 2.1](https://arxiv.org/pdf/1305.4745); the full primary proof and model were inspected. No extra-workspace, general nonunitary, nonlinear or finite-field lower bound follows. In particular this gate count must not be compared directly with the finite-field GT addition/multiplication ledger.

### Output-order qualification

The supplied entropy sanity program applies normalized DIF butterflies and leaves bit-reversed rows. At N≥4 its accumulated matrix is not the canonical ordered Fourier matrix until that permutation is applied. Our separate numerical controls compare the actual matrix with Fourier after bit reversal and also verify the mismatch before it.

The entropy lower bound is unaffected by row permutations. The code demonstrates saturation of the bound in *mixing-gate count up to output relabeling/free wiring*. If the exact computational model permits only paid pairwise row gates on fixed coordinate labels, implementing a nontrivial output permutation requires an explicit account. The source's entropy-only comparison does not establish that canonical-order implementation has exactly the same gate count. No new lower bound for that permutation problem is claimed here.

Five independent trajectories through N=32 check every observed gate's two-bit increase, the stage values 0,N,2N,...,N log₂N, and the final reordered matrix. They are numerical sanity checks with stated tolerances, separate from the exact proof above.
