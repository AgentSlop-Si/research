# Phase38 joint-mask source: full static review

All five assigned source hashes (23,324 bytes: four Python programs and one C++ program) were read in full as inert text. No uploaded program, compiler command, native binary, SymPy calculation or unittest was executed. Earlier independent Phase38 mathematical/certificate reviews remain separately scoped evidence.

## Principal findings

1. **Native input validation is incomplete.** The C++ checker uses n and P before verifying that the header extraction succeeded, and does not validate n>=3, a prime modulus or a safe multiplication range. A zero-size input can complete with zero checked mappings and successful exit; random mode at zero length has modulo-zero undefined behavior, while fewer than three columns cannot complete its distinct-column sampling. Invalid/empty headers can leave n indeterminate before allocation. All intended exported instances have N>=4, so these are general verifier/API defects rather than contradictions to the recorded admitted-family result.

2. **The native uint64 arithmetic needs a bounded modulus.** `mul(a,b)` computes a*b in uint64 before reduction. This is safe for canonical residues at the two documented roughly-billion-size primes, but not arbitrary uint64 primes admitted by the unchecked header. The rolling hash is a noncryptographic checksum of the processed results, not an authentication of the input family or a portable determinant witness. Limited enumeration exits all loops correctly via goto; it does not share the older Phase30 inner-loop limit bug. A sampled success remains sampled, and zero-resultant exit1 indicates an inconclusive modular test rather than a constructed complex Fourier solution.

3. **Consolidated audit output mixes fresh computation and saved records.** `make_audit.py` reuses an existing native executable without checking its source hash or rebuilding it. For N<=32 it runs that binary on existing instance files after an existence check, without comparing those files to the newly built in-memory target and generators. N64 permutation reports are read from earlier JSON; N128/N256 sample reports are also read from JSON. The code checks reported counts and expected zero counts, but does not bind saved prime/N/family/version or recompute those runs. The filename `phase38_recomputed_audit.json` therefore must not imply all attached permutation evidence was freshly regenerated. The special N64 second-prime collision description is hard-coded metadata, with a separate regression test that can check it when actually run.

4. **NumPy exactness has a restricted input/range contract.** `field_mm` and `field_inv` use signed int64 products and require canonical residues and sufficiently small p. For both documented primes, (p−1)^2+(p−1) is below 2^63, so the rank-one accumulated modular multiplication and inversion updates fit. Arbitrary larger moduli or unreduced inputs do not inherit this guarantee. Inversion checks raw nonzero entries before modular normalization and trusts prime-field Fermat inversion; it is not a robust arbitrary-residue API. Multiplying an unreduced arbitrary lambda into a NumPy array can similarly overflow before the later remainder.

5. **Module-global field state remains a dependency.** Instances store p, but polynomial gcd/Bézout helpers use the current `phase37_curvature.P`. Building an instance in another field before calling witness on an older instance can mix fields. The intended build-then-witness loops keep them aligned; a reusable public API needs explicit field passing or a checked binding. The inherited Phase37 zero-inversion and N<4 cycle-generation gaps remain dependencies of direct unsupported calls.

6. **Certificate labels must not replace their inputs and proof.** `witness` computes a nonzero quadratic Sylvester determinant and a modular gcd, then sets several characteristic-zero/family flags without independently checking the complete source provenance of an arbitrary supplied instance dictionary. The fixed-family producer and earlier lifting proof provide those assumptions. A nonzero padded quadratic Sylvester determinant is itself a valid sufficient exclusion even if an actual degree drops; the returned `full_characteristic_zero_degree` label is stronger than the bare runtime check. Nonzero-resultant specialization requires a bound algebraic family with invertible reduction denominators. Saved counts, a success exit or a zero-resultant collision alone do not establish that binding.

## Algebra and code path inspection

The identity T=A^-1 F C^-1 correctly removes the fixed outer mixers. The two cross-multiplied anchored equations cancel arbitrary nonzero row/column masks, yielding quadratic polynomials in the middle scalar. The Python and native formulas use matching row/column orientation. Their expression

(a h−c d)^2−(a e−b d)(b h−c e)

is the degree-two Sylvester determinant for f=aX²+bX+c and g=dX²+eX+h. Nonzero determinant excludes a common finite root (and the corresponding homogeneous pair), subject to the exact family/lifting contract. It is an exclusion of the fixed outer matrices and inner cycles, not of all tunable Green networks.

The native enumeration count is n(n−1)*n(n−1)(n−2). Fixing the target's first two rows and first three columns while enumerating every ordered source pair/triple gives a necessary obstruction to any global permutations. No arbitrary-target permutation variable is silently missing from that local necessary test. The native sampled mode uses a fixed xorshift generator and modulus sampling; it is an empirical deterministic sample, not an exact-uniform probability certificate. None of its finite tests proves all-N exclusion.

Mask calibration uses supplied anchor entries and checks the resulting first row/column. Full recover_masks additionally compares every matrix entry. These routines assume nonzero canonical matrices; zero/raw-residue handling and shape validation are limited. O(N) anchor arithmetic counts field inversions as operations; the literal separate Fermat powers add O(N log p) elementary field multiplications if p grows. Preparing the Fourier-conjugated dense target is explicitly not a linear-time operation.

The planted positive control chooses an expensive outer A=F T^-1 and deliberately records cheap_Green_outer=False. It is a sound logical positive control against a universal veto, not an O(N) Fourier construction. `charzero_n4.py` reconstructs the N4 equations over exact Q(i), relying on the same seeded-cycle generator but not finite-field gcd. Its scope is identity interior permutations at that explicit small instance; the full permutation claims require separate enumeration evidence.

The tests include documented-prime modular inverses, resultant comparison with SymPy, bounded exact permutation loops, mask reconstruction, the one second-prime collision, a characteristic-zero N4 case and native compilation/runs. Reading those test bodies is not running them. The test named native_positive_limit_and_sample actually exercises only random_count=30000 with max_checks=0, so it supplies no positive-limit test despite its name. Assertions throughout source helpers disappear under Python optimization.
