# Phase 25 — exact finite-field operation and memory ledger

## Precise common cost model

- Count each `F_p` addition/subtraction and nonidentity field multiplication as one unit. Both algorithms skip multiplying by `1`.
- Count complete Winograd-style `DFT_3` codelet as `6 additions + 2 multiplies = 8` units, with shared coefficients precomputed.
- Use the same finite field, primitive `N`th root, three dyadic subtransform sizes and 3-point codelet in both Good–Thomas (GT3) and mixed-radix Cooley–Tukey (CT3).
- Exclude from this **steady-state arithmetic proxy**: root-generator exponentiation, CRT/permutation integer arithmetic, Python object overhead, data movement, modular integer bit cost and coefficient/root setup. Charge/document those separately.
- Cold GT3 setup: `G−1` field multiplications for the length-G root table, plus 3 field operations for the common triple coefficients. CT3's present reference builds `2G−1` root powers plus the same triple coefficients. Setup need not repeat when cached.

\[
C_{GT3}(3G)=\frac92 G\log_2G+5G+3,\qquad
C_{CT3}(3G)=C_{GT3}(3G)+2(G-1).
\]

**These values are deliberately not presented as a speedup.** In this implementation, both certified and generic branches lose to native GT3 at these sizes. Even though GT3's preview arithmetic is shared perfectly with the fallback, the determinant/resultant search and recovery have large constants. This directly corrects conclusions that compared specialized Fourier forcing against Bluestein alone for favorable composite lengths.

## Memory and other resources

The mixed-radix graph has `N` persistent in-place dyadic data elements, `G` root elements, temporary `N` startup input-row elements (released after constructing its three row sessions), up to `N−3|J|` retained backup field elements in a preview, and `O(G)` codelet-node/cache metadata. Returning a full output creates `N` output elements. CRT input and output permutations each require `O(N)` integer index operations and memory reads/writes. The `N` input reindex writes, `N` row-data copies, and `N` output writes are separately acknowledged, but machine-level allocation and byte traffic are not benchmarked. The Good–Thomas output has a nontrivial permutation unlike radix-2 alone.

The finite-field model provides exact equality, **not** a claim about the cost of modular multiplication in bits. For unbounded lengths, a suitable prime `p` and roots of unity must be supplied or constructed. The entropy lower bound in `THEOREM.md` concerns normalized complex unitary `2×2` circuits and is not silently applied to this prime-field cost model.

See machine-readable `PHASE25_BENCHMARK.json` and executable tests for all raw counts.
