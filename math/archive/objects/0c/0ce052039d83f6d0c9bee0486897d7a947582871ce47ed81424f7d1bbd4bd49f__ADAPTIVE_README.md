# Reusable adaptive binary FFT

This is an implemented, tested standalone C/Python prototype. It is not a
production FFT library or a patch to the user's original repository.

## Fast path for one-off or a few transforms

Skip calibration explicitly. This builds the ordinary FFT plan and two tiny
lookup tables once, then selects the arithmetic eight-point kernel immediately:

```python
import numpy as np
from adaptive_fft import BinaryFFTPlan

x = np.random.default_rng(7).integers(0, 2, 4096, dtype=np.uint8)
with BinaryFFTPlan(len(x), x.dtype, method="codelet8") as plan:
    y = plan.execute(x)                 # New independent complex128 output
    out = np.empty(len(x), np.complex128)
    plan.execute(x, out=out)             # Reuse caller-owned output
    assert plan.calibration_count == 0
```

Other explicit methods are radix2_fused2, codelet4, codelet16, lookup4, and
lookup8. An explicit method never calibrates unless `plan.retune()` is called.

## Autotuning for many repeated transforms

```python
from adaptive_fft import get_plan, binary_fft, clear_plan_cache

plan = get_plan(len(x), x.dtype)          # Calibrates on the first cache miss
print(plan.method, plan.calibration)
y = plan.execute(x)
z = binary_fft(x)                        # Uses the same cached plan
assert get_plan(len(x), x.dtype) is plan

# Optional, deliberate remeasurement; never triggered by execute().
# plan.retune()

clear_plan_cache()                       # Releases cache references
plan.close()                            # Close your retained plan when finished
```

`get_plan` and `binary_fft` use autotuning by default. They are intended for
repeated use; use the explicit fixed-method example above to avoid tuning cost.
The process-local LRU cache contains at most eight `(length, dtype)` plans.
Do not close a shared cached plan while another caller is using it. Cache
clearing/eviction releases cache references; an explicitly retained plan remains
valid until it is closed or released. Closed cached plans are replaced on their
next lookup. Plans support context managers and idempotent close.

## Input/output contract

- Input must be a one-dimensional, C-contiguous NumPy uint8 or bool array.
- Values must be exactly 0 or 1. Native validation runs before output writes and
  before computing table addresses. Arbitrary floats or integers are rejected;
  the wrapper never silently casts them into binary values.
- Length must be an integer power of two, from 16 through 2^31, subject to memory
  availability. Unsupported lengths fail clearly. Length is validated before
  cache lookup, so a float cannot reuse an integer-key cache entry.
- Output is the full unnormalized forward complex128 FFT. Without `out=`, each
  call returns a separate array that later calls do not overwrite.
- An explicit `out=` must be an aligned, writable, C-contiguous complex128 array
  of matching length. It must not overlap input. Passing it intentionally permits
  its contents to be overwritten. Invalid binary input leaves it unchanged.
- The plan owns twiddles, permutation indices, and 1 KiB/32 KiB tables. The caller
  owns inputs and outputs. No input conversion or copying is performed.
- Concurrent execution requires separate outputs; do not close or retune during
  concurrent execution. The cache itself is a process-local convenience, not an
  interprocess/shared-memory tuning service.

## Selector

Default calibration runs once per cached length/dtype: nine randomized balanced
rounds, approximately 8 ms per candidate sample, four seeded binary input arrays.
It checks every candidate against NumPy before selecting. Candidate choices are
four arithmetic kernels and only the four/eight-input lookup tables. The 16 MiB
sixteen-input table is deliberately excluded from this API.

A lookup must beat the best arithmetic median by at least 8% and win at least 75%
of paired calibration rounds. Otherwise the best arithmetic kernel is selected.
Every timed transform includes binary validation, input gathering, key packing,
full spectrum row copying, and upper FFT merges. The selected C path uses one
function-pointer dispatch; there is no per-node dictionary or retuning.

The selector uses random binary calibration data, which may differ from a real
application's distribution and memory/cache conditions. It is conservative,
not an oracle: an 8% guard can intentionally leave small gains unclaimed.

## Measurements and limitations

`adaptive_results.json` uses the default calibration settings above. Held-out
performance uses eight new random seeds and 13 independently randomized timing
rounds on the same retained plan. Held-out correctness passed at N=4,096,
16,384, 65,536, 262,144, and 1,048,576.

In the recorded run, selected methods were lookup8 at 4,096; arithmetic8 at
16,384, 65,536, and 262,144; and arithmetic16 at 1,048,576. At 16,384 the lookup
calibration advantage was 6.9%, below the 8% guard, so the selector stayed with
arithmetic. Held-out lookup8 was faster there. Candidate-choice regret is
reported separately from the selected API path's measured time.

Calibration took about 0.44–0.81 seconds for the four smaller sizes and 4.02
seconds at 1,048,576. This includes calibration input generation, candidate
correctness checks, warmup, and timing; compiler/import startup is excluded.
Shared ordinary plan setup, adaptive setup, and calibration are reported
separately. Against fixed arithmetic8 at N=4,096, observed savings repaid tuning
after roughly 317,000 FFTs. Therefore tuning is not the default recommendation
for a one-off call or a small batch. Break-even entries are null whenever the
held-out measured saving is nonpositive; small positive savings within noise
should not be treated as a dependable payoff.

The virtualized machine had variable timing. Candidate and selected-path sample
ranges often overlap. Their difference is not a reliable isolated measurement of
C dispatch overhead. The JSON retains raw samples and variability, plus separate
public-Python-call measurements. Public calls include shape/dtype/buffer checks,
ctypes overhead, native binary validation, and allocation where labeled. They
are not allocation-free and were not assumed equivalent to C-batch timings.

## Reproduce and test

Requirements: GCC, Python, NumPy. SciPy is needed only for the earlier comparison
benchmark. No package is downloaded or installed by the code.

```sh
python adaptive_fft.py --size 4096
python test_adaptive.py --output adaptive_results.json
python test_api_guards.py
```

The wrapper builds `libadaptive_fft.so` from the neighboring C sources when
needed. Build locally rather than loading untrusted precompiled shared objects.

Files:
- adaptive_fft.c: native plan, validation, candidate timing, single-dispatch API
- adaptive_fft.py: reusable plans, cache, calibration, explicit fast path
- test_adaptive.py / adaptive_results.json: held-out and end-to-end evaluation
- test_api_guards.py / api_guard_results.json: input/lifetime/cache regression tests
- test_adaptive_sanitizers.c / adaptive_sanitizer_result.txt: native safety checks

AddressSanitizer and UndefinedBehaviorSanitizer test all six selectable methods
at every power-of-two length from 16 through 1,048,576. Leak checking is disabled
because LeakSanitizer cannot run under this sandbox's tracing; it is unverified.
