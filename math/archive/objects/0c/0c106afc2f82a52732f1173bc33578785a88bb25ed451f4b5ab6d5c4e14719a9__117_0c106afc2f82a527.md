# Structural FFT Research — Phase 2

**Input-independent computation sharing, compact split-radix plans, two real transforms from one complex FFT, and finite-field lookup batching.**

This is a reproducible research exploration. It does **not** claim a new general FFT complexity bound or any new theorem about integer multiplication.

## Quick start

```bash
pip install -r requirements.txt
python -m unittest -v
python demo.py
python benchmark.py
```

The core implementation `structural_fft.py` uses only the Python standard library. `numpy` is needed for reference FFT tests and benchmarks.

## Contents

- `structural_fft.py` — static symbolic DAG builder (`FFTGraph`), `CompactSplitRadix` with `O(N)` twiddle storage, two-real-FFT packing, fixed-field Walsh-Hadamard transformer and shared table compiler.
- `test_structural_fft.py` — correctness, resource-count and inverse-transform tests.
- `benchmark.py` — operations, precomputation cost, wall-time comparisons; writes `benchmark_results.json`.
- `benchmark_results.json` — recorded results for this environment.
- `demo.py` — prints a packed-transform and a finite-field table example.
- `RESEARCH.md` — derivations, proofs, scope limitations, related literature and next falsifiable research goal.

## Provable results in their respective models

**Arbitrary complex FFT:** the input-independent split-radix plan reduces generic nontrivial twiddle multiplications from asymptotically `(N/2)log2 N` to `(N/3)log2 N`, while preserving `Theta(N log N)` total arithmetic cost. The compact implicit plan takes `O(N)` preprocessing and `O(N)` twiddle storage.

**Two independent real FFTs:** one complex FFT of `a+i*b` plus `O(N)` output unpacking obtains both real-input transforms. The general cost remains `Theta(N log N)`.

**Walsh–Hadamard over a fixed finite field:** tabulate all `p^b` blocks, with `b=Theta(log N)` chosen as a power of two and access in a `Theta(log N)`-word RAM. Offline table construction fits in `O(N^c log N)` for chosen `0<c<1`, online work `O(N log N/loglog N)` and table space `O(N^c log N)`. This implements a version of an **established** finite-field tabulation technique, not a drop-in faster arbitrary complex FFT.

## Why two representations?

- **`FFTGraph`** expands arithmetic operations into a diagnostic symbolic DAG, including explicit operation counts; it uses `Theta(N log N)` space and compilation time.
- **`CompactSplitRadix`** stores a constant-size recursive template plus `O(N)` precomputed twiddles, representing the same circuit implicitly. It works for any complex-valued input, and is much smaller than the expanded graph.

Neither Python implementation is intended to outperform native FFT libraries, which have SIMD and much more optimized arithmetic kernels.
