# Phase 26 — full-scalar operation and setup accounting

**Finite-field steady-state model:** `F_p` additions and subtractions cost 1; multiplying by any scalar other than 1 costs 1, including `i=ω^(N/4)` and `−2`. Input data and roots are provided; constructing cached root tables is charged separately. The arithmetic counters are actual executed operations in Python reference circuits, not asymptotic estimates and **not** wall-clock performance measurements. Modulo/integer exponentiation, indexing, Python allocations and I/O are not treated as constant-time mathematical field operations in a bit-complexity theorem.

## Cold setup and memory: the phase-26 prototype is not superior

- `root_table(N)` incurs `N−1` field multiplications to build an `N`-entry table, excluding primitive-root search, generator tests and exponentiation. Both Phase 26 dyadic alternatives reuse the same root table.
- For `3G`, the Phase 26 trial implementation builds an `N`-entry table. Phase 25's tuned GT3 builds a `G`-entry table and its triple coefficients, so Phase 26 has **about `2G` additional root-setup multiplications** if neither has precomputed roots. This makes the trial worse, not better, for cold calls.
- Split-radix here is **not in place**: recursive vectors, sum/difference intermediates, and outputs cause additional allocations and data moves. The counters record selected scalar reads/writes but do **not** claim a complete platform-independent byte-traffic census. Peak live mathematical vector storage is `O(N)` under the stated depth-first recursion; Python allocator and object overhead were not benchmarked.
- The direct FFT stage of Phase 25 is in place and can share partial results with deferred completions. Phase 26's split-radix prototype does not implement an equivalent zero-recomputation preview. Therefore the new trial loses in workspace and features even when field arithmetic counts tie.
- For the complex volume/entropy diagnostics, the counts are **dimensionless inequalities on complex matrices**, not observed finite-field runtime or field-operation lower bounds. The models and target normalization differ intentionally.

## Bottom line

The all-input split-radix circuit is a useful independent verification but saves **zero** paid prime-field scalar operations relative to the optimized radix-2 baseline under this model. The stated nonunitary butterfly lift adds exactly `(N/2)lgN` multiplications. No exact unrestricted `o(NlogN)` improvement is claimed.
