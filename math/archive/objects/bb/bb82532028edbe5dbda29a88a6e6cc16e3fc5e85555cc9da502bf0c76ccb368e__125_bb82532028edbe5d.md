# Phase 12 — Dense-safe exact convolution research

**Key result:** For two fresh, arbitrary length-`n` polynomials, the optimal count of *input-dependent bilinear scalar products* is `2n−1`, already achieved by classical evaluation/interpolation. We reproduced and tested it, but its surrounding computation still takes quadratic time in this simple implementation. FFT/NTT accelerates that surrounding linear-algebra work. This is **not** a novel all-input sub-`n log n` algorithm or an improvement to OpenAI #130.

## Quick start

Requires only Python 3.10+; no NumPy or network access required.


## API

```python
from dense_algebra import schoolbook, karatsuba, interpolation_product
from universal_dispatch import convolve

A=[4, 3, 2, 1]
B=[8, 7, 6, 5]

print(schoolbook(A,B).coeffs)
print(karatsuba(A,B).coeffs)
print(interpolation_product(A,B).coeffs)
print(convolve(A,B))
# (32, 52, 61, 60, 34, 16, 5)
```

All polynomial computations are exact modulo `998244353` by default; the NTT fallback supports the corresponding power-of-two transform-length limit. This is not a general integer bit-complexity algorithm.

The separate signed-digit experiment uses ordinary Python arbitrary-precision integers:

```python
from signed_digit import shift_multiply
assert shift_multiply(1234,5678).product == 7006652
```

## What we learned

Mathematically reducing the number of variable products is **not the same** as improving total asymptotic runtime. We already have O(n) pointwise products from Fourier evaluation; our hard problem is computing the two linear transforms with less total work on *all inputs*, with scalar preparation and indexing included. Phase 12 sharpens the failure mode of the user's `A−k` heuristic without claiming an FFT breakthrough.
