# Full static review of twelve inverse/quartic-gate source programs

All twelve assigned exact hashes were read from first to last line as inert text. No supplied Python program was executed, imported, compiled or syntax-parsed. Byte identity was checked against the frozen inventory. This closes source-reading coverage; it does not add historical execution receipts or certify every imported theorem.

## Important findings

- The stored matroid-census verifier does not require its supplied normal matrix to have rank4. An all-zero 4x64 matrix is orthogonal to every Jacobian and passes the census recomputation when accompanied by zero nonzero-count, 635376 zero-count, product1, first-zero [0,1,2,3], and no first-nonzero witness. It then prints that a uniform-output-matroid hypothesis was rejected. Such data are not a basis for a four-dimensional normal space. The generator has stronger rank/Jacobian checks, but the external verify function lacks them. This is a static acceptance counterexample, not a run of the source.
- Complex feasibility diagnostics report residuals and solver status without a proof-producing threshold, exact reconstruction or nonexistence certificate. The reported max_entry_error is the maximum absolute realified component, not the maximum complex-entry modulus. Derivative-check mode only prints an error. These are numerical probes, as the source correctly warns.
- A nonzero augmented 61x61 modular minor proves rank at least61 over characteristic zero, but transversality relative to a Jacobian additionally needs a characteristic-zero upper bound60 on that Jacobian. A modular rank60 alone supplies no upper bound. The separate chart/gauge argument is essential to that stated lift.
- Gauge-tangent and jet programs correctly distinguish local from global questions. Their finite control loops do not by themselves prove invariance for every gauge combination or every first-order direction; that relies on the exact gauge-action argument. In particular, testing individual diagonal gauge Hessians and one random combination does not exhaust all mixed pairs.
- Almost all certificate safeguards use assert. Optimized Python can return literal successful fields after skipping substantive checks; apply_stage even places its entire check call inside assert, so its CLI can print PASS without running any vector comparisons.
- NumPy int64 modular products are safe for the displayed small dimensions and primes, not arbitrary dimension/modulus APIs. Mutable imported field globals and sys.path-based fallback imports require precise dependency binding.

## Per-source review

### 9977656abe31efb7c610cc714d60f0c0c56a33abfc295b3e423aa7664a156ea3 — fourier_support_elimination.py

74 lines. Constructs a restricted C chart from21 parameters, t!=0, and a new proportionality scalar beta. With xi=w^-1, it forces C[:,0]−beta C[:,7] to the two-frequency span and obtains the five lower-column identities after the fixed shuffle. The formula for b uses xi^7=w and the prescribed endpoint values; the t and w−1 divisions are explicit. It asserts the generated support relation and lower identities for120 bounded random field/root controls. It does not solve the remaining25 equations. The regular B corner conditions are counted, not enforced as an acceptance return condition; equivalence/recovery of beta is only claimed on that patch. The actual source returns no all-strata elimination certificate or cleared-denominator resultant. Its imported inverse_quartic implementation is identity-bound in DEPENDENCIES.json, not fully read in this batch. The fixed p=12289,65537 and N8 products are within int64. Root/field validity comes from the helper. Assertions and source-generated passed counters are not adversarial dataset verification.

### bd781a330d7d924a0407c151ff8a63d5dd42ce567334a04f34e6041a29dcbc3d — circuit_search.py

45 lines. Builds the4-dimensional modular left-nullspace of the sampled Jacobian, enumerates triples of its64 columns, computes a nonzero exterior normal, and collects coordinates lying on that hyperplane. It compares two seeded points. Explicit Python-int 3x3 arithmetic avoids intermediate int64 overflow; q@N remains safe for defaultp12289. The search discards rank-deficient triples, and therefore does not enumerate every degenerate lower-dimensional flat. Shared sampled hyperplanes are heuristic candidates, not polynomial identities; the header makes that distinction. rank60 and normal dimension depend on the helper and fixed point. Imported j.MOD is mutated globally, with no restoration or thread-safety. A same-basename module on an alternate path can change behavior. No Fourier membership decision or complete matroid classification follows.

### 6d95d3210b99a1acf9fed18c5b0a3a6e55299ab902d275bf2322e2d9bd0a4f1d — complex_solver.py

93 lines. Dense complex polynomial chart has26 first-stage and34 second-stage variables, with fixed first diagonal and separated-generator normalizations. Analytic derivative arrays follow the product rule, realification is [Re,Im], and the real Jacobian block form is appropriate for holomorphic equations. The one-point cache is bounded and keyed by the optimizer's real vector bytes. Random starts and the positive synthetic target use deterministic seeds, but timing and optimizer outcomes depend on runtime/libraries. SciPy least_squares is a numerical search. Nonzero residual does not exclude any solution; small residual is not exact factorization. Singular/zero-normalization charts are omitted. Report max_entry_error refers to realified components, not full complex moduli. No fitted coefficient array is returned for independent exact reconstruction. Jacobian-check mode prints rather than asserts its discrepancy. Dense matrices/Jacobians and repeated least-squares solves are not a fast transform.

### 026b0883b7a81d04e28839e21adf9c9bfed8b9a7ee97cb009d4d56baa2840977 — ct_positive_control.py

91 lines. Builds exact Cooley–Tukey block stages, twiddles and explicit input/middle/output permutations for the three displayed radix pairs. It compares the dense product to the correspondingly permuted Fourier matrix. The quasiseparable order is computed over every offdiagonal cut. The repeated block-diagonal rank-one example has nonzero lower entries in two blocks and a forced cross-block zero, so it lies outside the global separated-generator chart; this prevents extending chart exclusions to every QS matrix. The N32 case uses a radix8 block and returns its actual rank rather than asserting all block stages have order1. Generic root and rank helpers require valid dimensions and the fixed prime; qs_order at n1 has an empty maximum. Larger uncontrolled dimensions can overflow dense int64 sums. Assertions carry identity acceptance; the returned exact_all_entries=True is literal. This verifies a known factorization, not a new all-length constant-stage FFT.

### b0bb3c1182b6ce764ccdae00fed39906b1a445db533be9f0bd15bbc4eb96ed5f — curvature_minor.py

This certifies a characteristic-zero rank lower bound for the augmented integer matrix when the helper's construction and determinant are correct. ### 963065a5067bc8d9eeb3bf55a836661fe22681cb21e1d1ef547d2b0dda8a32c8 — fft_elimination_gate.py

115 lines. Eliminates B using B=M(PA)^−1. Fifteen lower and15 upper minors characterize the separated-generator chart on nonzero corners B[7,0],B[0,7]. Reconstruction correctly divides by those pivots, restores its diagonal and normalized row generators, and compares the full matrix. Replacing inverse by adjugate multiplies each minor by det(PA)²; retaining det(PA)!=0 is indispensable. det_mod is fixedN8 and raises on a singular pivot rather than returning0. analyze reports all_equations_zero even when regular=False, so callers must retain both fields; vanishing minors alone do not certify chart membership on boundary strata. Random failing Fourier inputs are explicitly not a nonexistence proof. First-stage diagonal/generator gauges assume the stated nonzero chart. Shape/root/globalmodulus assumptions and optimized assertions remain. The advertised polynomial reduction is a mathematical interface; the finite driver evaluates equations but does not export or solve their general symbolic system.

### 737dcee19548832f2f4bcf8a2a2fdfecc6a229fd64f9f8ca1a22dabc85d93670 — gauge_curvature.py

98 lines. Implements stage derivatives and bilinear Hessians, then the full two-stage product Hessian including both cross terms. The twenty gauge columns consist of eight unused boundary coordinates, four offdiagonal rescalings and eight intermediate diagonal directions. At the displayed point the code checks rank20, JG=0 and rankJ60. Its special diagonal direction produces2E[0,7], so dividing by2 matches a second-order coefficient. Individual mixed Hessians with that direction and individual gauge squares are tested, plus one random gauge combination. These finite checks do not enumerate all210 gauge pairings or establish the continuous gauge identities; the separate algebraic action is needed for the universal reparameterization conclusion. The script also labels the projected Hessian nonzero in its conclusion without an explicit nonzero assertion on target; the companion curvature-minor evidence supplies the stronger certification. Its scope correctly remains one local chart point, not Fourier nonmembership. Global j.MOD is set on import and retained.

### ae03f31f6038188a92cb73e5e9c044246c81981be5ef3243c117cfcbc28136a1 — jet_compatibility.py

114 lines. Chooses a rank60 square submatrix of J, solves for a canonical first lift, then verifies Jv=d1 on all coordinates. For that v, solves Jw=d2−H(v,v)/2 and verifies it. This is sufficient whenever it accepts. Necessity for existence over all possible first lifts requires the projected-Hessian invariance under the whole kernel, supplied by the explicit complete gauge-action argument, not solely the20 random control iterations. The report's fixed regular point and prime must remain. Five-point interpolation correctly recovers coefficients of a degree≤4 parameter-line image; it is a distinct check of the Hessian formula. Singular inverse inputs are assertion failures and not normal rejection statuses; shape and external data validation are limited. Outputs retain local two-jet scope, and no full formal-series or global implicit equation is produced.

### 99e4c07a2a0089c478094ebef89857741f402eda524c7775160e0272eef256e2 — apply_stage.py

39 lines. The backward sums accumulate future W*x coordinates and evaluate U dot sums; forward sums accumulate past V*x and evaluate L dot sums, plus diagonal. Thus fast_apply performs the supported separated-generator product in O(n(r+1)) scalar field work and O(n+r) scratch beyond stored generators. For positive r this is O(nr). It is not an arbitrary quasiseparable representation compiler or FFT constructor. Only diagonal length is asserted; all generator shapes and field consistency are assumed. A copied default MOD can disagree with a subsequently mutated jacobian_gate.MOD used to construct dense reference data. Displayed tests use default consistent field and safe small matrix sizes. Each CLI check is inside assert, so optimized Python prints its PASS lines without any comparisons. Twelve random vectors per size are controls, not a symbolic correctness proof.

### ee8942405b13f41b75e318803840ec3707fa5b748e887bf81a6495bca8b34689 — jacobian_gate.py

150 lines. The exact modular generator chart and product-rule Jacobian are correctly oriented as S2 P S1. variants enumerates diagonal and each lower/upper generator-coordinate derivative with strict-triangular support. The finite-difference check is exact for a single coordinate because the polynomial is affine in that one coordinate, so a unit difference needs no limiting argument. Modular elimination/nullspace code is standard under prime/shape/int64-range assumptions. Nullspace assertions validate each returned vector, but complete rank basis depends on the elimination logic. The study's dimension bound is stated from separate gauge/chart mathematics; a sampled rank cannot prove an upper bound. row_col_constraints explicitly needs actual rank to be maximal allowed. Defaults are safe at the displayed dimensions and p12289, not unlimited n,r,p. The stale comment saying12288 is divisible by2^12 is true (3*4096), but does not itself establish all arithmetic ranges. The mutable global field affects all generation/products and imports, requiring isolated consistent use.

### 50fee06761b01f6bebae7d73aaa67f14689bed7b3381a4c59858f01f34d1072a — matroid_census.py

70 lines. Enumerates all C(64,4)=635376 modular determinants by shared triple cofactors, keeping counts, product, and first examples. Python integer determinant arithmetic is exact; defaultp1000003 and the small nullspace products fit int64. Generation checks Jacobian rank60 and nullspace shape/orthogonality. The verify routine does not check rankJ60, rankQ4, metadata field/order, or a fixed intended shuffle. The header distinguishes this, but its returned rejection wording should say “at this sampled finite-field point.” A nonzero modular normal-coordinate minor can lift to a rational normal-space witness only with the valid rank/chart setup retained.
