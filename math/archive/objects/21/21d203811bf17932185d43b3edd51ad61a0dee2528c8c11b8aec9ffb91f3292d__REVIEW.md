# Regression and lineage source review

## Scope and method

All 24 assigned exact source hashes were read first-to-last as inert text: 65,513 bytes and 1,476 lines. No supplied source was executed, imported, compiled, syntax-parsed, or used to run tests. Only reviewer-authored byte hashing, JSON inspection, dependency crosswalking and report packaging were run. Static inspection completion is separate from theorem acceptance and runtime success.

The recursive duplicate scan covers the frozen inventory, additive registry and every existing COVERAGE.json found under [local workspace]. No assigned hash had prior full-read credit or even an exact-hash match in another completed coverage manifest at scan time. All 24 hashes receive new source-reading credit. No dependency-only hash receives credit.

## Main conclusions

- No new Fourier algorithm, general lower bound, all-chart impossibility or executed regression result is established by this review.
- The Weyl/Green source has a sound intended fixed-linear-map model and explicit finite-field scope, but lacks output-shape/fixed-state validation and emits an unconditional independent-randomness bound even for deterministic seeds.
- Lineage runners rely on exit codes, weak import identities and hard-coded test totals; zero discovered tests and optimized-away assertions weaken acceptance.
- The fixed-eight-point resultant work supports necessary regular-chart constraints and a bounded slice exclusion under exact dependency identities. Preserved coefficients and prior proofs remain separate from source-reading coverage.
- The triple-intersection issue is an acceptance/label limitation, not a demonstrated invalid rank-9 exclusion or invalid archived factorization. Kernel-only solutions must not be promoted to nonzero common images.
- Saved exact polynomial tests compare term counts, not coefficients, and do not read the saved resultant export. A successful test result would not authenticate those artifact contents.
