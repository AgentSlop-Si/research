# Independent audit and exact extensions of the restricted NTT

Date: 10 October 2026.

**Review status.** The sealed binary predecessor was independently audited here within the imported Frobenius-transform theorem. The adaptive growing-alphabet result and arbitrary-length mod-two convolution result are newly derived extensions in this report. They have finite checks and the written derivations below, but have not yet received a separate second proof audit. No historical novelty or priority finding has been made for either extension.

## Conclusions

1. I found no asymptotic-cost or algebraic defect in the binary-input theorem as stated, provided the RAM is address-capable, field elements occupy a constant number of words, and the published Frobenius additive FFT is taken as an imported theorem. The result is a restricted exact finite-field transform, not a complex FFT result.
2. There is a fully charged, adaptive growing-alphabet extension. For length N = 2^d − 1, d a power of two, let b be the affine F₂-dimension of the actual field-valued input coefficients. The full cyclic transform can be computed in expected O(N(b+1) log(d+2)) word operations and O(N) working words. The algorithm discovers the affine basis and coordinates; they need not be supplied.
3. Consequently, a particular alphabet of size log₂(N+1) admits exact transforms in O(N(log log N)²) expected word time. More generally, b = o(log N / log log N) gives o(N log N). This does not establish O(N log log N) for unbounded b.
4. The same ingredients, plus the published inverse transform, give deterministic O(L log log(L+2)) word time for binary polynomial multiplication of total output length L, for arbitrary lengths after additive-domain padding. This is convolution modulo two.
5. They do not give integer convolution. The smallest relevant obstruction is (1+x)²: the integer coefficient vector is [1,2,1], whereas every characteristic-two version returns [1,0,1]. This is lost information, not floating-point error.

These are mathematical consequences and finite checks, not a novelty claim, benchmark, independently formalized proof of the cited FFT, or lower bound against other integer-convolution algorithms.

## 1. Model and audit of the binary result

The sealed starting document is `EXACT_RESTRICTED_NTT.md`; its supplied checks and bounded-word addendum were read but not executed or modified. New checker code was authored separately.

Use a random-access RAM with w = Θ(log(N+2)) bits, enough address bits for its O(N)-word memory, ordinary shifts, Boolean operations, integer arithmetic/division, and independent random words. If a field element or an address requires a bounded number of words rather than exactly one, all bounds change by a constant. No operation on an N-bit packed string is assumed unit-time. The input and final output may be one coefficient/field element per constant-size group of words.

Write Q = 2^d = N+1. The following ledger survives independent review:

| Component | Charged word cost | Audit point |
|---|---:|---|
| Explicit Artin–Schreier tower | poly(d) | The trace-one tower constants specify each extension. Slow recursive arithmetic is polynomial in d. |
| Positional multiplication tables | Q^(1/4) poly(d) | Eight d/8-bit chunks give 64 tables of 2^(d/4) d-bit answers. Full multiplication is 64 lookups and XORs. Small d are base cases. |
| Reading and packing binary input | O(N) | Also covers one input bit per word. |
| Monomial-to-novel conversion | O(Q log(d+2)) | The packed-shift cost is O(1+H/w), not one operation on the entire coefficient string. |
| Pruned coefficient arithmetic | O(Q log(d+2)) | In a positive-state subtree, retained-node count at depth t is bounded by O(2^t/(t+1)). |
| Twiddle evaluation | O(Q) | Summing O(k) squaring/XOR steps at a size-2^k node is compatible with the retained tree. |
| Factor N and test a root | O(sqrt(N)+poly(d)) | Trial division is cheap relative to N, although expensive relative to the bit length of N. Use p ≤ N/p to avoid overflow in a p² test. |
| Generate a root | expected poly(d) | Primitive-root density is at least 1/(d+1); rejection testing is exact. |
| Expand Frobenius orbits | O(Q) | Each point is written once. The map is evaluated, not provided as an oracle. |
| Permute to cyclic root order | O(N) | Iterate 1,g,…,g^(N−1), reading the address-indexed field-value array. |

The deterministic coefficient-conversion recurrence is particularly important. For n = 2^m coefficient positions and h-bit vector coefficients, its volume cost is O((nh/w)m log(m+2)); constant-overhead pieces contribute O(n). With h=1, m=d and w=Θ(d), this is O(Q log(d+2)). Multiword shifts, boundary handling, copying, and contiguous block interpretation do not require a transpose oracle.

Field-table preparation is genuinely sublinear in Q because any fixed polynomial in d is dominated by Q^(3/4). The constant 64 is large but independent of N. The asymptotic result says nothing about practical speed at accessible sizes.

The root routine is Las Vegas: every returned root passes the exact order tests. All transform answers are exact. A supplied primitive root makes the computation deterministic after exact order verification. Generating and returning a root computes the transform defined by that returned root; it does not silently supply a particular externally designated root.

Depth-first transforms need O(Q) field words. Table space is o(Q); conversion storage, the address-indexed evaluation array and explicit cyclic output are all O(Q). The final N field elements contain Θ(N log N) bits, but only Θ(N) RAM words. There is therefore no output-size contradiction in a sub-N-log-N word bound, and no corresponding bit-operation improvement has been demonstrated.

### Imported facts and primary sources

The Cantor flag, its binary subspace polynomials, and correctness of the pruned forward and inverse additive transforms are established machinery from Li, Chen, Kuo, Cheng and Yang, [Frobenius Additive Fast Fourier Transform](https://arxiv.org/pdf/1802.03932), especially Algorithms 3–4. The use of Frobenius symmetry for Fourier transforms predates that paper; see van der Hoeven and Larrieu, [The Frobenius FFT](https://www.texmacs.org/joris/ffft/ffft.pdf). The word-table ledger and extensions below are separately derived here. Their asymptotic correctness remains conditional on those imported mathematical facts, rather than on the small tests alone.

## 2. Adaptive extension to growing coefficient alphabets

### Theorem

Let x₀,…,x_(N−1) be arbitrary elements of the same explicitly represented field F_(2^d), with d a power of two and N=2^d−1. Let

    b = dim_F₂ span { x_j − x₀ : 0 ≤ j < N }.

Thus b is the affine dimension of the actual input values, not necessarily the dimension or cardinality of a larger advertised alphabet. There is a uniform algorithm that returns all N field elements

    X_k = Σ_j x_j g^(jk),  0 ≤ k < N,

in expected O(N(b+1) log(d+2)) word operations and O(N) working words, with exact answers. Tables, affine-basis discovery, coordinates, primitive-root preparation, and full outputs are included. The only randomness is the optional Las Vegas primitive-root search.

### Discovering the basis without a hidden coordinate oracle

Set β=x₀ and process each d-bit word x_j+β by streaming binary elimination. Keep independent pivot vectors μ₀,…,μ_(t−1), ordered by decreasing pivot position, and a t-bit coordinate label.

For each pivot whose bit is present, XOR its vector from the residual and toggle its coordinate bit. If a nonzero residual remains, append that residual as a new basis vector and set its new label bit. Previously recorded coordinate words stay valid: their representations use the earlier basis vectors, which are not subsequently changed. Inserting the new vector into pivot order does not change its assigned coordinate index.

Each input requires at most b pivot tests/XORs. Finding a new pivot by a simple O(d)-bit scan and maintaining the order happens at most d times. The total is O(N(b+1)+d²) word operations and O(N+d) words. Each label has at most d bits. No leading-zero-count instruction, free bit transpose, alphabet lookup, or preprocessing advice is needed.

This yields, for every j,

    x_j = β + Σ_(t=0)^(b−1) μ_t c_(t,j),  c_(t,j) ∈ {0,1}.

### Compute one binary transform per coordinate

For each t, extract c_(t,0),…,c_(t,N−1), run the binary transform with the common root g, and accumulate μ_t times its N outputs. Reuse the field tables, root, and scratch arrays. Extracting each plane and accumulating it cost O(N), while its transform costs O(N log(d+2)). Only one plane's full output needs to be held at a time.

The constant coefficient offset β contributes just β to output k=0 and zero elsewhere: N is odd, and the geometric sum of all N powers of a nontrivial N-th root is zero. Thus no extra binary transform is needed for this offset.

The total cost is

    O(Q^(1/4) poly(d) + sqrt(N) + poly(d)
      + N(b+1) + bN log(d+2)),

which has the stated bound. If b=0, the constant-vector transform can instead be emitted directly in O(N) time once the desired root contract is resolved.

### Precisely what grows

Take d=2^r and the coordinate alphabet

    A_d = span_F₂ {v₀,…,v_(r−1)}.

It has 2^r=d=log₂(N+1) elements, and its affine dimension is at most r=log₂d. Hence every input over this growing alphabet has a full exact transform in expected O(N(log log N)²) word operations. Closure under field multiplication is unnecessary.

More generally the bound is o(N log N) whenever b log(d+2)=o(d). No result preserving O(N log log N) for an unbounded b follows from this reduction.

Alphabet cardinality S alone is insufficient to replace b by log₂S. For example, {0,v₀,…,v₃} has five elements but dimension four, exceeding ceil(log₂5). In general an S-symbol field alphabet has affine dimension at most min(S−1,d), and this may be tight.

The usual binary Frobenius shortcut cannot simply be applied to the growing-alphabet polynomial. For the constant polynomial f(x)=μ with μ²≠μ,

    f(a²)=μ ≠ μ²=f(a)².

If all coefficients lie in a subfield F_(2^b), the 2^b-th-power identity does hold; this does not justify reusing the binary pruning tree or ignoring its changed cost. The coordinate-plane reduction avoids that unproved step.

## 3. Arbitrary-length binary polynomial convolution

This extension is useful to distinguish an actual multiplication result from the cyclic NTT's sparse family of lengths.

Let two binary coefficient arrays have lengths a and c, and put L=a+c−1. Choose

    n=2^m ≥ L, with n<2L,
    d=the least power of two at least m.

For nontrivial sizes m≤d<2m, so the ambient field has Q=2^d<n² elements. Evaluate only on the Frobenius-stable n-element Cantor subspace W_m. The field elements still occupy O(1) words when w=Θ(log(L+2)). Eight-chunk tables cost Q^(1/4)poly(d) ≤ n^(1/2)polylog(n)=o(n). No size-Q output or scan is performed, and no primitive root or factorization is needed.

Convert both polynomials to the novel basis, evaluate at the pruned representative set, multiply matching values, run the inverse pruned transform, and convert back to monomials. Since the product degree is less than n, interpolation recovers exactly its coefficients in F₂.

### Arbitrary-m conversion accounting

The input restriction d=2^r does not force m to be a power of two. For m>1 choose k to be the largest power of two strictly smaller than m and set t=m−k, so 1≤t≤k. Let D=2^k and y=x^D+x. The contiguous division and upper/lower conversion construction works unchanged.

Normalize volume-dependent work by nh/w. Then

    V(m) ≤ V(k)+V(t)+O(t) = O(m log(m+2)).

The final bound follows, for example, from

    m log₂m − k log₂k − t log₂t ≥ t.

The constant-piece recurrence is

    J(m) ≤ 2^t J(k)+J(t)+C·2^t.

Write j(m)=J(m)/2^m and A_r=max_(m≤2^r) j(m). For 2^(r−1)<m≤2^r, k=2^(r−1), giving

    A_r+C ≤ (A_(r−1)+C)(1+2^(−2^(r−1))).

The product of these factors converges, so J(m)=O(2^m)=O(n). Therefore each binary basis conversion costs O((n/w)m log(m+2)+n)=O(n log(m+2)).

The inverse conversion has the same cost. At a division split, the high-half map is q=high XOR S(high), where S shifts by H−R and S²=0. Hence high=q XOR S(q); the low half is recovered from the remainder by the same shifted XOR. Reverse the recursive upper/lower steps. No giant-integer operation is needed in the implementation model.

The inverse transform also has the forward tree's asymptotic cost. At an unpruned node, invert the two butterfly equations. At a pruned node with power-of-two state l, the child value is expressed as R₀+uR₁ in the next tower extension and its multiplier as c+u. Recover P₁=R₁ and P₀=R₀+cR₁. In tower coordinates, extracting R₀,R₁ is a mask and a shift, followed by one field product/XOR per coefficient. This accounts for the operation that is easy to overlook when simply saying “invert the FFT.”

The transform tree costs O(n log(m+2)), its twiddles O(n), and pointwise multiplication/output handling O(n). Thus total deterministic time is O(L log log(L+2)) word operations and space O(L) words. Answers are exact. Outputting binary coefficients separately costs O(L); packed output can be smaller.

This is carryless polynomial multiplication. It is not integer multiplication or integer convolution, despite using exact finite-field arithmetic.

## 4. Integer-convolution obstruction and error model

For nonnegative B-bit inputs of length at most n, integer convolution may contain coefficients as large as n(2^B−1)². A fully explicit output can require Θ(n(2B+log(n+2))) bits, or Θ(n ceil((2B+log(n+2))/w)) words. With B=O(log n), this remains O(n) words, so output size alone does not rule out a fast integer algorithm.

The obstruction here is algebraic. A characteristic-two sum forgets every even multiplicity. Even the binary example

    [1,1] * [1,1] = [1,2,1] over the integers
                 = [1,0,1] in every characteristic-two field

already fails. For even n, the middle coefficient of two length-n all-one arrays is n but maps to zero. Absolute error is unbounded and relative error can be one. Hence the output is not a controlled approximation to integer convolution either.

An additive unital encoding of integers into any characteristic-two field necessarily sends 2 to zero. Using many such fields, more tower levels, or CRT over them cannot fix this: every component has the same parity kernel. Splitting coefficients into binary planes and weighting parity convolutions still loses the number of contributions in each plane-pair.

Possible genuinely different approaches would need carry information, odd-characteristic residues with a sufficiently large reconstruction modulus, or an appropriate characteristic-2^k ring algorithm. None is proved by the construction audited here. Merely replacing F₂ by integers modulo 2^k invalidates the identities used in the binary proof: squaring is no longer additive, and the binary division/vanishing-polynomial identities do not carry over unchanged. A more sophisticated lifted automorphism might be useful, but it would require its own algorithm and cost proof.

Thus the exact established outputs are the finite-field NTT and mod-two convolution above. No new integer-convolution, ordinary complex DFT, or unrestricted-input FFT bound is asserted.

## 5. Independent finite checks and limitations

`independent_extension_checks.py` imports no supplied source or checker code. It uses polynomial-basis fields with explicit irreducible moduli, searches for Artin–Schreier tower generators inside those fields, and builds the tower-coordinate maps explicitly. This differs from the supplied recursive tower-arithmetic oracle.

The checker uses direct Horner evaluation and triangular monomial/novel-basis elimination as slow independent references. A separately written iterative pruned forward transform and recursive inverse are checked against them. It also checks adaptive affine-coordinate discovery and the concrete integer obstruction.

Results in `INDEPENDENT_CHECKS.json`:

- 656 binary transform/inverse cases, including exhaustive small inputs and non-power-of-two domain exponents
- 285 binary polynomial convolution cases with varied operand lengths
- 120 growing-coordinate-alphabet cases, including coefficient subspaces that are not subfields
- 85 adaptive affine-input cases, including zero-dimensional constant inputs
- All 65,536 operand pairs for positional product reconstruction in F₂⁸
- Explicit failure of binary Frobenius expansion on a nonbinary constant polynomial

The separate `conversion_and_cost_checks.py` replay adds 1,680 quotient/remainder identity checks, 198 arbitrary-m vector-coefficient conversion/inverse checks, and symbolic recurrence evaluations through m=1024. Its JSON output is `CONVERSION_AND_COST_CHECKS.json`.

All passed. These checks establish finite algebraic consistency, not the infinite complexity theorem. They use Python integer operations and slow reference conversion; the bounded-word costs are supplied by the mathematical ledger and recurrences, not inferred from Python execution time. No practical speed or large-size benchmark is claimed.

Input hashes were recorded before and after the work; the original sealed files were preserved.
