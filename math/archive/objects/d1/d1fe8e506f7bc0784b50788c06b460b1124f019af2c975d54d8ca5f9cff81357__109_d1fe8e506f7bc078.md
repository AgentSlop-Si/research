# End-to-end finite-word approximation audit

This integrates exact integer-mass sampling with the guarded phasor-table
decoder. It tests arbitrary fresh data; the method does not assume a sparse
input or spectrum. Its guarantee is a global additive approximation, and is
not an exact or ordinary high-accuracy FFT claim.

For the negative-sign unnormalized Fourier transform F, write
L = sum_j (|Re x_j| + |Im x_j|). For fixed epsilon and polynomially small
failure probability, the mathematical construction approximates every output
to additive error epsilon L using O(N) randomized Word-RAM operations,
including all preparation. `SAMPLING_AND_MODEL.txt` supplies the sampling
proof and finite-input model; the decoder component supplies the packed
algorithm and uniform cost argument. For the unitary transform divide both
output and bound by sqrt(N).

## Executed checks

Run from the bundle root:

```bash
python3 fft_wordram_integration/run_audit.py
```

NumPy is used only for the independent reference and comparison timing.
The sampler and decoder do not call FFT. Inputs have exact integer real and
imaginary components. All outputs are explicit integer pairs over a common
denominator, multiplied by the exact input mass. Complex conversions are
provided for checking and convenience.

The audit uses 8 workloads at N=64,257,1024: flat, rounded Gaussian,
random phase, power law, spike with noise, coherent dense tone, dense tone
mixture with noise, and a cancelling comb. The dense tone and spike controls
ensure the test is not limited to noisy signals whose true coefficients are
all smaller than the allowed error.

- 24 fresh input cases, all 10,760 coefficients checked.
- Largest observed error divided by L: 0.115171 (rounded upward).
- Requested total tolerance: 0.5 L; mathematical failure bound: 0.02 per run.
- Sampling error allocation: 0.25 L; decoder bound is about 0.108 L.
- Full eager table contains 16,384 entries; no missing row is built lazily.
- Each run writes exactly 2N integer component outputs.
- Bounded word sizes, partial blocks, non-power-of-two N, zero input,
  single-atom sampling, and invalid inputs are checked.

Passing numerical trials supports implementation correctness. It does not
prove a failure probability from observed frequencies; that probability comes
from the independent Hoeffding and rejection-cap arguments.

## What these experiments do and do not establish

The tested schedule uses B=4 and group size g=1, with 650–828 samples.
It exercises the algorithm on accessible inputs, but is **not** the growing
B,g schedule used for the asymptotic O(N) theorem. The decoder's separate
audit includes g=2 and multiple packed words. The asymptotic grouping regime
starts at very large sizes; building a theoretical table there is not a
practical performance experiment.

For efficiency, the audit builds the same input-independent eager plan once
per N. Every reported cold-call operation count includes the complete table
setup, and every reported cold-call time adds that measured setup time to
sampling and decoding. Online counts are computed per call, not from the
decoder's cumulative lifetime counter. Loop and interpreter overhead are not
individual entries in the operation ledger; they obey the same proved order.

At these sizes, this Python prototype is much slower than NumPy's FFT and
has over 1.5 million counted setup operations. No practical crossover or
FFT runtime win is claimed. Nor is the fixed-error theorem uniform in
epsilon: taking epsilon toward zero with N changes the sample count, tables,
word precision and running-time analysis. Exact integer multiplication
therefore does not follow.

`results.json` retains every error, operation count, parameter, comparator
time and source hash. Reproducible seeds do not replace the theorem's ideal
independent-random-word assumption.
