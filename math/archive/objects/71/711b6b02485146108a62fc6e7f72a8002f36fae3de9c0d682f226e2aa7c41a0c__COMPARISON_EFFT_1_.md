# Comparison with eFFT (Tapia et al.)

The eFFT project (2024 method / 2026 open-source eFFT-C++ release) **already maintains a radix-2 FFT computation tree and only updates affected branches** as events arrive. It also groups events into packets and shares repeated work. We must not claim that tree-based event FFT updating was invented by this project.

- GitHub: https://github.com/raultapia/efft
- Peer-reviewed software paper (April 16, 2026): https://doi.org/10.5334/jors.642
- The public implementation has C++ and Python bindings, using Eigen3 and optional FFTW3. Its code is GPLv3. We did not copy or bundle its implementation.

## Different emphasis

| | eFFT | Phase 5 RelationFFT |
|---|---|---|
| Primary workflow | Event-based frame/camera-like updating | Arbitrary 1-D real arrays, known relations, reusable spectra |
| Persistent radix-2 tree | Yes | No; compact base spectrum + sparse deltas |
| Known sparse event updates | Yes | Yes |
| Fork multiple related reference versions | Not the central published API | Yes, with shared immutable bases |
| Known shifts and rank-r combinations | Not claimed here as eFFT features | Yes |
| Lazy individual-frequency retrieval | Not claimed here as eFFT feature | Yes |
| Cost-aware native fallback | Not evaluated here | Yes; conservative policy with optional calibration |
| Numerical model | C++/Eigen native FFT arithmetic | SciPy/NumPy floating-point rfft |

We checked the published eFFT README and 2026 peer-reviewed description. The `efft` package is **not installed in this environment**, so **no direct eFFT speed comparison was performed**. Our current benchmarks compare against SciPy. A valid head-to-head would need matching dimensionality, event streams, output subscription patterns, precision, included initialization, warm-ups, thread policy and memory limits.

**Core research question:** Does relation-aware dispatch/lazy output offer a workload-level advantage over a persistent event-tree implementation once both receive the same known event stream? This remains to be tested.
