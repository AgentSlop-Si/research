# Exact-Subproblem Reuse for FFT: a Small Research Investigation

**Date:** 2026-10-08  
**Status:** Working prototype and derived, model-specific bounds; **not a new general FFT asymptotic breakthrough**.

## Research question

If an FFT repeatedly encounters identical or related subproblems, can unlimited or sufficiently large memoization yield a real improvement over the usual O(N log N) arithmetic bound? What happens for uniformly random binary inputs, and when does the method become linear?

## Prototype and construction

`fft_collision_research.py` implements *hash-consed recursive FFT* for input sizes N=2^h.

1. Decompose each FFT node into its even-index and odd-index subsequences (Cooley–Tukey).
2. Assign a unique canonical ID to every leaf value and to every internal pair `(length, even_ID, odd_ID)`. Matching IDs represent **provably identical ordered coefficient arrays** (not probabilistic hash collisions: dictionary equality is on exact integer IDs).
3. Build this DAG bottom-up in O(N) expected dictionary operations without copying entire subarrays. The logical recursion tree has 2N-1 nodes.
4. Compute the transform of every **unique** DAG node once. Retain and reuse its full output array. An FFT node with size m uses m/2 butterflies in the combine phase.
5. Produce the N transform outputs at the root.

Let U_m(a) be the number of distinct size-m nodes in the recursive decomposition of an input a. Then the EXACT butterfly count of this algorithm is

    B(a) = Σ_{m∈{2,4,...,N}} (m/2) U_m(a).

The uncached radix-2 FFT has U_m=N/m at every size, hence

    B_standard = (N/2) log₂ N.

Hash-consing costs O(N) **expected** on an ordinary random-access word-RAM, assuming constant expected-time dictionary operations with O(log N)-bit keys and unit-cost arithmetic. Caching the complete transform vectors uses O(Σ m U_m) complex-value storage. Exact multi-precision bit complexity and sequential-tape layout costs are not included.

## Correctness

If two nodes have the same canonical ID, their input sequences agree exactly. This follows inductively from the equality of both ordered even- and odd-index child sequences. Cooley–Tukey performs deterministic operations on those sequences, so their transforms agree. Reusing the result changes neither the DFT nor the numerical precision relative to the same radix-2 calculation.

## Bound 1: Fixed-period inputs admit linear arithmetic

Assume the input is periodic with some period p independent of N: a[j]=s[j mod p]. At a fixed FFT recursion depth, all nodes sample with the same stride. Such a node is determined by its starting offset modulo p, so there are at most p distinct size-m nodes:

    U_m ≤ p.

Therefore,

    B(a) ≤ (p/2) (2 + 4 + ... + N) < pN.

So for constant p, the algorithm performs O(N) butterflies, has O(N) expected canonicalization time, and uses O(N) cached output values (with constants depending on p). This is a *restricted input family* and not novel on its own: the DFT of a periodic input can also be computed more directly from one period and expanded in O(N+p log p) operations when p divides N.

## Bound 2: Random binary inputs do not get asymptotic gains from exact matching

For independent uniform random binary input, the N/m size-m subproblems at a fixed FFT level have independent uniform binary coefficient sequences (because their input index sets are disjoint). There are Q=2^m possible sequences.

The exact expected number of distinct size-m subproblems is the balls-in-bins expectation:

    E[U_m] = 2^m * (1 - (1 - 2^(-m))^(N/m)).

For m ≥ 3 log₂N, at that FFT level the probability of **any** pair collision is at most

    choose(N/m, 2) * 2^(-m) ≤ 1/(2N).

A union bound over at most log₂N levels shows that, with probability 1 - O(log N / N), every subproblem on all these large-block levels is unique. There are log₂N - O(log log N) such levels, each requiring N/2 butterflies, hence

    B(a) = Ω(N log N)

with high probability for this **exact-subproblem reuse algorithm**; the standard O(N log N) upper bound also applies. This does **not** prove an FFT lower bound in arbitrary computational models, nor rule out more general equivalence relations or nonlinear algorithms.

## Infinite / prepopulated lookup tables: a different time-space model

If all 2^b binary-input FFTs of size b are already stored, and retrieving and copying one b-output block costs O(b), the conventional FFT can start from those blocks and perform only log₂(N/b) remaining merge levels. The **online** arithmetic/lookup time is

    T(N,b) = O(N + N log₂(N/b)),

excluding preprocessing, table storage and, depending on the machine, address/pointer navigation. The table stores Θ(b 2^b) complex values. This holds for b dividing N and both being powers of two. As b approaches N, online processing approaches linear; however, lookup memory becomes exponential. With b=Θ(log N), full lookup tables can have polynomial size but the remaining time remains Θ(N log N). With b=Θ(N/log N), the online time becomes O(N log log N), but the table becomes of size about 2^(Θ(N/log N)) outputs (subexponential but enormous). With b=Θ(N), online time is O(N) with exponential storage.

Unlimited **available** memory is not the same as unlimited, free **precomputed** answers. A cache initially empty still must construct its entries. Constant-time lookup on an arbitrarily enormous addressed table may require a stronger memory model than a standard Turing machine or word-RAM.

## Where a further improvement might exist

The exact statistic B(a)=Σ(m/2)U_m(a) provides a clear test. To obtain O(N (log N)^(1-ε)), we would need

    Σ_{h=1}^{log₂N} ρ_h = O((log N)^(1-ε)),
    ρ_h = U_(2^h)/(N/2^h).

Thus a large proportion of *large* FFT subproblems must be reusable, or an alternative representation must make distinct subproblems cheap to derive from one another. Simply making collisions abundant among tiny blocks is not enough. Candidate transformations to inspect include input scaling, complement, cyclic shift, reversal, periodicity and sparsity; these reduce lookup-key variation but have reconstruction costs. Symmetries with only polynomially many variants cannot by themselves remove the exponential explosion of distinct random m-bit blocks.

A stronger research project would search for larger families of subproblems whose FFTs can be reconstructed with o(m log m) arithmetic each, while including normalization, equivalence discovery, memory access and precomputation in the cost. No such general-purpose construction has been established here.

## Assessment

The proposed canonical-DAG FFT is a working data-dependent transform and is linear in arithmetic operations for fixed-period inputs. Uniformly random binary inputs have many collisions in tiny subproblems, but the larger subproblems remain unique, giving Θ(N log N) operations for this algorithm. To obtain a general improvement, one must exploit structures beyond exact equality (or genuinely change the computation model using enormous precomputation). These are reproducible findings, **not a claim of a new general FFT exponent**.
