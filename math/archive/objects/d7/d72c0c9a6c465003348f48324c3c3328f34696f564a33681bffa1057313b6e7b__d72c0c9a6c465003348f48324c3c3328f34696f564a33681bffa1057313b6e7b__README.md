# Deterministic head/tail energy pruning at the stronger Fourier error scale

Research continuation, 9 October 2026. The target throughout is the SAME scale
as sparse-surrogate v2:

    ||approximation - U_N x||_infinity <= epsilon ||x||_1 / sqrt(N),

where U_N is the unitary DFT. No epsilon||x||_2 guarantee is substituted for it.
This work does not establish a deterministic worst-case O(N log log N) bound
at this scale, and does not solve the fresh exact FFT problem.

The positive result is a deterministic adaptive head/tail bound, including a
linear-work family with an arbitrary dense tail. The negative result is an
explicit Omega(N log N) cost family for this PARTICULAR head/tail program,
even with an oracle choosing its best head. Both are proved below.

## A deterministic adaptive algorithm

Choose h largest-magnitude input coordinates and write x=head+tail. Compute the
complete unitary Fourier transform of the h-sparse head by the classical
sparse-input decomposition. For a dyadic b>=max(1,h), b<2max(1,h), N=bm:

    T_r[q] = sum_t head[r+b*t] exp(-2 pi i t q/m),
    C[q,r] = T_r[q] exp(-2 pi i r q/N).

Each length-b DFT of C[q,:] supplies outputs q+m*l; divide by sqrt(N). The sparse
phase summation processes mh<=N terms, and the m ordinary radix-2 b-DFTs use
N log_2(b)/2 butterflies. This is an O(N[1+log(h+1)]) exact-arithmetic formula,
not a call to an asymptotically faster external DFT theorem.

Set L1=||x||_1 and theta=epsilon L1/sqrt(N). Apply the previous energy-pruned
DIF algorithm to tail with its ABSOLUTE threshold theta. Add the two complete
output vectors. The head is exact; every tail coefficient error is <=theta.
Thus the stated all-bin guarantee is deterministic in ideal arithmetic.

Let E_h=||tail||_2^2. The earlier energy argument bounds the count of active
depth-d tail nodes by

    min(2^d, E_h/theta^2).

Writing log_+(t)=max(0,log_2(t)), with log_+(0)=0, the total work is

    O(N [1 + log(h+1)
           + min(log_2 N, log_+(N E_h / (epsilon^2 L1^2))) ]).

Zero x is handled directly. A deterministic heap selects the head in
O(N log(h+2)) comparisons and O(h) space, within the same bound. Input scans,
tail creation, norm evaluation, root preparation, complete output writes and
the final vector addition are all included. Depth-first tail pruning and the
sparse-head intermediate array use O(N) space. The displayed numerical program
materializes all outputs.

The proof uses an adaptive exact-real arithmetic model with magnitude/norm
evaluation and comparisons charged. Alternatively, to avoid square roots when
computing L1, use L=sum_j max(|Re x_j|,|Im x_j|) instead: L<=L1<=sqrt(2)L.
Taking theta=epsilon L/sqrt(N) still meets the required L1 error contract and
changes the work bound by only a constant inside the logarithm. Largest-head
selection can compare squared magnitudes. Squared thresholds and the weighted
unnormalized DIF formulation avoid branch-test square roots as in the prior
proof. The supplied complex128 prototype uses standard numerical magnitudes.

## A positive linear-work family at the stronger scale

Suppose a constant-size head contains the large coordinates and its remaining
dense tail satisfies

    E_h <= C L1^2/N,

for a fixed C. The algorithm costs O(N[1+log_+(C/epsilon^2)]). For fixed accuracy
epsilon this is O(N), deterministically, without a probabilistic failure event.

A concrete family is x_0=1 and arbitrary complex tail entries satisfying
|x_j|<=c/N for j>0, with fixed c and sufficiently large N. The largest coordinate
is the spike, L1>=1, and E_1<=c^2/N. One exact spike transform plus energy
pruning therefore meets

    error <= epsilon L1/sqrt(N)

in O(N[1+log_+(c^2/epsilon^2)]). This allows arbitrary phases in a fully dense
tail. Pure energy pruning of the original vector has a worst-case bound of
order N log N here, because the spike dominates its energy; removing the spike
first eliminates that pessimistic parameter. Head-only l1 truncation is not
automatically certified when the tail l1 mass is comparable to the spike.

More generally, if h and N E_h/L1^2 are both polylogarithmic in N, and
epsilon^-1 is polylogarithmic, this hybrid gives deterministic O(N log log N)
for that explicit input class. The condition is data dependent, not universal.

## An explicit adversary for the whole head-size choice

Fix 0<epsilon<1. Let N=4^m and s=2^m=sqrt(N). Choose

    x_j = any complex number of magnitude 1,  0<=j<s,
    x_j = 0,                               s<=j<N.

Then L1=s and theta=epsilon, so theta^2=epsilon^2. Permit an oracle to select
ANY head subset H of the nonzero coordinates, with h=|H|. Head coordinates are
transformed using the sparse-head backend defined above; the remainder is
processed by norm-threshold DIF pruning with threshold theta. Even this oracle
cannot make this program sub-N-log-N on the family.

Case 1: h<=s/2. The tail has at least s/2 unit-magnitude entries. In the first
m DIF levels, every node's vector is supported inside its first s positions;
before each split, its second half is zero. Hence every child has exactly half
the parent energy, regardless of phases or which head entries were removed.
Every depth-d node therefore has energy

    (s-h)/2^d,   0<=d<m.

This is at least 1 throughout those levels, and hence strictly exceeds
epsilon^2. EVERY node in all first m levels must split. Each such level processes
N values and executes N/2 butterflies. The tail alone costs at least Nm/2
butterflies.

Case 2: h>s/2. The sparse-head backend uses a dyadic radix b>=h, forcing b>=s.
Its m_head=N/b length-b transforms execute

    N log_2(b)/2 >= N m/2

ordinary radix-2 butterflies. The head alone already costs this much.

Thus for EVERY head size and choice, the defined hybrid executes at least

    N m/2 = N log_2(N)/4

butterflies. This lower bound excludes input scans, planning, norm tests, phase
preparation, indexing and output work; charging them only increases the cost.
An exact sparse-input bypass on the entire support uses b=s and also has this
order for this backend. All nonzero magnitudes are equal, so merely grouping
coordinates into magnitude scales produces one group and does not remove the
example.

This is a lower bound on the explicitly defined compiler/program, NOT a lower
bound on all deterministic approximation algorithms. A program exploiting
additional phase structure, changing the transform representation, or using a
different nontrivial primitive is outside the argument. Likewise, arbitrary
partitions of an equal-magnitude group are not analyzed by this one-group claim.
The native NumPy FFT may use different kernels; the exact count concerns the
stated classical radix-2 realization, not NumPy's machine instructions.

## Verification and limitations

Run `python3 run_audit.py` (NumPy required).

- Exact integer certificates check ALL 32,780 head sizes over m=1,...,14,
  reaching N=4^14=268,435,456 without constructing vectors at the large sizes.
  The certificate only evaluates forced early-level energies and the sparse
  head backend's emitted butterfly count. It does not measure huge transforms.
- 48 numerical cases at N=64,256,1024,4096 compare the prototype with the full
  unitary NumPy DFT, at the same stated error threshold. Cases cover prefix
  sqrt(N) support, a spike with a dense diffuse tail, and flat signs.
- `prior_energy_pruned.py` is an unchanged copy of the previous implementation;
  its SHA-256 is recorded in `results.json`.

The complex128 checks are empirical checks of the prototype, not certified
floating-point error guarantees. The all-size accuracy and cost claims above
refer to ideal arithmetic. Large or tiny floating inputs can require further
scaling and interval-aware norm decisions; the new wrapper is not a replacement
for such certification. Nothing here converts sparse-surrogate v2's randomized
worst-case guarantee into a deterministic universal one.
