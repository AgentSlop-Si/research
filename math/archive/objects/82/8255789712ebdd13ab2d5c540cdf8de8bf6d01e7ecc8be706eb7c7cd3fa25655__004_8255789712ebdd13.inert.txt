## 1. Primary goal — exactly state the problem

The user's original hypothesis is:

> As N grows, the number of repeated FFT computations grows. Can we exploit that growth to reduce a full fresh FFT on an arbitrary length-N input to O(N), without multiple processors or uncharged memory/precomputation?

This question is **not the same as** (a) updating an old spectrum after known changes, (b) outputting a few bins instead of N, (c) handling highly compressible, periodic or recurrence-generated inputs, (d) caching a repeated request, (e) saving only a constant fraction of butterflies, or (f) proving a faster integer-multiplication bound in another computational model.

The target needs an exact computational contract: arbitrary or distributional inputs; real/complex, finite-field or bit data; exact arithmetic vs finite precision; word-RAM vs bit model vs fixed-tape; full explicit N-vector output vs an implicit handle; charged table construction and indexing; sequential work count. **No prototype here establishes O(N) for an arbitrary fresh exact complex DFT under a standard uniform model.** OpenAI result #130 separately claims an all-length sub-N-log-N bound in a permissive exact-complex-arithmetic model, with much weaker exponent improvement than linear time, not in bit complexity.

## 3. Mathematical check of the user's original collision-to-O(N) hypothesis

Let N=2^L. At a recursive level comprising r=N/m disjoint length-m blocks, suppose the input entries are iid uniform from an alphabet of q>=2 values. There are S=q^m possible blocks. The number U_m of distinct blocks satisfies

\[ \mathbb E U_m=S\left(1-(1-1/S)^r\right). \]

Under an *ideally free* exact-subproblem memoization scheme, the butterfly count is

\[ B(N)=\sum_{m=2,4,8,\ldots,N}(m/2) U_m. \]

The bottom levels have many repeats. But for every m at least roughly 3 log_q N, a collision between disjoint random blocks is very unlikely, so almost every subtree at those levels is distinct. There are \(\log_2 N-O(\log\log N)\) such levels, each incurring essentially N/2 butterflies. Thus even this optimistic scheme has

\[ \mathbb E B(N)=\Theta(N\log N) \]

for iid random finite-alphabet inputs, rather than O(N). The saved **fraction** from repeated exact subtrees actually tends to zero as N grows, even though the absolute number of collisions increases. This is restricted to standard recursive exact-match sharing—not a lower bound on all FFT algorithms or on OpenAI #130's unrestricted exact-arithmetic model.

- **Infinite complete answer oracle:** With nonuniform uncharged tables for all possible length-N inputs, O(N) explicit output is trivial for any finite-input function, including multiplication. That no longer constitutes a uniform low-resource algorithm.
- **Polynomial-size small-block table:** b=O(log N) under fixed input alphabet permits table size polynomial in N, but replacing only bottom b-leaves removes O(log log N) FFT levels, leaving Θ(N log N).
- **Repeated table at every stage:** Works for fixed-field Walsh–Hadamard, where every intermediate remains in a constant alphabet, yielding the known O(N log N/log log N) improvement. Complex FFT has growing exact intermediate value diversity (even for binary original inputs); standard NTT needs growing field order. Reusing those tables without charging state widths is invalid.
- **Special signal ensembles:** Fixed-period or low-description-complexity families *can* admit O(N) explicit transforms. That's a valid average-/instance-conditional result, not a uniform worst-case one.

## 4. What would count as *new* evidence?

**Track U — fresh arbitrary input, full N-vector:** Declare a *specific* model and give an input-independent or otherwise provably universal exact algorithm with a complete recurrence and charged precomputation. Compare to the genuine #130 bound **in the same model**; linear-time would need much stronger mathematics than exact collision reuse. Do not restart CrocSwap rank-frame optimization without explicitly choosing that separate competitive track.

**Track C — input-dependent collision theory:** First demonstrate a rigorously specified source family or equivalence class in which the **expected number of distinct expensive subproblems** grows sublinearly enough across *almost all* FFT levels. State entropy, access model and whether input recognition is charged. Existing iid uniform binary model is a negative control, not a candidate for improvement. Do not claim average-case generality from periodic or cached data.

**Track D — persistent/dynamic systems:** Reuse the already-developed hardened projected-spectral/view graph, explicit producer relationship metadata, lazy materialization and calibrated native fallback. Compare against eFFT/FFTW/FFTW-codelets on **identical work and output scope**. This is an engineering benchmark path, not a proof of arbitrary-input O(N).

**Minimal acceptance gate for any proposed breakthrough:** arbitrary versus restricted inputs; first transform versus updated transform; exact versus numerical and bit complexity; same output requirements; one processor; preprocessing, all table/index/descriptor costs charged; no silently supplied cached spectra or known transformations; independent exact verification; a family-of-N bound rather than one finite instance; new idea checked against this prior-work register before coding.

## 5. Recommended action before another experimental phase

Do not write another broad 'Phase 13' engine or rerun known searches yet. Instead choose one precisely stated unsolved proposition and attempt to **falsify it on paper** using the existing occupancy, dimension, bit-size, matrix-ratio, rank and circuit-grammar obstructions. Only then implement a small independent verifier for the surviving hypothesis. Maintain unique descriptive project names and compare SHA/provenance before copying source.

For the user's original hypothesis, the immediate conclusion of the complete audit is clear: **growing input size guarantees more short collisions but does not imply convergence to O(N) work on uniformly random inputs.** Turning that into a different asymptotic theorem requires a new notion of reusable structure, not another implementation of exact-value cache entries.
