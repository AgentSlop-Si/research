# Phase 6 Fourier graph reuse

This continues the supplied Phase 4 engine, Phase 5 dispatcher, and projected
relation-view update. It adds a graph planner for related versions, a compressed
Fourier correction for edits on a cyclic coset, and a fix for the projected
view's retained-history scan.

Read **[RESEARCH.md](RESEARCH.md)** for proofs, measured wins and losses, model
boundaries, and the comparison with the linked integer-multiplication project.
All reported new timings are generated by the included scripts.

## What changed

- **Choose a reuse parent across versions.** A minimum spanning forest can use
  another version's spectrum or start a new native FFT. Its weights are measured
  estimates. Sparse producer-supplied candidate links avoid all-pairs discovery.
- **Use support geometry.** Regularly spaced edits have a small quotient DFT.
  For 64 positions on a length-262,144 grid, the correction can retain 64 complex
  values and generate the full requested output when needed.
- **Verify the graph reasoning.** Exact small-field identities, independently
  traced butterfly dependencies, exhaustive small-graph optimization checks,
  and numerical comparisons cover the new routes.
- **Repair projected replay.** `projected_fourier.py` now reads just the H new
  events. It also counts retained numeric event fields in its storage report.
- **Keep the previous interfaces.** `GraphRelationFFT` extends the supplied
  Phase 5 class; shifted and multiple-base states retain its individual route.

These are workload-specific enhancements built from known Fourier and graph
ideas. They do not establish a new fresh-input FFT or multiplication exponent.

## Run

Python 3.10 or newer, NumPy and SciPy:

```bash
pip install -r requirements.txt
python run_all_checks.py
python demo.py
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python benchmark_graph.py --repeats 5
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python benchmark_history.py

```

The checked runtime is recorded in `results/benchmark_graph.json`. The benchmark
scripts overwrite only their corresponding result files. Wall times depend on
the machine; the algebraic tests and graph certificates do not depend on speed.

## Extend the existing Phase 5 states

```python
import numpy as np
from relation_adapter import GraphRelationFFT

engine = GraphRelationFFT()
root = engine.register(np.arange(65536, dtype=float))
a = root.fork().edit(9, 2)
b = a.fork().edit(21, -3)
c = b.fork().edit(37, 1)

# Every row is a separate full rFFT. Candidate indices refer to [a, b, c].
outputs, plan, stats = engine.materialize_batch(
    [a, b, c], candidates=[(0, 1), (1, 2)]
)
print(stats)
```

`register()` has already computed the cached base in this example. For a fully
cold measurement, use `graph_reuse.run_graph(base, patches, candidates)`; it
includes metadata ingestion, optional calibration, planning and all transforms.
With a simple known chain, executing that lineage directly is cheaper than
running a general graph optimizer. Avoid the graph route on small or unrelated
inputs. `candidates=None` explicitly requests all-pairs discovery and can be slow.

## Use the correction view

```python
from support_graph import CosetSpectrum

n = 262144
changes = [(3 + 4096*t, float(t + 1)) for t in range(64)]
view = CosetSpectrum.from_changes(n, changes)
assert view.reduced_length == 64
selected = view.frequencies([0, 1, 123, n - 1])
dense_correction = view.materialize()  # n//2 + 1 rFFT bins
```

The compact view describes the **correction**, not the entire base spectrum.
Its construction and dense materialization are separate costs.
