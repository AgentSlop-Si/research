# Combining OpenAI #130 with Relation-Aware Adaptive Fourier Computation

Date: October 9, 2026

## Summary: a conditional, parameterized speedup

OpenAI #130 (September 25, 2026) states that a **fresh, arbitrary, exact** complex DFT of length `b` admits a deterministic algorithm in its unrestricted exact complex-arithmetic model with cost

    A(b) = O(b (log b)^theta (log log b)^(4-theta))

where `theta = log_m (m - Delta/W*) < 1` with `m=10^6`, `W*=2^71`, `Delta=6871402692000000`. Its simpler corollary is

    A(b) = O(b (log(b+2))^(1-delta)), delta = 10^-13.

The theorem includes scheduled arithmetic, root preparation (given an appropriate specified root), and logarithmic-word indexing. It is **not** a finite-precision or bit-complexity result.

By a radix decomposition of the DFT, a *k-sparse correction with known positions* can be transformed using `N/b` length-`b` DFTs and linear additional work, with `b` the least power of two >= `max(k,1)` (assuming `N` is a power of two and `0 <= k <= N`). Thus

    T_sparse(N,k) = O(N + (N/b) A(b))
                  = O(N [1 + (log(k+2))^(1-delta)]).

This improves the classical **input-pruned radix-2** bound `O(N(1 + log(k+1)))` asymptotically when `k` grows, **conditional** on the availability and correctness of OpenAI #130's exact DFT primitive and its model. It does not improve the `1-delta` exponent for worst-case fresh dense inputs; when `k=N`, it merely calls the #130 algorithm on N coordinates.

### Crucial boundaries

- The claimed complexity is a straightforward black-box composition, not an established newly discovered theorem with research priority. Related sparse/pruned Cooley–Tukey decompositions are classical.
- Our Python prototype below **does not implement OpenAI #130**. It uses SciPy/NumPy FFTs only to test the decomposition. Practical performance is frequently worse than a full optimized FFT.
- The exact finite-field NTT test verifies the algebra, **not** #130's complex model or its asymptotic bound.
- Known locations and amplitudes of sparse changes, plus existing cached basis spectra or prior spectrum, are part of the interface. Guessing those relationships from unrelated dense data adds detection time.
- A dense N-output result costs Omega(N) merely to materialize.

## 1. Algebraic derivation with every index accounted for

Let `N=b*m`, with `b` a power of two and `b>=k`. Fix `omega_N=exp(-2*pi*i/N)`. Let `d[0..N-1]` be a vector with `k` nonzero entries (a sparse delta in the dynamic application). The unnormalized DFT is

    Y[u] = sum_{j=0}^{N-1} d[j] omega_N^(j*u).

Write `j=r+b*t` with `0<=r<b`, `0<=t<m`. Write the output index `u=q+m*l` with `0<=q<m`, `0<=l<b`. Then

    Y[q+m*l]
      = sum_r sum_t d[r+b*t] omega_N^((r+b*t)*(q+m*l))
      = sum_r (omega_N^(r*q) * sum_t d[r+b*t] omega_m^(t*q)) omega_b^(r*l).

The cancellation uses `omega_N^(b*m*t*l)=1`, `omega_N^b=omega_m`, and `omega_N^m=omega_b`.

Define the inner partial spectra

    T_r[q] = sum_t d[r+b*t] omega_m^(t*q).

Define the length-b vector for each output residue q:

    C_q[r] = omega_N^(r*q) T_r[q].

Then the full result is exactly

    Y[q + m*l] = DFT_b(C_q)[l].

### Charged work

1. Iterate through the `k` nonzero pairs `(r+b*t, value)`. For each, generate its `m` contributions to `T_r[0..m-1]`. Cost `O(k*m)` arithmetic. Since `b>=k`, `k*m<=N`.
2. Multiply `T_r[q]` by the twiddle `omega_N^(r*q)` and form `C`. At most `N` scalar operations and `O(N)` memory writes. Precompute the N powers of `omega_N` in O(N) exact scalar operations if desired; access by modular integer indices. This means all variable-input scalings use prepared constants.
3. For each of the `m=N/b` values of q, compute one exact length-b DFT. Cost `m*A(b)` including its transform arithmetic and scheduling. Scalar preparation can be reused across all equal-sized calls; pessimistically charging it per call also preserves the displayed big-O bound.
4. Permute all results into index order `u=q+m*l` and optionally add them to a cached reference spectrum. Cost O(N).

Total `O(N + (N/b) A(b))`. Since `k<=b<2*k` for k>=1, use `log(b+2)=Theta(log(k+2))` in the big-O expression. For k=0, the sparse DFT is identically zero; materializing that dense vector costs O(N).

### Root supply

For a single query `(N,k)`, it suffices to provide a primitive root of order divisible by `N` and the polynomial-order root required by #130 for length `b`. The least common multiple has order bounded by `N * 1024 * b^3 <= 1024*N^4`, polynomial in N. Its powers supply both roots. Thus this has the same *kind* of polynomial-order supplied-root assumption as #130, though the order may depend on the supplied sparsity metadata as well as N. Preparing the necessary scalars is charged; no unbounded roots are assumed to arise from rational operations alone.

## 2. Adaptive engine merger

If a spectrum X=F_N(x) is cached and a list of changed positions describes the difference `d=x'-x`, then

    F_N(x') = X + F_N(d).

The correction is computed by the grouped algorithm above. If the data producer directly provides `(index,delta)` metadata, no dense comparison is required. For k=O(1), this is Theta(N), asymptotically optimal for writing the full spectrum.

If `x = B*c + d` where B contains `r` cached basis signals and d is k-sparse with known support, then

    F_N(x) = (F_N(B))*c + F_N(d).

After computing and caching the r basis spectra (at cost `O(r*A(N))` under #130), each query has dense-output work

    O(N*r + N*(1+(log(k+2))^(1-delta)))

in the same arithmetic model. For a batch of M queries:

    O(r*A(N) + M*N*(r+1+(log(k+2))^(1-delta)))

if k is a common upper bound on the residual sparsities. Coefficient metadata is supplied. For arbitrary dense inputs with no known structure, the dispatcher calls the #130 DFT black box. This provides an **adaptive guarantee**, not a stronger unrestricted upper bound.

## 3. Complexity comparisons

| Input condition | Established/conditional bound |
|---|---|
| New arbitrary dense input | #130: `O(N*(log N)^(1-delta))` exact arithmetic, as claimed |
| k-sparse known delta, standard pruned FFT | `O(N*(1+log(k+1)))` |
| k-sparse known delta, #130 as small-DFT oracle | `O(N*(1+(log(k+2))^(1-delta)))` |
| k=O(1), cached reference, dense output | `Theta(N)` |
| r fixed basis signals and k=O(1) known residual | `Theta(N)` after basis spectra are available |
| Fresh unrelated dense signal | No improvement beyond #130 demonstrated |

For `k=(log N)^c`, the hybrid upper bound is `O(N*(log log N)^(1-delta))` (up to constants and a +N term). For `k=exp(sqrt(log N))`, it becomes `O(N*(log N)^((1-delta)/2))`. For k=N, the bound is OpenAI #130's own bound, not an exponent improvement.

OpenAI #130 also provides an exact convolution corollary in this model already. Merely putting the sparse-update scheme inside integer multiplication does not prove a smaller bit-complexity exponent.

## 4. What the prototype demonstrates (and doesn't)

`hybrid_sparse.py` uses the residue decomposition with exact index placement, but NumPy/SciPy FFTs implement the `DFT_b` calls numerically in `O(b log b)`. That means **the shipped Python implementation is not asymptotically faster than O(N log k)**. It is designed to validate correctness, interface compatibility, and practical overhead.

`tests/test_exact_modular.py` checks the decomposition with exact arithmetic modulo 998244353, where 3 is a suitable primitive root generator. The modular transform validates only the algebraic identity; it neither implements nor validates #130's complex arithmetic theorem.

The bundled prior `AdaptiveFFT` engine has a real-to-complex optimized baseline, LRU cache and reuse methods. `adapter.HybridAdaptiveFFT` integrates the new sparse-DTF logic without changing the baseline's ordinary behavior. `benchmark.py` provides reproducible medians for numerical performance.

### Early measurements (this environment)

Using NumPy/SciPy for all inner transforms, not #130: At N=65536, the factorized path was slower than a full SciPy FFT at k=1, 8, 128. Most cost was NumPy exp arrays, allocation and non-contiguous transform memory. These results **must not** be described as practical speedups. They are an existence proof of correct code and a cost accounting experiment for the algebraic decomposition.

## 5. Why no new worst-case exponent follows automatically

1. Unknown exact DFT coefficients and unlimited scalar precision are not a finite fixed-alphabet lookup table. Our finite-field WHT tables cannot be substituted into #130 without changing the algorithm and proving the state representation.
2. A cache of past spectra only helps with repeated or certified related inputs; a fresh arbitrary dense vector can be independent of every cached item.
3. Packed two-real-in-one-complex FFT exploits conjugation of **variable complex results**. #130's input computation permits only complex-linear operations on variable inputs, so the ordinary packing extraction cannot automatically be counted as an allowed #130 operation without extending its model or giving another construction.
4. #130's proof uses enormous fixed constants (its network has `m=10^6`, `W*=2^71`) and has no practical crossover estimate. A generic plug-in to FFTW does not currently exist.
5. For true integer multiplication one must pay for finite representations, precision, data movement and final rounding; #130 expressly does not provide that bit-complexity result.

## 6. Further testable directions

- Implement compiled/vectorized structured sparse-update path with twiddle caches, and compare **complete** wall-clock cost to FFTW and eFFT.
- Implement a backend-independent exact scalar circuit API that could accept a verified #130 implementation when one exists; document root preparation and indexing requirements.
- In an end-to-end application, propagate true producer metadata (exact edited indices, shifts, basis coefficients), instead of scanning for relationships.
- For convolution update streams: a single coefficient edit in one factor changes the product by a shifted, scaled copy of the other factor, itself O(N) dense-update work. This may be simpler than recomputing any DFT.
- Study whether the #130 base circuit can be reorganized to support efficient output-subset and dynamic state updates directly. That is an open engineering/theoretical project, not established by the simple black-box composition above.

## 7. Practical prepared-point updates (complementary to the #130 hybrid)

The `prepared_update.py` module addresses a different but useful workload: an upstream producer tells the engine that **the same input position** receives a sequence of known real-valued changes. We precompute its N/2+1 Fourier phase factors once, then maintain the compact real-FFT spectrum using

    F(x + delta*e_t)[q] = F(x)[q] + delta*exp(-2*pi*i*t*q/N).

This is a classical identity, not a new exact-DFT algorithm. It takes `Theta(N)` work for each dense-output update; it is numerically approximate (SciPy/rFFT). The benchmark below counts **one initial rFFT and phase precomputation** on the adaptive side before performing 40 edits. The baseline computes a fresh SciPy rFFT for each of the 40 edited inputs. All 40 updated spectra are constructed, even though the benchmark does not retain all of them. Values are local timings, median of 3 repetitions; the last cached spectrum was numerically compared against a fresh transform.

| N | 40 full SciPy rFFTs | 1 initial rFFT + phase prep + 40 updates | Ratio | Max absolute difference at final step |
| ---: | ---: | ---: | ---: | ---: |
| 16,384 | 3.36 ms | 0.73 ms | 4.58x | 8.5e-13 |
| 65,536 | 15.75 ms | 2.41 ms | 6.53x | 5.4e-12 |
| 262,144 | 100.93 ms | 9.41 ms | 10.72x | 2.5e-11 |
| 1,048,576 | 547.15 ms | 53.13 ms | 10.30x | 1.5e-10 |

These timings do **not** measure an implementation of #130. They demonstrate that sharing with producer-supplied metadata is worthwhile for real workloads, and they count the relevant initial work. A fixed-location phase cache costs `Theta(N)` memory; maintaining phases for too many separate edit locations would violate a small cache budget. Accumulated floating-point error, copy semantics, allocations and cache policy require engineering attention.

## 8. Sign convention

This prototype uses the conventional numerical **negative-sign** DFT `exp(-2*pi*i*j*k/N)`. OpenAI #130 defines its canonical Fourier matrix using **positive-sign** roots. The negative-sign DFT can be obtained by running the positive-sign algorithm and reversing the nonzero frequency indices (a deterministic O(N) permutation). The sign convention does not change the asymptotic bound, but a real backend adapter must implement it explicitly.
