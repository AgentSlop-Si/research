# Negative chirp complete certificate chain

This self-contained bundle contains the original negative-chirp impossibility theorem, its separate independent whole-theorem review, and the complete exact certificate chain. The accepted theorem applies only to odd N = 5m with gcd(m, 5) = 1 and N congruent to 3 modulo 4, for every primitive Nth root. In the precise fixed-coordinate representation grammar stated in THEOREM.md, the matrix B = (F inverse + A) inverse is not the sum of two diagonal-endpoint Hamiltonian Green terms. Singular or identically zero diagonal masks and zero edge weights remain allowed; Green denominators must be legal. There is no lower-size cutoff. The exceptional set is empty within this exact original eligible negative family.

The evidence partitions all 576 ordered pairs of five-cycles: 384 baseline row exclusions and 192 residual pairs covered by 28 symmetry representatives. The algebraic leaves exclude the original closed necessary system for every positive real parameter, both imaginary square-root signs and every primitive fifth root. That larger algebraic domain is not an extension of the full-matrix theorem to other families.

This is not a claim about the positive-Gauss family, moduli divisible by 25, independent endpoint permutations, unrestricted Fourier algorithms, FFT complexity or speedups, a construction with three terms, an exact three-term minimum, historical novelty, or completion of any broader research agenda.

## Verify and reconstruct

Use Python 3.12 with SymPy 1.14.0 already installed. Verification and materialization use only the Python standard library. No network access is required.

    python -B verify.py
    python -B materialize.py ../negative-chirp-sources

Choose a reconstruction directory that does not already exist. The source tree has the original relative directory structure, including all manifest-bound inert snapshots. To avoid storing repeated snapshots multiple times, objects/ holds one copy of each distinct public file. This is storage deduplication only: materialize.py reconstructs every logical file; no mathematical payload is dropped. Historical recursive ZIP releases are not embedded.

ALIASES.json separately documents six exact-byte copies needed to complete the nested frozen-candidate inventories in three reviews and their fusion snapshots. Their outer inventories omitted a copied review-manifest file, but the included frozen author manifests explicitly bind its exact bytes. The materializer copies that already-included accepted manifest to the declared locations without changing any existing file. These six added runnable aliases are distinct from the 3,000 original source-map entries; the alias metadata is independently pinned and checked.

## Reproduce the calculations

    python -B replay.py --jobs 2 --output ../negative-chirp-replay.json

The bounded runner copies the entire logical source tree into a fresh directory for each independent group, executes the unchanged scientific programs, deletes requested result files before regeneration, compares every mathematical field, and leaves the released bundle unchanged. It runs at most three groups concurrently, with 1,800 seconds wall time, 1,200 seconds CPU time and 4 GiB address space per command. The default is two concurrent groups. Assertions must remain enabled.

Some older reviewer result records contain measured runtimes. Those fields necessarily vary. The receipt distinguishes literal byte-identical outputs from exact mathematical comparisons with only named runtime or root-locator metadata rebound to the frozen values. This rebinding occurs only after equality of every other field, so later SHA-bound checks use the same frozen certificate bytes. It is not evidence that fresh runtimes equal historical ones.

Use --groups followed by one or more source directory names to replay a subset. The final author fusion and the independent whole-theorem review have their own groups. Running their programs directly is possible from the reconstructed tree, subject to the disclosed operational inventory adaptation below.

## Original bytes and public locator projections

All frozen manifests, mathematical reports, scientific programs, polynomials, determinants, norms and substantive certificates are preserved byte for byte. A small, fully listed set of operational records contains public root-locator substitutions. These are historical traceback filenames, input-source locators, or provenance/recovery-location descriptions, not mathematical data. SOURCES.json records both original and public hashes and byte counts, the substitution kind and count, and every logical occurrence. The original bytes were checked against their frozen manifests before projection. The public bundle does not reconstruct or pretend to contain those original locator bytes.

Public integrity is checked against MANIFEST.json and SEAL.json. Original membership is checked separately against original frozen manifests and the source map. The explicitly disclosed portable_check.py adapter is used only for old inventory routines that require original file identities: it first verifies the sealed public bundle, then adapts file SHA-256 and file-size calls for the exact known projected bytes to their recorded original identity. Ordinary files retain normal hash and size behavior. No stored source, polynomial expression, mathematical comparison or acceptance pin is edited. Adapter receipts list every syntactic substitution and every projected identity used.

An adapter-mapped identity is a provenance assertion about a previously verified original, not the literal SHA-256 of the public projected file. The independent mathematical review binds the original frozen candidate, not this distribution projection. The separate packaging validation checks the actual public bytes, exact projection differences, replay results, archive paths and CRCs, and rejection of package tampering.
