# Validation evidence and its limits

The original accepted author/reviewer manifests remain the primary mathematical certificate chain. The final public verifier separately binds those exact acceptance pins, the narrow original-family scope, the full public source map, the seven operational locator-projection byte sets, and the six exact-byte materialization aliases.

The validation records distinguish three forms of new execution.

1. The preliminary full leaf orchestration executed the independently reviewed programs against the earlier source map. Its missing nested-manifest locator caused that orchestration to fail overall. Completed commands emitted PASS only after successful exit and comparison of every declared output. The aggregate rich result was not written because of that failure. OBSERVED_LEAF_COMPARISONS.json therefore records only individually observed post-comparison completions, exact command/source/expected-output identities and the unchanged-source bridge. It does not invent fresh runtime-byte hashes, claim an overall preliminary PASS, or claim that this was a cold final-archive execution. The captured stderr and the exact preliminary harness/source-map bytes are retained for audit. Any public log-locator projection is separately disclosed.

2. LEAF_SIX_FINAL_REPLAY.json is a durable new replay of the entire repaired locator-dependent group from the alias-complete final source map. The scientific program bytes are unchanged. It records actual expected/replayed hashes and confirms that all original materialized files and all six aliases remain unchanged. Differences in older runtime metadata are expressly distinguished from byte-identical outputs.

3. The independent packaging audit cold-extracted the sealed public candidate, checked original/public byte mappings and alias closure, rejected package mutations, and reran all 25 repaired leaf-six commands plus the six fusion and independent whole-review entry points with original execution locations and network access denied. Its receipts explicitly identify the tested candidate archive. Added validation records change the final containing ZIP checksum, not the pinned scientific source objects or runnable alias/harness content. A detached final validation receipt binds the ultimate containing ZIP; no receipt inside this ZIP purports to contain its own ZIP checksum.

SOURCE_BRIDGE.json proves that every preliminary source-map entry and original package pin is present unchanged in the final accepted source map. Exact preserved preliminary harness files are evidence, not the supported public replay entry point. Use the top-level replay.py for a new complete run.

Replays have defined resource limits and use installed Python 3.12 / SymPy 1.14.0 only. Historical author/reviewer timing receipts in the source tree remain historical, not new executions and not performance evidence.
